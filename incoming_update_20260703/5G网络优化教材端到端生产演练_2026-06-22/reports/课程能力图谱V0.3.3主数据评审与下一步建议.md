当前基线：`reports/课程能力图谱主数据合并说明V0.3.3.md` 及四张V0.3.3主数据表  
评审结论：V0.3.3通过结构和版本化合并门禁，可以作为当前推荐主数据基线；但字段治理仍不够稳定，不建议直接进入批量拆全书、页面生产或工具链模块拆解。下一步建议优先制定V0.4字段治理升级方案。

## 3. 已经稳定的部分

### 3.1 版本化增量合并机制成立

从V0.3到V0.3.3，主数据已经完成三轮普通任务增量验证：

| 版本 | 增量任务 | 验证类型 | 关键修订 |

| V0.3.1 | P2-T2 5G网络测试问题处理 | 问题处理类小任务 | 旧版六节点偏碎，改为四个稳定能力节点 |

这说明当前机制已经能承接不同任务类型，并能通过内部评审发现“过碎”“过粗”“关系误写成线性流程”等问题。

### 3.2 能力节点和资源卡片边界更清楚

三轮验证共同确认一条主规则：

> 课程能力图谱节点承载稳定职业任务，具体设备、参数、截图、表格字段、投诉类型、话术、案例和操作步骤优先下沉为资源、活动、评价或治理对象。

这一规则目前是有效的。P2-T2没有把GPS、逆变器、软件授权等检查项升格为主节点；P3-T3没有把公式、参数项、截图逐项升格为主节点；P1-T3没有把普通投诉、紧急投诉、升级投诉、话术条目和信息表字段逐项升格为主节点。

## 4. 仍不稳定的部分

### 4.1 字段治理不足以支撑复杂风险

V0.3.3中，节点风险分布如下：

| 风险等级 | 节点数 |
| --- | ---: |
| high | 50 |
| medium | 48 |
| low | 34 |

其中P1-T3五个新增详细能力节点全部包含 `data_security` 审核类型，且N02、N04、N05为高风险节点。P1-T3新增风险包括：

1. 客户姓名、电话、地址、工单号等个人信息；
2. 电话录音和客户授权；
3. 投诉升级边界；
4. 服务承诺和处理时限；
5. 客户反馈表达；
6. 真实案例脱敏与教学模拟边界。

V0.2字段规范已有 `review_required_type=data_security`，但这个字段只能说明“需要数据安全审核”，不能说明为什么需要、审核什么、是否已经脱敏、是否涉及录音、是否已取得授权、是否存在服务承诺风险。

因此，如果现在继续批量拆任务，大量风险会继续被写入 `notes` 或 `review_notes`，后续难以自动筛查和平台治理。

### 4.2 专业风险类型枚举不覆盖P1-T3新增风险

V0.2的 `professional_risk_type` 枚举包括：

```text
none;threshold;case_logic;conclusion;terminology;procedure;data_source;simulation_validity;tool_screenshot;signal_analysis
```

该枚举适合P2/P3/P4/P5/P6中的指标、参数、截图、信令和结论类风险，但不充分覆盖P1-T3的客户沟通类风险。当前P1-T3已经使用了 `privacy`、`communication` 等值，但这些并不在V0.2枚举中，说明字段规范和实际主数据已经发生偏离。

这不是简单的数据错误，而是需求变化暴露出的规范升级信号。

### 4.3 资源活动评价挂接能成立，但质量门禁仍偏粗

V0.3.3资源活动评价挂接表中：

| 挂接类型 | 数量 |
| --- | ---: |
| resource_card | 111 |
| assessment_output | 41 |
| media_asset_review | 32 |
| overall_prototype_resource | 9 |

挂接机制是成立的，但目前仍存在三类质量风险：

1. `resource_card` 只能说明“有资源”，不能说明资源是否由原文直接抽取、AI改写、教学模拟、脱敏生成或专业复核生成；
2. `assessment_output` 只能说明“有产出”，不能说明该产出能否自动评价、教师评价、专家评价或必须数据安全审核后评价；
3. `media_asset_review` 已能治理截图和图片，但P1-T3这类文本、录音、表单、话术资源也需要类似的精细审查对象。

所以挂接表可以继续作为主数据基线，但还不适合直接驱动正式资源包生产。

### 4.4 内部评审仍依赖人工判断，尚未形成可执行门禁

P2-T2、P3-T3、P1-T3三轮增量都经历了“结构校验通过，但内部评审发现关键问题”的过程。

这说明：

1. 结构校验已经有效；
2. 教学结构和风险治理门禁仍主要依赖人工报告；
3. 还没有把“过碎、过粗、关系误写、风险字段缺失、资源越界”等判断转成可执行检查规则。

如果要走向工具链，下一步必须把这些评审经验沉淀到字段规范和门禁规则中，而不是继续靠人工逐篇判断。

## 5. 是否可以继续拆第四类任务

可以继续拆，但不建议现在马上拆。

理由如下：

1. V0.3.3已经证明主数据能承接第三类普通任务，继续拆第四类任务当然可行；
2. 但P1-T3已经暴露出字段规范不足，如果不先升级字段，第四类任务仍会把新风险写入备注；
3. 继续增量会扩大数据量，但不一定提高机制稳定性；
4. 当前最有价值的工作不是再证明“能拆”，而是把“怎么治理复杂风险”做成稳定字段和门禁。

因此，下一步不建议直接进入第四类任务增量。

## 6. V0.4字段治理升级建议

建议先制定 `reports/课程能力图谱字段规范V0.4升级方案.md` 和 `reports/课程能力图谱字段规范V0.4字段清单.csv`。

V0.4不应大改现有主数据结构，而应在V0.2/V0.3主数据基础上补齐风险治理字段。建议至少新增或明确以下字段组。

### 6.1 数据安全字段组

| 建议字段 | 含义 | 示例枚举 |
| --- | --- | --- |
| `contains_personal_info` | 是否包含个人信息 | yes;no;not_applicable |
| `personal_info_type` | 个人信息类型 | name;phone;address;location;work_order_id;recording;terminal_id;customer_level;other |
| `anonymization_required` | 是否必须脱敏 | yes;no;pending |
| `anonymization_status` | 脱敏状态 | not_needed;required;completed;pending;blocked |
| `authorization_required` | 是否需要客户授权 | yes;no;pending |
| `authorization_status` | 授权状态 | not_applicable;teaching_simulated;consent_required;consent_obtained;not_available |
| `recording_involved` | 是否涉及电话录音或音频 | yes;no |

### 6.2 服务表达与承诺边界字段组

| 建议字段 | 含义 | 示例枚举 |
| --- | --- | --- |
| `service_commitment_risk_type` | 服务承诺风险类型 | none;time_limit;effect_promise;responsibility;compensation;escalation;uncertain_conclusion |
| `customer_communication_review_type` | 客户沟通审核类型 | none;tone;commitment;privacy;liability;escalation |
| `communication_expression_status` | 反馈表达状态 | draft;needs_editorial_review;reviewed;disabled |
| `external_statement_allowed` | 是否允许作为对外话术 | yes;no;teaching_only |

### 6.3 案例真实性与教学模拟字段组

| 建议字段 | 含义 | 示例枚举 |
| --- | --- | --- |
| `case_authenticity_type` | 案例真实性类型 | real_desensitized;teaching_simulation;ai_created;source_adapted;unknown |
| `case_applicability_boundary` | 案例适用边界 | 文字说明 |
| `source_sensitivity_level` | 来源敏感等级 | low;medium;high |
| `publishability_status` | 可发布状态 | not_ready;internal_review;ready_after_redaction;ready_after_expert_review;approved |

### 6.4 门禁状态字段组

| 建议字段 | 含义 | 示例枚举 |
| --- | --- | --- |
| `professional_gate_status` | 专业复核门禁 | not_required;pending;revision_required;passed |
| `editorial_gate_status` | 编辑复核门禁 | not_required;pending;revision_required;passed |
| `data_security_gate_status` | 数据安全门禁 | not_required;pending;revision_required;passed |
| `media_gate_status` | 媒体门禁 | not_required;pending;revision_required;passed |
| `student_text_gate_status` | 学生正文门禁 | not_started;draft;review_pending;passed |
| `platform_gate_status` | 平台接口门禁 | not_started;pending;passed |

这组字段的价值是把“仍未通过哪些门禁”从自然语言备注转为可筛选、可统计、可阻断的状态。

## 7. 对既有V0.3.3主数据的处理建议

V0.4形成后，不建议立刻重做全部主数据。建议分三步处理：

1. 先制定V0.4字段规范和字段清单；
2. 选取P1-T3、P3-T3、P4-T2三个代表任务做字段回填试验；
3. 回填试验通过后，再决定是否批量迁移V0.3.3主数据。

三个代表任务的价值不同：

| 任务 | 回填价值 |
| --- | --- |
| P1-T3 | 验证数据安全、客户授权、服务表达和投诉案例治理 |
| P3-T3 | 验证公式、参数、截图、媒体审查和专业口径治理 |
| P4-T2 | 验证深样章、学生正文、教师材料、评价量规和页面呈现门禁 |

这种小范围回填比直接全表改字段更稳。

## 9. 最终建议

当前不建议直接继续第四类任务增量，也不建议进入页面生产或工具链模块拆解。

推荐下一步是：

1. 制定 `reports/课程能力图谱字段规范V0.4升级方案.md`；
2. 制作 `reports/课程能力图谱字段规范V0.4字段清单.csv`；
3. 用P1-T3、P3-T3、P4-T2做小范围字段回填试验；
4. 回填试验通过后，再决定第四类任务增量验证对象。

核心判断是：V0.3.3已经证明主数据机制阶段性成立，但P1-T3暴露出的数据安全和服务表达风险说明字段治理还不够细。现在最应该做的是把这些风险沉淀为可执行字段和门禁，而不是继续扩大任务数量。
