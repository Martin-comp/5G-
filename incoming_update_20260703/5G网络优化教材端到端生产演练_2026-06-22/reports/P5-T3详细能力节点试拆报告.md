# P5-T3详细能力节点试拆报告

生成日期：2026-06-23  
试拆对象：项目五 / 任务3：5G全网性能提升验证  
对应图谱版本：课程能力图谱V2优化版  
执行规范：课程能力图谱字段规范V0.1  
配套结构化表：`reports/P5-T3详细能力节点字段表.csv`

## 1. 试拆结论

本轮选择 `P5-T3 任务3 5G全网性能提升验证` 作为第二个非P4-T2任务试拆对象。

结论：**P5-T3适合作为V0.1字段规范的第一次应用验证，试拆结果有条件成立。**

成立点：

1. P5-T3能检验 `AU-09 全网性能提升与复测` 是否成立；
2. P5-T3能把P4-T2“单任务验收结论”向后扩展为“全网指标持续提升验证”；
3. P5-T3能检验字段规范V0.1中的前置/后续关系、资源卡片ID、学习记录事件、评价量规和审核状态是否足够支撑试拆；
4. P5-T3能暴露一个重要边界：它可以连接 `JP-07 持续提升与复杂复盘`，但还不能完全证明 `AU-10 信令分析与复杂问题复盘` 成立。AU-10仍需后续P6任务验证。

限制点：

1. 原教材P5-T3材料较短，但图片和案例很多，仍偏“案例罗列 + 仿真截图”；
2. 原文对“五类性能提升验证”的数据口径、判断阈值和报告结构说明不足，需要后续教学化补强；
3. 所有涉及RSRP、SINR、掉线、接入失败、吞吐量、PDU会话、A2/A3事件等专业判断，仍需通信专业教师复核；
4. 本轮只是图谱节点试拆和字段规范验证，不是学生端教材正文或可运行页面。

## 2. 选择P5-T3的理由

P2-T3已经验证了“测试数据分析”链，P4-T2已经验证了“优化结果验收”链。P5-T3位于项目五“全网性能提升”末端，天然适合检验以下问题：

1. V2是否能从单点任务验收扩展到全网指标持续提升；
2. `JP-07 持续提升与复杂复盘` 是否有合理的教学承载任务；
3. `AU-09 全网性能提升与复测` 是否能够拆成可学习、可训练、可评价的学生动作；
4. 字段规范V0.1是否能支撑更复杂的节点记录，而不是只记录“名称、资源、活动、评价”。

本轮不优先选择P4-T3的原因仍然成立：P4-T3主要检验职业表达能力，距离P4-T2过近，迁移难度较低。P5-T3更能检验课程能力图谱后半段是否连得起来。

## 3. 原教材内容诊断

P5-T3原文主要包含以下内容：

1. 任务导入：性能提升方案制定和实施后，如何验证方案有效性；
2. 任务要求：完成接入类、保持类、移动性类、资源类、可用类五类性能提升方案验证；
3. 知识准备：验证数据源包括网管平台、大数据平台、测试软件路测、用户回访；
4. 任务实施：使用仿真软件和数据中心界面提取优化前后指标，导出数据并用图表呈现；
5. 随堂测试：提取优化前后的掉线率、接通率并对比；
6. 经典案例：接入类、保持类、移动性类、资源类、可用类验证案例；
7. 直击难点：掌握接入全网性能提升方案验证总体方法、验证途径、验证报告结构和呈现方式；
8. 网优趣味课堂：按总体组、专项组、前台测试组分工完成指标提取、短板分析、方案制定、实施和验证。

诊断判断：

1. 原教材P5-T3的职业价值较高，能体现真实网优工作中的“实施后复测、未闭环再优化”；
2. 原文对验证数据源的说明有价值，适合转化为“验证路径选择”学习活动；
3. 五类性能提升案例很适合做多案例对照，但不宜让学生一次读完所有截图；
4. 原仿真系统截图和大量信令/路测图不能裸用，至少需要重绘、标注或改造成教学化图表；
5. 本任务应先形成能力节点和字段化数据，不急于制作完整页面。

## 4. 图谱挂接位置

P5-T3在V2中不应只是“项目五任务3”，而应挂接到以下位置：

| 层级 | 节点 | P5-T3角色 |
| --- | --- | --- |
| 岗位工作过程 | JP-07 持续提升与复杂复盘 | 主挂接位置，验证全网性能提升是否闭环 |
| 岗位工作过程 | JP-06 验证效果与表达结论 | 前置经验来源，承接P4-T2验收结论表达 |
| 能力单元 | AU-09 全网性能提升与复测 | 主能力单元 |
| 能力单元 | AU-08 优化报告与职业表达 | 支撑验证报告表达 |
| 后续关联 | AU-10 信令分析与复杂问题复盘 | 对未闭环或复杂问题形成后续入口 |

客观判断：P5-T3能充分验证 `AU-09`，但只能部分连接 `AU-10`。若要证明复杂信令复盘链成立，还需要后续P6任务试拆。

## 7. 资源与活动转化建议

P5-T3后续适合转化为以下资源：

1. **验证口径卡**：说明验证对象、范围、基线、达成口径和不能证明的边界；
2. **数据源选择图**：把网管平台、大数据平台、路测复测、用户回访的适用场景做成选择表；
3. **KPI前后对比表**：接通率、掉线率、切换成功率、吞吐量、可用性等指标的前后对比；
4. **五类效果判断卡**：接入类、保持类、移动性类、资源类、可用类案例分组；
5. **未闭环判断互动**：让学生判断“已改善但未达标”“证据不足”“需要复测”“需要信令复盘”；
6. **全网性能验证报告模板**：形成“验证目标、数据来源、对比结果、结论边界、后续动作”的报告结构；
7. **角色协作任务单**：对应原文网优趣味课堂中的总体组、专项组、前台测试组。

## 8. 字段规范V0.1应用情况

本轮已按V0.1字段清单形成 `reports/P5-T3详细能力节点字段表.csv`。

字段应用结论：

1. 7个节点均填写了R1字段；
2. 节点层级统一为 `detail_capability`；
3. 主挂接岗位过程统一为 `JP-07`；
4. 主挂接能力单元统一为 `AU-09`；
5. 资源类型、学习活动类型、审核状态、来源类型均使用受控枚举；
6. 每个节点均设计了学生端标题、学生动作、学生产出、完成标准和学习记录事件；
7. 审核状态全部保留专业复核或媒体审查风险，没有写成已审核通过。

字段规范暴露的问题：

1. `job_process_id` 当前只适合记录主挂接过程，不能充分表达P5-T3同时承接JP-06、连接JP-07的特点，后续V0.2可考虑增加 `secondary_job_process_ids`；
2. `ability_unit_id` 当前只适合记录主能力单元，P5-T3同时涉及AU-08报告表达和AU-10复盘入口，后续可增加 `secondary_ability_unit_ids`；
3. `event_payload_summary` 是R3字段，但对后续平台数据回收很关键，P5-T3试拆时已经建议填写。

## 9. 质量边界

本轮试拆仍是图谱方法和字段规范验证，不是正式教材发布稿。

必须保留以下边界：

1. 原教材中的仿真系统截图、信令截图和路测图不能直接进入正式学生页面；
2. RSRP、SINR、掉线率、接通率、吞吐量等指标口径和阈值需专业复核；
3. 五类性能提升案例可作为教学案例，但不能伪装成真实项目数据；
4. P5-T3可以验证AU-09，但不能替代P6对AU-10信令分析能力的试拆；
5. 当前没有形成学生端教材正文、教师课堂脚本或可运行页面。

## 10. 本轮对V2和字段规范的验证结论

P5-T3试拆说明：

1. V2能覆盖课程后半段“持续提升”任务，不只服务P4-T2和P2-T3；
2. `JP-07` 和 `AU-09` 的设置基本成立；
3. 字段规范V0.1可以支撑比旧12列表更细的节点治理；
4. P5-T3暴露出“主挂接 + 次级挂接”的需求，字段规范V0.2应考虑补充；
5. 课程能力图谱仍应继续按“少量任务试拆 -> 对比评审 -> 修订规范”的方式推进，不宜直接批量拆全书。

结论：**P5-T3第二试拆有条件成立。下一步应对P2-T3、P4-T2、P5-T3三类任务做横向对比评审，判断V2主链和字段规范V0.1是否需要升级为V0.2。**
