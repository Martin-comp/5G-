# 阶段2项目四闭环轻量补强记录V0.1

生成日期：2026-06-26  
依据文件：`reports/阶段2项目四闭环内部全量评审报告V0.1.md`  
适用范围：阶段2项目四闭环样本收口后，进入第二项目级闭环复制验证前的规则收口。

## 1. 定位

本记录不是新的页面制作计划，也不是对项目四原型的大修方案。

它的作用是把阶段2内部全量评审发现的可复用规则固定下来，防止下一阶段复制验证时出现两种偏差：

1. 把P4-T1/P4-T3轻量样稿误认为正式深样章；
2. 直接进入工具链拆解，而没有先验证项目级闭环方法是否能迁移到第二个项目。

本记录形成后，阶段2项目四不需要继续大改。下一步应进入第二项目级闭环复制验证，优先对象为项目二。

## 2. 当前项目四样本保留判断

项目四样本保留当前版本，不启动大修。

理由：

1. P4-T1、P4-T2、P4-T3之间的项目级闭环已经成立；
2. P4-T1和P4-T3已经超过大纲草稿水平，具备轻量教材样稿价值；
3. P4-T2仍是质量锚点，能够代表深样章目标；
4. 当前阶段最需要验证的是方法迁移，不是继续把项目四单点打磨到更深；
5. 如果继续打磨项目四，会推迟对“是否可复制”的关键验证。

但必须保留以下边界：

1. P4-T1/P4-T3不能称为深样章；
2. 项目四不能称为正式教学验证通过；
3. 项目四不能称为出版社平台发布准备完成；
4. 项目四不能作为工具链模块拆解的充分依据；
5. 专业复核、媒体审查、真实试看和平台接口仍未完成。

## 3. 项目级闭环最小结构

后续任何项目级闭环复制验证，至少应包含以下结构。

| 要素 | 最低要求 | 说明 |
| --- | --- | --- |
| 项目定位 | 说明本项目解决什么岗位任务 | 不能只写项目标题。 |
| 任务角色 | 每个任务要说明在项目链中的角色 | 例如入口、判断、输出、支撑、分支、回流。 |
| 输入证据 | 说明本任务接收哪些前序材料 | 不允许任务之间只靠目录顺序连接。 |
| 学生动作 | 说明学生要做的可检查动作 | 例如分类、标注、排序、归集、改写、提交。 |
| 学生产出 | 每个任务至少有一个可评价产出 | 产出应能进入下一任务或形成评价依据。 |
| 回流关系 | 说明证据不足或判断错误时回到哪里 | 项目闭环不能只有单向流程。 |
| 深样章锚点 | 至少指定一个任务作为质量锚点 | 其他任务可先为轻量样稿。 |
| 图谱挂接 | 任务、资源、活动、评价能回挂节点 | 未挂接内容不能进入正式样本。 |
| 教师使用 | 说明教师如何带教、讲评和验收 | 不能只有学生端材料。 |
| 出版门禁 | 标明专业、媒体、平台、数据安全状态 | 不能因页面可运行就写成可发布。 |

## 4. 轻量教材样稿最低要求

轻量样稿不是深样章，但也不能退回大纲。后续项目复制验证中，轻量样稿至少应满足九项要求。

1. 有学习情境：用一个具体案例或工作场景引出问题；
2. 有核心问题：让学生知道本任务要解决什么；
3. 有学习步骤：一般控制在3到5个关键动作；
4. 有表格或图示：至少有一个能帮助学生整理证据的结构化支架；
5. 有学生产出：必须交付学习单、记录表、结论段、清单或报告片段；
6. 有完成标准：说明做到什么程度算完成；
7. 有教师讲评点：说明教师应重点追问什么；
8. 有风险门禁：标明专业、媒体、数据安全、授权或发布边界；
9. 有图谱绑定：说明对应的能力节点、资源、活动和评价产出。

轻量样稿不强制包含：

1. 完整前端互动；
2. 学生填写保存；
3. 即时自动反馈；
4. 二次修正闭环；
5. 完整教师课时脚本；
6. 可直接上传出版社平台的资源包。

这些属于深样章、正式教学样章或平台化样本阶段。

## 5. P4-T1/P4-T3后续不大修的条件

P4-T1和P4-T3当前可作为轻量样稿保留，但后续引用时必须附带以下说明：

| 任务 | 可保留内容 | 不可夸大内容 | 后续若升级为深样章应补什么 |
| --- | --- | --- | --- |
| P4-T1 优化方案实施 | 情境、边界表、参数依据、实施步骤、回退检查、复测交接 | 不能写成学生已具备真实工程变更能力 | 参数标注互动、责任边界判断、回退条件反馈、变更记录填写和二次修正 |
| P4-T3 优化报告输出 | 报告口径、证据链、结构组织、结论边界、典型案例、沟通修订 | 不能写成学生已具备真实客户交付能力 | 证据归集活动、报告段落重组、结论改写反馈、越权承诺检查和报告样稿生成 |

## 6. 教师视图最低要求

阶段2教师视图当前只是带教摘要。第二项目复制验证时，教师视图至少应比摘要多三类信息：

1. 本项目的课堂组织路径：先做什么，再做什么，最后如何验收；
2. 每个任务的讲评焦点：教师重点追问学生哪些依据、边界或错误；
3. 学生产出检查方式：哪些产出需要收集，按什么标准判断。

不要求第二项目马上形成完整教师手册，但不能只写“教师可查看项目结构”。

## 7. 资源中心最低要求

第二项目复制验证中的资源中心，至少要保留四类状态：

1. 已有样稿；
2. 待专业复核；
3. 待媒体重绘或替换；
4. 不可发布或仅作内部分析。

资源中心必须避免三种错误：

1. 把原教材截图默认写成可发布；
2. 把教学模拟数据写成真实项目数据；
3. 把资源标题列表写成资源治理完成。

## 8. 出版/编辑视图最低要求

第二项目复制验证中的出版/编辑视图，应至少说明以下边界：

1. 是否只是挂接位置原型；
2. 是否已有资源包字段样例；
3. 是否已有质量检测项；
4. 是否接入出版社平台接口；
5. 是否有使用数据回收和版本更新设计；
6. 哪些事项会阻断正式发布。

当前阶段只要求说明边界，不要求真实接入平台。

## 9. 第二项目选择建议

优先选择项目二作为第二个项目级闭环复制验证对象。

理由：

1. 项目二与项目四不同，能验证测试采集、异常处理、数据分析类任务，而不是继续验证报告表达类任务；
2. 项目二已经有主数据基础，P2-T1、P2-T2、P2-T3均有详细节点和项目链条评审依据；
3. 项目二内部结构不是机械线性流程，而是“测试采集主线 + 异常处理分支 + 数据分析输出”，适合检验项目级闭环表达能力；
4. 项目二能暴露现场测试、LOG数据、软件截图、位置数据、测试安全和数据完整性等不同风险；
5. 项目二与项目四存在后续关联，能验证“测试数据如何支撑优化验证”的跨项目衔接。

项目二复制验证不应直接写页面。更稳的顺序是：

```text
项目二闭环实施计划
-> 项目二V0.3.13闭环映射表
-> 项目二轻量教材样稿
-> 项目二资源活动评价和教师材料
-> 项目二闭环原型接入
-> QA和治理
-> 与项目四对比抽取共性流程
```

## 11. 最终判断

阶段2项目四闭环可以保留当前状态，作为第一个项目级闭环样本。

下一步应先用本记录和检查表固化规则，然后进入项目二闭环实施计划和映射表制作。

当前仍不得进入：

1. 生产工具链模块拆解；
2. 正式教学发布；
3. 出版社平台接口对接；
4. 全书批量页面生产；
5. 对外宣称完整数字教材完成。
