# P4-T1基于V0.3.4主数据补拆验证实施计划

生成日期：2026-06-25  
适用对象：项目四 / 任务1：5G网络优化方案实施  
当前基线：课程能力图谱主数据V0.3.4  
计划定位：第五类普通任务增量验证前置计划，不是正式补拆结果，不直接改写主数据。

## 1. 当前结论

P4-T1可以作为第五类普通任务增量验证对象，但不应直接进入详细节点补拆、页面制作、资源包生产或平台挂接。

本任务原文同时包含天线参数、无线参数、承载网参数、核心网参数、仿真软件截图、课堂测试和经典案例。它能验证V0.3.4是否能处理“优化实施与工程变更类任务”，但也容易被误拆成软件操作清单、参数知识清单或四类网络对象的并列目录。因此本轮必须先做实施计划，再做受控补拆。

本计划建议后续P4-T1补拆采用“能力动作主线 + 专业分支资源”的方式：详细能力节点围绕实施边界、责任判断、参数依据、实施步骤、变更记录和验证交接展开；天线、无线、承载、核心网等内容进入资源、活动或专业分支，不直接按知识点逐项升格为能力节点。

## 3. 本轮验证目标

本轮不是为了把P4-T1做成学生端教材页面，而是为了验证以下问题：

1. V0.3.4主数据是否能承接“优化实施与工程变更类任务”。
2. `AU-06 优化实施与变更记录` 是否需要通过P4-T1形成详细能力节点验证。
3. 优化实施类任务的节点颗粒度能否避免两种错误：过粗到只有“实施优化方案”，或过碎到按参数、截图、软件按钮拆分。
4. 资源、活动、评价和输入输出物能否明确区分“学生可训练动作”和“真实工程授权操作”。
5. V0.4风险治理字段是否足以表达参数变更、工程责任、软件截图、媒体重绘、数据安全和实训边界。

## 4. 本轮范围边界

## 6. 拆分规则

后续正式补拆应遵守以下规则：

1. 能力节点必须是稳定岗位动作，不是知识点、参数项、软件按钮或截图名称。
2. 天线、无线、承载网、核心网四类对象应作为分支资源、活动场景或案例材料，而不是简单拆成四个平行能力节点。
3. 参数知识只在支撑学生完成判断、记录和验证交接时进入节点；单纯解释概念应进入资源卡。
4. 原教材仿真软件截图必须先做媒体审查。正式学生端优先使用教学化重绘图、去厂商化流程图、参数对照表或简化数据界面。
5. 学生训练重点是“识别对象、说明依据、形成记录、标出风险、交接验证”，不是模拟真实网络现场独立操作。
6. 任何优化动作都应配套适用范围、可能副作用、回退条件和复测入口。

## 9. 风险治理重点

P4-T1后续补拆必须增加V0.4风险治理扩展记录，重点覆盖：

1. 工程实施风险：学生端不得暗示可无授权操作真实网络。
2. 参数变更风险：任何参数调整都必须说明适用范围、影响范围、回退条件和复测要求。
3. 专业责任边界：天线、无线、承载、核心网可能对应不同专业岗位，不能混写成单一学生动作。
4. 软件截图风险：原教材大量非通用仿真软件截图必须媒体审查、重绘、替换或仅作内部分析，不得裸进正式学生端。
5. 案例真实性风险：CSI-RS案例可作为教学案例，但需标注来源、复核状态和适用边界。
6. 数据安全风险：若涉及真实站点、参数、网元、日志或工程记录，必须脱敏或改为教学模拟数据。
7. 学生评价风险：评价应检查依据、记录和交接质量，不应考核真实网络操作能力。
