## 3. 通过点

### 3.1 没有把报告模板误拆成能力图谱

本次没有把以下对象升格为能力节点：

1. 网络问题概述。
2. 干扰原因分类。
3. 优化措施。
4. 干扰处理情况。
5. 典型案例标题。
6. 报告模板栏目。
7. 单张测试截图。
8. 单个客户沟通问题。

这些对象被下沉为资源卡、学习活动、评价产出、媒体审查对象或风险治理记录，符合“职业动作为节点，模板材料为支架”的拆分原则。

### 3.2 AU-08被实质补齐

V0.3.5中 `AU-08 优化报告与职业表达` 仍是骨架节点。本轮6个详细节点覆盖：

1. 报告对象与交付口径。
2. 实施与验证证据归集。
3. 报告结构选择和材料组织。
4. 指标对比和结论边界。
5. 典型案例分析表达。
6. 报告表达修订和客户沟通准备。

这比在任务层写“完成5G网络优化报告”更可验证，也更符合数字教材中“节点映射资源、活动、评价和质量门禁”的要求。

### 3.3 项目四闭环关系更清楚

P4-T3与P4-T1、P4-T2之间的关系成立：

1. P4-T1提供实施结果和变更凭据。
2. P4-T2提供验证依据、验收结论和职业表达修订经验。
3. P4-T3把这些材料组织成报告证据链、指标结论和沟通提纲。
4. 如果证据不足或边界不清，P4-T3可以回流到P4-T2补充判断依据。

这个链条说明P4-T3不是孤立的写作任务，而是项目四端到端闭环的表达出口。

### 3.4 风险治理覆盖面明显增强

P4-T3暴露的风险与前面任务不同，主要集中在：

1. 客户沟通。
2. 外部发布。
3. 指标结论边界。
4. 报告模板来源。
5. 站点案例脱敏。
6. 测试截图重绘。
7. 教学样稿与真实提交材料的边界。

本轮V0.4增量表已能承接这些风险。

## 4. 主要问题

### 4.1 对外发布和客户沟通控制仍偏粗

当前主要通过以下字段表达外部发布和客户沟通风险：

1. `external_statement_allowed`
2. `service_commitment_risk_type`
3. `customer_communication_review_type`
4. `service_wording_review_note`
5. `overall_publish_gate_status`

这些字段能满足本轮试拆，但如果后续进入平台挂接或出版社协作，可能还需要更细的“教学样稿、内部评审稿、出版社编辑稿、正式发布稿”状态区分。

### 4.2 指标结论仍必须专业复核

覆盖方案对比表很适合教学，但也有风险：

1. 总采样点增长不等于覆盖效果一定变好。
2. 覆盖率下降不一定能直接说明所有方案不可用。
3. 弱覆盖采样点增长需要结合样本变化和场景说明。
4. 教材中的阈值和案例结论不能自动泛化到所有网络场景。

因此P4T3-N04必须保留专业复核门禁。

### 4.3 典型案例材料不能直接使用

原文中的“城三5G海淀香泉环岛1小区越区覆盖”具备教学价值，但不具备直接发布条件。

主要问题：

1. 含具体站点或区域信息。
2. 含测试截图。
3. 优化措施和效果结论需要专业复核。
4. 截图可能包含软件界面、测试路径或网络参数。

后续如果制作学生端正文，应优先改写为教学化模拟案例，并重绘前后对比示意。

### 4.4 学生正文尚未生成

本轮完成的是图谱主数据增量验证，不是教材正文。即使结构通过，也不能说明学生已经能看懂、教师已经能用。

后续若进入教材页面，应继续坚持此前原则：

1. 先用实际案例引发问题。
2. 再解释为什么需要报告和证据链。
3. 再给低门槛指标解释和反例。
4. 再让学生完成可检查产出。
5. 最后进行表达修订和沟通边界检查。

## 5. 对节点方案的修订建议

当前6节点方案暂不建议拆得更细。

不建议新增的节点：

1. “编写问题概述”。
2. “编写原因分类”。
3. “编写优化措施”。
4. “编写处理情况”。
5. “粘贴典型案例图片”。
6. “选择原模板或新模板”。
7. “描述报告内容”。

这些都应保留在资源、学习活动、评价或教师讲评中，不应升格为课程能力图谱的详细能力节点。

可保留观察的问题：

1. N02“归集实施与验证证据”是否需要在后续页面生产时进一步拆分为基础证据识别和综合证据链组织两个学习层。
2. N04“指标对比结论段”是否需要更丰富的错误示例和反例。
3. N06“客户沟通提纲”是否需要在V0.5中增加更细的发布稿状态字段。
4. P4-T3是否应在合并准备时进一步连接P5-T3全网性能提升验证报告和P6-T2信令复盘报告。
