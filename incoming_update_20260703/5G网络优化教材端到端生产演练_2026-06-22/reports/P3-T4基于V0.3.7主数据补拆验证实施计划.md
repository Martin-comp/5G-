# P3-T4基于V0.3.7主数据补拆验证实施计划

生成日期：2026-06-26  
适用对象：项目三 / 任务4：5G网络参数设置  
当前基线：课程能力图谱主数据V0.3.7  
计划定位：第八类普通任务增量验证前置计划，不是正式补拆结果，不直接改写主数据。

## 1. 当前结论

P3-T4可以作为第八类普通任务增量验证对象，但不应直接进入详细节点补拆、学生端页面制作、资源包生产、出版社平台挂接或工具链模块拆解。

本任务原文以“5G网络参数设置”为主题，包含Massive MIMO子波束、邻区配置原则、NSA锚点参数、无线参数修改、邻区添加/删除/调整、随堂测试和典型切换案例。它能验证V0.3.7是否能处理“参数设置、授权变更、操作证据、回退记录和复测交接”这一类对象，但也最容易被误拆成网管软件操作步骤、截图按钮清单或真实生产变更教程。

本计划建议后续P3-T4补拆采用“变更依据确认 + 参数对象边界 + 教学仿真操作证据 + 回退复测交接”的方式：详细能力节点围绕变更依据、参数对象、邻区方案、教学仿真设置、结果核查和交接记录展开；Massive MIMO参数表、邻区参数表、NSA锚点参数表、网管截图和案例截图进入资源、活动、评价或媒体审查对象，不直接逐项升格为能力节点。

## 3. 本轮验证目标

本轮不是为了制作P3-T4学生端教材页面，而是为了验证以下问题：

1. V0.3.7主数据是否能承接“参数设置与变更执行类任务”。
2. P3-T4能否补齐项目三“运行监控 -> 参数检查 -> 参数设置”的任务闭环。
3. 参数设置能否与P3-T3参数检查、P4-T1优化实施准确区分，而不是互相替代。
4. 邻区添加、邻区删除、参数调整、NSA锚点参数管理如何抽象成稳定能力节点，而不是软件按钮清单。
5. 教学仿真操作、操作证据、变更记录、回退条件和复测交接如何进入资源、活动、评价和风险治理。
6. 原教材中大量网管截图、参数表和案例截图如何进入媒体审查、重绘、替换或禁用流程。
7. V0.4风险治理字段是否足以表达参数授权、误操作风险、真实网管边界、参数阈值复核、截图媒体和数据安全风险。

## 7. 拆分规则

后续正式补拆应遵守以下规则：

1. 能力节点必须是稳定岗位动作，不是软件按钮、截图名称、参数字段或表格行。
2. P3-T3负责“检查与发现参数差异”，P3-T4负责“依据确认后的设置、记录、核查与交接”，两者不得混写。
3. P4-T1负责更广义的优化方案实施，P3-T4只验证参数设置和变更证据，不扩大为完整工程实施任务。
4. 真实生产网管操作、账号权限、配置下发和参数修改必须保留仿真/教学边界，不得写成学生可在真实网管执行。
5. 参数取值、门限、推荐配置和案例结论必须保留专业复核门禁。
6. NSA锚点内容应作为教材来源场景和案例对象处理，需专业复核其当前教学适用性。
7. 原教材截图必须进入媒体审查，学生端正式材料优先使用教学化重绘界面、参数卡、流程图或模拟数据。
8. 评价重点是变更依据、影响边界、操作证据、风险核查和复测交接，不是截图是否提交。

## 8. 关系设计预案

后续关系增量样表至少应覆盖以下关系类型：

1. 任务拆分关系：`P3-T4 -> P3T4-N01...P3T4-N06`。
2. 内部递进关系：
   - `P3T4-N01 -> P3T4-N02`，先确认变更依据，再识别参数对象；
   - `P3T4-N02 -> P3T4-N03`，先判断参数对象和影响范围，再制定邻区或参数调整方案；
   - `P3T4-N03 -> P3T4-N04`，先形成方案，再在教学仿真中执行并记录证据；
   - `P3T4-N04 -> P3T4-N05`，先完成设置，再核查结果、风险和回退条件；
   - `P3T4-N05 -> P3T4-N06`，核查后形成变更记录和复测交接。
3. 前置基础关系：
   - `P3T2-N06 -> P3T4-N01`，运行监控结论确认需要参数设置或调整时进入P3-T4；
   - `P3T3-N03 -> P3T4-N02/P3T4-N03`，无线侧参数差异比较支撑参数对象识别和邻区调整方案；
   - `P3T3-N06 -> P3T4-N01/P3T4-N06`，参数异常清单支撑变更依据和后续记录；
   - `P3-T1 -> P3T4-N01/P3T4-N02`，网管架构和功能认知支撑参数设置入口理解。
4. 后续递进关系：
   - `P3T4-N06 -> P4T1-N01`，参数变更记录可进入优化对象与实施边界确认；
   - `P3T4-N06 -> P4T2-N01`，参数设置完成后需要进入验证场景识别；
   - `P3T4-N06 -> P5T3-N03`，全网性能提升类参数调整后需要进入优化前后KPI对比基线；
   - `P3T4-N05 -> P6T2-N02/P6T2-N04`，若切换、掉线或信令异常仍未闭环，可进入信令复盘。
5. 支撑判断关系：
   - `P2T3-N03 -> P3T4-N02`，关键指标读法支撑参数影响范围判断；
   - `P4T1-N05 -> P3T4-N06`，实施记录规范支撑参数变更记录完整性；
   - `P4T2-N07 -> P3T4-N06`，验收结论可反向要求补充参数变更证据。
6. 能力挂接关系：
   - N01至N03主挂AU-04，辅挂AU-06；
   - N04至N06主挂AU-06；
   - N06可辅挂AU-07，用于复测和验证交接。
7. 资源证据关系：
   - 参数对象卡、邻区调整方案、仿真操作记录、设置结果核查单、回退条件单、参数变更记录、媒体审查清单应回挂到对应节点。

## 11. 风险治理重点

P3-T4后续补拆必须增加V0.4风险治理扩展记录，重点覆盖：

1. 授权风险：学生端不得暗示可在真实生产网管中直接下发参数、添加邻区或删除邻区。
2. 误操作风险：参数设置可能影响业务连续性、切换、接入、负荷均衡和覆盖效果，必须保留回退条件和复测要求。
3. 专业口径风险：Massive MIMO、邻区参数、NSA锚点策略、A2门限和QCI相关判断必须专业复核。
4. 媒体风险：原教材网管截图和案例截图多为非通用系统界面，应重绘、标注、替换或禁用。
5. 数据安全风险：站点、账号、业务承载、信令截图、参数配置和日志记录可能涉及敏感生产信息。
6. 场景时效风险：NSA相关内容需判断当前教学适用性，不能默认代表所有5G网络场景。
7. 平台边界风险：仿真实训系统、厂家网管、出版社数字教材平台不是同一系统，不能混写接口能力。
8. 评价风险：评价应检查依据、边界、记录和交接质量，不应只检查学生是否提交截图。

## 13. 结构校验规则

后续增量样表至少应通过以下校验：

1. 新增节点ID唯一，不与V0.3.7既有节点冲突。
2. 关系起点和终点均能回溯到V0.3.7节点或本轮新增节点。
3. 资源活动评价挂接对象必须能回溯到任务节点或新增详细能力节点。
4. 输入输出物治理记录中的文件路径必须存在，或明确标记为待生成。
5. V0.4风险治理扩展记录的枚举值必须符合字段规范。
6. 不允许把旧版候选、草稿或未评审增量误写为当前推荐主数据。
7. 门禁状态不得写成“已专业复核”“已媒体审查”“已教学验证”“可对外发布”。
8. P3-T4补拆不得隐性改写P3-T2、P3-T3或P4-T1既有关系；如需新增跨任务关系，必须在增量样表中显式记录。
9. P3-T4风险治理记录继续作为V0.4旁挂层，不并入四张V0.3.7主表。

## 14. 内部评审标准

P3-T4补拆完成后，内部评审至少检查：

1. 是否围绕参数设置、变更证据、风险核查和复测交接形成清晰能力主线。
2. 是否避免按软件按钮、截图、参数字段或表格行过碎拆分。
3. 是否准确区分P3-T3参数检查、P3-T4参数设置和P4-T1优化实施。
4. 是否能承接P3-T2运行监控和P3-T3参数异常清单。
5. 是否能输出可评价的参数变更记录和复测交接单。
6. 是否为教师讲评、典型错误、回退条件和专业复核保留必要信息。
7. 是否保留专业、媒体、数据安全、平台边界、真实教学验证和编辑审查门禁。

## 15. 执行顺序

建议按以下顺序执行：

1. 基于原文和V0.3.7主数据形成P3-T4补拆验证报告。
2. 按候选结构生成五张增量样表和一张风险治理扩展样表。
3. 执行结构校验，发现阻断错误先修正样表，不进入评审。
4. 形成内部评审报告。
5. 若内部评审认为颗粒度偏碎、边界混乱或授权风险不足，先形成P3-T4修订版增量样表。
6. 只有在结构校验和内部评审均通过后，才讨论是否进入下一版主数据合并准备。
