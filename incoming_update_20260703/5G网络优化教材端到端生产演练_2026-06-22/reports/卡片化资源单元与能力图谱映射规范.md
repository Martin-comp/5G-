# 卡片化资源单元与能力图谱映射规范

生成日期：2026-06-22  
适用范围：职业教育数字教材 AI 生产工具链、项目四任务2高质量样章

## 0. 核心结论

卡片可以作为数字教材的最小资源单元，但不能被理解为“漂亮的 UI 卡片”。本项目中的卡片定义为：

> 一张卡片是承载一个完整学习动作的最小教材单元，并与能力图谱节点、学习证据、资源来源和审核状态建立可追踪关系。

因此，卡片必须同时满足三类要求：

1. 内容完整：学生不依赖外部解释，也能理解这张卡要讲什么；
2. 学习动作完整：学生知道读完、看完或操作完之后要做什么；
3. 教材关系完整：卡片知道自己从哪里来、服务哪个能力点、前后连接到哪里。

只含标题、封面图、摘要、按钮或装饰交互的内容块，不能算合格教材卡片。

## 1. 卡片与能力图谱的关系

不建议强制规定“一张卡片 = 一个图谱节点”。更合理的关系是：

| 关系 | 示例 | 说明 |
| --- | --- | --- |
| 一对一 | “SS-RSRP 含义”节点 -> 1 张指标知识卡 | 适合边界清晰的小知识点 |
| 一对多 | “判断覆盖优化是否达标”节点 -> 知识卡 + 证据卡 + 交互卡 | 适合能力型节点 |
| 多对一 | “SS-RSRP”“SS-SINR”“弱覆盖”多个节点 -> 1 张覆盖判断卡 | 适合综合判断场景 |
| 多对多 | “优化结果验证”能力群 -> 多张卡片组成学习单元 | 适合完整任务单元 |

工具链中应采用“可追踪映射”，而不是僵硬的一一对应。

## 2. 合格卡片的最小字段

每张卡片至少包含以下字段：

| 字段 | 含义 | 是否必需 |
| --- | --- | --- |
| card_id | 卡片唯一编号 | 必需 |
| title | 卡片标题 | 必需 |
| card_type | 情境、知识、证据、交互、任务、反馈、教师等类型 | 必需 |
| learning_goal | 这张卡要支持的学习目标 | 必需 |
| graph_node_ids | 对应能力图谱节点 | 必需 |
| source | 原教材、政策标准、行业标准、AI 重构、专家补充等 | 必需 |
| core_content | 完整正文或资源内容，不得只有标题 | 必需 |
| student_action | 学生需要完成的动作 | 必需 |
| feedback_rule | 学生完成动作后的反馈或教师讲评规则 | 必需 |
| evidence_output | 是否产生学习证据，产生什么证据 | 必需 |
| previous_cards | 前置卡片 | 建议必需 |
| next_cards | 后续卡片 | 建议必需 |
| media_assets | 图片、音频、视频、动画、仿真等资源 | 可选但需登记 |
| estimated_minutes | 建议学习时长 | 必需 |
| review_status | 待专家审核、待编辑审核、已审核等 | 必需 |
| copyright_status | 原教材授权、待确认、开放资源、自制等 | 必需 |

## 3. 卡片类型

### 3.1 情境卡

功能：把抽象知识转化为真实任务问题。

必须包含：

- 场景背景；
- 角色或岗位身份；
- 要解决的问题；
- 学生需要形成的产出。

不合格表现：只有“任务导入”四个字，或只有一段泛泛的职业情境。

### 3.2 知识卡

功能：讲清完成任务必须掌握的一个概念、指标、流程或规则。

必须包含：

- 概念解释；
- 与本任务的关系；
- 一个小例子或判断提示；
- 与后续任务卡的连接。

不合格表现：把原教材长文切成多个标题，或只列术语不解释。

### 3.3 证据卡

功能：提供学生进行判断的材料。

必须包含：

- 数据、图片、流程图或案例材料；
- 证据说明；
- 证据能支持什么判断；
- 证据不能支持什么判断。

不合格表现：图片只是插图，没有说明它用于判断什么。

### 3.4 交互卡

功能：让学生通过选择、排序、匹配、填写、拖拽、仿真等动作完成学习判断。

必须包含：

- 明确题干或任务；
- 可操作控件；
- 正误或分层反馈；
- 学习数据记录字段。

不合格表现：只有翻卡、轮播、点击展开，且不产生任何学习判断。

### 3.5 任务卡

功能：组织学生完成一个综合产出。

必须包含：

- 任务说明；
- 输入材料；
- 输出模板；
- 评价标准；
- 提交物格式。

不合格表现：只写“完成任务”但没有任务单和评价标准。

### 3.6 反馈卡

功能：帮助学生修正判断并形成可讲评结果。

必须包含：

- 参考思路；
- 常见误区；
- 学生自查点；
- 教师讲评提示。

不合格表现：只给出“正确/错误”。

### 3.7 教师卡

功能：支持教师组织课堂、观察学情和讲评。

必须包含：

- 教学目标；
- 建议时长；
- 课堂组织建议；
- 学情观察点；
- 讲评建议；
- 可调整项。

不合格表现：只把学生页面复制一份给教师。

### 3.8 多媒体卡

音频、视频、交互式动画、小游戏可以作为卡片，但必须满足教材功能。

必须包含：

- 它服务哪个学习目标；
- 学生看完或玩完要完成什么动作；
- 如何反馈；
- 如何形成学习证据；
- 如何与前后卡片衔接。

不合格表现：视频只是“看一看”，小游戏只是“玩一玩”。

## 4. 单元编排规则

单个数字教材单元不应只是卡片堆叠，应形成教学逻辑链。

建议采用以下最小结构：

```mermaid
flowchart LR
  A["情境卡：提出真实问题"] --> B["诊断卡：形成初步判断"]
  B --> C["知识卡：补足必要概念"]
  C --> D["证据卡：观察数据和图表"]
  D --> E["交互卡：完成判断动作"]
  E --> F["任务卡：形成综合产出"]
  F --> G["反馈卡：修正与讲评"]
  G --> H["教师卡：课堂使用与学情分析"]
```

其中，情境卡、任务卡、反馈卡是教材性的底座；知识卡、证据卡、交互卡是数字化增强；教师卡是课堂落地的关键。

## 5. 卡片完整性验收

每张卡片按 10 分制做快速验收：

| 维度 | 分值 | 判定问题 |
| --- | ---: | --- |
| 内容完整 | 2 | 是否有足够正文、数据、图示或任务材料 |
| 学习动作 | 2 | 学生是否知道要做什么 |
| 反馈闭环 | 2 | 学生或教师是否知道结果如何解释 |
| 前后衔接 | 1 | 是否知道上一张和下一张为什么连接 |
| 图谱映射 | 1 | 是否映射到能力节点 |
| 来源审核 | 1 | 是否标注来源和审核状态 |
| 教学可用 | 1 | 教师是否能直接用于讲解、练习或讲评 |

单卡低于 7 分，不应进入高质量样章；低于 5 分，应退回重新生成。

## 6. 卡片化与“教材性”的边界

数字教材可以采用更新颖、更美观的呈现方式，但不能失去教材的基本属性。

合格数字教材单元必须同时具备：

1. 目标：学生知道学完要形成什么能力；
2. 内容：知识、案例、材料足够完整；
3. 活动：学生有明确学习动作；
4. 评价：学生产出可以被判断；
5. 反馈：学生和教师知道如何改进；
6. 结构：前后内容有逻辑连接；
7. 可追溯：资源来源、能力点、审核状态清楚。

如果只有视觉拼贴、资源目录或交互展示，不能称为教材。

## 7. 对工具链的要求

后续 AI 生产工具链不能只生成页面，还要生成卡片级结构化数据。

建议工具链至少输出：

1. `card_manifest`：卡片清单；
2. `card_content`：卡片正文与多媒体说明；
3. `graph_mapping`：卡片与能力图谱节点映射；
4. `sequence_map`：卡片前后连接关系；
5. `assessment_map`：卡片产生的学习证据和评价规则；
6. `teacher_use_map`：教师讲评、课堂组织和学情观察说明；
7. `review_map`：来源、版权、专家审核状态。

这意味着工具链的核心对象不是“章节页面”，而是“可组织的完整学习卡片”。
