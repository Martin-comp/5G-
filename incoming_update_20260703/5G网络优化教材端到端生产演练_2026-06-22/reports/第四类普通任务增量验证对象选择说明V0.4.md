## 1. 选择结论

建议选择：

`P2-T1 任务1: DT/CQT测试准备和执行`

作为第四类普通任务增量验证对象。

本建议只进入“对象确认”阶段，不直接开始试拆。候选对象确认后，下一步才应形成P2-T1的任务试拆报告、增量样表、V0.4风险治理扩展增量样表和结构校验记录。

## 2. 选择原则

第四类普通任务不应按章节顺序选择，也不应按“哪个任务重要”简单选择，而应按验证价值选择。

本轮选择遵循五条原则：

1. 优先选择尚未被详细验证的能力单元；
2. 优先选择与P1-T3、P2-T2、P3-T3差异明显的任务类型；
3. 优先选择能检验V0.4风险治理扩展表迁移能力的任务；
4. 控制任务体量，避免一上来进入过大、过复杂任务；
5. 不选择已经作为深样章、V0.2代表任务或普通任务增量验证对象的任务。

## 3. 已覆盖任务边界

以下任务不再作为第四类普通任务候选：

| 任务 | 已验证内容 | 不再优先的原因 |
| --- | --- | --- |
| P2-T2 | 测试问题处理类普通任务增量 | 已合并进入V0.3.1 |
| P3-T3 | 参数检查与配置管理类普通任务增量 | 已合并进入V0.3.2 |
| P1-T3 | 投诉信息采集与客户沟通类普通任务增量 | 已合并进入V0.3.3，并用于V0.4回填 |
| P4-T2 | 结果验证深样章和V0.4回填代表任务 | 已深展开，不作为普通增量首选 |
| P2-T3 | 测试数据分析代表任务 | 已在V0.2/V2链路中试拆 |
| P5-T3 | 全网性能提升验证代表任务 | 已在V0.2/V2链路中试拆 |

因此，第四类普通任务应从剩余任务中选择，且应优先验证新的职业任务类型。

## 4. 推荐P2-T1的理由

### 4.1 它补齐AU-02能力单元

课程能力图谱V2中，P2-T1对应：

`AU-02 测试准备与测试执行`

当前AU-02仍主要停留在骨架层，尚未形成详细能力节点。前三轮普通任务分别验证了：

1. P2-T2：测试问题处理类；
2. P3-T3：参数检查类；
3. P1-T3：投诉信息采集与客户沟通类。

这些都没有真正验证“测试准备与测试执行”这一能力单元。P2-T1可以补齐从P1信息采集到P2测试执行，再到P2-T2问题处理和P2-T3数据分析的关键链路。

### 4.2 它能检验新的风险类型

P2-T1不是单纯知识讲解，也不是单纯报告表达。它包含：

1. DT/CQT测试概念；
2. 测试工具和设备清单；
3. 软件安装和硬件连接；
4. 测试路线规划；
5. CQT测试场景划分；
6. DT路测数据采集；
7. 测试数据保存；
8. 入场许可和客户接口人协调。

这能检验V0.4是否能治理以下新风险：

| 新风险 | 为什么重要 |
| --- | --- |
| 工具设备连接风险 | 测试终端、GPS、扫频仪、加密狗、逆变器等不能都升格为能力节点 |
| 现场执行风险 | 路测、CQT和入场许可涉及真实工作流程和安全边界 |
| 数据采集记录风险 | 测试数据保存、路线图、测试任务书需要形成可追溯产出 |
| 媒体和软件截图风险 | 原教材含软件界面图，不能默认直接用于数字教材 |
| 学生实训安全风险 | 车辆路测、现场测试、设备连接不能被写成无风险练习 |
| 平台资源封装风险 | 测试任务书、路线图、设备清单、数据记录表适合后续资源包化 |

这些风险与P1-T3、P2-T2、P3-T3不同，能真正检验V0.4扩展层是否有迁移价值。

### 4.3 它体量可控

P2-T1原文统计：

| 指标 | 数值 |
| --- | ---: |
| 原文行数 | 362 |
| 图片数 | 9 |
| 表格线索 | 41 |
| 测评信号 | 187 |
| 案例信号 | 2 |

它比P3-T2、P4-T1、P5-T1体量更可控，但又比过短任务更能暴露真实问题。作为第四类普通任务验证对象，风险和收益相对平衡。

## 5. 为什么暂不选择其他高分候选

### 5.1 P4-T1：验证价值高，但复杂度过高

P4-T1能验证优化实施、天馈调整、无线/承载/核心网并行处理和工程变更记录，确实很有价值。

暂不优先的原因：

1. 图片38张、表格线索78行，媒体治理压力大；
2. 专业分支复杂，容易重演P3-T3的并列分支问题；
3. 与P4-T2深样章距离较近；
4. 更适合作为P2-T1之后的专项验证。

### 5.2 P3-T4：能验证配置变更，但与P3-T3过近

P3-T4可以验证参数设置、邻区增删、网管配置和变更记录风险。

暂不优先的原因：

1. 与P3-T3参数检查同属参数链条；
2. 专业复核和截图重绘压力较高；
3. 第四类任务更需要先换一种任务形态，而不是继续参数类任务。

### 5.3 P4-T3：适合表达类验证，但新风险不足

P4-T3能验证优化报告、职业表达和客户沟通成果输出。

暂不优先的原因：

1. 与P4-T2验证结论和样章内容相邻；
2. 更适合后续专门验证AU-08；
3. 对V0.4工具、设备、现场、实训安全等新风险检验不足。

### 5.4 P1-T1/P1-T2：与P1-T3同属信息采集

P1-T1、P1-T2能补齐室内/室外环境信息采集，但AU-01已经通过P1-T3进行了较高风险验证。

暂不优先的原因：

1. 与P1-T3同属信息采集链；
2. 类型差异不如P2-T1；
3. 图片和场景材料较多，可能增加媒体治理而不是验证新机制。

## 6. P2-T1下一步试拆边界

如果确认选择P2-T1，下一步不应直接生成页面，也不应直接进入工具链。应先形成以下过程产物：

1. `reports/P2-T1基于V0.4主数据补拆验证报告.md`
2. `reports/P2-T1详细能力节点主数据增量样表V0.4.csv`
3. `reports/P2-T1关系增量样表V0.4.csv`
4. `reports/P2-T1资源活动评价挂接增量样表V0.4.csv`
5. `reports/P2-T1输入输出物治理增量记录V0.4.csv`
6. `reports/P2-T1风险治理扩展增量样表V0.4.csv`
7. `reports/P2-T1增量结构校验记录V0.4.md`
8. `reports/P2-T1增量补拆内部评审报告V0.4.md`

其中第6项是本轮新增要求：下一轮普通任务增量必须同步生成V0.4风险治理扩展记录，否则V0.4治理层会与主数据增量脱节。

## 7. P2-T1试拆时必须控制的边界

P2-T1很容易被拆成设备清单或操作步骤清单。试拆时应遵守以下边界：

1. GPS、测试手机、SIM卡、扫频仪、逆变器、软件、地图图层等不直接升格为能力节点；
2. 设备清单、路线图、测试模板、许可申请表应进入资源或评价产出；
3. 能力节点应围绕稳定职业任务，如“确认测试任务和数据需求”“准备测试工具与许可”“规划测试路线与CQT场景”“执行测试并保存数据”；
4. 软件截图和非通用工具界面必须进入媒体审查或重绘流程；
5. 车辆路测、现场入场和设备连接相关内容必须标记实训安全和责任边界；
6. 测试数据保存与报告模板必须进入输入输出物治理，不能只写在正文中。

## 8. 当前结论

P2-T1适合作为第四类普通任务增量验证对象。

成立的判断：

1. 它补齐AU-02详细能力节点缺口；
2. 它与前三类普通任务差异明显；
3. 它能检验工具设备、现场执行、测试数据、入场许可、媒体截图和实训安全等新风险；
4. 它的体量适合作为下一轮验证对象；
5. 它能连接P1信息采集、P2问题处理、P2数据分析和P4结果验证链路。

仍需保留的边界：

1. 选择P2-T1不等于立刻开始页面生产；
2. 选择P2-T1不等于它已通过专业复核；
3. 选择P2-T1不等于测试软件截图可以直接使用；
4. 选择P2-T1不等于可以批量拆全书；
5. 选择P2-T1后，必须同步生成V0.4风险治理扩展增量样表。

建议下一步在用户确认后进入：

`P2-T1基于V0.4主数据补拆验证报告`

及配套六张增量/治理样表的制作。
