## 1. 本次补拆定位

本次不是页面制作，也不是把P2-T1直接合并进入主数据表，而是做第四类普通任务的增量验证：

1. 验证 `AU-02 测试准备与测试执行` 能否从骨架层进入详细能力节点层；
2. 验证P2-T1这类“现场测试准备与执行”任务是否能稳定回写V0.3.3主数据；
3. 验证V0.4旁挂式风险治理字段能否覆盖工具设备、软件截图、路线规划、进场许可、测试数据采集和实训安全风险；
4. 判断节点颗粒度是否合理，避免把设备清单、软件按钮、线路点、表格字段误升为能力节点。

本报告只给出内部试拆结论。通信专业复核、媒体审查、学生正文、平台发布和真实教学验证均未完成。

## 3. 原文质量诊断

### 3.1 可用部分

原文能提供较完整的测试工作流程，尤其是测试资料准备、设备清单、路线规划、DT采集、CQT场景、LOG保存和问题记录。这些内容适合作为P2-T1详细能力节点和资源卡片的来源。

### 3.2 主要问题

1. 章节前半部分的NSA/SA组网知识与P2-T1核心能力关系较弱，应作为背景资源而非能力节点；
2. 测试设备清单很长，但设备本身不能成为能力节点；
3. 软件安装、任务配置、截图界面和按钮步骤不能直接裸用为数字教材资源，需要媒体审查或教学化重绘；
4. CQT测试包含时间、地点、人员、测试卡、业务拨测和质量记录，存在场地授权、真实客户环境和数据记录边界；
5. DT测试涉及车辆路测、GPS打点、设备供电和测试中断处理，学生实训时必须增加安全边界；
6. 原文存在测评题和操作步骤堆积问题，需要转为可完成的任务单、检查单、记录单和交付包。

## 4. 节点拆分方案

本次将P2-T1补拆为7个详细能力节点：

| 节点 | 节点名称 | 核心产出 | 拆分理由 |
| --- | --- | --- | --- |
| P2T1-N01 | 明确DT/CQT测试任务与验收口径 | 测试任务与指标口径确认单 | 先确定测试对象、业务类型、指标口径和数据来源，避免学生一开始就面对设备清单 |
| P2T1-N02 | 准备测试资料、工具设备与入场许可 | 测试准备核对单 | 把资料、工具、人员、车辆、许可和接口人统一治理，设备不单独升格为能力节点 |
| P2T1-N03 | 配置测试软硬件并完成连通性检查 | 设备连接与软件配置检查记录 | 训练学生确认设备和软件可采集数据，而不是背诵软件按钮 |
| P2T1-N04 | 规划DT路线与CQT测试场景 | 测试路线与场景规划表 | 覆盖DT路线、簇边界、重叠区、CQT室内外场景和测试点选择 |
| P2T1-N05 | 执行DT路测采集并记录异常事件 | DT采集与异常事件记录 | 训练路测过程中的设备状态、GPS打点、LOG命名和异常记录 |
| P2T1-N06 | 执行CQT定点业务测试并记录质量 | CQT业务测试记录 | 训练拨打、数据业务、近中远点、场景覆盖和质量记录 |
| P2T1-N07 | 保存测试LOG并移交测试资料包 | 测试数据交付包 | 将LOG、异常记录、路线图、测试点、设备信息和交接信息形成后续分析入口 |

该拆法保留P2-T1的完整工作闭环，但把工具、表格、截图、按钮和具体软件步骤下沉到资源活动层。

## 5. 与既有图谱的关系

P2-T1补拆后将补齐当前主数据中的三类关系：

1. `AU-02` 的详细能力节点从骨架变为可验证节点；
2. P1-T3投诉信息采集可以向P2-T1测试准备提供时间、地点、业务类型和现场现象输入；
3. P2-T1产生的测试LOG、异常事件和交付包可以进入P2-T2问题处理和P2-T3数据分析。

关键关系包括：

1. `P1T3-N02 -> P2T1-N01`：投诉关键信息支撑测试任务确认；
2. `P1T3-N03 -> P2T1-N04`：现场核实结果支撑路线和场景规划；
3. `P2T1-N05 -> P2T2-N01`：测试中异常进入问题处理；
4. `P2T1-N07 -> P2T3-N01`：测试交付包进入数据分析任务；
5. `P2T1-N07 -> P2T3-N02`：LOG文件进入导入和报告导出流程。

## 6. V0.4风险治理判断

P2-T1需要新增的V0.4风险治理重点如下：

| 风险对象 | 治理判断 |
| --- | --- |
| 测试设备清单 | 作为资源卡和核对单，不作为能力节点；设备规格需专业复核 |
| 软件安装和测试界面截图 | 需媒体审查，正式教材应优先重绘为教学化流程图或界面示意 |
| 入场许可和客户接口人 | 涉及授权、现场管理和个人联系信息，正式教材须使用模拟或脱敏信息 |
| 路线和测试点 | 涉及位置数据、道路安全和测试边界，应标注训练安全和来源边界 |
| DT路测采集 | 涉及车辆行驶、设备供电、GPS打点和异常停车处理，需实训安全门禁 |
| CQT业务测试 | 涉及场景授权、测试卡、主被叫记录和业务质量记录，需数据与场景边界 |
| 测试LOG交付包 | 可作为后续P2-T2和P2-T3输入，但不能包含真实客户和真实网络敏感数据 |

## 8. 试拆结论

P2-T1作为第四类普通任务增量验证对象成立。7节点方案比按设备、软件按钮、测试题或每张截图拆分更稳，能够覆盖测试准备、路线场景规划、软硬件连通、DT/CQT执行、异常记录和LOG交付闭环。

当前结论为“结构增量可进入校验和内部评审”，不建议直接合并V0.3.4，也不进入页面生产或工具链模块拆解。下一步应先完成结构校验和内部评审，重点检查：

1. 是否仍存在设备清单或软件步骤误升为能力节点；
2. 关系端点是否全部可回溯到V0.3.3主数据或本次新增节点；
3. V0.4风险扩展是否覆盖软件截图、授权、位置数据、训练安全和测试数据交付；
4. 是否需要在后续V0.4字段中进一步细化“实训安全”和“位置数据”门禁。
