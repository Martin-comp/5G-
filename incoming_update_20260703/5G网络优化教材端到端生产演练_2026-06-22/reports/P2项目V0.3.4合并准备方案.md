# P2项目V0.3.4合并准备方案

生成日期：2026-06-25  
准备对象：P2项目内部链条与P2-T1增量合并候选  
上一主数据基线：V0.3.3  
当前方案性质：合并准备方案，不是V0.3.4主数据成品

## 1. 方案结论

建议进入V0.3.4合并准备，但不直接生成V0.3.4主数据成品。

本方案建议采用以下口径：

1. V0.3.4候选主合并对象为P2-T1增量数据；
2. P2-T2和P2-T3不重拆、不改写既有V0.3.3节点结构；
3. P2-T2/P2-T3本轮V0.4风险治理补齐记录先作为旁挂风险治理层处理；
4. P2项目内部关系校正结果进入V0.3.4合并准备，但分为“新增关系采用推荐类型”和“既有关系保留校正依据”两类；
5. 合并准备通过后，下一步才可以生成V0.3.4主数据候选表和校验记录。

当前不能直接进入：

1. V0.3.4正式主数据发布；
2. 项目二学生页面或教师页面生产；
3. 正式资源包生产；
4. 出版社平台挂接；
5. 工具链模块拆解。

原因是：本轮仍处于课程能力图谱主数据治理阶段，专业复核、媒体审查、学生正文审读、真实教学验证、数据安全审核和平台接口验证均未完成。

### 4.2 不建议直接改写的内容

本轮不建议直接改写以下内容：

1. P2-T2四节点结构；
2. P2-T3八节点结构；
3. V0.3.3中已经合并的P2-T2节点、关系和挂接；
4. V0.3.3中已有的P2-T3节点、关系和挂接；

理由是：P2-T2/P2-T3本轮做的是风险治理补齐，不是节点结构再拆分；全局V0.4风险治理扩展表已有105条记录，若直接并入P2项目64条补齐/增量记录，必须先做独立汇总和校验，不能手工混入。

1. 把V0.3.4写成专家定稿课程能力图谱；
2. 把P2-T1、P2-T2、P2-T3的专业口径写成已复核；
3. 把软件截图、设备图片和路测路线写成可直接发布；
