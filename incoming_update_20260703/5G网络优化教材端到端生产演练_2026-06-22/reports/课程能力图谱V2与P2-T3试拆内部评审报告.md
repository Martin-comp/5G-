# 课程能力图谱V2与P2-T3试拆内部评审报告

生成日期：2026-06-23  
评审对象：课程能力图谱V2优化版、P2-T3详细能力节点试拆  
对应文件：

1. `reports/课程能力图谱V2优化方案.md`
2. `reports/课程能力图谱V2节点与映射表.csv`
3. `reports/P2-T3详细能力节点试拆报告.md`
4. `reports/P2-T3详细能力节点映射表.csv`
5. `samples/course_capability_graph_v2_optimized/`

## 1. 评审结论

综合结论：**有条件通过**。

V2已经基本解决V1“把教材目录画成图”的主要问题，可以继续作为当前课程能力图谱基线推进。P2-T3试拆也说明，V2不是只能服务项目四任务2深样章，而是具备初步跨项目迁移能力。

但本轮不能判定为完全通过，原因有五点：

1. 标准依据仍是摘要级挂接，尚未逐条绑定课程标准、职业标准或数字教材标准原文条款；
2. 节点字段还没有形成正式规范，尤其缺少前置关系、后续关系、卡片ID、学习记录事件、评价量规、学生端表达、审核责任人等字段；
3. P4-T2与P2-T3虽然都拆成8个详细能力节点，但P4-T2已经有样章验证，P2-T3仍停留在图谱与资源活动设计层；
4. `audit_status` 等字段目前为自然语言描述，缺少可批量处理的受控枚举；
5. 专业阈值、案例数据、问题归因和整改建议仍未经过通信专业教师或行业专家复核。

因此，当前判断是：**V2方向成立，P2-T3试拆成立，但下一步应先制定课程能力图谱字段规范V0.1，再继续选择第二个任务试拆。**

## 2. 评审标准

本次评审不以界面美观为核心，而以课程能力图谱是否能支撑整本数字教材生产为核心。评审标准如下：

| 评审项 | 判断问题 | 结论 |
| --- | --- | --- |
| 主链是否脱离目录映射 | 图谱主链是否体现岗位工作过程，而不是复制项目目录 | 通过 |
| 层级是否完整 | 是否包含依据、岗位过程、能力单元、项目任务、资源评价等层级 | 有条件通过 |
| 节点是否可学习 | 节点是否能转化为学生动作，而不是抽象能力口号 | 有条件通过 |
| 节点是否可训练 | 是否能挂接资源、互动、任务单、表图、案例或练习 | 通过 |
| 节点是否可评价 | 是否能产生可检查的学习产出或评价结果 | 有条件通过 |
| 是否具备迁移能力 | P2-T3是否证明V2可用于非P4-T2任务 | 通过 |
| 是否可批量扩展 | 字段、枚举、关系和审核状态是否足以支撑全书生产 | 暂不通过 |

## 3. 主要成立点

### 3.1 V2主链已经从目录链转为岗位工作过程链

V1的主要问题是课程主链容易被理解为项目目录。V2改为7个岗位工作过程节点：

1. 明确场景与需求；
2. 组织测试与采集数据；
3. 整理数据与识读指标；
4. 定位问题与制定方案；
5. 实施优化与记录变更；
6. 验证效果与表达结论；
7. 持续提升与复杂复盘。

这条链条比“项目一到项目六”更接近岗位工作过程，也更适合作为数字教材的暗线骨架。它能解释学生为什么先学测试数据、再学问题定位、再学优化实施、再学结果验证和报告表达。

### 3.2 五层结构方向正确

V2设置了“依据层 -> 岗位工作过程层 -> 能力单元层 -> 项目任务层 -> 资源评价层”。这一结构符合本任务此前形成的要求：课程能力图谱不能只是可点击目录，而应连接标准依据、岗位能力、教材任务、资源卡片、学习活动和评价产出。

当前33条节点数据已经覆盖：

1. 7个岗位工作过程节点；
2. 10个能力单元；
3. P4-T2的8个深展开节点；
4. P2-T3的8个试拆节点。

这说明V2已经具备“课程级骨架 + 任务级深拆”的基本数据形态。

### 3.3 P2-T3试拆能证明初步迁移能力

P2-T3不是P4-T2的相邻报告任务，而是位于测试数据分析环节。选择它作为首个迁移试拆对象是合理的。

P2-T3被拆为8个详细能力节点：

1. 明确分析任务与数据来源；
2. 完成LOG导入与报告导出；
3. 识读关键指标与判断边界；
4. 判断覆盖类异常；
5. 判断移动性/邻区异常；
6. 归纳问题类型与原因链；
7. 制定整改建议；
8. 输出分析报告并连接复测。

这组节点没有停留在“指标知识 + 软件操作”的教材目录层，而是形成了“接收数据 -> 读指标 -> 判断异常 -> 归因 -> 提建议 -> 写报告”的能力链。它能支撑资源卡、学习活动和评价产出设计，因此本轮迁移试拆成立。

### 3.4 P2-T3与P4-T2之间的前后关系清晰

P2-T3不是孤立任务，而是P4-T2的前置能力来源：

| P2-T3能力 | 支撑的P4-T2能力 | 关系 |
| --- | --- | --- |
| 识读关键指标与判断边界 | 读覆盖、移动性、体验指标 | 先会读数据，后会判断是否达标 |
| 判断覆盖类异常 | 读覆盖指标 | 先会发现覆盖问题，后会验证覆盖改善 |
| 判断移动性/邻区异常 | 读移动性指标 | 先会定位移动性问题，后会验证切换结果 |
| 归纳问题类型与原因链 | 选择判断依据 | 先会整理原因链，后会判断依据是否充分 |
| 输出分析报告并连接复测 | 形成验收结论、修正职业表达 | 先会写分析报告，后会写验收结论 |

这说明课程能力图谱已经开始承担“整本教材学习路径暗线”的作用，而不只是单个任务页面的导航。

## 4. 主要问题

### 4.1 字段规范不足，暂不能批量扩展

当前CSV字段已经能记录节点名称、层级、依据、岗位过程、关联任务、能力目标、资源类型、学习活动、评价产出和审核状态。但如果要支撑整本教材生产，还不够。

至少还需要补充以下字段：

| 字段方向 | 需要补充的原因 |
| --- | --- |
| 标准条款ID | 目前依据是摘要级，不能追溯到具体政策或标准条文 |
| 前置节点、后续节点 | 课程能力图谱必须表达学习路径和能力依赖 |
| 资源卡片ID | 需要把节点稳定映射到最小资源单元 |
| 学习记录事件 | 后续平台需要知道学生完成了什么动作 |
| 评价量规 | 仅有评价产出不够，还要知道怎么判定达成 |
| 学生端表达 | 后台节点名称不能直接暴露给学生 |
| 教师端使用方式 | 教师需要知道该节点如何讲、如何观察、如何讲评 |
| 审核责任与状态枚举 | 目前自然语言状态不利于批量生产和质量检测 |
| 版本字段 | 后续图谱会迭代，需要可追溯 |

### 4.2 节点粒度还需要校准

P4-T2和P2-T3都拆为8个详细能力节点，这在演练阶段便于对照。但后续不能机械要求每个任务都拆8个节点。

更合理的原则是：

1. 一个详细能力节点应对应一个可学习、可训练、可评价的学生动作；
2. 一个节点不应过大到覆盖多个不同学习动作；
3. 一个节点也不应过小到只剩软件按钮或孤立术语；
4. 每个任务可根据复杂度拆为3到8个详细节点；
5. 只有核心任务、综合任务和深样章任务才需要完全拆到P4-T2粒度。

### 4.3 P2-T3仍缺少学生端教材正文验证

P2-T3当前已经完成图谱试拆，但还没有形成学生能直接阅读和完成的数字教材页面。

这意味着本轮只能证明：

1. 节点拆分方法可行；
2. 资源活动评价设计可行；
3. 与P4-T2的前置关系可解释。

但还不能证明：

1. 学生拿到P2-T3页面就能学会；
2. 教师能直接拿P2-T3组织课堂；
3. P2-T3中的软件截图、指标阈值和案例数据已经可正式发布。

### 4.4 专业复核仍是硬门禁

P2-T3涉及LOG导入、指标识读、覆盖异常、邻区漏配、问题归因和整改建议。这些内容需要通信专业教师或行业专家复核。

当前可接受的表述是“教学模拟与方法验证”，不能写成“专业结论已确认”。

### 4.5 下一轮不宜直接拆完整18个任务

如果现在直接把18个任务全部拆成详细节点，会出现两个风险：

1. 字段口径未固化，后续返工成本高；
2. 节点数量增加后，审核状态、资源卡片、学习活动、评价产出的关系会变乱。

因此，继续大规模扩展前，应先形成字段规范V0.1。

## 5. 门禁判断

| 门禁 | 结果 | 说明 |
| --- | --- | --- |
| 是否解决目录映射问题 | 通过 | V2主链已改为岗位工作过程 |
| 是否可作为当前图谱基线 | 通过 | 可继续作为后续试拆和整体原型的数据骨架 |
| 是否证明可迁移到非P4-T2任务 | 有条件通过 | P2-T3成立，但样本数量仍少 |
| 是否可直接扩展到整本教材详细节点 | 暂不通过 | 字段规范、枚举、复核和节点粒度未稳定 |
| 是否可进入工具链模块拆解 | 暂不通过 | 仍处于整书原型与图谱模型验证阶段 |
| 是否可进入专业发布口径 | 不通过 | 专业复核、标准条款绑定和媒体治理未完成 |

## 6. 下一步建议

### 6.1 立即下一步：制定课程能力图谱字段规范V0.1

建议先形成 `课程能力图谱字段规范V0.1`，至少包括：

1. 节点ID规则；
2. 节点层级枚举；
3. 岗位工作过程枚举；
4. 能力单元枚举；
5. 任务ID与教材项目映射；
6. 前置节点、后续节点字段；
7. 资源卡片ID与资源类型字段；
8. 学习活动类型字段；
9. 评价产出与评价量规字段；
10. 学习记录事件字段；
11. 学生端表达字段；
12. 教师端使用字段；
13. 审核状态、审核责任人、审核时间字段；
14. 来源依据与标准条款字段；
15. 版本与变更说明字段。

字段规范的目的不是做文档美化，而是为后续批量拆任务、生成资源卡片、构建前端页面和接入平台接口提供稳定数据结构。

### 6.2 第二个试拆任务建议选择P5-T3

第二个非P4-T2试拆任务建议优先选择 `P5-T3 任务3 5G全网性能提升验证`。

理由：

1. P2-T3已经验证了测试数据分析链；
2. P4-T2已经验证了结果验收链；
3. P5-T3能检验 `JP-07 持续提升与复杂复盘` 和 `AU-09 全网性能提升与复测` 是否成立；
4. P5-T3与P4-T2相邻但不重复，更能验证“未闭环问题如何继续提升”的链条；
5. 如果P5-T3也能被稳定拆分，V2对课程后半段的支撑能力会更可信。

`P4-T3 优化报告输出` 仍然重要，但它更适合作为职业表达专项试拆。当前若优先P4-T3，验证难度偏低，容易重复P4-T2和P2-T3-N08已经覆盖的报告表达能力。

### 6.3 不建议立即做的事

当前不建议立即做以下工作：

1. 不建议把全部18个任务一次性拆到详细节点；
2. 不建议继续优化V2界面样式作为主任务；
3. 不建议把P2-T3直接做成完整页面；
4. 不建议进入工具链模块拆解；
5. 不建议宣称课程能力图谱已完成专业复核。

更稳妥的顺序是：

```text
V2内部评审
-> 字段规范V0.1
-> P5-T3第二试拆
-> 对比P2-T3 / P4-T2 / P5-T3三类任务
-> 决定是否批量拆全书任务
```

## 7. 最终判断

本轮评审确认：课程能力图谱V2方向成立，P2-T3试拆成立，V2可以继续作为当前基线。

但当前成果仍处于“内部方法验证”阶段，不是正式课程能力图谱定稿。下一步的关键不是继续画图，也不是继续做页面，而是把图谱从“可理解的样本”推进为“可批量生产、可审核、可接平台的数据规范”。
