# P1-T3增量补拆修订说明V0.3.2A

生成日期：2026-06-24  
修订对象：`P1-T3 任务3：投诉信息采集`  
基线来源：课程能力图谱V0.3.2 + P1-T3 V0.3.2增量 + P1-T3内部评审报告  
修订结论：V0.3.2A作为V0.3.3候选合并依据；尚未直接合并主数据

## 1. 修订原因

P1-T3 V0.3.2增量已经通过结构校验，但内部评审判定不应直接合并V0.3.3。核心原因不是“节点太碎”，而是原 `P1T3-N04 初步定位问题并沟通处理结果` 过粗，混合了两个不同能力动作：

1. 根据投诉信息和现场核实结果形成初步问题判断，并指出后续测试、分析或验证入口；
2. 面向客户沟通处理结果，控制服务承诺边界，并形成后续跟踪闭环。

这两个动作连续但能力属性不同。前者偏专业初判和后续任务路由，容易连接AU-05问题定位及P4结果验证；后者偏客户沟通、职业表达、数据安全和处理承诺边界，容易连接AU-08职业表达。如果继续合并在一个节点中，后续资源、评价、审核和学生学习任务都会混杂。

V0.3.2A只解决合并前必要修订，不生成页面样章，不生成正式教材正文，不进入生产工具链模块拆解。

## 4. 关系表修订

V0.3.2关系表共17条。V0.3.2A关系表调整为21条。

内部主线由：

```text
P1T3-N01 -> P1T3-N02 -> P1T3-N03 -> P1T3-N04
```

调整为：

```text
P1T3-N01 -> P1T3-N02 -> P1T3-N03 -> P1T3-N04 -> P1T3-N05
```

跨任务关系调整为：

1. P1T3-N02 -> P2-T1：投诉信息单支撑测试准备；
2. P1T3-N02 -> P2T3-N01：投诉信息单支撑数据分析任务来源；
3. P1T3-N03 -> P2-T1：现场核实确认后进入测试准备和执行；
4. P1T3-N04 -> P4T2-N01：投诉初判支撑结果验证场景识别；
5. P1T3-N05 -> AU-08：处理结果沟通和闭环表达支撑职业表达能力。

这样可以把“采集投诉信息”与“后续测试、数据分析、验证、职业表达”连接起来，同时避免P1-T3越界承担P2/P3/P4/P5/P6的专业分析任务。

## 6. 数据安全和服务表达门禁

P1-T3首次系统引入客户沟通、投诉记录、地址电话、录音和处理承诺边界，因此本轮明确以下门禁：

1. 不使用真实客户姓名、电话、住址、工单号、录音或可识别地点；
2. 投诉信息单、反馈话术和跟踪记录只能使用教学模拟或脱敏数据；
3. 电话录音和现场核实必须体现客户知情、授权和记录边界；
4. 投诉升级和处理时限不写成通用运营规则，只作为教学化边界判断；
5. 反馈话术必须经过编辑复核，专业原因必须经过通信专业复核；
6. P1-T3只形成投诉初判和后续入口，不替代P2/P3/P4/P5/P6中的专业测试、参数检查、数据分析、验证和复盘。
