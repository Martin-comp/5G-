# P2-T2基于V0.3主数据补拆验证报告

生成日期：2026-06-24  
适用范围：《5G网络优化教材（高级）》数字教材端到端生产演练  
补拆对象：`P2-T2 任务2：5G网络测试问题处理`  
当前定位：V0.3主数据增量验证样例，不直接合并V0.3总表

配套增量样表：

- `reports/P2-T2详细能力节点主数据增量样表V0.3.csv`
- `reports/P2-T2关系增量样表V0.3.csv`
- `reports/P2-T2资源活动评价挂接增量样表V0.3.csv`
- `reports/P2-T2输入输出物治理增量记录V0.3.csv`

## 1. 本轮验证目的

V0.3主数据基线已经建立，但它还需要证明一个关键问题：当后续从未详细试拆的普通任务继续生产时，新增节点、关系、资源活动和评价产出能不能稳定回写到图谱主数据。

因此，本轮不继续做页面原型，也不直接扩展整书前端，而是选择一个普通任务做小规模补拆，验证四件事：

1. 任务骨架能否拆成详细能力节点；
2. 新节点能否接入既有课程能力图谱；
3. 新资源、学习活动、评价产出能否挂接到节点；
4. 新增成果能否进入输入输出物治理清单。

## 2. 为什么选择P2-T2

选择 `P2-T2 5G网络测试问题处理`，不是因为它最重要，而是因为它适合验证V0.3的增量机制。

理由如下：

| 判断维度 | P2-T2特点 | 对V0.3验证的价值 |
| --- | --- | --- |
| 当前状态 | 在V0.3中只是任务骨架，占位而非详细节点 | 能验证“结构占位 -> 详细能力节点”的回写流程 |
| 内容体量 | 原教材125行，体量适中 | 适合小规模补拆，不会变成全任务重做 |
| 任务类型 | 处理硬件、软件、协调类测试问题 | 能检验图谱是否只适合指标分析，还是能承接现场问题处理 |
| 位置关系 | 位于P2-T1测试执行和P2-T3数据分析之间 | 能补强“测试执行 -> 问题处理 -> 数据分析”的链条 |
| 能力挂接 | 同时连接AU-03和AU-05 | 能验证主能力与次能力、数据处理与问题定位之间的关系 |
| 媒体风险 | 包含车载逆变器图片 | 能测试媒体审查是否能进入增量挂接表 |

本轮不选择P3、P4-T1或P5-T1，是因为这些任务体量更大或专业风险更分散，容易把验证主数据机制的问题扩大成内容重构问题。P2-T2更适合做第一轮增量试拆。

## 3. 原教材内容诊断

P2-T2原教材包含五类内容：

1. 任务导入：提出测试现场会遇到各种问题；
2. 任务要求：硬件类、软件类、协调类问题处理；
3. 知识准备：说明三类问题及处理流程意义；
4. 任务实施：列举GPS、终端、扫频仪、逆变器、软件授权、设备连接、数据保存、项目协调和现场协调；
5. 经典案例：部分道路GPS打点失败，最终定位为电脑USB接口问题。

原文对现场问题类型有一定覆盖，但作为数字教材还存在四个问题：

1. 内容按经验条目罗列，学生不容易看出处理顺序；
2. 硬件、软件、协调三类问题之间缺少统一判断入口；
3. “怎么记录问题、怎么形成预案”没有被提升为可评价产出；
4. 图片和软件/设备相关内容存在媒体治理和专业复核风险。

因此，本轮补拆的核心不是把原文改写得更长，而是把它转成可学习、可操作、可评价、可回写图谱的能力链。

## 4. 增量详细能力节点

本轮将P2-T2拆成6个详细能力节点：

| 节点ID | 节点名称 | 学生要解决的问题 | 主要产出 | 主挂能力 |
| --- | --- | --- | --- | --- |
| P2T2-N01 | 识别测试问题类型与处理优先级 | 现场出了哪类问题，先处理什么 | 问题类型判断表 | AU-03 |
| P2T2-N02 | 排查硬件连接与供电类问题 | 设备、线缆、端口、供电哪里可能出问题 | 硬件排查记录单 | AU-03 |
| P2T2-N03 | 排查测试软件启动与设备连接问题 | 软件、授权、驱动、端口和电脑环境如何排查 | 软件连接排查流程单 | AU-03 |
| P2T2-N04 | 检查采集数据保存与完整性 | 测试数据能不能留下来、能不能分析 | 数据保存与完整性检查表 | AU-03 |
| P2T2-N05 | 处理现场协调与责任升级问题 | 该找谁、怎么反馈、什么不能越权承诺 | 现场协调升级记录 | AU-05 |
| P2T2-N06 | 形成测试问题处理记录与预案 | 如何把问题处理过程闭环记录下来 | 测试问题处理记录与预案 | AU-05 |

这组节点的逻辑是：

```text
识别问题类型
-> 硬件排查 / 软件排查 / 现场协调
-> 数据保存与完整性检查
-> 形成问题处理记录与预案
-> 支撑P2-T3数据分析入口
```

## 5. 关系回写验证

`reports/P2-T2关系增量样表V0.3.csv` 当前包含15条增量关系，覆盖五类关系：

1. 任务拆分详细节点：`P2-T2 -> P2T2-N01`；
2. 直接递进：问题识别进入硬件、软件、协调和记录节点；
3. 支撑判断：P2-T2的数据保存和问题记录支撑P2-T3数据分析；
4. 能力挂接：P2T2节点挂接AU-03和AU-05；
5. 跨任务衔接：`P2-T1 -> P2T2-N01`、`P2T2-N04 -> P2T3-N02`、`P2T2-N06 -> P2T3-N01`。

这说明V0.3关系表可以承接新增任务的内部关系，也可以接入既有图谱节点。

## 8. 本轮验证结论

本轮验证结论为：有条件通过。

成立的部分：

1. P2-T2可以从任务骨架拆成6个详细能力节点；
2. 增量节点能接入既有项目、任务、AU-03、AU-05、P2-T1和P2-T3；
3. 增量资源、活动和评价产出可以挂接到节点；
4. 媒体风险和专业复核状态可以保留在增量表中；
5. 输入材料和生成输出物可以进入增量治理清单；
6. 增量表通过CSV结构校验和节点端点校验后，具备合并到后续V0.3.1的条件。

仍不成立或不能过度声称的部分：

1. P2-T2尚未形成学生端教材正文；
2. P2-T2尚未形成可运行前端样章；
3. 硬件排查、软件排查和现场协调口径尚未经过专业教师复核；
4. 车载逆变器图片不能默认进入正式教材，需要媒体审查或重绘；
5. 当前只是验证V0.3增量机制，不代表全书18个任务都可以无风险批量拆分；
6. 当前不应直接合并进V0.3主表，应先人工评审增量样表。

## 9. 对V0.3主数据方案的反馈

本轮补拆说明V0.3主数据结构总体可用，但暴露出两个后续需要注意的问题：

1. V0.3节点表能承接新增详细能力节点，但如果后续要进入平台化，还需要增加更细的字段版本、节点排序、学生正文段落ID和教师材料ID；
2. 增量样表最好先作为独立文件评审，通过后再合并到主表，避免未经审核的节点污染当前基线。

因此，建议形成一个后续执行规程：

```text
任务骨架
-> 增量补拆样表
-> 增量结构校验
-> 人工评审
-> 合并为V0.3.1或下一版主数据
-> 再进入正文、资源和页面生产
```

## 10. 下一步建议

建议下一步先人工评审本轮P2-T2增量补拆：

1. 6个节点是否过细或过粗；
2. AU-03和AU-05挂接是否合理；
3. 与P2-T3的支撑关系是否成立；
4. 资源活动评价挂接是否足够表达学习动作；
5. 车载逆变器图片是否重绘、替换或仅保留为内部审查对象；
6. 是否允许将本轮增量合并到V0.3.1主数据。

如果本轮通过，再选择一个不同类型任务做第二个增量验证。建议候选为 `P3-T3 5G网络参数检查` 或 `P5-T1 5G全网性能指标采集`，用于检验V0.3能否承接参数/指标采集类任务。
