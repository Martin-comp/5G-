# 课程能力图谱字段规范V0.1

生成日期：2026-06-23  
适用范围：《5G网络优化教材（高级）》数字教材端到端生产演练  
依据文件：

1. `reports/课程能力图谱V2优化方案.md`
2. `reports/课程能力图谱V2节点与映射表.csv`
3. `reports/P2-T3详细能力节点试拆报告.md`
4. `reports/课程能力图谱V2与P2-T3试拆内部评审报告.md`
5. `research/findings_capability_graph.md`
6. `research/findings_policy_standards.md`

配套字段清单：`reports/课程能力图谱字段规范V0.1字段清单.csv`

## 1. 制定目的

本规范用于把课程能力图谱从“可看的样本图”推进为“可批量生产、可审核、可接平台的数据结构”。

V2与P2-T3内部评审已经确认：V2方向成立，P2-T3试拆成立。但当前字段仍不足以支撑全书详细拆分，主要缺口包括标准条款、前置/后续关系、资源卡片ID、学习记录事件、评价量规、学生端表达、教师端使用、审核责任和版本追踪。

因此，V0.1的目标不是一次性定义最终平台接口，而是先给后续P5-T3试拆和全书逐步扩展提供稳定字段口径。

## 2. 适用边界

本规范适用于以下工作：

1. 课程能力图谱节点拆分；
2. 项目任务到能力节点的映射；
3. 能力节点到资源卡片、学习活动、评价产出的映射；
4. 学生端和教师端表达转译；
5. 专业复核、媒体审查、编辑审核和版本更新；
6. 后续平台接口、学习数据事件和资源包封装的前置设计。

本规范当前不解决以下问题：

1. 不替代通信专业教师对指标、阈值、案例和结论口径的专业复核；
2. 不直接等同于出版社平台正式接口字段；
3. 不要求全书18个任务一次性拆到详细能力节点；
4. 不要求每个任务都拆成8个节点；
5. 不把AI生成内容视为已审核事实。

## 3. 数据组织方式

V0.1采用“一个主表、三个可扩展子表”的逻辑模型。当前演练阶段可以先用主表承载大部分信息，后续进入平台化或批量生产时再拆成多表。

| 表 | 用途 | 当前阶段处理 |
| --- | --- | --- |
| `capability_node` | 课程能力图谱节点主表 | V0.1必须先建 |
| `capability_relation` | 节点之间的前置、包含、支撑、评价等关系 | V0.1可先用字段记录，后续拆表 |
| `node_resource_binding` | 节点与卡片、表图、互动、学习单、评价产出的绑定 | V0.1可先用字段记录，后续拆表 |
| `node_review_record` | 专业复核、媒体审查、编辑审核、版本变更记录 | V0.1可先用字段记录，后续拆表 |

当前建议先形成一张增强版节点表，字段见 `课程能力图谱字段规范V0.1字段清单.csv`。P5-T3试拆时应按该字段清单填写，不再沿用V2当前12列的简化字段。

## 4. 节点层级枚举

`node_layer` 必须使用受控枚举，不能随意填写自然语言。

| 枚举值 | 中文名称 | 说明 |
| --- | --- | --- |
| `basis` | 依据层 | 政策、教学标准、职业标准、数字教材标准、企业岗位要求等依据 |
| `job_process` | 岗位工作过程层 | 课程能力图谱主链，如明确场景、组织测试、整理数据、定位问题等 |
| `ability_unit` | 能力单元层 | 可学习、可训练、可评价的中层能力单元 |
| `project_task` | 项目任务层 | 原教材项目和任务在图谱中的承载位置 |
| `detail_capability` | 详细能力节点层 | 面向具体任务拆出的学生动作节点 |
| `resource_activity` | 资源活动层 | 卡片、表图、互动、学习单、报告模板等资源与活动绑定 |
| `assessment` | 评价证据层 | 测验、任务产出、学习记录、评价量规和达成证据 |

说明：现有V2中的“岗位工作过程”“能力单元”“详细能力节点”等中文值，在后续数据表中应转换为上述英文枚举，同时保留中文显示名字段。

## 5. 岗位工作过程枚举

`job_process_id` 必须使用以下枚举：

| 枚举值 | 中文名称 | 当前说明 |
| --- | --- | --- |
| `JP-01` | 明确场景与需求 | 收集站点、场景、投诉和业务需求，判断要解决什么问题 |
| `JP-02` | 组织测试与采集数据 | 设计并执行DT/CQT、业务体验和专项测试 |
| `JP-03` | 整理数据与识读指标 | 整理测试、监控、参数和日志，形成可判断数据基础 |
| `JP-04` | 定位问题与制定方案 | 定位覆盖、干扰、切换、容量、体验等问题，并形成优化方案 |
| `JP-05` | 实施优化与记录变更 | 执行参数、工程、容量或策略优化，并记录变更 |
| `JP-06` | 验证效果与表达结论 | 复测优化效果，形成判断、依据、边界和报告表达 |
| `JP-07` | 持续提升与复杂复盘 | 对未闭环问题做性能提升、信令分析和复杂问题复盘 |

## 7. 节点ID规则

节点ID必须稳定、可读、可追溯。

| 节点类型 | ID规则 | 示例 |
| --- | --- | --- |
| 岗位工作过程 | `JP-序号` | `JP-03` |
| 能力单元 | `AU-序号` | `AU-07` |
| 项目任务 | `P项目号-T任务号` | `P5-T3` |
| 详细能力节点 | `P项目号T任务号-N序号` | `P2T3-N05` |
| 资源卡片 | `P项目号T任务号-C序号` | `P4T2-C03` |
| 学习活动 | `P项目号T任务号-ACT序号` | `P5T3-ACT02` |
| 评价量规 | `P项目号T任务号-RUB序号` | `P2T3-RUB01` |
| 学习事件 | `EVT-动作-序号` | `EVT-submit-report-01` |

禁止事项：

1. 禁止使用“节点1”“能力点A”等不可追溯ID；
2. 禁止同一个节点在不同文件中使用不同ID；
3. 禁止删除已发布ID后复用给新节点；
4. 节点废弃时应保留ID，并将 `node_status` 标为 `deprecated`。

## 8. 必填字段分级

字段分为三级：

| 等级 | 含义 | 后续处理 |
| --- | --- | --- |
| `R1` | 当前试拆必须填写 | P5-T3试拆必须完整填写 |
| `R2` | 当前建议填写，暂缺可标注原因 | 可填 `pending`、`not_applicable` 或说明 |
| `R3` | 平台化或正式发布前填写 | 当前可预留，但不能删除 |

P5-T3第二试拆时，至少要完整填写所有 `R1` 字段，并尽量填写 `R2` 字段。

## 11. 审核状态枚举

`audit_status` 必须使用受控枚举，不能再只写自然语言。

| 枚举值 | 中文名称 | 使用场景 |
| --- | --- | --- |
| `draft_ai_generated` | AI生成待审 | AI补强、改写或推断内容 |
| `source_extracted` | 原教材抽取 | 来自原教材但尚未教学化处理 |
| `teaching_transformed` | 已教学化改写 | 已转为教材正文、卡片或活动 |
| `pending_professional_review` | 待专业复核 | 指标、阈值、案例、结论口径待通信专业复核 |
| `pending_media_review` | 待媒体审查 | 图片、截图、视频、仿真资源待审 |
| `pending_editorial_review` | 待编辑审核 | 文字、版权、出版规范待审 |
| `review_passed` | 审核通过 | 已通过相应审核 |
| `revision_required` | 需修改 | 审核发现问题，需要返修 |
| `disabled` | 禁用 | 不进入正式教材 |
| `deprecated` | 已废弃 | 历史保留，不再作为当前节点 |

如果一个节点同时存在多类审核风险，应在 `review_required_type` 中列出，如 `professional;media;editorial`。

## 13. 学生端与后台字段分离

同一个节点必须同时保留后台字段和前端表达字段。

| 后台字段 | 学生端字段 | 说明 |
| --- | --- | --- |
| `node_name` | `student_title` | 后台可写“判断移动性/邻区异常”，学生端应写“判断是不是切换或邻区出了问题” |
| `capability_goal` | `student_learning_goal` | 后台描述能力目标，学生端描述这一页要学会什么 |
| `assessment_output` | `student_output` | 后台写评价产出，学生端写你要交什么 |
| `mastery_criteria` | `student_completion_criteria` | 后台写达成标准，学生端写怎样算完成 |
| `audit_status` | 不直接显示 | 审核状态不进入学生学习主界面 |

原则：学生端不得直接暴露节点ID、证据ID、审核字段、资源状态字段和生产流程字段。

## 14. 学习记录事件字段

每个详细能力节点原则上应至少设计一个学习记录事件。事件不是现在必须接入数据库，但字段必须先存在。

推荐事件类型：

| 事件类型 | 说明 |
| --- | --- |
| `view_resource` | 查看资源 |
| `start_activity` | 开始学习活动 |
| `submit_answer` | 提交判断或答案 |
| `revise_answer` | 修改答案 |
| `submit_worksheet` | 提交学习单 |
| `submit_report` | 提交报告 |
| `pass_check` | 通过检查 |
| `need_remediation` | 需要补救学习 |
| `teacher_review` | 教师讲评或确认 |

事件字段至少包括：

1. `learning_event_id`
2. `learning_event_type`
3. `event_trigger`
4. `event_payload_summary`
5. `remediation_rule`

## 15. 评价量规字段

每个详细能力节点必须有评价产出，但不一定都需要复杂量规。V0.1采用三级量规：

| 等级 | 含义 | 使用场景 |
| --- | --- | --- |
| `checklist` | 检查清单 | 任务单、流程记录、字段核对 |
| `rubric_3_level` | 三档量规 | 结论表达、报告输出、原因分析 |
| `expert_review` | 专业复核 | 指标阈值、案例结论、整改建议 |

字段要求：

1. `assessment_output` 写学生产出；
2. `assessment_method` 写评价方式；
3. `rubric_id` 写量规ID；
4. `mastery_criteria` 写达成标准；
5. `common_errors` 写常见错误；
6. `feedback_strategy` 写反馈与二次修正方式。

## 16. P5-T3试拆填写要求

下一轮 `P5-T3 任务3 5G全网性能提升验证` 试拆时，应按本规范执行：

1. 不再只填V2旧表的12列；
2. 必须填写所有 `R1` 字段；
3. 必须使用受控枚举；
4. 必须显式写出前置节点和后续节点；
5. 必须写出资源卡片候选ID；
6. 必须写出学习记录事件；
7. 必须写出审核状态和审核类型；
8. 对不确定专业结论必须标为 `pending_professional_review`；
9. 对原教材图片、截图和仿真软件界面必须标为 `pending_media_review` 或说明重绘策略；
10. 不得把P5-T3拆成固定8个节点，应根据任务复杂度拆成3到8个详细能力节点。

## 18. 质量门禁

后续任何新增课程能力图谱节点，至少要通过以下检查：

1. 是否有稳定 `node_id`；
2. 是否明确 `node_layer`；
3. 是否映射到 `job_process_id` 或说明不适用；
4. 是否映射到 `ability_unit_id` 或说明不适用；
5. 是否有来源和审核状态；
6. 是否有学生端表达；
7. 是否有学习动作；
8. 是否有评价产出；
9. 是否有资源或活动绑定；
10. 是否有前置或后续关系；
11. 是否能被教师用于教学组织或讲评；
12. 是否标注专业复核、媒体审查、编辑审核风险。

若以上任一项缺失，节点可以作为过程草稿保留，但不得作为正式图谱节点进入批量生产。

## 19. 与后续工作的关系

字段规范V0.1完成后，下一步不是继续完善文档，而是用它约束第二个任务试拆：

```text
字段规范V0.1

```

只有当字段规范经过至少三类任务验证后，才建议进入工具链模块拆解。
