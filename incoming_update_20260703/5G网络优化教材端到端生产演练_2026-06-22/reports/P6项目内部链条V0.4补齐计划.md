# P6项目内部链条V0.4补齐计划

生成日期：2026-06-26  
计划对象：项目六内部链条 `P6-T1 -> P6-T2`  
前置依据：`reports/项目六内部链条评审报告V0.3.9.md`  
当前结论：先补齐P6-T2风险治理与项目六关系校正，再判断是否进入第十类普通任务候选选择。

## 1. 本计划解决什么问题

项目六内部链条评审已经判断 `P6-T1 基础信令流程解析与证据入口` -> `P6-T2 复杂信令问题分析、优化建议和复盘报告` 有条件成立。

但当前仍有三个结构性缺口：

1. P6-T1已经形成16条V0.4风险治理记录，P6-T2仍主要停留在V0.2/V2风险表达，项目内治理口径不一致；
2. V0.3.9同时保留了P6-T1到P6-T2的旧任务级支撑关系和新增详细节点级支撑关系，后续可视化、检索和学习路径推荐可能出现重复路径；
3. `P6T1-N08 分析5G重选到4G案例并连接复杂复盘` 是必要过渡节点，但必须限制为“小案例证据链和复杂复盘入口”，不能扩张成P6-T2完整复杂复盘。

因此，本计划不继续选择第十类普通任务，而是先把项目六内部链条补稳。

## 2. 补齐边界

本计划只做治理补齐和关系校正，不做以下事项：

1. 不重拆P6-T1八个详细能力节点；
2. 不重拆P6-T2七个详细能力节点；
3. 不直接改写V0.3.9四张主数据表；
4. 不生成P6学生端教材正文；
5. 不制作P6可运行页面；
6. 不制作正式流程图、动画、互动或小游戏；
7. 不生成正式资源包；
8. 不接入出版社平台、学习记录库或AI助手；
9. 不选择第十类普通任务；
10. 不把V0.4补齐等同于专业复核、媒体审查、学生正文审查、平台验证或真实教学验证完成。

本计划要回答的是：P6-T2需要补哪些V0.4风险记录，P6-T1与P6-T2之间的关系需要怎样校正，补齐后用什么门禁判断是否可以继续选择下一类普通任务。

## 3. 项目六关系表达原则

项目六不应被写成简单的：

```text
P6-T1 -> P6-T2
```

更准确的表达应是：

```text
P6-T1 先让学生看懂5G关键信令流程、系统消息、RRC重配和工具证据入口
-> 用小案例把“流程知识”连接到“问题复盘入口”
-> P6-T2再处理复杂信令问题分类、接入/切换/掉线排查、优化建议和复盘报告
```

后续关系校正应区分四类关系：

| 关系类型 | 含义 | 项目六示例 |
| --- | --- | --- |
| 先修基础 | P6-T1中必须先学会的流程或字段基础 | `P6T1-N02 -> P6T2-N03` |
| 证据入口 | 用于定位P6-T2数据来源或工具入口 | `P6T1-N07 -> P6T2-N01` |
| 问题分类支撑 | 用于支持P6-T2的问题类型区分 | `P6T1-N05 -> P6T2-N02` |
| 过渡边界 | 小案例进入复杂复盘，但不替代完整复盘 | `P6T1-N08 -> P6T2-N07` |

旧任务级关系可以保留为项目级概括关系，但必须标注为“已由详细节点关系细化”或“仅用于项目总览”，不能和详细节点关系混成同等学习路径。

### 7.1 ID规则

| 文件 | ID前缀 |

| P6项目内部关系校正清单 | `P6REL-V04-001` 起 |

### 7.2 门禁状态规则

当前阶段不允许出现以下误标：

1. `overall_publish_gate_status=approved`
2. `professional_gate_status=passed`
3. `media_gate_status=passed`
4. `student_text_gate_status=passed`
5. `platform_gate_status=passed`
6. `teaching_validation_gate_status=passed`

除非有真实专业复核、媒体审查、学生正文审读、平台接口验证或一线教学验证证据，否则一律保持 `pending`、`revision_required`、`review_pending`、`not_started` 或 `internal_review`。

### 7.3 典型字段规则

| 场景 | 字段填写规则 |
| --- | --- |
| 涉及信令流程或协议字段 | `professional_risk_type` 包含 `terminology` 或 `procedure`，`professional_gate_status=pending` |
| 涉及信令分析工具界面或截图 | `resource_review_object_type=screenshot`，`source_transformation_type=redrawn`，`media_gate_status=revision_required` |
| 涉及真实日志、信令文件、测试数据 | `data_security_review_scope` 必须明确，必要时标注脱敏要求 |
| 涉及优化建议 | `professional_risk_type` 包含 `engineering_boundary`，并在 `gate_blocking_reason` 写明适用边界 |
| 涉及教学模拟案例 | `case_authenticity_type=teaching_simulation`，填写 `case_applicability_boundary` |
| 涉及报告输出 | `editorial_gate_status=pending`，`student_text_gate_status=review_pending` |

## 10. 内部评审标准

`reports/P6项目V0.4补齐内部评审报告.md`
