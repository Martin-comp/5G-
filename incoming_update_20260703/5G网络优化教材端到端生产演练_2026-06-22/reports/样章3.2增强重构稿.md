## 1. 重构结论

原3.2文本稿已经解决了“大纲化”和“标题堆叠”的主要问题，但仍偏向“围绕现有样章数据写一版可读正文”。本增强稿进一步明确：数字教材不能被原教材质量锁死，必须在保留原教材任务范围的同时，对原内容进行纠偏、补强和扩展。

本稿不推翻3.2初稿，而是把它升级为可进入前端改造的内容母本。升级重点有四个：

1. 学生端仍然读到自然的教材正文，不看到后台元数据；
2. 教师和编辑端能看到来源、依据、待复核点和媒体处理建议；
3. 专业内容不只来自原教材，而是综合专业教学标准、职业技能标准、3GPP/ETSI技术规范和教学化推断；
4. 对原教材中不清楚、不适合学生自学或可能有口径风险的内容，主动进行纠偏。

## 4. 原教材需要纠偏和补强的地方

### 4.1 任务导入过弱

原教材导入提出“微信视频卡顿、掉线、直播时延大”等现象，但没有把学生放入一个清晰的岗位任务中。学生读完可能知道“本节会讲这些问题”，但不知道自己要完成什么判断。

增强处理：改成“校园宿舍区优化后，网页恢复但视频/直播仍异常”的真实任务，让学生先判断“本次优化是否达标”，再进入数据阅读。

### 4.2 知识准备过长

原教材按覆盖、切换、时延、速率、容量、掉线展开大量知识和参数，适合做资料库，但不适合作为学生第一次进入任务时的阅读顺序。

增强处理：学生端先读完成本任务所需的最小知识；详细参数、事件公式和扩展知识转为资源抽屉或教师讲解层。

### 4.3 阈值口径不能泛化

原教材引用运营商覆盖要求和场景阈值，但不同运营商、频段、波束配置、业务场景、测试口径可能不同。并且原文中“SS-RSRP≥105dBm覆盖率满足95%”疑似缺少负号，必须核对原规范或教材源文件，不能原样进入正式数字教材。

增强处理：学生端不把某个阈值写成普遍标准；正文只训练“看目标值、看优化前后、看是否达标、看是否能支撑结论”。具体阈值放入待专家复核项。

### 4.4 仿真软件截图不能直接作为学生主材料

原教材任务实施依赖特定仿真软件截图查询覆盖、切换、时延、速率、容量、掉线结果。截图如果缺少字段解释、操作入口、指标口径和读图路径，学生难以自学，出版社也不能默认其版权和平台适配无问题。

增强处理：正式学生主学习区使用重绘教学图、指标表或交互数据面板；原截图可进入附录、教师材料或媒体审查层。

### 4.5 缺少职业表达训练

原教材有任务测评，但学生不一定能把数据组织成“优化结果验证结论”。

增强处理：增加“判断状态、关键依据、不能说明的边界、后续建议”的报告句式训练。

## 5. 学生端教材正文增强版

以下内容是学生可直接阅读的正文。前端可以拆成任务流、卡片、材料详情、弹层提示或自学支架，但不能只保留标题。

### 5.1 真实任务：网页好了，为什么还不能直接说优化成功

某高职院校宿舍区完成了一轮5G网络优化。优化前，学生集中投诉晚间网络体验差：微信视频经常卡顿，直播推流延迟明显，个别位置还会短时掉线。优化后，普通网页访问基本恢复，图片和文字页面打开明显顺畅。

但新的投诉又出现了：到了晚间高峰，视频通话仍然偶发卡顿，直播上行仍有明显延迟。现场负责人要求网优小组给出一个判断：本次优化结果是否可以验收通过？

现在，你扮演网络优化助理工程师。你不能只回答“好了”或“没好”，而要写出一个能被追问的结论：

```text
本次优化结果是否达标？
我依据哪些数据这样判断？
哪些数据还不能证明结论？
下一步还要补充什么测试或优化？
```

先写下你的初步判断：

```text
我初步判断本次优化结果为：达标 / 部分达标 / 未达标 / 暂时无法判断。

我的第一理由是：

我最想先查看的数据是：
```

这个判断可以先不正确。岗位工作中，先判断、再找依据、再修正，是比“等老师讲完再抄答案”更重要的能力。

### 5.2 先学会工作顺序：验证不是看一张截图

优化结果验证不是打开软件看一张“结果图”，也不是看到某个指标变好就写“优化成功”。更可靠的顺序是：

```text
先明确投诉和验收目标；
再查看优化前后的覆盖、切换和业务体验数据；
然后判断每类数据能支持什么、不能支持什么；
最后写出是否达标、依据和后续建议。
```

本任务原教材包含六类验证对象：覆盖、切换、时延、速率、容量和掉线。为了让你先学会判断方法，本样章把它们组织成三组：

| 学习入口 | 对应原教材内容 | 它回答的问题 |
| --- | --- | --- |
| 覆盖与质量 | 覆盖优化结果、SS-RSRP、SS-SINR、弱覆盖 | 信号是否够强、质量是否够好 |
| 移动与保持 | 切换优化结果、A类事件、SA/NSA切换、掉线 | 移动过程中业务是否连续 |
| 业务体验 | 时延、速率、容量、卡顿、直播上行 | 用户真实业务是否恢复 |

这里做了一个教学化重组：原教材的六类内容没有被删掉，而是先合并成学生更容易理解的三条判断线。等你掌握判断方法后，再回到六类指标细分。

### 5.3 覆盖与质量：信号强，不代表体验一定好

先看覆盖。覆盖验证常见指标包括SS-RSRP和SS-SINR。

SS-RSRP可以先理解为“同步信号接收功率”，学生端可暂时把它看作信号强度入口。它适合回答：优化后信号是不是更强，弱覆盖是不是减少。

SS-SINR可以先理解为“信号质量和干扰情况”。它适合回答：信号是不是更干净，干扰是不是仍然可能影响业务。

下面是样章教学模拟数据，不代表真实验收标准。

| 指标 | 优化前 | 优化后 | 目标状态 | 读法 |
| --- | ---: | ---: | --- | --- |
| SS-RSRP覆盖率 | 88.4% | 96.3% | 需按场景复核 | 覆盖强度明显改善 |
| SS-SINR覆盖率 | 84.2% | 94.1% | 需按场景复核 | 质量改善，但不能直接写成完全达标 |
| 弱覆盖采样点占比 | 12.6% | 3.8% | 越低越好 | 弱覆盖明显减少 |

这组数据能支持什么？

它能支持“覆盖强度改善”“弱覆盖问题减少”。如果你写报告，可以这样表达：

```text
覆盖侧优化有效。SS-RSRP覆盖率由88.4%提升至96.3%，弱覆盖采样点占比由12.6%降至3.8%，说明覆盖强度和弱覆盖问题已有明显改善。
```

这组数据不能说明什么？

它不能单独证明视频通话不卡顿，也不能单独证明直播上行已经恢复。因为视频和直播还会受干扰、切换、容量、上行资源、传输和服务器等因素影响。

更稳妥的结论是：

```text
覆盖侧已有明显改善，但还不能仅凭覆盖数据判断整体优化达标，需要继续查看业务体验和移动过程数据。
```

### 5.4 移动与保持：流程图能帮助理解，但不能替代现场日志

学生在宿舍区移动时，手机可能从一个小区切换到另一个小区。切换做得好，视频或直播能较平稳地继续；切换过早、过晚、失败或过于频繁，都可能导致卡顿、掉线或重连。

原教材讲了A1、A2、A3、A4、A5等测量事件。学生第一次学习时，不需要背完每个公式。先抓住A3事件的岗位含义：当邻区比当前服务小区更适合服务终端时，网络可能触发切换判断。

切换流程可以先拆成三步：

```text
测量：终端上报服务小区和邻区情况；
判决：网络判断是否需要切换；
执行：网络准备资源并让终端切到目标小区。
```

流程图能说明正常情况下切换怎么发生，但不能证明本次现场切换没有问题。要判断“视频卡顿是不是切换造成的”，还需要现场日志，例如：

| 需要补充的数据 | 用来判断什么 |
| --- | --- |
| 切换成功率 | 是否存在大量切换失败 |
| 切换时延 | 切换是否过慢影响业务连续性 |
| 重建立/异常释放记录 | 是否出现无线链路失败或掉线 |
| 事件触发位置和服务小区/邻区RSRP、SINR | 是否存在切换过早、过晚或邻区漏配 |

所以，看到切换流程图后，合理表达不是“切换正常”，而是：

```text
切换流程图只能说明验证思路。若要判断本次现场移动过程中业务是否连续，还需要查看切换成功率、重建立、异常释放和相关信令日志。
```

这就是数字教材需要补强原教材的地方：不能只给复杂流程图，还要告诉学生图能用来做什么，不能直接证明什么。

### 5.5 业务体验：平均值变好，不代表晚高峰用户都满意

业务体验最接近用户真实感受。网页访问、视频通话、直播上行、游戏和下载对网络的要求不同。本任务的投诉重点不是“网页能否打开”，而是“视频和直播是否稳定”。

下面仍然使用样章教学模拟数据。

| 指标 | 优化前 | 优化后 | 读法 |
| --- | ---: | ---: | --- |
| 视频通话平均端到端时延 | 78 ms | 42 ms | 平均体验明显改善 |
| 直播上行95分位时延 | 180 ms | 110 ms | 有改善，但仍需按目标判断是否达标 |
| 10分钟业务卡顿次数 | 6次 | 2次 | 卡顿减少，但问题未必完全解决 |

视频平均端到端时延从78 ms降到42 ms，可以说明平均体验明显改善。但报告不能只看平均值。直播上行95分位时延提醒我们关注体验较差的那部分情况：即使大多数时间还可以，少数高时延时段也可能让直播用户明显感到延迟。

卡顿次数从6次降到2次，说明问题缓解，但仍可能影响用户感知。如果课程或项目目标要求更低卡顿次数，优化后仍不能写成全部达标。

这组数据更适合支持这样的判断：

```text
业务体验已有改善，其中视频通话平均时延明显下降；但直播上行95分位时延和卡顿次数仍需结合目标值复核，不能直接判断为全部达标。
```

### 5.6 容量、速率和掉线：为什么本样章不直接展开所有细节

原教材还包含速率、容量和掉线优化结果验证。它们不是不重要，而是本样章先聚焦“学生如何形成结果验证结论”。

你可以先这样理解三者：

| 验证对象 | 学生端先这样理解 | 常见补充数据 |
| --- | --- | --- |
| 速率 | 用户上传、下载是否达到业务需要 | 上/下行吞吐率、边缘速率、资源块利用率 |
| 容量 | 晚高峰用户多时网络是否还能承载 | 用户数、PRB利用率、负荷、拥塞记录 |
| 掉线 | 业务是否异常中断 | 掉线率、异常释放、RLF、重建立失败 |

如果视频和直播投诉集中在晚高峰，就不能只看覆盖。晚高峰可能同时涉及容量和上行资源问题。如果学生移动时卡顿明显，就要补看切换和掉线日志。

因此，本任务的完整判断应至少包含一句“还需补充核查”的内容，而不是把所有未展示的数据都默认正常。

### 5.7 仿真截图怎么处理：看不懂的图不能强行当依据

原教材任务实施中使用仿真软件查询覆盖、切换、时延、速率、容量、掉线等优化结果。仿真软件对实训有价值，但截图不能直接成为学生主学习材料，原因有三点：

1. 学生不知道应看哪个字段；
2. 截图未必说明指标口径和目标值；
3. 特定软件界面可能不适合在出版社平台中直接复用。

正式数字教材应把截图改造成以下形式之一：

| 原材料 | 学生端替代形式 | 目的 |
| --- | --- | --- |
| 覆盖优化截图 | SS-RSRP/SS-SINR对比表或热力示意图 | 教学生读覆盖结果 |
| 切换优化截图 | 三阶段切换流程图 + 异常日志样例 | 教学生判断切换风险 |
| 时延优化截图 | 平均值、95分位、业务类型对比表 | 防止只看平均值 |
| 速率优化截图 | 上下行速率与业务需求对照表 | 连接用户体验 |
| 容量优化截图 | 晚高峰负荷与用户数关系图 | 解释高峰体验差 |
| 掉线优化截图 | 异常释放/RLF/重建立失败证据链 | 判断业务中断原因 |

如果一张图不能说明“看哪里、说明什么、不能说明什么”，就不应放在学生主学习区。

### 5.8 学生实践：完成一份短结论

请根据前面的数据，完成下面的结论任务。

第一步，判断状态：

```text
本次优化结果我判断为：达标 / 部分达标 / 未达标 / 暂时无法判断。
```

第二步，写两条支持依据：

```text
依据1：
这条数据说明：
它还不能说明：

依据2：
这条数据说明：
它还不能说明：
```

第三步，写一个还需要补充核查的数据：

```text
我还需要补充查看：
因为：
```

第四步，形成职业表达：

```text
本次优化结果建议判断为____。依据是____。但____仍不能证明全部达标，还需补充____。建议下一步____。
```

### 5.9 常见错误和修改示范

错误一：

```text
网页能打开了，所以优化成功。
```

问题：网页访问恢复不等于视频、直播等实时业务恢复。

修改：

```text
网页访问已有改善，但本次投诉重点还包括视频通话和直播上行体验，需要继续查看时延、卡顿、切换和容量相关数据。
```

错误二：

```text
覆盖率提升，所以整体达标。
```

问题：覆盖改善不能替代业务体验验证。

修改：

```text
覆盖强度改善明显，但整体是否达标还需结合SS-SINR、业务时延、卡顿次数、切换和掉线数据综合判断。
```

错误三：

```text
流程图显示切换流程完整，所以切换没有问题。
```

问题：流程图说明理论流程，不代表现场日志正常。

修改：

```text
切换流程图可以帮助理解验证步骤，但仍需查看切换成功率、重建立、异常释放和测量报告日志，才能判断现场切换是否影响业务。
```

错误四：

```text
仿真截图显示结果改善，所以可以作为最终依据。
```

问题：未标注截图无法说明字段含义、指标口径和适用边界。

修改：

```text
仿真截图可作为辅助材料，但正式结论应优先引用可解释的数据表、日志或重绘后的教学图；未标注截图不能单独作为最终判断依据。
```

### 5.10 可提交结论示例

```text
本次优化结果建议判断为部分达标。

依据是：SS-RSRP覆盖率由88.4%提升至96.3%，弱覆盖采样点占比由12.6%下降至3.8%，说明覆盖强度和弱覆盖问题已有明显改善；视频通话平均端到端时延由78 ms下降至42 ms，说明视频通话平均体验明显改善。

但还不能判断为全部达标。SS-SINR优化后为94.1%，是否满足本场景目标值需要复核；直播上行95分位时延由180 ms下降至110 ms，虽然有改善，但仍可能影响高峰期直播体验；10分钟卡顿次数由6次下降至2次，说明卡顿减少但尚未完全消除。

后续建议补充晚高峰路测数据、直播上行业务日志、切换成功率、异常释放和容量负荷数据，并将原仿真截图改造成带字段解释和读图路径的教学图后再进入正式教材。
```

## 8. 进入3.2前端的改造建议

1. 首屏先显示真实任务和初步判断输入，不先显示材料目录；
2. 中间区域按“覆盖与质量、移动与保持、业务体验、媒体边界”四个材料入口组织；
3. 每个材料入口必须包含正文解释、数据表、学生动作和反馈提示；
4. 自学模式加入术语解释、读数步骤、句式支架和错误原因；
5. 课堂模式加入教师暂停点、小组分工、投票或汇报提示；
6. 能力地图节点点击后跳转到对应正文段落和练习，不只显示资源标题；
7. 右侧学习记录不要叫“证据X”，改为“我已查看的数据、我的判断依据、还缺少的数据”；
8. 教师/编辑视图显示来源层级、审核状态、专业复核清单和媒体处理建议；
9. QA脚本应检查首屏是否包含真实案例、初判任务、至少一个数据表、至少一个“能说明/不能说明”反馈、课堂/自学差异和无横向溢出。
