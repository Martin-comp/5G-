# P1-T3基于V0.3.2主数据补拆验证报告

生成日期：2026-06-24  
验证对象：P1-T3 任务3：投诉信息采集  
当前主数据基线：课程能力图谱V0.3.2  
结论：P1-T3适合作为第三个普通任务增量验证对象。本轮建议形成4个详细能力节点和配套增量样表，但不直接合并为V0.3.3。

## 1. 本轮定位

本轮只做课程能力图谱主数据增量验证，不制作页面样章，不生产正式资源包，也不进入工具链模块拆解。

P1-T3的验证价值不在于补一个普通章节，而在于验证课程能力图谱能否承接此前较少覆盖的“上游信息采集、客户沟通、投诉受理、隐私信息记录和投诉处理反馈”类任务。此前V0.3.2已覆盖数据分析、结果验证、问题处理、参数检查、性能提升和信令复盘，但AU-01仍停留在骨架层，缺少详细能力节点。

本轮生成的四张表是增量样表，不是主表；只有经过内部评审、必要修订和用户确认后，才考虑是否进入V0.3.3合并。

## 2. 原教材内容诊断

P1-T3原文位于 `extracted/textbook.md` 第1259至1595行，任务模块包括：

1. 投诉的应答和信息记录；
2. 投诉信息现场采集；
3. 投诉信息定位处理；
4. 与客户沟通投诉处理结果。

原文的可用价值包括：

1. 任务边界清楚，能说明投诉信息是网络优化前端输入；
2. 有投诉分类、投诉处理原则、投诉处理流程、现场核实流程和用户投诉信息表；
3. 有结果反馈话术、经典案例和角色扮演练习；
4. 媒体风险较低，主要风险不在图片，而在话术、隐私、专业判断和服务承诺边界。

原文的主要问题包括：

1. 话术很多，但教材化支架不足，学生可能照读话术而不理解为什么这样问；
2. 投诉分类和紧急投诉条目容易被机械背诵，需要转为“处理边界判断”；
3. 用户姓名、地址、联系电话、录音等信息涉及隐私和数据安全，不能只按普通学习表格处理；
4. 部分案例偏4G语境，进入5G数字教材前需要标注“教学案例”和适用边界；
5. 定位处理部分包含覆盖、干扰、室分、参数、网管协同等复杂专业判断，不能在P1-T3中展开成完整问题定位课，应保持为“初步定位和后续任务入口”。

## 3. 节点拆分判断

本轮不建议把普通投诉、紧急投诉、重大投诉、升级投诉、批量投诉、重复投诉、跨区域投诉等每一类都拆成图谱节点。这些内容更适合进入分类表、判断卡和练习活动。

本轮也不建议把每一种反馈话术都拆成节点。话术是资源卡和评价材料，不是稳定能力节点。

建议形成4个详细能力节点：

| 节点ID | 节点名称 | 拆分理由 |
| --- | --- | --- |
| P1T3-N01 | 完成投诉应答、分类与升级判断 | 承接投诉入口，判断普通/紧急/升级/批量/重复等处理边界 |
| P1T3-N02 | 核实投诉关键信息并填写信息单 | 将客户描述转为可用于测试、分析和后续处理的结构化信息 |
| P1T3-N03 | 现场核实投诉场景与业务现象 | 把投诉信息与现场环境、业务体验、无线环境和测试准备连接起来 |
| P1T3-N04 | 初步定位问题并沟通处理结果 | 将现场核实结果转成初步原因、后续处理入口和客户反馈口径 |

这个拆法保留了原教材四个模块的主线，同时避免把图谱拆成客服话术清单或投诉表字段清单。

## 4. 关系设计

P1-T3内部关系采用线性主线：

```text
P1T3-N01 -> P1T3-N02 -> P1T3-N03 -> P1T3-N04
```

但P1-T3不能只作为本任务内部流程，还需要连接整门课：

1. P1-T1室内环境信息采集、P1-T2室外环境信息采集支撑P1T3-N03现场核实；
2. P1T3-N02形成的投诉信息单支撑P2-T1测试准备和P2T3-N01分析任务来源；
3. P1T3-N03形成的现场核实记录支撑P2-T1测试执行；
4. P1T3-N04形成的初步定位和反馈口径支撑P4T2-N01识别验证场景；
5. 4个详细节点均主挂AU-01，N03次级连接AU-02/AU-03，N04次级连接AU-05/AU-08。

## 5. 资源、活动与评价设计

本轮共规划14条资源活动评价挂接。

核心资源类型包括：

1. 投诉类型与紧急程度判断卡；
2. 应答原则与升级边界卡；
3. 投诉信息字段核对卡；
4. 教学化用户投诉信息表；
5. 现场预约与上门核实流程卡；
6. 现场业务现象观察表；
7. 投诉原因初步定位案例卡；
8. 处理结果反馈话术边界卡；
9. 经典案例回复辨析卡；
10. 投诉受理分类单、投诉信息记录单、现场核实记录和投诉处理反馈单等评价产出。

互动转化方向建议为：

1. 场景归类：根据投诉描述判断普通、紧急、升级、批量或重复投诉；
2. 信息补全：从客户口述中提取时间、地点、业务类型、终端型号、影响范围等字段；
3. 流程排序：预约、准备、上门、测试、告知、回访的顺序判断；
4. 话术辨析：判断哪些话术越权承诺、缺少同意、缺少安抚或缺少处理边界；
5. 案例复盘：把弱覆盖、测试正常、室内无覆盖案例转成原因、证据和反馈口径。

## 6. 特殊治理问题

P1-T3暴露的治理问题和前两轮不同。

| 问题 | 影响 | 本轮处理 |
| --- | --- | --- |
| 用户隐私信息 | 投诉单包含姓名、地址、联系电话、工作单位、录音等敏感信息 | 在节点N02和挂接表中加入数据安全/脱敏检查，后续可考虑形成隐私治理专门字段 |
| 客户沟通话术 | 话术若表达不当，会造成越权承诺或服务争议 | 作为资源卡和评价活动处理，需教师/编辑复核 |
| 投诉升级边界 | 紧急、重大、升级、批量、重复等分类涉及运营商制度 | 当前只作为教学模拟和原则性训练，需专业复核 |
| 定位处理口径 | 弱覆盖、干扰、室分、参数、网管协同等判断复杂 | 在P1-T3只做初步定位，不展开为完整问题定位课 |
| 案例年代与网络制式 | 原文案例偏4G，不能直接写成5G真实案例 | 标注为教学案例，进入正式教材前需改写或补充5G适用边界 |

## 8. 当前结论

P1-T3作为第三个普通任务增量验证对象成立。4节点方案比按投诉类型、话术条目、表格字段逐项拆分更稳，符合“能力节点承载稳定职业任务，具体话术、字段、案例和练习下沉为资源、活动、评价或治理项”的原则。

但本轮不建议直接合并V0.3.3。原因是P1-T3首次引入客户沟通和用户信息治理问题，需要先做内部评审，重点检查：

1. 4个节点是否仍过粗或过细；
2. N04是否把“初步定位”写得过深，侵入后续网络问题定位课程；
3. 用户隐私、录音、联系方式和地址字段是否需要独立治理规则；
4. 话术、投诉升级、处理时限和客户承诺是否需要专业/编辑双重复核；
5. 经典案例是否应改写为5G教学模拟案例后再进入资源包。

建议下一步先做 `P1-T3增量补拆内部评审报告.md`，通过后再决定是否形成P1-T3 V0.3.2A修订表或合并V0.3.3。
