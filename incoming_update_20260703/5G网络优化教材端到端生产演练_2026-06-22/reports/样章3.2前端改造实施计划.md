# 样章3.2前端改造实施计划

生成日期：2026-06-23  
改造对象：`samples/task_workbench_3_0_sample/`  
内容母本：`reports/样章3.2增强重构稿.md`  
样章对象：《5G网络优化教材（高级）》项目四 / 任务2：5G网络优化结果验证

## 1. 执行结论

样章3.1已经证明“任务工作台 + 材料聚焦看板 + 能力地图导航层”可以运行，但仍不能充分解决学生“不知道怎么学、仔细看也学不会”的问题。3.2改造不应继续主要调整卡片布局，而应把 `样章3.2增强重构稿.md` 中的教材正文、读数据方法、判断边界、实践任务和反馈示范写入前端。

本轮实施目标是把3.1从“可运行任务工作台原型”改造成“教材正文驱动的可运行样章3.2”。3.1目录继续作为实施载体，不新建目录；原因是当前结构、QA脚本和浏览器运行方式已经稳定，适合快速验证3.2内容是否成立。

## 2. 改造边界

### 2.1 本轮必须完成

1. 首屏从“任务说明 + 材料入口”升级为“真实案例 + 初步判断 + 学习路线”；
2. 中间区域承载连续教材正文，而不是只显示材料摘要和条目；
3. 四个材料入口调整为“覆盖与质量、移动与保持、业务体验、媒体边界”；
4. 每个材料详情必须包含正文解释、数据表或图示、学生动作、反馈提示和判断边界；
5. 课堂模式和自学模式基于同一正文形成不同学习组织；
6. 能力地图节点点击后跳转到对应正文段落、材料详情或结论练习；
7. 右侧学习记录改为“我已查看的数据、我的判断依据、还缺少的数据、我的结论草稿”；
8. 教师/编辑层显示来源分层、审核状态、专业复核清单和媒体处理建议；
9. QA脚本增加教材性断言，检查首屏案例、初判任务、数据表、能说明/不能说明、自学支架、课堂停顿点和能力地图跳转。

### 2.2 本轮暂不完成

1. 不接入真实出版社平台接口；
2. 不建立后端数据库；
3. 不引入大型前端框架；
4. 不把教学模拟数据包装成真实运营商数据；
5. 不把原教材非通用仿真软件截图直接放入学生主学习区；
6. 不解决所有专业阈值最终口径，仍保留专业教师或行业专家复核标记。

## 3. 当前3.1到3.2的结构迁移

| 3.1现状 | 主要问题 | 3.2改造结果 |
| --- | --- | --- |
| 首屏展示任务、模式切换和材料入口 | 情境有了，但学生未被引导先判断、再找依据 | 首屏展示宿舍区投诉案例、岗位角色、初步判断输入和学习路线 |
| 中间区是4个材料入口 + 当前材料详情 | 更像材料看板，不像可连续阅读的教材正文 | 中间区改为“教材正文段落 + 当前材料 + 学生动作” |
| 材料条目以 evidence item 为核心 | 底层数据感较强，学生仍可能只看条目 | 改为“数据读法、能支持什么、不能说明什么、该怎么写” |
| 课堂/自学模式已有差异 | 差异主要是组织提示，学习支持仍不够深 | 课堂模式增加停顿点、分组任务、汇报提示；自学模式增加术语解释、步骤提示、句式支架和错误原因 |
| 能力地图显示节点和资源 | 点击价值不足，容易像目录 | 点击节点直接定位到对应正文段落、材料详情、练习或反馈 |
| 教师/审查视图独立 | 有分离，但来源分层和专业审核不够充分 | 教师/编辑层展示来源A-F、审核状态、复核清单、媒体处理路径 |

## 4. 内容承载方案

### 4.1 首屏

首屏必须承载 `样章3.2增强重构稿.md` 第5.1节。

前端呈现要求：

1. 保留任务角色：网络优化助理工程师；
2. 使用真实任务标题：“网页好了，为什么还不能直接说优化成功”；
3. 展示投诉变化：网页恢复，但视频通话和直播上行仍异常；
4. 提供初步判断输入：达标、部分达标、未达标、暂时无法判断；
5. 提供两项开放输入：第一理由、最想先查看的数据；
6. 提醒学生初判可以修正，重点是形成“判断-依据-修正”的工作过程。

不应出现：

1. 首屏只显示目录；
2. 首屏只显示四个资源入口；
3. 学生端直接暴露来源层级、审核状态、evidence id 等后台字段。

### 4.2 主学习区

主学习区按以下段落组织，不再只按材料条目组织。

| 段落ID | 前端标题 | 来源章节 | 主要学习动作 |
| --- | --- | --- | --- |
| `seg-scenario` | 网页好了，为什么还不能直接说优化成功 | 5.1 | 写初步判断 |
| `seg-workflow` | 验证不是看一张截图 | 5.2 | 选择先看哪类数据 |
| `seg-coverage` | 覆盖与质量：信号强，不代表体验一定好 | 5.3 | 读覆盖数据，写覆盖判断句 |
| `seg-mobility` | 移动与保持：流程图不能替代现场日志 | 5.4 | 列出还需补充的切换/日志数据 |
| `seg-experience` | 业务体验：平均值变好，不代表晚高峰用户都满意 | 5.5 | 区分改善和达标 |
| `seg-extension` | 容量、速率和掉线为什么暂不全部展开 | 5.6 | 判断还需补充哪些数据 |
| `seg-media` | 看不懂的图不能强行当依据 | 5.7 | 判断图片材料如何处理 |
| `seg-practice` | 完成一份短结论 | 5.8 | 形成结构化短报告 |
| `seg-feedback` | 常见错误和修改示范 | 5.9 | 对照修改自己的表达 |
| `seg-conclusion` | 可提交结论示例 | 5.10 | 检查最终结论是否有依据和边界 |

### 4.3 材料区

四个材料入口保留，但语义从“证据组”改为“学习材料”。

| 材料ID | 学生端名称 | 对应段落 | 必须包含 |
| --- | --- | --- | --- |
| `coverage` | 覆盖与质量 | `seg-coverage` | SS-RSRP、SS-SINR、弱覆盖采样点表；能支持什么；不能说明什么；覆盖判断句 |
| `mobility` | 移动与保持 | `seg-mobility` | 测量-判决-执行三阶段说明；还需补充日志清单；不能把流程图当现场结论 |
| `experience` | 业务体验 | `seg-experience` | 视频平均时延、直播上行95分位、卡顿次数表；改善与达标区分 |
| `media` | 媒体边界 | `seg-media` | 原截图问题、学生端替代形式、处理建议 |

3.1中的 `handover` 可改名为 `mobility`，`performance` 可改名为 `experience`。如果为减少改动保留旧ID，学生端显示名称必须改为3.2名称。

### 4.4 资源抽屉

资源抽屉不再只放资源摘要，应按“补充解释”和“可追溯依据”分层。

学生可见层：

1. 术语小解释；
2. 数据怎么看；
3. 常见误解；
4. 句式支架；
5. 相关练习。

教师/编辑可见层：

1. 来源层级A-F；
2. 审核状态；
3. 适用边界；
4. 待复核问题；
5. 媒体处理建议。

### 4.5 结论区

结论区必须承载5.8和5.10，而不是只做自由文本框。

字段建议：

1. 判断状态；
2. 依据1；
3. 依据1能说明什么；
4. 依据1不能说明什么；
5. 依据2；
6. 依据2能说明什么；
7. 依据2不能说明什么；
8. 还需补充查看的数据；
9. 后续建议；
10. 最终职业表达。

前端可提供句式：

```text
本次优化结果建议判断为____。依据是____。但____仍不能证明全部达标，还需补充____。建议下一步____。
```

### 4.6 教师讲评区

教师讲评区不进入学生学习路径。它应服务课堂组织和学情诊断。

必须包含：

1. 课堂停顿点：初判后、覆盖数据后、业务体验数据后、结论提交前；
2. 小组分工建议：覆盖组、移动组、业务体验组、媒体边界组；
3. 常见错误讲评：网页能打开就成功、覆盖率提升就达标、流程图等于现场正常、截图改善就可作最终依据；
4. 追问问题：这条数据能说明什么，不能说明什么；
5. 专业复核提醒：阈值、指标口径、模拟数据、切换日志字段。

### 4.7 编辑审核区

编辑审核区应把 `样章3.2增强重构稿.md` 第2节、第6节、第7节显性化。

必须包含：

1. 来源层级A-F；
2. 段落来源与审核状态表；
3. 专业复核清单；
4. 媒体重构清单；
5. 不可发布提示：模拟数据不得冒充真实数据，阈值口径不得泛化，原截图不得裸用。

## 5. 课堂模式和自学模式

两种模式可以共用同一套教材正文，但不能只是换提示语。

### 5.1 课堂模式

课堂模式面向“教师组织学生共同完成任务”。

呈现重点：

1. 每个关键段落后出现教师暂停点；
2. 四个材料入口对应小组分工；
3. 学生先个人判断，再小组补证据，再全班汇报；
4. 结论区突出课堂汇报句式和教师追问；
5. 教师讲评区可查看常见错误和复核提醒。

示例停顿点：

| 停顿点 | 触发位置 | 教师动作 |
| --- | --- | --- |
| 初判停顿 | `seg-scenario` 后 | 让学生投票：达标/部分达标/未达标/无法判断 |
| 覆盖停顿 | `seg-coverage` 后 | 追问覆盖改善能不能证明视频不卡顿 |
| 体验停顿 | `seg-experience` 后 | 比较平均值和95分位的判断差异 |
| 结论停顿 | `seg-practice` 后 | 选取两份学生结论进行讲评 |

### 5.2 自学模式

自学模式面向“没有教师即时讲解时，学生也能读懂并完成任务”。

呈现重点：

1. 术语即时解释；
2. 每张数据表给出阅读顺序；
3. 每段后给出自检问题；
4. 结论区提供句式支架；
5. 错误反馈必须指出错因，而不是只提示“再想想”。

自学支架示例：

| 位置 | 支架 |
| --- | --- |
| `seg-coverage` | 先看优化前后变化，再看目标状态，最后写“能说明/不能说明” |
| `seg-mobility` | 如果只有流程图，不要写“现场切换正常”，应写“还需查看日志” |
| `seg-experience` | 平均值说明大多数情况，95分位提醒较差体验，二者不能混用 |
| `seg-practice` | 用“判断状态 + 两条依据 + 一个边界 + 后续建议”完成表达 |

## 6. 能力地图联动

能力地图仍是探索导航层，不作为第一屏主形态。

联动规则：

| 能力节点 | 点击后定位 | 同步动作 |
| --- | --- | --- |
| 识别优化验证场景 | `seg-scenario` | 打开初步判断区 |
| 区分验证对象 | `seg-workflow` | 高亮学习路线 |
| 验证覆盖优化结果 | `seg-coverage` | 切换材料为覆盖与质量 |
| 验证切换/掉线风险 | `seg-mobility` | 切换材料为移动与保持 |
| 验证业务体验 | `seg-experience` | 切换材料为业务体验 |
| 判断媒体材料边界 | `seg-media` | 切换材料为媒体边界 |
| 形成验证结论 | `seg-practice` | 定位到结论编辑区 |

节点弹层应显示：

1. 这个知识点解决什么问题；
2. 去看哪段正文；
3. 完成哪个动作；
4. 当前是否已形成学习记录；
5. 相关资源，不只显示标题。

## 10. 验收标准

本轮完成后，样章3.2至少应满足：

1. 一个不懂网优专业的人打开首屏，能知道自己扮演谁、面对什么问题、要交什么结果；
2. 学生能沿着正文完成“先判断、再看数据、再修正、再形成结论”；
3. 每组关键数据都有读法、能支持什么、不能说明什么；
4. 自学模式能实际帮助学生读懂，而不是重复通用提醒；
5. 课堂模式能让教师组织讨论和讲评；
6. 能力地图能作为导航层发挥作用，点击节点能到正文和练习；
7. 学生端不出现机器化字段；
8. 教师/编辑端能看到来源、审核、复核和媒体处理风险；
9. 非通用仿真截图没有裸进学生主学习区；
10. 浏览器QA通过。

## 11. 专业和出版风险

本轮即使前端QA通过，仍不能视为正式教材内容完成。以下问题必须保留待审核状态：

1. 原教材中疑似 `SS-RSRP≥105dBm` 的阈值符号问题；
2. 覆盖率、SS-SINR、视频时延、直播上行时延和卡顿次数的目标口径；
3. A类事件、切换日志、RLF、重建立等内容对当前学生层级是否过深；
4. “部分达标”的行业表达和课程评分口径；
5. 仿真软件截图的版权、授权和平台适配；
6. 教学模拟数据是否需要替换为教师认可的实训数据。
