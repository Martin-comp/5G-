# 第六类普通任务增量验证对象选择说明V0.3.5

生成日期：2026-06-25  
依据基线：课程能力图谱V0.3.5当前推荐主数据  
配套矩阵：`reports/第六类普通任务增量验证候选矩阵V0.3.5.csv`  
结论：推荐 `P4-T3 任务3：5G网络优化报告输出` 作为第六类普通任务增量验证对象。当前只完成对象选择，不直接开始P4-T3补拆。

## 1. 当前选择目标

第六类普通任务增量验证的目标不是继续扩大任务数量，而是检查V0.3.5推荐主数据和V0.4风险治理口径能否迁移到“报告输出、证据链表达、资源封装和平台交付边界”这类尚未充分验证的任务。

此前已经覆盖的代表类型包括：

| 已验证任务 | 已验证类型 |
| --- | --- |
| P1-T3 | 投诉信息采集、客户沟通、隐私和服务表达 |
| P2-T1 | DT/CQT测试准备与执行 |
| P2-T2 | 测试问题处理分支 |
| P2-T3 | 测试数据分析 |
| P3-T3 | 参数检查和配置管理 |
| P4-T1 | 优化实施、责任边界、变更记录和复测交接 |
| P4-T2 | 优化结果验证和深样章呈现 |
| P5-T3 | 全网性能提升验证 |
| P6-T2 | 信令问题分析与复杂复盘 |

当前尚未被充分验证的是完整报告输出链条。P4-T3不应被理解成“写一份格式模板”，而应被理解成把实施记录、验证证据、结论边界、专业表达和交付口径组织成可评价产出的职业任务。

本轮候选矩阵共纳入18个任务。已验证任务继续排除，未验证任务重新评分。

前三名为：

| 排名 | 任务 | 分数 | 判断 |
| ---: | --- | ---: | --- |
| 1 | P4-T3 5G网络优化报告输出 | 91 | 推荐作为第六类普通任务 |
| 2 | P3-T4 5G网络参数设置 | 84 | 第二候选 |
| 3 | P3-T2 5G网络运行监控 | 81 | 第三候选 |

## 3. 推荐P4-T3的理由

P4-T3最适合作为第六类任务，理由如下：

1. V0.3.5已经补齐P4-T1“优化实施与变更记录”能力链，P4-T3可以检验P4项目内“实施记录 -> 结果验证 -> 报告输出”的证据链是否成立；
2. P4-T3主挂AU-08“优化报告与职业表达”，目前AU-08只有局部支撑，还没有通过完整报告输出任务验证；
3. P4-T3能暴露数字教材后续必须面对的资源封装和平台交付问题，例如报告模板、证据附件、结论边界、学生产出、教师评价量规和出版社平台挂接；
4. P4-T3比P3-T4更能转向新的能力缺口。P3-T4仍然重要，但紧接P4-T1继续做参数设置，会使第六类验证继续停留在实施变更主题；
5. P4-T3比P3-T2更适合当前小步验证。P3-T2的大表、监控看板和平台数据治理价值很高，但体量过大，容易把当前阶段拖入大规模表格治理。

因此，第六类首选不应再选“实施类”，而应选“报告输出与证据链表达类”。

## 4. 为什么不是P3-T4

P3-T4有价值，但不宜作为第六类首选。

主要原因：

1. P3-T4与P3-T3同属参数链条，虽然一个是检查、一个是设置，但类型差异小于P4-T3；
2. P3-T4与P4-T1都涉及变更授权、回退记录和误操作风险，紧接P4-T1继续验证会造成主题重复；
3. P3-T4更适合在P4-T3证据链稳定后，作为参数配置专项验证对象，用于检查网管配置、配置授权、回退记录和截图重绘风险。

因此P3-T4保留为第二候选。

## 5. 为什么不是P3-T2

P3-T2也有价值，但当前不宜优先。

主要原因：

1. P3-T2涉及大量监控表、指标看板、告警筛选和软件截图，治理价值高，但工作量明显大于P4-T3；
2. 如果现在优先P3-T2，任务重心会从“课程能力图谱结构验证”转向“大表和平台数据结构治理”，容易扩大范围；
3. P3-T2更适合作为后续“大表、指标看板、平台数据回收”专项验证对象。

因此P3-T2保留为第三候选。

## 6. P4-T3的主要风险

选择P4-T3并不表示它简单。主要风险包括：

1. 容易被拆成报告标题、章节格式、固定句式和大纲清单，而不是职业能力节点；
2. 必须明确哪些证据来自P4-T1实施记录，哪些证据来自P4-T2验证结论，哪些结论仍需专业复核；
3. 报告输出不能默认等于优化成功，必须保留未达标、部分改善、证据不足和需二次分析的表达边界；
4. 学生端不能只给模板，应能完成“选证据、写判断、说明边界、修正表达”的学习闭环；
5. 教师端需要评价量规、典型答案、常见错误和讲评优先级，否则报告输出任务难以评价。

这些风险正是P4-T3适合作为第六类增量验证对象的原因。
