# 项目二闭环复制验证实施计划V0.1

生成日期：2026-06-26  
执行范围：项目二 `P2-T1 / P2-T2 / P2-T3` 闭环复制验证  
数据底座：课程能力图谱主数据 `V0.3.13`  
阶段定位：项目四闭环样本之后的第二个项目级复制验证  

## 1. 目标

本轮目标不是继续打磨项目四，也不是进入生产工具链拆解，而是用项目二验证项目级闭环方法能否从“优化结果验证类任务”复制到“测试采集与数据分析类任务”。

项目二的职业逻辑不能写成简单的线性流程。更准确的表达是：

```text
P2-T1 DT/CQT测试准备和执行
-> 正常路径：形成测试LOG和测试资料包，直接进入P2-T3数据分析
-> 异常路径：测试中出现设备、软件、数据完整性或现场协调问题，进入P2-T2问题处理
-> P2-T2处理后形成可用数据和问题背景，再进入P2-T3数据分析
-> P2-T3输出测试数据分析报告，支撑后续P4-T2结果验证和P5-T3持续提升
```

本阶段完成后，应能回答四个问题：

1. 项目二19个详细能力节点是否能支撑一个项目级学习闭环；
2. `P2-T2` 是否能作为“异常处理分支”被清楚表达，而不是被误写成必经任务；
3. `P2-T3` 是否适合作为下一轮深样章候选；
4. 项目四阶段2形成的映射表、样稿、原型、QA、治理流程能否被复制到另一个项目。

## 2. 范围

### 2.1 本轮先做

本轮先完成两项准备性成果：

| 文件 | 职责 |
| --- | --- |
| `reports/项目二闭环复制验证实施计划V0.1.md` | 固定项目二闭环复制验证的目标、路径、交付物、门禁和后续顺序。 |
| `reports/项目二V0.3.13闭环映射表V0.1.csv` | 从V0.3.13抽取P2-T1、P2-T2、P2-T3共19个详细节点，形成后续内容生产和原型接入依据。 |

### 2.2 本轮暂不做

本轮不直接生成学生端页面、教师端页面、正式资源包或工具链模块。原因是项目二还需要先完成闭环表达、异常分支表达和风险门禁确认，否则页面会把尚未稳定的结构固化。

暂不做事项包括：

1. 不把项目二写成完整正式数字教材；
2. 不直接复制项目四原型并替换标题；
3. 不把真实路测路线、GPS点位、测试LOG、客户场地或软件截图写成可发布资源；
4. 不宣称通信专业复核、数据安全审核、媒体重绘、一线教学验证或出版社平台接口已经完成；
5. 不进入AI生产工具链模块拆解。

## 4. 项目二三任务角色

| 任务 | 当前角色 | 教材表达重点 |
| --- | --- | --- |
| `P2-T1 DT/CQT测试准备和执行` | 测试采集主线入口 | 让学生明白测试任务从哪里来、测什么、怎么准备、怎么采集、怎么交付可分析数据。 |
| `P2-T2 5G网络测试问题处理` | 异常处理分支 | 让学生明白测试过程中出现设备、软件、数据、现场协调问题时如何判断、处理、记录和升级。 |
| `P2-T3 5G网络测试数据分析` | 数据分析输出 | 让学生把测试LOG和问题背景转化为指标判断、异常归因、整改建议和分析报告。 |

## 5. 映射表口径

`reports/项目二V0.3.13闭环映射表V0.1.csv` 沿用项目四阶段2映射表的字段结构，便于后续横向比较。

映射表覆盖：

| 任务 | 详细节点数 | 说明 |
| --- | ---: | --- |
| `P2-T1` | 7 | 测试任务确认、准备、配置、路线/场景规划、DT采集、CQT测试、LOG移交。 |
| `P2-T2` | 4 | 异常现象判断、设备软件数据排查、现场协调升级、闭环记录与预案。 |
| `P2-T3` | 8 | 数据来源确认、LOG导入、指标识读、覆盖异常、移动性/邻区异常、原因链、整改建议、分析报告。 |

映射表保留以下字段作为后续生产依据：

1. 学生端可读字段：`student_title`、`student_learning_goal`、`student_action`、`student_output`、`assessment_output`；
2. 资源活动字段：`resource_type`、`learning_activity_type`、`binding_count`；
3. 图谱关系字段：入向关系数、出向关系数、关系类型；
4. 门禁字段：审核状态、风险等级、媒体处理状态、专业风险类型；
5. 原型接入字段：后续项目二闭环原型中的入口位置。

## 6. 后续实施步骤

### 任务1：形成项目二内容闭环样稿

输入：

1. `reports/项目二V0.3.13闭环映射表V0.1.csv`
2. `reports/项目二内部链条评审报告V0.4.md`
3. 项目四阶段2内容闭环样稿和原型经验

建议输出：

`reports/项目二内容闭环样稿V0.1.md`

样稿要求：

1. 写成教材正文，不写成大纲；
2. 先用一个低门槛测试案例说明“为什么要做DT/CQT测试”；
3. `P2-T1` 写清测试前、测试中、测试后各做什么；
4. `P2-T2` 写成条件分支：遇到异常才进入，不把它写成所有学生都必须机械经过；
5. `P2-T3` 写成从LOG到指标、从指标到异常、从异常到报告的递进过程；
6. 每个任务至少有一个学生产出、一个评价标准、一个教师带教提示；
7. 专业阈值、软件截图、位置数据和真实LOG保留待复核标记。

### 任务2：判断项目二深样章锚点

初步建议把 `P2-T3` 作为下一轮深样章候选，而不是优先选择 `P2-T1` 或 `P2-T2`。

理由：

1. `P2-T3` 与前期已有P2-T3试拆材料衔接较好；
2. 它能把测试数据转化为学生可读、可练、可评价的分析任务；
3. 它与项目四 `P4-T2` 的结果验证形成明显前后关系；
4. 相比真实路测执行，`P2-T3` 更适合先做教学化数据、表格、图示和互动练习。

该建议不是最终定论。形成项目二内容闭环样稿后，需要再评估 `P2-T1` 是否更适合作为实践主锚点。

### 任务3：制作项目二闭环原型样本

建议新增目录：

`samples/digital_textbook_overall_prototype_phase3_p2_loop/`

修改原则：

1. 不覆盖项目四阶段2原型；
2. 复用整书原型结构，但项目二必须呈现“正常路径+异常分支”；
3. 学生端先显示主线学习路径，再提供异常分支入口；
4. 教师端需要说明何时让学生进入P2-T2，何时可以直接进入P2-T3；
5. 资源中心需要区分测试任务单、测试准备清单、LOG样例、异常处理记录、分析报告模板；
6. 出版/编辑视图需要显式标注位置数据、真实LOG、软件截图、设备图片和场地授权门禁。

### 任务4：执行QA和内部评审

QA至少检查：

1. 六个主视图可切换；
2. 项目二三任务可进入；
3. 正常路径和异常分支不混淆；
4. P2-T2不是默认必经关卡；
5. 学生能看懂第一步要做什么、做到什么程度算完成；
6. 教师能看出课堂组织方式、提问点、典型答案和验收方式；
7. 资源中心和出版门禁状态一致；
8. 无横向溢出、无控制台错误、移动端基本可读。

评审输出建议：

1. `reports/项目二闭环原型内部评审报告V0.1.md`
2. `reports/项目二闭环原型QA记录V0.1.md`

### 任务5：横向比较项目四与项目二

项目二闭环样本完成后，应生成一份横向比较报告，判断方法是否稳定。

建议输出：

`reports/项目级闭环复制验证对比报告V0.1.md`

比较维度：

1. 项目四：优化实施、结果验证、报告输出；
2. 项目二：测试采集、异常处理、数据分析；
3. 两个项目是否都能从图谱映射到教材正文、资源活动评价、教师支持和出版门禁；
4. 哪些结构可以抽象为工具链模块；
5. 哪些仍必须人工专业复核。

只有当项目四和项目二两个项目级闭环都稳定后，才建议进入生产流程和工具链模块拆解。

## 7. 质量门禁

项目二复制验证必须满足以下门禁：

1. 以 `V0.3.13` 主数据为准，不回退到旧版增量表；
2. 映射表覆盖19个详细节点，且三任务节点数为 `7 / 4 / 8`；
3. `P2-T2` 明确为异常处理分支，不写成固定必经任务；
4. 学生端文本必须是教材正文，不是节点清单或大纲；
5. 资源、活动、评价必须围绕学生完成任务组织，而不是围绕后台字段展示；
6. 真实路线、位置数据、测试LOG、客户场地、入场许可、软件截图和设备图片不得直接作为可发布资源；
7. 教师端必须说明课堂模式下如何控节奏，自学模式下如何布置和验收；
8. 治理文件和成果索引必须在每个阶段完成后同步更新。

## 8. 当前结论

项目二适合作为项目四之后的第二个项目级闭环复制验证对象，但当前仍处于计划和映射表阶段。

建议下一步不是做页面，而是先生成 `项目二内容闭环样稿V0.1.md`。样稿通过内部评审后，再制作项目二闭环原型。
