# P2项目内部链条V0.4补齐计划

生成日期：2026-06-25  
计划对象：项目二内部链条 `P2-T1 -> P2-T2 -> P2-T3`  
前置依据：`reports/项目二内部链条评审报告V0.4.md`  
当前结论：先补齐治理口径，再判断是否进入P2-T1主数据合并候选。

## 1. 本计划解决什么问题

项目二内部链条评审已经判断三任务逻辑有条件成立，但存在一个关键缺口：三任务治理成熟度不一致。

当前状态如下：

| 任务 | 当前数据状态 | 主要缺口 |
| --- | --- | --- |
| P2-T1 DT/CQT测试准备和执行 | 已形成V0.4增量补拆、结构校验、内部评审和风险治理扩展增量样表 | 通过结构验证，但暂不合并主数据 |
| P2-T2 5G网络测试问题处理 | V0.3A四节点版已合并进入V0.3.1/V0.3.3 | 尚未补齐V0.4风险治理扩展记录 |
| P2-T3 5G网络测试数据分析 | V0.2字段表和V0.3.3主数据中已有节点、关系和挂接 | 尚未补齐V0.4风险治理扩展记录 |

如果此时直接合并P2-T1为V0.3.4，会造成同一项目内三任务治理口径不一致。更稳的做法是：不重拆P2-T2和P2-T3，先补齐它们的V0.4风险治理记录，并校正项目二内部关系表达。

## 2. 补齐边界

本计划只做治理补齐，不做以下事项：

1. 不重拆P2-T2四节点结构；
2. 不重拆P2-T3八节点结构；
3. 不改写V0.3.3四张主数据表；
4. 不直接把P2-T1合并为V0.3.4；
5. 不生成项目二学生页面或教师页面；
6. 不制作正式资源包；
7. 不进入工具链模块拆解；
8. 不把字段补齐等同于专业复核、媒体审查、数据安全审核、平台验证或真实教学验证完成。

本计划要回答的是：P2-T2和P2-T3需要补哪些V0.4风险记录，项目二关系需要怎样校正，补齐后用什么门禁判断是否可以进入下一步。

## 3. 项目二关系表达原则

项目二不应被写成机械的：

```text
P2-T1 -> P2-T2 -> P2-T3
```

更准确的表达应是：

```text
P2-T1 测试准备与执行
-> 形成测试LOG、异常事件和测试资料包
-> 正常情况下进入P2-T3测试数据分析
-> 出现设备、软件、数据完整性或现场协调问题时进入P2-T2处理
-> P2-T2形成问题背景和数据可用性说明
-> 再支撑P2-T3分析
```

因此，后续关系校正应区分四类关系：

| 关系类型 | 含义 | 项目二示例 |
| --- | --- | --- |
| 正常主线 | 没有异常时的直接学习和职业流程 | `P2T1-N07 -> P2T3-N01` |
| 异常处理分支 | 采集、设备、软件、现场或数据异常时进入处理 | `P2T1-N05 -> P2T2-N01` |
| 数据可用性支撑 | 问题处理结果支撑后续导入、分析和报告 | `P2T2-N02 -> P2T3-N02` |
| 后续复用关系 | 项目二产出支撑P4/P5等后续任务 | `P2T3-N08 -> P4T2-N01` 或后续复测入口 |

关系校正的重点不是增加线，而是避免关系类型混乱。

## 8. V0.4字段填写规则

两张风险补齐样表均采用：

```text
7个定位字段 + 39个V0.4字段
```

其中7个定位字段为：

1. `backfill_record_id`
2. `source_table`
3. `source_record_id`
4. `task_id`
5. `object_level`
6. `object_title`
7. `source_risk_summary`

39个V0.4字段按 `reports/课程能力图谱字段规范V0.4字段清单.csv` 顺序填写。

### 8.1 ID规则

建议使用以下ID：

| 文件 | ID前缀 |
| --- | --- |
| P2-T2风险补齐样表 | `BF-V04-P2T2-001` 起 |
| P2-T3风险补齐样表 | `BF-V04-P2T3-001` 起 |
| 关系校正清单 | `P2REL-V04-001` 起 |

### 8.2 门禁状态规则

当前阶段不允许出现以下误标：

1. `overall_publish_gate_status=approved`
2. `professional_gate_status=passed`
3. `media_gate_status=passed`
4. `student_text_gate_status=passed`
5. `platform_gate_status=passed`
6. `teaching_validation_gate_status=passed`

除非有真实专业复核、媒体审查、学生正文审读、平台接口验证或一线教学验证证据，否则一律保持 `pending`、`revision_required`、`review_pending`、`not_started` 或 `internal_review`。

### 8.3 典型字段规则

| 场景 | 字段填写规则 |
| --- | --- |
| 涉及软件界面或截图 | `resource_review_object_type=screenshot` 或 `image`，`source_transformation_type=redrawn`，`media_gate_status=revision_required` |
| 涉及设备供电、车辆、现场测试 | `review_required_type` 包含 `teaching_validation`，`professional_risk_type` 包含 `procedure` 或 `data_source`，并在 `gate_blocking_reason` 中标注实训安全 |
| 涉及路线、GPS、位置、场地 | `contains_personal_info` 可按对象填 `no` 或 `yes`，但 `personal_info_type` 和 `data_security_review_scope` 应明确是否涉及 `location` |
| 涉及客户接口、授权、责任升级 | `authorization_required` 和 `customer_communication_review_type` 不得默认 `not_applicable`，需要标注沟通边界 |
| 涉及指标阈值 | `professional_risk_type` 包含 `threshold`，`professional_gate_status=pending` |
| 涉及教学模拟案例 | `case_authenticity_type=teaching_simulation`，并填写 `case_applicability_boundary` |
| 涉及分析报告或结论表达 | `editorial_gate_status=pending`，必要时 `student_text_gate_status=review_pending` |

## 10. 结构校验规则

三张补齐/校正文件生成后，必须通过以下校验：

1. CSV可解析；
2. 两张风险补齐样表均为46列；
3. 风险补齐样表字段顺序与V0.4字段清单一致；
4. `backfill_record_id` 无重复；
5. `source_table` 只允许 `node_master` 或 `binding_master`；
6. `source_record_id` 能回溯到对应节点表或挂接表；
7. V0.4 R1字段无空值；
8. 枚举字段不出现字段清单外取值；
9. 不出现误标为通过或可发布的门禁状态；
10. 关系校正清单中的节点ID均能回溯到V0.3.3主数据或P2-T1增量节点；
11. `chain_role` 只能使用规定枚举；
12. 学生端解释不得使用“节点、边、挂接、证据X”等后台化表达。

## 11. 内部评审标准

结构校验通过后，再形成：

`reports/P2项目V0.4补齐内部评审报告.md`

评审问题包括：

1. P2-T2风险是否已覆盖设备供电、软件授权、数据完整性、现场协调和GPS打点案例；
2. P2-T3风险是否已覆盖LOG脱敏、软件界面重绘、指标阈值、邻区漏配案例和报告表达；
3. 项目二关系是否已经明确区分正常主线和异常处理分支；
4. 是否仍有关键风险只能写入备注；
5. 是否仍需要V0.5字段细化实训安全和位置数据；
6. 是否可以把P2-T1纳入下一轮主数据合并候选；
7. 是否可以选择下一轮普通任务验证对象。

评审结论分三类：

| 结论 | 含义 | 后续动作 |
| --- | --- | --- |
| 通过 | P2项目三任务治理口径基本统一 | 可进入P2-T1主数据合并候选评估 |
| 有条件通过 | 补齐方向成立，但仍有字段或关系需修正 | 修正补齐样表或关系清单后再评审 |
| 不通过 | 风险治理或关系表达仍不稳定 | 暂停P2-T1合并和下一轮任务扩展 |

## 12. 通过后的下一步

如果补齐内部评审通过，下一步仍不应立即进入页面生产。更稳的顺序是：

1. 形成P2-T1是否进入V0.3.4合并候选的短复核；
2. 如通过，再制作V0.3.4候选合并说明和四张候选主数据表；
3. 对V0.3.4候选表做结构校验；
4. 再判断是否选择下一轮任务验证对象。

只有在主数据、风险治理、关系表达和质量门禁都稳定后，才考虑进入项目二页面样章或资源包生产。
