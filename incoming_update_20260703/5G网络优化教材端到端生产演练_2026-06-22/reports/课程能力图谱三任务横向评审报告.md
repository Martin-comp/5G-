# 课程能力图谱三任务横向评审报告

生成日期：2026-06-23  
评审对象：P2-T3、P4-T2、P5-T3 三类任务详细能力节点  
对应图谱版本：课程能力图谱V2优化版  
对应字段规范：课程能力图谱字段规范V0.1  

## 1. 评审结论

综合结论：**有条件通过。**

三任务横向对比说明，课程能力图谱V2以岗位工作过程为主链的方向基本成立。P2-T3、P4-T2、P5-T3分别覆盖了“数据分析前置能力”“优化结果验收能力”“全网性能提升持续验证能力”，三者能够组成一条较清晰的学习闭环：

```text
P2-T3 读数据、找异常、提建议
-> P4-T2 用证据判断单次优化是否验收
-> P5-T3 验证全网性能提升是否闭环，未闭环则进入复盘
```

但本轮不能判定为完全通过，原因有四点：

1. P5-T3已经按V0.1的59字段规范落表，P2-T3和P4-T2仍主要保留在旧的12/13字段结构中，三任务数据治理成熟度不一致；
2. V0.1可以支撑单个任务试拆，但对“主挂接 + 次级挂接”的表达不足，尤其是P5-T3同时承接JP-06、主挂JP-07、连接AU-08和AU-10；
3. AU-09“全网性能提升与复测”经P5-T3试拆基本成立，但AU-10“信令分析与复杂问题复盘”仍没有通过P6任务验证；
4. 三个任务都仍处于内部方法验证或样章验证阶段，专业阈值、案例数据、媒体资源和标准条款绑定仍未通过外部专业复核。

因此，当前建议是：**V2继续作为当前课程能力图谱基线；字段规范应升级到V0.2；升级前不应批量拆全书任务，也不应进入生产工具链模块拆解。**

## 2. 三任务在图谱中的分工

| 任务 | 主要岗位过程 | 主要能力单元 | 图谱角色 | 评审判断 |
| --- | --- | --- | --- | --- |
| P2-T3 5G网络测试数据分析 | JP-03 整理数据与识读指标；JP-04 定位问题与制定方案 | AU-03 测试问题处理与数据分析；AU-05 网络问题定位与方案制定 | 前置数据分析能力 | 成立，能支撑后续结果验证 |
| P4-T2 5G网络优化结果验证 | JP-06 验证效果与表达结论 | AU-07 优化结果验证；AU-08 优化报告与职业表达 | 深样章和单次验收样板 | 成立，但字段需补齐到V0.1/V0.2 |
| P5-T3 5G全网性能提升验证 | JP-07 持续提升与复杂复盘；承接JP-06 | AU-09 全网性能提升与复测；连接AU-08/AU-10 | 持续提升和未闭环判断试拆 | 有条件成立，AU-09成立，AU-10仍待P6验证 |

这说明三类任务不是重复关系。P2-T3解决“怎么看懂数据并发现问题”；P4-T2解决“这次优化结果能不能验收”；P5-T3解决“全网性能提升是否持续闭环，未闭环问题往哪里回流”。

## 3. 节点颗粒度评审

| 任务 | 当前节点数 | 节点组织方式 | 判断 |
| --- | ---: | --- | --- |
| P2-T3 | 8 | 明确数据来源 -> LOG处理 -> 指标识读 -> 异常判断 -> 原因链 -> 整改建议 -> 分析报告 | 粒度基本合适 |
| P4-T2 | 8 | 场景识别 -> 改善/达标边界 -> 覆盖/移动性/体验指标 -> 依据选择 -> 验收结论 -> 职业表达 | 粒度已通过样章验证，但字段治理不足 |
| P5-T3 | 7 | 验证口径 -> 数据源选择 -> KPI基线 -> 五类效果判断 -> 未闭环入口 -> 验证报告 | 粒度基本合适，不需要机械补成8个 |

评审结论：

1. 后续不应规定每个任务必须拆成8个节点；
2. 更合理的口径是“一个详细能力节点对应一个可学习、可训练、可评价的学生动作”；
3. 普通任务可拆3到6个节点，核心综合任务可拆7到10个节点；
4. 节点不能小到只剩软件按钮，也不能大到覆盖多个判断动作；
5. 是否继续拆某个任务，应看它能否产生独立资源、学习活动、评价产出和复核责任，而不是看目录标题。

## 4. 学习闭环评审

### 4.1 已经形成的闭环

三任务合起来，已经能说明当前课程能力图谱具备以下学习闭环：

| 闭环环节 | 对应任务与节点 | 学生动作 | 可检查产出 |
| --- | --- | --- | --- |
| 读懂材料 | P2T3-N01至P2T3-N03 | 明确分析对象，识读关键指标和边界 | 数据分析任务单、指标读法与边界表 |
| 判断异常 | P2T3-N04至P2T3-N06 | 判断覆盖、移动性、邻区等异常并归因 | 覆盖异常记录、移动性证据链、异常清单 |
| 提出处理 | P2T3-N07至P2T3-N08 | 形成整改建议和分析报告 | 整改建议卡、测试数据分析报告 |
| 验证结果 | P4T2-N01至P4T2-N07 | 用优化前后证据判断是否达标 | 覆盖/移动性/体验判断、四段式验收结论 |
| 修正表达 | P4T2-N08 | 修正过度判断、依据不足和边界缺失 | 修正后的职业表达 |
| 持续提升 | P5T3-N01至P5T3-N07 | 选择数据源，做前后对比，判断未闭环，输出验证报告 | KPI对比表、未闭环清单、全网性能提升验证报告 |

这个闭环比“项目目录顺序”更接近岗位工作过程，也能支撑教材页面、资源卡片、互动练习、学习单和教师讲评。

### 4.2 尚未形成的闭环

当前仍缺两类闭环：

1. **AU-10复杂问题复盘闭环**：P5-T3只能把未闭环问题导向AU-10，不能证明学生已经掌握信令分析和复杂复盘。该闭环必须通过P6-T1或P6-T2试拆验证。
2. **标准条款闭环**：当前依据多为摘要级，尚未逐条绑定课程标准、专业标准、数字教材标准或相关政策条款。后续正式发布前必须补齐。

## 5. 字段规范V0.1适配性评审

V0.1已经解决了旧表的核心问题：它把课程能力图谱从“节点清单”推进到“可治理数据结构”，覆盖节点ID、层级、前后关系、资源、活动、评价、学习事件、学生端表达、教师端使用、审核状态和版本治理。

但三任务横向对比暴露出V0.1的四个主要不足：

| 问题 | 具体表现 | 影响 |
| --- | --- | --- |
| 主挂接与次级挂接混在一起 | P5-T3主挂AU-09，但同时涉及AU-08和AU-10；P2-T3也跨AU-03/AU-05 | 如果都写进一个字段，后续统计和前端过滤会混乱 |
| 关系字段不够结构化 | `prerequisite_node_ids`、`next_node_ids`和`relation_types`只能粗略并列 | 难以表达某个前置节点对应哪种关系 |
| P4-T2/P2-T3未迁移到59字段 | 三任务不能直接按同一字段口径比较 | 影响批量扩展和质量检测 |
| 外部标准条款仍为空或pending | `standard_clause_id`尚未真正落地 | 不能支撑正式出版级依据审查 |

判断：**V0.1可以作为试拆规范，但不宜作为全书批量拆分规范。V0.2必须先解决主次挂接、结构化关系和三任务字段统一问题。**

## 6. 对V2主链的判断

| 主链节点 | 横向评审判断 |
| --- | --- |
| JP-03 整理数据与识读指标 | 经P2-T3验证成立，是后续验证和复盘的前置能力 |
| JP-04 定位问题与制定方案 | 经P2-T3部分验证成立，但仍需P4-T1或P3-T3继续验证方案制定链 |
| JP-06 验证效果与表达结论 | 经P4-T2深样章验证成立，是当前最成熟的样板链 |
| JP-07 持续提升与复杂复盘 | 经P5-T3验证“持续提升”部分成立，但“复杂复盘/信令分析”仍需P6验证 |

当前不建议大改V2主链。JP-07本身可以保留，但在说明中应明确它包含两个子方向：

1. 全网性能持续提升与复测，对应AU-09；
2. 信令分析与复杂问题复盘，对应AU-10。

P5-T3只能验证第一方向，并为第二方向提供入口。

## 8. 下一步建议

建议按以下顺序推进：

1. **先形成字段规范V0.2小版本**：不是重写规范，而是在V0.1基础上补充主次挂接、结构化关系、节点功能类型、跨任务角色等字段。
2. **把P2-T3和P4-T2迁移到V0.2字段表**：使三任务处于同一字段口径，避免P5-T3一张表很细、P2/P4仍停留在旧表。
3. **选择P6-T1或P6-T2做AU-10验证试拆**：判断信令分析与复杂问题复盘是否真的能拆成可学习、可训练、可评价的节点。
4. **再决定是否做有限批量扩展**：通过P2、P4、P5、P6四类任务后，再考虑把其余任务拆到一级或二级详细节点。

不建议立即做：

1. 不建议直接把18个任务全部拆到详细节点；
2. 不建议继续优化课程能力图谱界面作为主任务；
3. 不建议把P5-T3做成完整页面；
4. 不建议进入工具链模块拆解；
5. 不建议宣称课程能力图谱已经完成专业复核。

## 9. 最终判断

三任务横向评审确认：课程能力图谱V2的主方向成立，节点颗粒度基本可迁移，P2-T3、P4-T2、P5-T3之间已经形成“数据分析 -> 结果验证 -> 持续提升”的内部闭环。

但当前成果仍是内部方法验证，不是全书级课程能力图谱定稿。下一步关键不是扩数量，而是先把字段规范升级到V0.2，并把已有三任务统一到同一字段口径；随后用P6任务验证AU-10，避免把“持续提升”误写成“复杂信令复盘已经成立”。
