评审结论：结构机制有条件通过；不建议直接合并为V0.3.2

## 2. 总体判断

P3-T3作为第二个普通任务增量验证对象是合理的。它和P2-T2、P2-T3、P4-T2、P5-T3、P6-T2的任务类型不同，能检验课程能力图谱主数据是否能承接“配置管理、参数检查、参数异常归因入口”这一类任务。

当前六节点拆分总体方向成立：

| 节点 | 评审判断 |
| --- | --- |
| P3T3-N01 明确参数检查场景与检查对象 | 成立，适合作为入口节点，能避免学生直接面对大量公式和截图 |
| P3T3-N02 识读容量、覆盖与功率参数口径 | 基本成立，但内容负荷很高，后续必须通过资源卡、表格和示例分担 |
| P3T3-N03 完成无线侧参数查询、导出与差异比较 | 成立，但高度依赖网管截图重绘和参数边界复核 |
| P3T3-N04 完成传输侧参数查询与承载参数核对 | 成立，但不能脱离承载场景判断参数是否异常 |
| P3T3-N05 完成核心网参数查询与业务控制参数核对 | 成立但风险最高，协议、QoS和厂家实现差异必须专业复核 |
| P3T3-N06 形成参数异常清单与后续处理建议 | 成立，是P3-T3连接P3-T4、P4-T1、P4-T2的关键出口 |

但当前版本不应直接合并V0.3.2。主要原因不是结构校验问题，而是关系边、媒体治理和报告一致性尚未达到合并门禁。

## 3. 主要问题

### 3.1 N03、N04、N05不应被简单写成线性顺序

当前关系表中使用了：

```text
P3T3-N02 -> P3T3-N03 -> P3T3-N04 -> P3T3-N05 -> P3T3-N06
```

这个写法适合作为课堂讲授顺序，但不完全适合作为职业任务逻辑。无线侧、传输侧、核心网侧参数检查在真实问题处理中更像三条并列检查分支，是否全部检查取决于任务场景、问题现象和排查范围。

更合理的图谱关系应调整为：

```text
P3T3-N01 -> P3T3-N02
P3T3-N02 -> P3T3-N03
P3T3-N02 -> P3T3-N04
P3T3-N02 -> P3T3-N05
P3T3-N03 -> P3T3-N06
P3T3-N04 -> P3T3-N06
P3T3-N05 -> P3T3-N06
```

如果保留线性关系，后续页面和学习路径容易误导学生：仿佛必须先查无线、再查传输、再查核心网。这会把“参数检查任务”变成固定操作流程，而不是根据问题现象选择检查对象。

评审要求：合并主表前，应形成P3-T3关系增量修订版，将三类检查对象改为并列分支，再汇聚到异常清单。

### 3.2 报告中的资源挂接数量与CSV不一致

验证报告第6节写“资源活动评价挂接共19条”，但实际CSV为20条。

这属于文档一致性问题，虽然不影响CSV结构校验，但影响治理可信度。后续如果进入主数据合并说明，这类数量错误会造成版本追踪混乱。

评审要求：修订验证报告，将资源活动评价挂接数量改为20条，或说明其中哪一条不应计入正式挂接。

### 3.3 经典案例图片未形成独立媒体审查记录

验证报告提到A3事件未触发切换案例涉及 `image178`、`image179`，但资源活动评价挂接表中没有对应的 `media_asset_review` 记录。当前只把案例作为 `P3T3-C10 A3事件未触发切换案例复盘卡` 处理，这不足以覆盖原图的媒体风险。

同类问题还包括：

1. 无线侧主界面、无线侧入口、导出窗口被合并为 `IMG-173-176`，可以接受，但需要在备注中明确包含范围；
2. 核心网任务实施中出现 `image177` 和 `image172`，当前只显式记录 `IMG-172`；
3. 经典案例图片 `image178`、`image179` 应单独列入待媒体审查或重绘清单。

评审要求：合并主表前，应补充或修订媒体审查挂接，至少明确 `IMG-178-179` 的治理状态。

### 3.4 N02内容负荷过高，不能直接进入学生正文

N02将容量、覆盖、功率、公式变量、参数边界集中为一个节点，这在图谱颗粒度上可以接受，因为这些内容都服务“读懂参数口径”。但如果直接转成学生页面，会重新出现原教材的问题：公式堆叠、表格堆叠、学生不知道看哪一个。

评审要求：N02合并主表可以保留为一个能力节点，但资源层必须拆成至少三类教学资源：

1. 容量参数读法卡；
2. 覆盖/链路预算参数读法卡；
3. 功率与接入参数边界表。

这些资源不能写成纯公式表，应回答“这个参数支持什么判断、不能说明什么、什么时候需要继续查”。

### 3.5 核心网节点专业风险被正确标注，但仍不能作为学生学习定稿

N05已经标注 `protocol;terminology;parameter_boundary` 高风险，这是正确处理。核心网控制类参数、QoS参数、5GC/EPC对照和厂家实现差异较大，不能仅凭原教材表格形成定稿结论。

评审要求：N05可以进入图谱主数据，但必须保持待专业复核状态；后续生成学生教材正文时，应只选取与当前参数检查任务直接相关的概念，不应扩展成完整核心网协议讲义。

### 3.6 N06次级能力挂接略宽，应在修订版中收敛说明

N06主挂AU-05是合理的，因为“形成参数异常清单与后续处理建议”已经从信息管理进入问题定位和方案制定。当前次级挂接包含AU-04、AU-06、AU-07，其中AU-06、AU-07更像后续任务关系，不一定需要作为N06自身的次级能力。

评审要求：修订版应说明AU-06、AU-07是后续流转对象，还是N06本身需要训练的次级能力。如果只是流转关系，应保留在关系表中，不必写入节点次级能力。
