当前方案性质：合并准备方案，不是V0.3.5主数据成品

## 1. 方案结论

P4-T1 V0.3.4增量具备进入V0.3.5候选主数据合并准备的结构条件，但不能直接宣布完成V0.3.5主数据合并。

本方案建议采用以下口径：

1. P4-T1的6个详细能力节点可作为V0.3.5候选节点增量；
2. P4-T1的24条关系可作为V0.3.5候选关系增量；
3. P4-T1的18条资源活动评价挂接可作为V0.3.5候选挂接增量；
4. P4-T1的10条输入输出物治理记录可进入V0.3.5候选输入输出物治理清单；
5. P4-T1的12条V0.4风险治理扩展记录继续作为旁挂风险治理层，不并入四张V0.3.5主表；
6. 当前不提前追加P4-T1到P4-T3的详细关系，等待P4-T3后续细拆后再判断；
7. 合并准备通过后，下一步才可以生成V0.3.5候选主数据表和结构校验记录。

当前仍不能进入：

1. V0.3.5正式主数据发布；
2. P4-T1学生端教材页面生产；
3. P4-T1正式资源包生产；
4. 出版社平台挂接；
5. 工具链模块拆解；
6. 下一轮普通任务候选选择。

原因是：本轮仍处于课程能力图谱主数据治理阶段，通信专业复核、媒体审查、学生正文审读、真实教学验证、数据安全审核和平台接口验证均未完成。

### 6.1 内部链条处理

P4-T1内部主线建议完整进入V0.3.5候选关系表：

```text
P4T1-N01 -> P4T1-N02 -> P4T1-N03 -> P4T1-N04 -> P4T1-N05 -> P4T1-N06
```

这条链条表达的是：

1. 先确认优化对象和实施边界；
2. 再判断优化动作类型和责任边界；
3. 再读取参数依据；
4. 再制定受控实施步骤和回退检查；
5. 再记录实施结果和变更凭据；
6. 最后形成复测验证入口并交接P4-T2。

### 6.2 上游支撑和问题回流处理

P4-T1与前序任务的关系建议按原增量保留：

| 关系 | 处理建议 | 说明 |
| --- | --- | --- |
| P2T3-N07 -> P4T1-N01/N02 | 保留为支撑判断 | 数据分析形成的整改建议支撑优化对象和动作类型判断 |
| P3T3-N06 -> P4T1-N01/N03 | 保留为支撑判断 | 参数异常清单支撑实施边界和参数依据读取 |
| P4T1-N03 -> P3T3-N06 | 保留为问题回流 | 参数依据不足或发现新异常时回到参数异常分析 |

这些关系都应继续标记为待专业复核，不应在V0.3.5合并时改成已审核。

### 6.3 P4-T2关系处理

P4-T1与P4-T2的关系建议进入V0.3.5候选关系表：

| 关系 | 处理建议 | 说明 |
| --- | --- | --- |
| P4T1-N05 -> P4T2-N01 | 保留为支撑判断 | 实施变更记录支撑P4-T2识别验证场景 |
| P4T1-N06 -> P4T2-N01 | 保留为直接递进 | 复测验证交接清单进入P4-T2结果验证 |

该处理可以把“实施完成”和“效果达标”分开，防止学生端误读为优化实施完成就等于验证通过。

### 6.4 P4-T3关系边界

当前不建议提前增加P4-T1到P4-T3的详细关系。

理由：

1. P4-T3尚未进入详细能力节点细拆；
2. P4-T3报告输出应同时承接P4-T1实施记录和P4-T2验证结论；
3. 只从P4-T1直接连到P4-T3，容易弱化P4-T2验证门禁；
4. 提前新增关系会制造看似完整但实际未审核的跨任务链条。

后续若P4-T3进入增量验证，应重点检查：

1. P4T1-N05变更记录是否支撑报告中的实施过程描述；
2. P4T1-N06交接清单是否支撑报告中的验证对象说明；
3. P4T2验证结论是否作为P4-T3报告输出的必要依据；
4. P4-T3是否需要单独的报告结构、证据链和职业表达节点。
