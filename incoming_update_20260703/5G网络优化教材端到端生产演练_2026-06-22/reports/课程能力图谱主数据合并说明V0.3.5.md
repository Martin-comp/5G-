## 1. 合并结论

V0.3.5候选主数据是在V0.3.4推荐主数据基线基础上，合并P4-T1 V0.3.4增量形成。

本次合并内容包括：

1. P4-T1的6个详细能力节点；
2. P4-T1的24条增量关系；
3. P4-T1的18条资源、学习活动、评价和媒体审查挂接；
4. P4-T1的10条输入输出物治理记录；
5. V0.3.5自身合并说明、四张候选主表和结构校验记录6条治理记录。

本次不合并为正式发布版，不进入页面生产、资源包生产、出版社平台挂接或工具链模块拆解。

## 4. 关系合并

P4-T1新增关系24条。按V0.3.5候选表实际写入后的关系类型分布如下：

| 关系类型 | 数量 |

本次合并不改写V0.3.4既有关系，不提前追加P4-T3详细关系。

### 4.1 P4-T1内部主线

P4-T1内部主线写入V0.3.5候选关系表：

```text
P4T1-N01 -> P4T1-N02 -> P4T1-N03 -> P4T1-N04 -> P4T1-N05 -> P4T1-N06
```

该链条表达的是“实施边界 -> 责任边界 -> 参数依据 -> 实施步骤 -> 变更记录 -> 复测交接”，避免把P4-T1写成参数知识点清单、软件按钮清单或越权工程操作流程。

### 4.2 上游支撑和问题回流

本次保留以下上游关系：

1. `P2T3-N07 -> P4T1-N01/N02`：测试数据分析形成的整改建议支撑优化对象和动作类型判断；
2. `P3T3-N06 -> P4T1-N01/N03`：参数异常清单支撑实施边界和参数依据读取；
3. `P4T1-N03 -> P3T3-N06`：关键参数依据不足或发现新异常时回流到参数异常分析。

上述关系仍包含待专业复核项，不得写成通信专业专家已确认。

### 4.3 P4-T2交接关系

本次保留以下P4-T2关系：

1. `P4T1-N05 -> P4T2-N01`：实施变更记录支撑验证场景识别；
2. `P4T1-N06 -> P4T2-N01`：复测验证交接清单进入P4-T2结果验证。

该处理明确区分“实施完成”和“优化达标”。P4-T1只形成实施记录和复测入口，达标判断必须进入P4-T2。

### 4.4 P4-T3关系暂不追加

本次不新增P4-T1到P4-T3的详细关系。原因是P4-T3尚未细拆，报告输出应同时承接P4-T1实施记录和P4-T2验证结论；提前追加容易形成未审核的跨任务链条。

## 8. 当前边界

V0.3.5候选主数据不能被表述为专家定稿图谱。当前不能声称：

1. P4-T1优化实施流程、工程授权、参数依据和回退条件已经专业审核通过；
2. 原教材仿真软件截图可以直接进入学生端或正式资源包；
3. CSI-RS案例已经通过通信专业复核并可作为通用优化处方；
4. 优化实施变更记录模板可以作为真实工程记录模板；
5. P4-T1已经形成学生端教材正文或教师端课堂材料；
6. V0.3.5可以直接进入出版社平台或工具链模块拆解。

## 9. 后续建议

建议下一步先做V0.3.5短内部复核，重点确认：

1. P4-T1六节点是否适合作为AU-06详细能力补齐方案；
2. P4-T1与P2-T3、P3-T3、P4-T2的关系是否稳定；
3. P4-T3关系暂不提前追加是否仍然成立；
4. P4-T1风险治理旁挂方式是否足以支撑后续专业、媒体、数据安全和教学验证派单；
5. 是否将V0.3.5候选主数据作为新的推荐主数据基线。

短内部复核完成前，不选择下一轮普通任务候选，不进入页面生产、资源包生产、平台发布或工具链模块拆解。
