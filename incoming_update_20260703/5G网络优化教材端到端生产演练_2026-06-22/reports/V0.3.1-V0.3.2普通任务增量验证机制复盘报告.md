当前主数据基线：课程能力图谱V0.3.2

## 3. 机制有效点

### 3.1 字段和表结构已经可复用

P2-T2 V0.3A和P3-T3 V0.3.1A均能落入同一套主数据结构：

1. 节点主数据表；
2. 关系主数据表；
3. 资源活动评价挂接表；
4. 输入输出物治理清单。

V0.3.2结构校验结果为：

| 校验项 | 结果 |
| --- | --- |
| 节点数 | 127 |
| 关系数 | 251 |
| 资源活动评价挂接数 | 176 |
| 输入输出物治理记录数 | 30 |
| 重复节点ID | 0 |
| 重复关系ID | 0 |
| 重复挂接ID | 0 |
| 重复资产ID | 0 |
| 关系端点缺失 | 0 |
| 挂接节点缺失 | 0 |
| 资产路径缺失 | 0 |

这说明主数据表结构已经具备继续增量验证的技术条件。

### 3.2 内部评审能发现机器校验发现不了的问题

P2-T2旧版通过了结构校验，但内部评审发现节点颗粒度偏碎；P3-T3原始增量也通过了结构校验，但内部评审发现三类检查对象不应线性排列。

这说明后续每个任务至少需要两类门禁：

1. 结构门禁：字段、ID、端点、路径、枚举和表头；
2. 教学结构门禁：节点颗粒度、学习闭环、关系语义、资源边界和学生可理解性。

只有两类门禁都通过，才适合合并主数据。

### 3.3 “能力节点”和“资源卡片”的边界更清楚

P2-T2验证了一个关键规则：GPS、逆变器、软件授权、驱动、存储空间等具体排查项不应全部升格为图谱节点，应下沉为资源卡片或学习活动。

P3-T3进一步验证了同一规则：公式、参数项、网管截图和个别案例不应成为主节点，应下沉为参数读法卡、边界表、媒体审查对象和评价产出。

因此，当前主数据增量机制可以形成一条稳定原则：

> 课程能力图谱节点承载稳定职业任务，具体设备、参数、截图、表格、案例和操作步骤优先进入资源、活动、评价或媒体治理层。

### 3.4 关系类型需要表达职业逻辑，不只是顺序

P2-T2主要验证“先判断现象 -> 排查处理 -> 协调升级 -> 记录闭环”的问题处理闭环。

P3-T3主要验证“从参数口径进入多个并列检查分支，再汇聚到异常清单”的分支汇聚结构。

这说明后续关系表不能只保留 `precedes`，还要继续使用：

1. 直接递进；
2. 并列分支；
3. 汇聚关系；
4. 支撑判断；
5. 问题回流；
6. 能力挂接；
7. 资源证据。

如果只做线性路径，课程能力图谱会退化为目录或流程图。

## 4. 当前不足

### 4.1 还不能批量拆全书

两轮普通任务增量验证覆盖了问题处理类和参数检查类，但尚未覆盖以下薄弱类型：

1. 信息采集与客户沟通类；
2. 测试准备与执行类；
3. 优化实施与变更记录类；
4. 报告输出与职业表达类。

如果现在批量拆全书，仍可能把不同类型任务套进同一种节点模板，导致图谱看似完整但教学逻辑不稳。

### 4.2 专业和媒体门禁仍未通过

P2-T2的设备、软件、数据保存和现场协调口径尚未经过专业教师复核。P3-T3的容量、覆盖、功率、传输、核心网、QoS和A3事件案例也尚未完成专业复核。

媒体方面，P2-T2和P3-T3均存在原教材图片或截图审查问题。P3-T3目前仍是分组级媒体挂接，后续正式资源生产前必须拆到单图审查。

### 4.3 没有学生端正文验证

主数据合并只能说明“图谱结构上能承接任务”，不能说明学生已经能读懂、学会、完成任务。

后续若进入某个任务的学生端呈现，必须重新经过教材正文、学习活动、评价反馈和教师使用场景验证，不能直接把主数据表转成页面。

## 5. 第三个增量验证对象判断

当前第三个普通任务不建议继续选择P3/P5/P6技术链条任务。原因是P3-T3已经验证了参数检查类任务，P5-T3和P6-T2已经在V0.2阶段验证了性能提升和信令复盘链条。继续选择同类任务，新增验证价值有限。

更需要验证的是目前主数据中最薄弱的任务类型：信息采集与客户沟通类。

因此，本轮建议第三个普通任务优先选择：

**P1-T3 任务3：投诉信息采集**

推荐理由：

1. 它主挂 `AU-01 场景、站点与投诉信息采集`，当前详细能力节点中AU-01尚未被验证；
2. 它属于上游输入类任务，可以检验课程能力图谱是否能从“用户投诉和场景信息”一路连接到测试、分析、优化和验证；
3. 它不是纯技术参数任务，而是包含客户沟通、信息记录、投诉分类和处理边界，能检验图谱是否能承接职业沟通类能力；
4. 原文体量适中，337行、图片1张、表格31行、案例信号1个，媒体风险较低；
5. 它能避免继续围绕P4/P5/P6中后段任务打转，有利于整书级图谱从课程开端补齐。

第二优先候选为：

**P4-T3 任务3：5G网络优化报告输出**

它能验证 `AU-08 优化报告与职业表达`，但与P4-T2深样章距离较近，独立类型验证价值略低于P1-T3。

## 6. 建议的下一步

下一步建议制作P1-T3增量验证方案，而不是直接合并主表。

建议流程：

1. 先形成 `P1-T3基于V0.3.2主数据补拆验证报告.md`；
2. 同步生成P1-T3四张增量样表；
3. 重点评审投诉受理、信息记录、现场采集、定位处理和结果沟通是否应拆为图谱节点，还是部分下沉为资源卡片；
4. 重点评审客户沟通话术、投诉升级边界和用户隐私信息是否需要特殊治理字段或专门审核状态；
5. 通过内部评审后，再决定是否形成V0.3.3。

本阶段仍不进入页面生产、正式资源包生产或工具链模块拆解。
