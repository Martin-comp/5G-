# 阶段1基线对齐报告V0.1

生成日期：2026-06-26  
阶段定位：数字教材内容生产与呈现验证阶段之前的基线对齐  
结论：阶段1可以收口，后续可进入阶段2“小范围内容闭环设计与制作”。

## 1. 阶段1要解决的问题

阶段1不是重新制作原型，也不是继续补拆课程能力图谱任务。

本阶段只解决四个对齐问题：

1. 后续到底以哪一个图谱数据版本为底座；
2. 之前已经做出的整书原型、任务样章和图谱关系评审页各自还能怎么用；
3. V0.3.13主数据中的字段分别进入学生端、教师端、出版/编辑端还是只留在后台；
4. 下一阶段的小范围闭环从哪里开始，避免直接铺全书或直接拆工具链模块。

## 2. 三个正式复用基线

### 2.1 数据底座基线：V0.3.13课程能力图谱主数据

正式基线文件：

1. `reports/课程能力图谱节点主数据表V0.3.13.csv`
2. `reports/课程能力图谱关系主数据表V0.3.13.csv`
3. `reports/课程能力图谱资源活动评价挂接表V0.3.13.csv`
4. `reports/课程能力图谱输入输出物治理清单V0.3.13.csv`
5. `reports/课程能力图谱阶段完成审计报告V0.3.13.md`

基线作用：

1. 决定课程、项目、任务、详细能力节点和资源活动评价的主数据来源；
2. 决定后续教材正文、资源卡、学习活动、评价产出和教师材料必须挂接到哪些节点；
3. 决定哪些内容可以进入学生学习路径，哪些内容必须留在教师/编辑/专家审核层。

不能误用：

1. V0.3.13不是学生可直接阅读的教材正文；
2. V0.3.13不是专家定稿图谱；
3. V0.3.13不代表媒体、专业、数据安全、平台发布和真实教学验证已经通过。

### 2.2 呈现框架基线：整书级数字教材整体原型overall-0.2

正式基线目录：

`samples/digital_textbook_overall_prototype/`

基线作用：

1. 保留课程首页、项目视图、任务链、课程能力图谱、教师带教、资源中心、出版/编辑视图的整体框架；
2. 保留P4-T2深样章入口和V2.1关系评审入口；
3. 保留整书层级流转、角色切换和出版边界说明的呈现经验。

不能误用：

1. 该原型目前仍是静态HTML评审样本；
2. 该原型中的图谱数据不等于V0.3.13全量主数据；
3. 除P4-T2外，其他任务没有完整教材正文，不能当成整本数字教材成品。

### 2.3 教材质量样章基线：任务级样章3.5A-1

正式基线目录：

`samples/task_workbench_3_5a1_two_period_sample/`

基线作用：

1. 作为学生端正文、任务引导、完成标准、二次修正、学习单和术语字典的质量样板；
2. 作为教师端2课时组织、提问脚本、模拟学情、专业复核表的结构样板；
3. 作为“页面好看不能替代教材能教能学”的质量门禁参照。

不能误用：

1. 3.5A-1只代表P4-T2深样章，不代表全书所有任务已经达到同等质量；
2. 2课时安排只适用于当前P4-T2样章，不自动套用到全书；
3. 教学模拟案例和阈值仍需通信专业教师或行业专家复核。

## 3. 辅助基线

1. `samples/course_capability_graph_v2_relation_review/`：保留为关系可视化评审样本，用于观察节点邻域、关系类型和图谱暗线呈现方式。
2. `reports/整书层级与流转关系图.md`：保留为整书层级和多角色路径依据。
3. `reports/课程能力图谱跨层映射表.csv`：保留为早期跨层映射样本，但后续正式生产应以V0.3.13主数据为准。

这些辅助基线不能替代V0.3.13主数据，也不能替代真实教材正文生产。

## 4. V0.3.13字段进入各端的原则

### 4.1 学生端

学生端只接收已经教学化转译后的内容。可进入学生端的字段主要包括：

1. `student_title`
2. `student_learning_goal`
3. `student_action`
4. `student_output`
5. `assessment_output`
6. `resource_type`
7. `learning_activity_type`

学生端不得直接暴露以下后台字段：

1. `node_id`
2. `v03_record_id`
3. `audit_status`
4. `review_required_type`
5. `risk_level`
6. `media_handling_status`
7. `professional_risk_type`
8. `source_files`

这些字段可以影响学生端内容是否显示、如何提示、是否需要换图或补充解释，但不能原样显示给学生。

### 4.2 教师端

教师端可以看到比学生端更多的教学组织信息，但仍应以教学语言呈现。可进入教师端的内容包括：

1. 节点对应的学习目标、学生动作和产出；
2. 任务之间的前置、递进、支撑、回流关系；
3. 典型错误、讲评优先级和建议提问；
4. 专业复核风险、媒体风险和数据安全提示；
5. 课堂组织、作业布置和验收建议。

教师端可以引用节点和任务编号，但应作为辅助信息，不应让教师界面变成数据表后台。

### 4.3 出版/编辑端

出版/编辑端应承接完整治理信息，包括：

1. 审核状态；
2. 专业复核类型；
3. 媒体处理状态；
4. 风险等级；
5. 来源文件；
6. 输入输出物治理记录；
7. 平台发布、质量检测、资源封装和版本更新状态。

该端可以看到后台字段，但必须保留“未审不能发布、未复核不能定稿、未接入平台不能宣称发布”的门禁。

## 5. 后续生产的最小闭环

阶段2不建议直接铺全书。建议选择项目四作为第一个小范围闭环对象：

1. P4-T1：5G网络优化方案实施；
2. P4-T2：5G网络优化结果验证；
3. P4-T3：优化报告与职业表达。

理由：

1. P4-T2已有3.5A-1深样章，可以作为质量锚点；
2. 项目四已有“优化实施 -> 结果验证 -> 报告输出”的项目链条基础；
3. 该范围可以同时验证项目页、任务页、图谱暗线、学生正文、教师材料、资源中心和出版/编辑门禁；
4. 风险可控，不会直接进入全书铺开或工具链模块拆解。

## 6. 阶段2入口条件

进入阶段2前，必须满足以下条件：

1. 三类基线确认完成；
2. V0.3.13字段到学生端、教师端、出版/编辑端的路由规则明确；
3. 整书原型只作为呈现框架复用，不再把其静态数据当成当前图谱主数据；
4. 3.5A-1只作为教材质量样板，不扩写为全书完成状态；
5. 阶段2优先对象明确为项目四小范围闭环；
6. 新增成果进入治理文件和成果索引。

本报告与两张配套表共同满足上述条件：

1. `reports/阶段1三类基线复用判定表V0.1.csv`
2. `reports/V0.3.13接入整书原型字段视图映射表V0.1.csv`

## 7. 阶段1收口判断

阶段1可以收口。

收口后，不应继续停留在“原型有没有用”的讨论上。准确结论是：

1. 原型有用，作为呈现框架和样章质量参照继续复用；
2. 原型不能直接当作当前最终数字教材；
3. V0.3.13是后续内容生产的数据底座；
4. 下一步应进入项目四小范围内容闭环，而不是继续补拆图谱任务或拆工具链模块。
