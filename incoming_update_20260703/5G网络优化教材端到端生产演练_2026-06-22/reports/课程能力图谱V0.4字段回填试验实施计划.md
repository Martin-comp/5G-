# 课程能力图谱V0.4字段回填试验实施计划

生成日期：2026-06-24  
适用范围：《5G网络优化教材（高级）》数字教材端到端生产演练  
当前基线：`reports/课程能力图谱主数据合并说明V0.3.3.md` 及四张V0.3.3主数据表  
字段依据：`reports/课程能力图谱字段规范V0.4升级方案.md`、`reports/课程能力图谱字段规范V0.4字段清单.csv`  
计划结论：先做P1-T3、P3-T3、P4-T2三任务V0.4字段回填试验；回填试验通过前，不继续页面生产、正式资源包生产或工具链模块拆解。

## 1. 本计划解决什么问题

V0.3.3已经证明课程能力图谱主数据可以版本化合并，也能承接不同类型任务。但V0.3.3还不能稳定支撑规模化生产，主要原因是风险治理字段不足。

具体表现为：

1. P1-T3出现个人信息、电话录音、客户授权、服务承诺和反馈表达风险，但V0.3.3只能粗略写入 `review_required_type=data_security` 或备注；
2. P3-T3出现公式口径、参数边界、专业截图和媒体重绘风险，但专业、媒体、发布状态还不能被精细筛选；
3. P4-T2已经形成深样章和整体原型入口，但学生正文、教师材料、评价量规、页面发布和真实教学验证门禁仍没有统一字段承载。

因此，当前最有价值的下一步不是继续增加任务数量，而是验证V0.4字段能否把这些风险从自然语言备注转为可检查、可筛选、可阻断的结构化数据。

## 2. 试验边界

本轮只做字段回填试验，不做以下事项：

1. 不重写V0.3.3四张主数据表；
2. 不把回填样表自动合并为新的主数据版本；
3. 不生成新的学生页面或教师页面；
4. 不制作正式资源包；
5. 不进入工具链模块拆解；
6. 不把字段填写完成等同于专业复核、编辑复核、数据安全审核或真实教学验证完成。

本轮产物只回答三个问题：

1. V0.4字段是否覆盖三类代表风险；
2. V0.4字段是否能减少备注字段堆积；
3. V0.4字段是否能支撑后续自动化门禁和批量迁移判断。

## 3. 试验对象

选择三个任务做小范围回填：

| 任务 | 选择原因 | 重点验证字段 |
| --- | --- | --- |
| P1-T3 投诉信息采集 | 覆盖客户沟通、个人信息、电话录音、授权、服务承诺和投诉反馈 | 数据安全、服务表达、案例真实性、门禁状态 |
| P3-T3 5G网络参数检查 | 覆盖公式、参数、专业口径、网管截图和媒体重绘 | 专业门禁、媒体门禁、资源审查、案例与来源治理 |
| P4-T2 5G网络优化结果验证 | 覆盖深样章、学生正文、教师带教、评价量规和页面呈现 | 学生正文门禁、教学验证门禁、平台门禁、综合发布门禁 |

三任务足以覆盖V0.4当前最关键的风险类型。回填试验不追求数量，而追求字段是否真的可用。

## 6. 回填样表结构

每张回填样表采用“定位字段 + V0.4字段”的结构。

### 6.1 定位字段

定位字段用于说明本行回填的是哪个对象，不属于V0.4字段规范正文，但回填试验必须保留。

建议定位字段如下：

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `backfill_record_id` | 回填记录ID | `BF-V04-P1T3-001` |
| `source_table` | 来源主表 | `node_master`、`binding_master`、`asset_governance` |
| `source_record_id` | 来源记录ID | `P1T3-N02`、`BV032A-INC-P1T3-005` |
| `task_id` | 任务ID | `P1-T3` |
| `object_level` | 回填对象层级 | `detail_capability`、`resource_card`、`assessment_output`、`media_asset_review` |
| `object_title` | 对象名称 | `核实投诉关键信息并填写信息单` |
| `source_risk_summary` | 来源风险摘要 | `包含客户电话、地址和工单号，需要脱敏和授权检查` |

### 6.2 V0.4字段

定位字段之后，按 `reports/课程能力图谱字段规范V0.4字段清单.csv` 中的字段顺序填写全部39个V0.4字段。

原则：

1. `field_schema_version` 统一填写 `V0.4`；
2. 高风险对象的R1字段必须填写明确值，不得留空；
3. 不适用字段填写 `not_applicable`，不能用空值代替；
4. 未完成审核的门禁字段填写 `pending`、`revision_required`、`not_started` 或 `blocked`，不得为了好看填写 `passed`；
5. 综合发布门禁 `overall_publish_gate_status` 原则上不得填写 `approved`，除非专业、编辑、媒体、数据安全、学生正文、平台和教学验证门禁均通过。

## 7. 回填对象颗粒度

### 7.1 P1-T3

P1-T3建议回填：

1. 5个详细能力节点；
2. 17条资源活动评价挂接；
3. 重点覆盖 `P1T3-PRIV01`、`P1T3-PRIV02`、`P1T3-C07`、`P1T3-C08B`、`P1T3-RPT01` 等高风险对象。

核心填写规则：

1. 涉及姓名、电话、地址、工单号、录音、客户反馈的对象，`contains_personal_info` 应填 `yes`；
2. 涉及电话录音或音频材料的对象，`recording_involved` 应填 `yes`，并同步填写授权字段；
3. 投诉反馈话术原则上填写 `external_statement_allowed=teaching_only` 或 `pending`，不得默认填写 `yes`；
4. 服务承诺类资源必须填写 `service_commitment_risk_type`；
5. 真实案例、脱敏案例、教学模拟案例必须填写 `case_authenticity_type` 和 `case_applicability_boundary`；
6. 未经数据安全和编辑复核的对象，`overall_publish_gate_status` 不得超过 `conditional`。

### 7.2 P3-T3

P3-T3建议回填：

1. 6个详细能力节点；
2. 22条资源活动评价挂接；
3. 重点覆盖公式卡、参数表、网管截图、媒体审查对象和参数异常报告模板。

核心填写规则：

1. 一般不涉及个人信息，`contains_personal_info` 可填 `no` 或 `not_applicable`；
2. 涉及公式、参数阈值、协议术语和厂家实现差异的对象，`professional_gate_status` 应填 `pending` 或 `revision_required`；
3. 涉及原教材截图、网管界面和仿真软件截图的对象，`resource_review_object_type` 应填 `screenshot` 或 `image`，`media_gate_status` 不得填写 `passed`；
4. 需重绘资源的 `source_transformation_type` 应填 `redrawn`，`publishability_status` 应填 `ready_after_expert_review` 或 `not_ready`；
5. 公式和参数样例不得写成通用行业标准，`case_applicability_boundary` 必须说明适用范围。

### 7.3 P4-T2

P4-T2建议回填：

1. 8个详细能力节点；
2. 47条资源活动评价挂接；
3. 重点覆盖学生正文、五个教学模拟案例、表图资源、互动练习、评价产出、教师2课时带教材料和专业复核表。

核心填写规则：

1. 教学模拟案例必须填写 `case_authenticity_type=teaching_simulation`；
2. AI改写或教学化扩展内容必须填写 `source_transformation_type=ai_created`、`adapted` 或 `teaching_simulation`；
3. 涉及学生正文的对象必须填写 `student_text_gate_status`；
4. 涉及教师带教、学习单、评价量规的对象必须填写 `teaching_validation_gate_status`；
5. 涉及页面呈现或出版社平台挂接的对象必须填写 `platform_gate_status`；
6. 当前尚无真实一线教师/学生试看，`teaching_validation_gate_status` 不得填写 `passed`；
7. 当前尚未完成出版社平台接口，`platform_gate_status` 不得填写 `passed`；
8. 原教材媒体或需重绘图示的对象，`media_gate_status` 应保持 `pending` 或 `revision_required`。

## 8. 结构校验规则

三张回填样表生成后，必须通过以下校验：

1. CSV可被解析；
2. 三张样表字段顺序一致；
3. 定位字段完整；
4. 39个V0.4字段全部存在；
5. R1字段无空值；
6. 枚举字段不出现清单外取值；
7. `source_record_id` 能在V0.3.3节点主数据表、资源活动评价挂接表或输入输出物治理清单中找到；
8. 高风险对象不得填写 `overall_publish_gate_status=approved`；
9. `contains_personal_info=yes` 时，个人信息类型、脱敏、授权和数据安全门禁字段必须有明确值；
10. `recording_involved=yes` 时，授权字段不得填写 `not_applicable`；
11. `external_statement_allowed=yes` 时，编辑门禁和专业门禁必须均为 `passed`；
12. `media_gate_status=passed` 时，媒体资源不得仍处于 `pending_media_review`；
13. `teaching_validation_gate_status=passed` 时，必须有真实教师或学生试看依据；当前阶段原则上不应出现该值；
14. `platform_gate_status=passed` 时，必须有平台接口或出版社平台适配依据；当前阶段原则上不应出现该值。

## 9. 内部评审标准

结构校验通过后，再进行内部评审。

评审问题包括：

1. 字段是否覆盖P1-T3的数据安全和服务表达风险；
2. 字段是否覆盖P3-T3的专业口径和媒体重绘风险；
3. 字段是否覆盖P4-T2的学生正文、教师材料、评价和平台发布门禁；
4. 是否仍有大量关键风险只能写入 `notes`；
5. 是否出现字段过多但无法判断的情况；
6. 是否能根据字段筛选出“可继续生成”“需专业复核”“需脱敏”“禁止发布”“需平台验证”的对象；
7. 是否能为后续工具链提供可执行的门禁条件。

内部评审结果分为三类：

| 结论 | 含义 | 后续动作 |
| --- | --- | --- |
| 通过 | V0.4字段可支撑三任务风险治理 | 制作V0.4回填合并建议或选择第四类任务增量 |
| 有条件通过 | 字段总体可用，但个别字段或枚举需修订 | 修订V0.4字段清单或样表后再评审 |
| 不通过 | 字段不能覆盖核心风险，或回填成本明显失控 | 返回V0.4字段规范重做，不进入后续生产 |

## 10. 时间顺序

建议按以下顺序执行：

1. 根据本计划生成三张V0.4回填样表；
2. 对三张样表做结构校验；
3. 修复结构问题和枚举问题；
4. 形成 `reports/课程能力图谱V0.4字段回填结构校验记录.md`；
5. 做内部评审；
6. 形成 `reports/课程能力图谱V0.4字段回填试验内部评审报告.md`；
7. 根据评审结论决定下一步。

## 11. 通过后的下一步

如果V0.4回填试验通过，下一步有两条可选路线：

1. 路线A：先形成V0.4回填合并建议，把三任务样表作为V0.3.3主数据的风险治理扩展层；
2. 路线B：选择第四类任务增量，继续验证课程能力图谱主数据能否承接新的任务类型。

更稳妥的优先顺序是先走路线A。原因是当前问题已经从“能不能拆任务”转向“能不能治理风险并支撑生产门禁”。如果不先稳定V0.4回填层，继续增加任务数量只会扩大后续治理负担。
