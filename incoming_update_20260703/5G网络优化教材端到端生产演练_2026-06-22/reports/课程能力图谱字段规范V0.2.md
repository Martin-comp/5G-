# 课程能力图谱字段规范V0.2

生成日期：2026-06-23  
适用范围：《5G网络优化教材（高级）》数字教材端到端生产演练  
上一版本：`reports/课程能力图谱字段规范V0.1.md`  
配套字段清单：`reports/课程能力图谱字段规范V0.2字段清单.csv`

## 1. 制定目的

V0.2不是重做课程能力图谱体系，而是在V0.1基础上做一次必要的小版本升级。

三任务横向评审已经确认：P2-T3、P4-T2、P5-T3可以组成“数据分析 -> 结果验证 -> 持续提升”的内部闭环，课程能力图谱V2以岗位工作过程为主链的方向有条件成立。但V0.1暴露出四个治理问题：

1. P5-T3已经按59字段V0.1落表，P2-T3和P4-T2仍主要保留在旧12/13字段结构中；
2. `job_process_id` 和 `ability_unit_id` 只能表达主挂接，不能稳定表达次级挂接；
3. 前置、后续和关系类型并列记录，无法准确表达“哪个节点以什么关系连接哪个节点”；
4. 标准条款、媒体问题、专业口径风险、学生正文段落和教师材料绑定仍不够明确。

因此，V0.2的目标是把课程能力图谱字段从“单任务试拆可用”推进到“三任务统一治理可用”，为后续P2-T3、P4-T2迁移和P6试拆提供统一口径。

## 2. 适用边界

V0.2适用于：

1. 已试拆任务迁移到统一字段口径；
2. 后续P6任务试拆；
3. 课程能力图谱节点到资源、活动、评价和审核状态的治理；
4. 出版平台接口、学习记录事件和资源包封装的前置设计。

V0.2当前不解决：

1. 不替代通信专业教师对指标、阈值、案例和结论口径的专业复核；
2. 不直接等同于出版社平台正式接口；
3. 不要求全书18个任务立即拆到详细能力节点；
4. 不证明AU-10已经成立，AU-10仍需P6任务试拆；
5. 不把AI生成内容、教学模拟案例或待审媒体写成已审核通过。

## 4. V0.2相对V0.1的主要变化

| 变化 | V0.1问题 | V0.2处理 |
| --- | --- | --- |
| 字段规范版本独立 | `graph_version`被混用为图谱版本和字段版本 | 新增 `field_schema_version`，`graph_version`只记录图谱数据版本 |
| 主次岗位过程拆分 | `job_process_id`无法表达P5-T3承接JP-06但主挂JP-07 | 改为 `primary_job_process_id` 和 `secondary_job_process_ids` |
| 主次能力单元拆分 | `ability_unit_id`多值会影响统计和前端过滤 | 改为 `primary_ability_unit_id` 和 `secondary_ability_unit_ids` |
| 结构化关系记录 | 前置、后续、关系类型并列后无法一一对应 | 新增 `relation_records`，作为关系记录主字段 |
| 节点功能类型 | 不能横向统计节点是读数、诊断、验证还是报告 | 新增 `node_function_type` |
| 跨任务角色 | 不能区分前置、深样章、延展、补救入口 | 新增 `cross_task_role` |
| 标准条款绑定状态 | `standard_clause_id=pending`缺少治理状态 | 新增 `standard_binding_status` 和 `standard_clause_note` |
| 媒体治理对象 | 只知道需媒体审查，不知道审查哪些对象 | 新增 `media_asset_review_ids` 和 `media_issue_summary` |
| 专业口径风险 | 只知道需专业复核，不知道风险类型 | 新增 `professional_risk_type` |
| 学生正文绑定 | 图谱节点和教材正文段落未稳定挂接 | 新增 `student_text_block_ids` |
| 教师材料绑定 | 教师端只有说明，缺少脚本/讲评材料ID | 新增 `teacher_support_asset_ids` |
| 学习事件载荷 | V0.1说明提到事件载荷，但字段清单缺失 | 新增 `event_payload_summary` |

## 5. 主次挂接规则

### 5.1 岗位工作过程

`primary_job_process_id`只能填写一个主岗位工作过程。它回答：这个节点主要训练哪一段岗位过程。

`secondary_job_process_ids`用于填写承接、支撑或后续连接的岗位过程。没有次级挂接时填 `none`。

示例：

| 节点 | primary_job_process_id | secondary_job_process_ids | 说明 |
| --- | --- | --- | --- |
| P2T3-N05 判断移动性/邻区异常 | JP-03 | JP-04 | 主要读测试数据，同时连接问题定位 |
| P4T2-N07 形成验收结论 | JP-06 | none | 主体是验证效果与表达结论 |
| P5T3-N01 确认性能提升方案与验证口径 | JP-07 | JP-06 | 主体是持续提升验证，同时承接P4-T2验收表达经验 |

### 5.2 能力单元

`primary_ability_unit_id`只能填写一个主能力单元。它回答：这个节点主要归属于哪个能力单元。

`secondary_ability_unit_ids`用于填写支撑能力、报告表达能力或后续入口能力。没有次级挂接时填 `none`。

示例：

| 节点 | primary_ability_unit_id | secondary_ability_unit_ids | 说明 |
| --- | --- | --- | --- |
| P2T3-N08 输出分析报告并连接复测 | AU-03 | AU-08 | 主体是测试数据分析，延展到报告表达 |
| P4T2-N08 修正职业表达 | AU-08 | AU-07 | 主体是职业表达，服务优化结果验证 |
| P5T3-N06 判断未闭环指标与二次分析入口 | AU-09 | AU-10 | 主体是全网提升复测，未闭环时导向复杂复盘 |

## 6. 结构化关系记录规则

V0.2保留 `prerequisite_node_ids` 和 `next_node_ids`，用于前端导航和快速筛选；但准确关系以 `relation_records` 为准。

`relation_records`采用以下记录方式：

```text
source_node_id>relation_type>target_node_id>relation_note
```

多条关系用英文分号 `;` 分隔。

示例：

```text
P2T3-N03>requires>P4T2-N03>指标读法支撑覆盖验证;
P4T2-N08>supports>P5T3-N01>验收表达经验支撑性能提升验证口径
```

当前阶段允许先用字符串承载，后续平台化时可拆为独立 `capability_relation` 表。

## 7. 新增枚举说明

### 7.1 `node_function_type`

用于说明节点的教学功能，可多选：

```text
orientation
data_preparation
data_reading
metric_interpretation
problem_diagnosis
proposal_design
implementation_record
result_verification
evidence_selection
conclusion_writing
expression_revision
continuous_improvement
remediation_routing
complex_review
resource_activity
assessment
not_applicable
```

该字段用于横向比较不同任务的节点结构，避免所有节点都只写成“能力点”。

### 7.2 `cross_task_role`

用于说明节点在跨任务学习链中的角色，可多选：

```text
core_task
prerequisite_task
supporting_task
deep_sample
extension_task
remediation_entry
next_task_entry
review_gate
resource_binding
not_applicable
```

示例：P2-T3对P4-T2是 `prerequisite_task;supporting_task`，P4-T2对当前演练是 `deep_sample`，P5-T3对AU-10是 `remediation_entry;next_task_entry`。

### 7.3 `standard_binding_status`

用于说明标准条款绑定成熟度：

```text
not_applicable
summary_only
pending_clause
clause_mapped
clause_verified
```

发布前不应长期保留 `summary_only` 或 `pending_clause`。当前阶段可保留，但必须在 `standard_clause_note` 中说明缺口。

### 7.4 `professional_risk_type`

用于说明专业复核风险类型，可多选：

```text
none
threshold
case_logic
conclusion
terminology
procedure
data_source
simulation_validity
tool_screenshot
signal_analysis
```

该字段用于区分“需复核”的具体原因，避免所有节点都只写“待专业复核”。

## 8. 迁移规则

### 8.1 P5-T3从V0.1迁移到V0.2

P5-T3已按V0.1完成7行59字段试拆，迁移时按以下规则处理：

1. `field_schema_version`填 `V0.2`；
2. `graph_version`填当前图谱版本，如 `V2`；
3. `job_process_id`迁移为 `primary_job_process_id`；
4. `ability_unit_id`迁移为 `primary_ability_unit_id`；
5. 根据P5-T3报告补 `secondary_job_process_ids` 和 `secondary_ability_unit_ids`；
6. 根据 `prerequisite_node_ids`、`next_node_ids` 和试拆报告补 `relation_records`；
7. 根据节点功能补 `node_function_type` 和 `cross_task_role`；
8. 媒体重绘、专业阈值和案例风险分别补到 `media_issue_summary` 与 `professional_risk_type`。

### 8.2 P2-T3从旧13字段表迁移到V0.2

P2-T3不能只做字段名映射。旧表缺少学生端表达、学习事件、量规、资源卡片ID、结构化关系和审核责任。

迁移时应同时读取：

1. `reports/P2-T3详细能力节点试拆报告.md`
2. `reports/P2-T3详细能力节点映射表.csv`
3. `reports/课程能力图谱V2节点与映射表.csv`
4. `reports/课程能力图谱三任务横向评审报告.md`

迁移结果必须形成独立V0.2字段表，不应继续以旧13字段表作为主数据。

### 8.3 P4-T2从样章/V2旧表迁移到V0.2

P4-T2是当前最成熟的深样章，但字段散落在V2旧表、样章数据和多份设计稿中。

迁移时应同时读取：

1. `reports/项目四任务2一线教学型高质量样章设计稿.md`
2. `reports/样章3.5A-1小修订实施记录.md`
3. `reports/样章3.5A-1专业复核表.csv`
4. `reports/课程能力图谱V2节点与映射表.csv`
5. `samples/task_workbench_3_5a1_two_period_sample/`

迁移重点是把学生正文段落、学习活动、教师材料、专业复核和媒体治理与P4T2-N01至P4T2-N08稳定挂接。

## 9. 质量门禁

使用V0.2后，以下门禁必须执行：

1. 未填写R1字段的节点只能作为草稿，不能进入当前主线图谱；
2. `primary_job_process_id` 和 `primary_ability_unit_id` 必须唯一，不能用多值替代；
3. `relation_records` 必须能解释主要前后置关系，不能只填前置/后续节点列表；
4. `standard_binding_status=summary_only` 或 `pending_clause` 的节点不能写成标准依据已完成；
5. `audit_status=review_passed` 只能在真实专业、媒体或编辑审核完成后使用；
6. P2-T3、P4-T2、P5-T3未统一到V0.2字段口径前，不批量拆全书18个任务；
7. AU-10未通过P6任务试拆前，不写成复杂问题复盘能力已验证；
8. 字段规范V0.2不是出版社平台正式接口，后续接平台时仍需接口适配。

## 10. 下一步建议

建议顺序：

1. 按V0.2字段清单迁移P2-T3；
2. 按V0.2字段清单迁移P4-T2；
3. 将P5-T3从V0.1补齐到V0.2；
4. 对三张V0.2任务表做一致性校验；
5. 选择P6-T1或P6-T2试拆，用于验证AU-10；
6. 通过P6验证后，再判断是否开始有限批量拆全书任务。

当前不建议：

1. 不建议直接拆全书18个任务；
2. 不建议继续优化图谱界面作为主任务；
3. 不建议直接进入工具链模块拆解；
4. 不建议把V0.2写成出版社平台正式接口；
5. 不建议将P5-T3的未闭环入口当成AU-10已经验证。
