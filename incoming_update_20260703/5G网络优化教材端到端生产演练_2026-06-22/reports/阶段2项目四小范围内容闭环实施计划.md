# 阶段2项目四小范围内容闭环实施计划

生成日期：2026-06-26  
执行范围：项目四 `P4-T1 -> P4-T2 -> P4-T3` 小范围内容闭环  
数据底座：课程能力图谱主数据 `V0.3.13`  
呈现底座：`samples/digital_textbook_overall_prototype/`  
质量锚点：`samples/task_workbench_3_5a1_two_period_sample/`

## 1. 目标

阶段2的目标不是制作完整全书，也不是拆解生产工具链模块，而是在一个可控范围内验证“图谱主数据 -> 教材正文 -> 资源活动评价 -> 教师支持 -> 整书原型呈现 -> 出版门禁”的闭环能否成立。

本阶段选择项目四作为验证对象：

```text
P4-T1 5G网络优化方案实施
-> P4-T2 5G网络优化结果验证
-> P4-T3 5G网络优化报告输出
```

阶段2完成时，应能回答五个问题：

1. V0.3.13的项目四节点能否支撑学生端教材正文；
2. P4-T1和P4-T3能否先形成轻量但可读、可教、可练的样稿；
3. P4-T2深样章能否作为项目四判断中枢继续复用；
4. 整书原型能否承载项目、任务、图谱、资源、教师和出版视图的闭环；
5. 现阶段还不能发布、不能定稿、不能进入工具链拆解的门禁是否清晰。

## 2. 架构

阶段2采用“三层一门禁”结构。

第一层是图谱数据层，以 `V0.3.13` 为唯一当前主数据来源，不再使用旧版本增量表作为当前事实来源。第二层是教材内容层，把 `student_title`、`student_learning_goal`、`student_action`、`student_output`、`assessment_output` 等字段转译成学生能读懂的正文、任务、表格、活动和评价。第三层是整书呈现层，在新增样本目录中复用整体原型框架，并加入项目四闭环页、资源中心、教师带教和出版/编辑状态。门禁层负责标记专业复核、媒体重绘、数据安全、平台接口和一线试看未完成的边界。

## 4. 任务拆分

### 任务1：抽取项目四闭环映射表

输入：

1. `课程能力图谱节点主数据表V0.3.13.csv`
2. `课程能力图谱关系主数据表V0.3.13.csv`
3. `课程能力图谱资源活动评价挂接表V0.3.13.csv`

输出：

`reports/阶段2项目四V0.3.13闭环映射表.csv`

验收标准：

1. 包含P4-T1、P4-T2、P4-T3共20个详细能力节点；
2. 每个节点保留学生端可用字段、能力单元、关系数量、挂接数量、风险状态和原型接入目标；
3. 不把 `audit_status`、`risk_level`、`source_files` 等后台字段直接当作学生端正文。

### 任务2：生成项目四内容闭环样稿

输入：

1. `阶段2项目四V0.3.13闭环映射表.csv`
2. P4-T1、P4-T2、P4-T3既有验证报告
3. `3.5A-1`深样章经验

输出：

`reports/阶段2项目四内容闭环样稿V0.1.md`

验收标准：

1. 样稿必须写成教材正文，不写成标题堆叠或大纲；
2. P4-T1和P4-T3使用低门槛语言说明任务情境、学习动作、表格、活动和完成标准；
3. P4-T2不重写深样章，只说明其在项目四中的判断中枢作用，并链接到3.5A-1；
4. 每个任务至少形成一个学生产出、一个评价标准、一个教师带教提示；
5. 所有专业阈值、仿真截图、客户沟通和对外承诺都保留待复核边界。

### 任务3：制作阶段2整书原型样本

新增目录：

`samples/digital_textbook_overall_prototype_phase2_p4_loop/`

修改方式：

1. 从 `samples/digital_textbook_overall_prototype/` 复制基础结构；
2. 更新 `data.js`，把项目四三任务状态改为阶段2闭环；
3. 增加P4-T1和P4-T3的轻量内容样稿、资源、活动、评价和教师支持；
4. 保留P4-T2深样章入口；
5. 更新 `app.js`，在项目四页面显示闭环路线、任务内容样稿、学生完成标准和教师带教说明；
6. 更新 `README.md` 和QA脚本。

验收标准：

1. 原始 `overall-0.2` 目录不被覆盖；
2. 新原型首页能说明阶段2范围；
3. 项目四页面能看到 `P4-T1 -> P4-T2 -> P4-T3` 的学习闭环；
4. 资源中心能看到P4-T1、P4-T2、P4-T3三类资源；
5. 教师视图能看到项目四三任务的带教组织；
6. 出版/编辑视图能看到未发布、待专业复核、待媒体重绘和平台未接入门禁。

### 任务4：执行结构和浏览器QA

QA项目：

1. 桌面端无横向溢出；
2. 移动端无横向溢出；
3. 控制台无错误；
4. 六个主视图可切换；
5. 项目四闭环内容可见；
6. P4-T2深样章入口存在；
7. 图谱节点可点击；
8. 资源中心显示三任务资源；
9. 出版/编辑视图显示平台接口未接入。

输出：

1. `samples/digital_textbook_overall_prototype_phase2_p4_loop/qa/playwright_qa_summary.json`
2. `samples/digital_textbook_overall_prototype_phase2_p4_loop/qa/desktop.png`
3. `samples/digital_textbook_overall_prototype_phase2_p4_loop/qa/mobile.png`

### 任务5：治理和收口

需要同步的治理文件：

1. `00_治理与索引/README_先读我.md`
2. `00_治理与索引/任务连续性记录.md`
3. `00_治理与索引/数字教材样章设计原则与质量门禁.md`

5. `00_治理与索引/资产总表.md`

验收标准：

1. 阶段2新增成果均进入索引；
2. 当前主线明确为“项目四小范围内容闭环”；
3. 当前推荐图谱基线仍为V0.3.13；
4. 原始整体原型 `overall-0.2` 仍作为基线，不误写为废弃；
5. 阶段2新增原型不能写成正式全书成品；
6. 下一步建议从阶段2审计结果推出，不提前进入工具链拆解。

## 5. 阶段2完成标准

阶段2只有同时满足以下条件，才可以收口：

1. 映射表存在且覆盖项目四20个详细节点；
2. 内容闭环样稿存在，且P4-T1/P4-T3不是大纲式拼接；
3. 阶段2整书原型目录存在且可打开；
4. QA脚本通过，或失败项被明确记录为外部环境问题；
5. 治理文件和成果索引已更新；
6. 收口审计报告明确说明已完成项、未完成门禁和下一阶段建议。

## 6. 不做事项

阶段2不做以下事项：

1. 不把项目四样稿写成整本数字教材已经完成；
2. 不直接铺开全书18个任务；
3. 不把仿真软件截图直接作为正式资源；
4. 不宣称通信专业复核、一线教学验证或出版社平台验收已经完成；
5. 不进入AI生产工具链模块拆解；
6. 不覆盖原始 `samples/digital_textbook_overall_prototype/` 基线目录。

## 7. 后续判断口径

阶段2完成后，下一步不自动等于“拆工具链”。应先根据审计结果判断：

1. 如果项目四闭环在教材正文、原型流转和资源活动评价上成立，下一阶段可以选择另一个项目做横向复制验证；
2. 如果项目四闭环仍存在学生读不懂、教师不好用或图谱挂接不清的问题，应先修订阶段2样本；
3. 只有当至少两个项目级闭环样本稳定后，才建议进入生产工具链模块拆解。
