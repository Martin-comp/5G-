## 4. 项目二关系逻辑复核

V0.3.4中的P2项目关系不应理解为简单的：

```text
P2-T1 -> P2-T2 -> P2-T3
```

更准确的表达是：

```text
测试采集主线：P2-T1 -> P2-T3
异常处理分支：P2-T1 -> P2-T2 -> P2-T3
```

P2-T2不是所有场景必经关卡，而是测试异常、数据完整性、软件设备故障和现场协调问题的处理分支。

本次关系校正已正确处理P2-T1新增关系：

| 关系ID | 处理结果 | 复核判断 |
| --- | --- | --- |
| EV04-INC-P2T1-027 | 由支撑判断调整为问题回流 | 正确 |
| EV04-INC-P2T1-028 | 保持问题回流 | 正确 |
| EV04-INC-P2T1-029 | 保持直接递进 | 正确 |
| EV04-INC-P2T1-030 | 保持直接递进 | 正确 |

复核判断：项目二关系表达通过短复核。V0.3.4没有把P2项目写成机械线性流程，且没有隐性改写既有V0.3.3关系。

3. 软件截图、测试界面、路线图、LOG和现场许可类材料不能裸用；
4. 后续生成学生正文或资源卡时，必须回挂这些节点和挂接对象，不能绕过主数据。

## 6. 风险治理层复核

P2项目V0.4风险治理扩展汇总表共64条记录：

| 对象 | 数量 |
| --- | ---: |
| P2-T1 | 14 |
| P2-T2 | 13 |
| P2-T3 | 37 |
| node_master | 19 |
| binding_master | 45 |
| overall_publish_gate_status=not_ready | 64 |

复核判断：风险治理层足以支撑V0.3.4升为推荐主数据基线，但不足以支撑生产。

理由：

1. P2-T2/P2-T3没有被重拆，也没有被强行并入V0.3.4四张主表；
2. P2项目三任务的风险记录已经统一到V0.4字段口径；
3. 64条记录均保持 `not_ready`，没有误标为可发布；
4. 阻断原因和下一步动作比早期V0.4全局扩展表更具体；
5. P2-T1中7条 `binding_master` 风险记录使用 `binding_target_id` 作为 `source_record_id`，可回溯，但与全局风险治理扩展表常用 `binding_id` 的口径不完全一致。该问题不阻断V0.3.4基线成立，但若后续并入全局风险治理表，必须统一ID口径。

## 9. 内部评分

加分依据：

1. V0.3.4四张主表结构校验通过；
2. P2-T1七节点颗粒度合理，补齐AU-02能力链；

4. V0.3.4只是主数据基线，尚未生成学生正文、教师材料、资源包或页面样本；
5. 当前仍缺少外部专家和一线教师学生验证。
