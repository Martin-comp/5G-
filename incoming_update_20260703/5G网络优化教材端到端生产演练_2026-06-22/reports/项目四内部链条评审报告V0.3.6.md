## 4. 链条成立的主要证据

### 4.1 P4-T1到P4-T2的交接基本成立

P4-T1不是孤立的软件操作任务。它已经被拆成“实施边界、责任边界、参数依据、实施步骤、变更记录、复测交接”六个动作，其中最关键的出口是：

1. `P4T1-N05 记录实施结果与变更凭据`
2. `P4T1-N06 形成复测验证入口并交接P4-T2`

V0.3.6中已经保留两条关键关系：

| 关系 | 类型 | 评审判断 |
| --- | --- | --- |
| `P4T1-N05 -> P4T2-N01` | 支撑判断 | 实施变更记录可支撑验证场景识别 |
| `P4T1-N06 -> P4T2-N01` | 直接递进 | 复测验证交接清单进入结果验证 |

这说明P4-T1没有停留在“做了优化动作”，而是把实施证据交给P4-T2判断是否达标。

### 4.2 P4-T2承担了项目四的结果判断中枢

P4-T2八个节点承担结果验证主链：

```text
识别验证场景
-> 区分改善与达标
-> 读覆盖指标
-> 读移动性指标
-> 读体验与容量指标
-> 选择判断依据
-> 形成验收结论
-> 修正职业表达
```

该链条的优点是没有把结果验证写成“看几个截图得结论”，而是要求学生先识别验证对象，再区分改善与达标，之后读取覆盖、移动性、体验与容量指标，最后形成依据链和职业表达。

P4-T2在项目四中相当于判断中枢：它既承接P4-T1实施证据，也为P4-T3报告输出提供结论和边界。

### 4.3 P4-T2到P4-T3的证据链基本成立

P4-T3不是单纯报告模板任务。它通过多条前置支撑关系承接P4-T1和P4-T2：

| 输入关系 | 作用 |
| --- | --- |
| `P4T1-N05 -> P4T3-N02` | 实施变更记录进入报告证据链 |
| `P4T1-N06 -> P4T3-N02` | 复测验证交接清单说明验证资料来源 |
| `P4T2-N06 -> P4T3-N02` | 依据链分类结果支撑证据组织 |
| `P4T2-N07 -> P4T3-N04` | 验收结论支撑指标判断和未闭环边界 |
| `P4T2-N08 -> P4T3-N06` | 职业表达修正经验支撑报告样稿修订 |
| `P4T2-N02 -> P4T3-N04` | 改善与达标边界支撑报告结论表达 |

这些关系能说明P4-T3已经形成独立的“报告输出与职业表达”能力，不只是P4-T2结论的复制粘贴。

### 4.4 问题回流关系具备闭环价值

V0.3.6中保留了P4-T3回到P4-T2的两条问题回流关系：

| 回流关系 | 回流原因 |
| --- | --- |
| `P4T3-N02 -> P4T2-N06` | 报告证据链不足或依据与背景混淆时，回到依据链分类 |
| `P4T3-N04 -> P4T2-N02` | 把改善写成达标时，回到改善与达标边界判断 |

这两条关系很关键。它们避免了报告输出成为单向终点，也说明数字教材中的课程能力图谱可以支持“写报告时发现证据不足，再回到验证任务补证据”的学习闭环。

## 5. 当前链条的主要不足

### 5.1 P4-T1仍有工程授权和责任边界风险

P4-T1涉及参数变更、工程实施、责任边界和回退条件。当前节点结构能够保留这些风险，但并未完成通信专业教师或行业专家复核。

特别是以下内容不能直接进入学生端正式教材：

1. 参数变更依据和适用范围；
2. 工程授权边界；
3. 真实网络操作暗示；
4. 仿真软件截图；
5. CSI-RS案例的通用化表达。

### 5.2 P4-T2媒体治理风险仍集中

P4-T2中多个节点处于 `pending_media_review`，涉及覆盖、移动性、体验、容量、掉线等截图或流程图。当前可作为主数据结构，但不能直接作为正式学生端资源。

高风险节点包括：

1. `P4T2-N03 读覆盖指标`
2. `P4T2-N04 读移动性指标`
3. `P4T2-N05 读体验与容量指标`

这些节点需要把原教材非通用仿真软件截图转化为教学化指标表、流程图、热度条、证据链图或可交互动画。

### 5.3 P4-T3客户沟通和外部发布边界仍偏粗

P4-T3的价值是把证据链转成报告输出，但它也带来客户沟通、服务承诺和外部发布风险。当前客户沟通提纲只能用于教学模拟，不能作为真实客户话术或真实交付模板。

后续如果进入学生端正文或教师材料，必须明确：

1. 哪些表达是教学模拟；
2. 哪些结论必须由教师或企业导师复核；
3. 哪些内容不得对真实客户承诺；
4. 哪些站点、截图和案例信息需要脱敏或重绘。

### 5.4 学生端教材正文仍未覆盖项目四全链条

当前P4-T2已经有3.5A-1深样章，但P4-T1和P4-T3还没有对应的学生端教材正文、教师带教材料、练习反馈和真实课堂验证。项目四链条结构通过，不代表项目四数字教材整体样章已经可用。

### 5.5 专业复核压力较高

项目四20个详细能力节点中，13个节点为 `pending_professional_review`，5个节点为 `pending_media_review`，2个节点为 `pending_editorial_review`。项目四83条挂接中，40条高风险。

这说明当前链条可以继续用于图谱治理，但不能直接升级为教学定稿或平台资源。

## 6. 是否需要先做项目四关系校正

评审判断：暂不需要单独启动项目四关系校正清单。

理由如下：

1. P4-T1到P4-T2的关键交接关系存在，且方向合理；
2. P4-T2到P4-T3的证据、结论、表达支撑关系存在，且能解释报告输出来源；
3. P4-T3回到P4-T2的回流关系存在，能处理证据不足和结论边界错误；
4. 未发现节点端点缺失、任务链断裂、节点颗粒度失控或报告任务退化为模板清单的结构性错误。

但后续仍需保留四个观察项：

1. P4-T1工程授权和参数变更责任边界是否需要V0.5字段细化；
2. P4-T2媒体审查节点是否需要形成统一重绘规范；
3. P4-T3客户沟通与外部发布边界是否需要更细的风险字段；
4. P4-T3报告对象与交付口径是否需要连接P1客户沟通类节点作为远端支撑。
