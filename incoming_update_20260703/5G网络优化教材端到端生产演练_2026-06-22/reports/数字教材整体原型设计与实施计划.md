# 数字教材整体原型设计与实施计划

生成日期：2026-06-23  
适用阶段：样章3.5A-1个人评审正向之后、工具链模块拆解之前  
当前基线：`samples/task_workbench_3_5a1_two_period_sample/`

## 1. 阶段判断

当前还不适合进入“生产流程与工具链模块拆解”。原因是：现有成果只深度验证了项目四任务2这一个任务的呈现样板，尚未验证整本数字教材的课程层、项目层、任务层、课程能力图谱暗线、资源流转、教师/学生视图切换和出版社平台挂接关系。

如果此时直接拆工具链，容易把单任务样板过早固化为整书生产流程。下一阶段应先做“数字教材整体原型”，以验证整本教材在前端如何组织、如何流转、如何承载课程能力图谱。

## 2. 原型目标

本阶段目标不是把整本教材所有任务都做成高质量样章，而是形成一个可运行、可讲清楚逻辑的整书级样本。

建议采用“横向整书框架 + 一个纵向深样章”的策略：

1. 横向整书框架：展示课程首页、项目列表、任务列表、课程能力图谱、学习进度、资源中心、教师带教入口和平台输出入口；
2. 纵向深样章：嵌入现有3.5A-1作为项目四任务2的高完成度任务样板；
3. 其他项目和任务：先做低保真结构占位，不展开完整内容；
4. 课程能力图谱：作为贯穿课程、项目、任务、卡片、学习活动、评价记录的暗线数据骨架；
5. 角色流转：验证学生学习、教师带教、资源编辑/出版社平台视角之间的切换逻辑。

## 3. 原型范围

### 3.1 课程层

课程层应回答：

1. 这是一门什么课；
2. 学生从哪里开始学；
3. 教师如何看到课程整体组织；
4. 整本教材由哪些项目和任务构成；
5. 课程能力图谱如何作为整体入口但不压过学习任务；
6. 学习进度和能力完成状态如何呈现。

建议页面包含：

1. 课程首页；
2. 项目导航；
3. 课程能力图谱入口；
4. 当前学习建议；
5. 教师带教入口；
6. 资源/出版视图入口。

### 3.2 项目层

项目层应回答：

1. 项目目标是什么；
2. 项目下包含哪些任务；
3. 任务之间有什么先后关系；
4. 本项目对应课程能力图谱中的哪些能力群；
5. 哪个任务已有深度样章，哪些任务只是占位。

建议优先完整呈现项目四，因为现有深样章属于项目四任务2。其他项目可先展示标题、任务数量、能力群和占位状态。

### 3.3 任务层

任务层不再继续打磨任务级原型，而是将现有3.5A-1作为任务详情样板嵌入整体原型。

任务层应包含：

1. 任务标题和角色；
2. 学习入口；
3. 案例递进；
4. 学习活动；
5. 课程能力图谱当前位置；
6. 学习单和修正句；
7. 教师带教视图；
8. 资源转化视图。

其他任务只需做结构占位：标题、所属项目、关联能力节点、预计资源类型和开发状态。

### 3.4 课程能力图谱暗线

课程能力图谱在整体原型中不是一个孤立页面，而应贯穿四层：

1. 课程层：显示全课程工作过程主链；
2. 项目层：显示本项目对应的能力群；
3. 任务层：显示当前任务对应的能力节点；
4. 资源层：显示卡片、学习活动、评价记录与节点的映射。

图谱不应只是目录跳转。节点至少应能关联：

1. 课程标准或岗位任务；
2. 项目和任务；
3. 卡片资源；
4. 学习活动；
5. 学生学习产出；
6. 教师讲评依据；
7. 审核状态。

## 4. 页面与流转建议

整体原型建议包含以下视图：

1. 学生课程首页：看课程、项目、当前任务和学习进度；
2. 项目总览页：看项目目标、任务链和项目能力群；
3. 任务学习页：嵌入3.5A-1任务样板；
4. 课程能力图谱页：可展开课程主链、项目能力群和任务节点；
5. 教师带教页：查看项目/任务教学组织、学情观察和讲评入口；
6. 资源中心页：查看卡片、表图、动画/互动/小游戏转化位；
7. 出版/编辑视图：查看资源包输出、审核状态、平台挂接状态。

学生主路径建议为：

课程首页 -> 项目四 -> 任务2 -> 学习活动 -> 学习单/修正句 -> 任务完成状态回写课程能力图谱。

教师主路径建议为：

课程首页 -> 项目四教师带教 -> 任务2教师视图 -> 典型答案/模拟学情/专业复核点 -> 讲评记录。

出版/编辑路径建议为：

课程首页 -> 资源中心 -> 资源卡片/图谱节点/学习活动映射 -> 审核状态 -> 资源输出包或直接挂接页面。

## 5. 数据结构建议

整体原型不应只靠页面硬编码，应先形成轻量数据结构，便于后续工具链反推。

建议最小数据对象：

1. `course`：课程标题、简介、项目列表、课程能力图谱；
2. `project`：项目标题、项目目标、任务列表、能力群；
3. `task`：任务标题、所属项目、任务状态、关联能力节点、样章路径；
4. `capabilityNode`：节点名称、层级、前置后续、关联任务、关联资源、评价方式；
5. `resourceCard`：卡片类型、内容状态、媒体状态、审核状态、关联节点；
6. `learningActivity`：活动类型、学生动作、反馈方式、评价记录；
7. `teacherSupport`：课时安排、讲评脚本、观察点、专业复核点；
8. `publicationOutput`：资源包状态、直接呈现状态、平台挂接状态。

## 7. 质量门禁

整体原型进入评审前至少应满足：

1. 能从课程层进入项目层；
2. 能从项目层进入任务层；
3. 能从任务层回到课程能力图谱；
4. 课程能力图谱能显示课程、项目、任务、资源、学习活动之间的关系；
5. 3.5A-1能作为任务详情样板嵌入或跳转；
6. 学生视图、教师视图、资源/出版视图边界清楚；
7. 其他任务明确标注为结构占位，不伪装成完整内容；
8. 真实一线教师/学生试看和通信专业复核仍标注为未完成外部验证；
9. 浏览器QA覆盖桌面端和移动端，无横向溢出、无控制台错误。

## 8. 不做事项

本阶段暂不做：

1. 不继续打磨项目四任务2任务级样章；
2. 不把整本书所有任务都做成深样章；
3. 不制作正式动画、互动或小游戏；
4. 不接入真实AI助手；
5. 不接入出版社真实平台接口；
6. 不宣称真实一线教学验证已完成；
7. 不进入正式工具链模块拆解。
