# 项目四任务2一线教学型高质量样章设计稿

生成日期：2026-06-22  
样章对象：项目四 / 任务2：5G网络优化结果验证  
第一评审对象：一线教师与学生实际使用  
设计状态：已确认采用“完整学习卡片 + 能力图谱映射 + 单元编排”方向，待进入页面实现

## 0. 设计结论

本样章不应按原教材“任务导入 -> 任务要求 -> 知识准备 -> 任务实施 -> 测评”的顺序平铺。更合适的结构是围绕一个真实问题组织学习：

> 某区域完成 5G 网络优化后，视频通话仍偶发卡顿，直播上行时延偏高。请根据优化前后指标、切换流程和仿真截图，判断本次优化是否达标，并写出验证结论。

这样做的原因是：一线学生更需要知道“怎么判断问题和证据”，而不是先读完整理论；教师也更容易围绕一个任务组织讲解。

页面呈现可以采用卡片拼接、任务地图、卡片栈或更美观的新形式，但资源层必须按“完整学习卡片”管理。每张卡片都应包含完整内容、学习动作、反馈规则、前后衔接、能力图谱映射和审核状态。只生成标题卡或摘要卡，不符合教材要求。

## 1. 学习目标

学生完成样章后，应能完成以下最小能力闭环：

1. 区分覆盖问题、切换问题、性能问题的基本判断入口；
2. 读取 SS-RSRP、SS-SINR、切换事件、时延、速率、容量、掉线等关键指标；
3. 根据优化前后对比判断优化是否达标；
4. 形成一份简短的优化结果验证结论；
5. 说明自己的判断依据。

本样章不追求学生完整掌握 5G 网络优化全部理论。

## 2. 学习路径设计

### 2.1 学生端路径

建议分为 6 个步骤：

| 步骤 | 页面模块 | 学生活动 | 产出 |
| --- | --- | --- | --- |
| 1 | 故障情境 | 阅读视频卡顿/直播延迟场景 | 初步判断问题可能来源 |
| 2 | 诊断分流 | 根据现象选择覆盖、切换、性能三类入口 | 问题类型选择 |
| 3 | 微知识卡 | 学习对应判断所需指标和流程 | 指标理解 |
| 4 | 证据观察 | 查看优化前后指标、流程图、仿真截图 | 证据标注 |
| 5 | 实训判断 | 填写是否达标、原因、后续建议 | 结构化任务单 |
| 6 | 反馈讲评 | 查看参考思路和常见误区 | 修改完善结论 |

### 2.2 教师端路径

教师使用时应能看到：

1. 本任务教学目标；
2. 学生任务单；
3. 全班问题类型选择分布；
4. 指标判断错误分布；
5. 学生提交的验证结论；
6. 讲评建议和常见误区。

样章阶段可用模拟数据展示教师视图，但必须明确标注“模拟数据”。

## 3. 页面结构设计

### 模块一：任务情境

标题建议：`视频卡顿是不是优化没做好？`

内容：

- 给出一个真实业务体验问题；
- 不直接给答案；
- 引导学生进入诊断。

示例文案：

> 某校园区域完成 5G 网络优化后，普通网页访问恢复正常，但晚间直播上行仍有明显延迟，视频通话偶发卡顿。网络优化人员已经输出一组优化前后指标。请你判断：本次优化是否达标？问题更可能集中在哪一类？

教学功能：

- 把抽象的“优化结果验证”变成可判断任务；
- 降低学生进入门槛。

### 模块二：诊断分流

交互形式：

学生根据现象选择一个或多个问题入口：

1. 覆盖问题；
2. 切换问题；
3. 时延/速率/容量性能问题；
4. 掉线或业务保持问题；
5. 暂无法判断，需要补充证据。

反馈规则：

- 不直接判定唯一正确；
- 根据选择提示需要查看哪些证据；
- 引导学生进入对应微知识卡。

教学功能：

- 训练“先分类，再分析”的网优思维；
- 避免学生直接套公式。

### 模块三：微知识卡

不搬运原教材长文本，只保留完成任务必要的知识。

建议知识卡：

| 知识卡 | 内容边界 | 来源 |
| --- | --- | --- |
| 覆盖验证 | SS-RSRP、SS-SINR、弱覆盖、越区覆盖、交叉覆盖 | 教材原文 + 待专家审核 |
| 切换验证 | A1/A2/A3/A4/A5/A6/B1/B2，SA/NSA切换基本流程 | 教材原文 + 专业标准 |
| 性能验证 | 时延、速率、容量、掉线与业务体验关系 | 教材原文重构 |
| 证据链 | 优化前指标、参数调整、优化后指标、结论 | AI 教学重构 |

每张卡建议控制在 150-250 字，并配 1 张图或 1 个小表。

### 模块四：证据观察

应将原教材中的表格、流程图、仿真截图转为“证据材料”，而不是普通插图。

证据材料建议：

1. 覆盖指标对比表；
2. 切换事件流程图；
3. SA/NSA 切换流程图；
4. 仿真软件优化前后截图；
5. 参数调整记录样例。

交互方式：

- 学生点击证据，标注它支持哪类判断；
- 学生选择“该证据是否足以支持结论”；
- 如果证据不足，引导选择“需要补充哪类数据”。

### 模块五：实训任务单

学生提交结构化任务单。

建议字段：

| 字段 | 类型 | 是否必填 |
| --- | --- | --- |
| 问题类型判断 | 单选/多选 | 必填 |
| 核心依据指标 | 多选 | 必填 |
| 优化前后变化 | 表格填写 | 必填 |
| 是否达标 | 单选 | 必填 |
| 判断理由 | 短文本 | 必填 |
| 后续建议 | 短文本 | 选填 |

任务单要控制复杂度，避免变成完整网优报告。

### 模块六：即时反馈与讲评

学生提交后看到：

1. 自己的判断路径；
2. 是否遗漏关键证据；
3. 参考分析框架；
4. 常见误区。

教师看到：

1. 全班选择分布；
2. 错误集中点；
3. 典型答案；
4. 建议讲评顺序。

## 4. 教师视图设计

教师视图不是后台系统，只做样章中的一个“教师使用样例”即可。

建议包含：

| 区域 | 内容 |
| --- | --- |
| 任务概览 | 目标、建议时长、适用课堂环节 |
| 学情概览 | 完成人数、平均完成时间、证据链完整率 |
| 错误分布 | 覆盖/切换/性能判断错误分布 |
| 证据缺失 | 学生最常漏选的证据 |
| 讲评建议 | 推荐教师先讲什么、后讲什么 |

样章中的学情数据必须标注为模拟数据。

## 5. 资源包设计

本样章同时输出可编辑资源包，资源包与页面模块一一对应。

| 页面模块 | 资源包内容 |
| --- | --- |
| 任务情境 | 情境文本、任务目标、适用场景 |
| 诊断分流 | 问题类型选项、反馈规则 |
| 微知识卡 | 知识卡 Markdown、图表、来源标注 |
| 证据观察 | 指标表、流程图、截图、证据说明 |
| 实训任务单 | 表单字段 JSON、评分规则 |
| 反馈讲评 | 参考答案、常见误区、教师讲评建议 |

资源包必须包含：

1. 资源 ID；
2. 来源；
3. 能力点；
4. 适用模块；
5. 审核状态；
6. 版权状态。

资源包还必须新增卡片级清单：

| 文件 | 用途 |
| --- | --- |
| `metadata/card_manifest.csv` | 管理卡片 ID、类型、标题、能力节点、学习动作、证据产出、审核状态和后续卡片 |
| `reports/卡片化资源单元与能力图谱映射规范.md` | 定义什么是合格教材卡片 |
| `reports/项目四任务2卡片编排与图谱映射清单.md` | 定义本样章 12 张核心卡片的顺序、内容边界和图谱映射 |

第一版高质量样章建议采用 12 张核心卡片完成最小闭环：

| 顺序 | 卡片 | 类型 | 功能 |
| ---: | --- | --- | --- |
| 1 | 视频卡顿是不是优化没做好？ | 情境卡 | 提出真实任务 |
| 2 | 问题可能属于哪一类？ | 诊断交互卡 | 形成初步判断 |
| 3 | 覆盖验证看什么 | 知识卡 | 补足覆盖指标 |
| 4 | 优化前后覆盖指标对比 | 证据卡 | 判断覆盖改善 |
| 5 | 切换验证看什么 | 知识卡 | 补足切换流程 |
| 6 | 切换流程是否合理？ | 交互卡 | 判断流程合理性 |
| 7 | 端到端性能验证看什么 | 知识卡 | 补足性能指标 |
| 8 | 业务体验与性能指标对照 | 证据卡 | 判断业务体验改善 |
| 9 | 仿真截图能说明什么 | 证据卡 | 判断仿真证据边界 |
| 10 | 写出优化结果验证结论 | 任务卡 | 形成结构化短报告 |
| 11 | 你的证据链完整吗？ | 反馈卡 | 修正判断和表达 |
| 12 | 课堂讲评与学情观察 | 教师卡 | 支持教师讲评 |

## 6. 原教材内容处理原则

### 6.1 保留

保留以下内容：

- 任务导入中的真实业务体验场景；
- 六类优化验证对象；
- 覆盖指标表；
- A 类/B 类切换事件；
- SA/NSA 切换流程；
- 仿真软件验证步骤；
- 随堂测试和任务测评的核心问题。

### 6.2 重构

重构以下内容：

- 长篇知识准备拆为微知识卡；
- 测评题转为结构化评价任务；
- 图片转为证据材料；
- 任务实施转为实训任务单；
- 重点难点转为常见误区和教师讲评点。

### 6.3 暂缓

暂缓以下内容：

- 全部参数表完整呈现；
- 大段 3GPP 细节解释；
- 完整网优报告模板；
- 自动评分复杂专业实训；
- 未确认版权的外部素材替换。

## 7. 交互清单

高质量样章至少应包含以下交互：

| 交互 | 学习目的 | 数据产出 |
| --- | --- | --- |
| 问题类型判断 | 训练故障分类 | 学生选择、是否修改 |
| 证据匹配 | 训练指标与结论对应 | 证据选择记录 |
| 流程排序 | 理解切换验证流程 | 排序结果 |
| 优化前后对比 | 判断是否达标 | 指标表单 |
| 结论提交 | 形成表达与证据链 | 结构化短报告 |

不建议使用无教学意义的翻卡、轮播、装饰动画作为主要交互。

## 8. 页面验收标准

页面制作完成后，至少通过以下检查：

1. 桌面端和手机端均能阅读；
2. 首屏能说明任务，而不是只显示标题；
3. 学生不滚动超过 2 屏就能开始第一个操作；
4. 至少 3 个交互能产生学习数据；
5. 教师视图能支持一次课堂讲评；
6. 所有图表有说明文字；
7. 所有 AI 重构内容标注审核状态；
8. 浏览器中无图片加载失败和横向溢出。

## 9. 风险与处理

| 风险 | 判断 | 处理 |
| --- | --- | --- |
| 技术内容不准确 | 高风险 | 样章标注“待专家审核”，不能作为正式教学定稿 |
| 原教材图片质量不足 | 中风险 | 样章阶段可用，正式版需重绘或获取源图 |
| 课堂时长过长 | 高风险 | 只做一个最小任务闭环，不做全知识覆盖 |
| 教师视图伪数据误导 | 中风险 | 明确标注模拟数据 |
| 页面过度设计 | 中风险 | 以学习动作优先，视觉克制 |

## 10. 制作前确认项

进入页面制作前，需要确认以下设计边界：

1. 样章以 30 分钟学习任务为目标；
2. 样章优先服务学生学习和教师讲评；
3. 项目四任务2只做一个最小闭环，不追求全内容覆盖；
4. 教师视图使用模拟数据，但明确标注；
5. 所有专业结论保持待审核状态；
6. 页面产物同时配套资源输出包。

如果以上 6 项成立，下一步可以进入样章原型制作。
