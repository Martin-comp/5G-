# P2-T3详细能力节点试拆报告

生成日期：2026-06-23  
试拆对象：项目二 / 任务3：5G网络测试数据分析  
对应图谱版本：课程能力图谱V2优化版  
目的：验证V2图谱能否从P4-T2迁移到非P4-T2任务，而不是只服务一个深样章。

## 1. 试拆结论

本轮选择 `P2-T3 5G网络测试数据分析` 作为第一个非P4-T2试拆对象。

选择理由：

1. 它位于V2的 `JP-03 整理数据与识读指标` 和 `AU-03 测试问题处理与数据分析`，不是P4-T2相邻的报告输出任务，能更有效检验图谱跨项目迁移能力；
2. 它是P4-T2结果验证的前置能力，直接支撑后续“读覆盖指标、读移动性指标、读体验与容量指标”；
3. 原教材中P2-T3包含指标解释、软件导入导出、覆盖问题分析、邻区漏配案例和项目角色演练，内容基础较完整，但学生动作和评价产出不够清晰，适合检验V2是否能把传统教材材料转成“资源、活动、评价”的节点结构；
4. 该任务能暴露V2的一个关键问题：如果只按教材目录拆，会停留在“指标知识 + 软件截图”；如果按岗位工作过程拆，必须形成“接收数据 -> 识读指标 -> 判断异常 -> 归因 -> 提方案 -> 输出分析报告”的能力链。

不优先选择 `P4-T3 优化报告输出` 的原因：

1. P4-T3与P4-T2距离太近，迁移难度较低；
2. P4-T3主要检验 `AU-08 优化报告与职业表达`，对验证V2跨项目主链帮助不如P2-T3；
3. P4-T3适合下一轮作为“报告表达能力”的专项试拆。

## 2. 原教材内容诊断

P2-T3原文主要包含以下内容：

1. 任务导入和任务要求：提出测试LOG如何分析、如何导入导出、如何分析异常并输出解决方案；
2. 指标知识：PCI、SS-RSRP、SS-SINR、NR-RSSI、SS-RSRQ、吞吐量、CQI、MCS和切换事件；
3. 软件操作：导入原始数据、输出Word/Excel/PDF分析报告；
4. 覆盖类问题分析：弱覆盖、越区覆盖、覆盖不均衡、重复覆盖等问题，以及弱覆盖成因和优化思路；
5. 软件截图示例：问题站点、测试数据分析界面；
6. 经典案例：邻区漏配导致测量报告频繁上报但未下发切换命令，最终掉话；
7. 项目角色演练：数据分析工程师根据测试LOG发现问题并提出整改方案。

诊断判断：

1. 原教材材料可用，但组织方式偏“知识点 + 软件操作 + 案例罗列”；
2. 对学生来说，最关键的问题不是背完指标，而是知道拿到测试LOG后如何一步一步形成问题判断；
3. 原软件截图不能直接成为主学习材料，需要改造成带字段解释、读图路径和判断任务的教学资源；
4. “邻区漏配”案例有较好的职业教育价值，可作为移动性/邻区异常判断样例；
5. 本任务应先拆出能力节点和评价产出，不急于制作完整页面。

## 3. V2图谱挂接位置

P2-T3在V2中不再只是“项目二任务3”，而应挂接到以下图谱位置：

| 层级 | 节点 | P2-T3角色 |
| --- | --- | --- |
| 岗位工作过程 | JP-03 整理数据与识读指标 | 主挂接位置，训练把测试LOG和指标转化为可判断数据 |
| 岗位工作过程 | JP-04 定位问题与制定方案 | 次级挂接位置，训练从异常现象到问题原因和整改建议 |
| 能力单元 | AU-03 测试问题处理与数据分析 | 主能力单元 |
| 能力单元 | AU-05 网络问题定位与方案制定 | 延展能力单元 |
| 后续关联 | AU-07 优化结果验证 | 为P4-T2指标读法提供前置能力 |

## 4. P2-T3详细能力节点

本轮试拆出8个详细能力节点：

| 节点 | 名称 | 学生要学会的动作 | 评价产出 |
| --- | --- | --- | --- |
| P2T3-N01 | 明确分析任务与数据来源 | 判断本次要分析什么LOG、对应什么场景和业务问题 | 数据分析任务单 |
| P2T3-N02 | 完成LOG导入与报告导出 | 按流程导入测试数据，并确认报告输出字段 | 导入导出流程记录 |
| P2T3-N03 | 识读关键指标与判断边界 | 解释PCI、SS-RSRP、SS-SINR、RSSI、RSRQ、吞吐量等指标能说明什么、不能说明什么 | 指标读法与边界表 |
| P2T3-N04 | 判断覆盖类异常 | 根据覆盖指标和采样点判断弱覆盖、越区覆盖或覆盖不均衡风险 | 覆盖异常判断记录 |
| P2T3-N05 | 判断移动性/邻区异常 | 根据测量报告、目标小区、切换命令和掉话现象判断邻区或切换问题 | 移动性异常证据链 |
| P2T3-N06 | 归纳问题类型与原因链 | 把测试现象归入覆盖、干扰、切换、容量、体验等问题类型，并说明可能原因 | 异常问题清单 |
| P2T3-N07 | 制定整改建议 | 根据问题原因匹配工程、参数、邻区、功率或复测建议 | 整改建议卡 |
| P2T3-N08 | 输出分析报告并连接复测 | 把问题、依据、原因、建议和复测要求整理成分析报告 | 测试数据分析报告 |

## 5. 与P4-T2深样章的关系

P2-T3不是P4-T2的重复，而是P4-T2的前置能力来源。

| P2-T3节点 | 支撑P4-T2节点 | 关系说明 |
| --- | --- | --- |
| P2T3-N03 识读关键指标与判断边界 | P4T2-N03/N05 | 先学会指标含义和边界，后续才能判断优化是否达标 |
| P2T3-N04 判断覆盖类异常 | P4T2-N03 | 先学会发现覆盖问题，后续才能验证覆盖优化效果 |
| P2T3-N05 判断移动性/邻区异常 | P4T2-N04 | 先学会从日志和邻区关系判断移动性问题，后续才能验证切换优化结果 |
| P2T3-N06 归纳问题类型与原因链 | P4T2-N06 | 先学会整理依据链，后续才能判断哪些材料支持验收结论 |
| P2T3-N08 输出分析报告并连接复测 | P4T2-N07/N08 | 先学会分析报告表达，后续才能形成验收结论和职业表达 |

## 6. 资源与活动转化建议

P2-T3后续不宜直接复用原教材截图作为学生主学习材料。建议转化为以下资源：

1. **指标读法卡**：把PCI、SS-RSRP、SS-SINR、RSSI、RSRQ、吞吐量、CQI、MCS拆成“能说明什么、不能说明什么、常见误判”；
2. **LOG导入流程卡**：把软件操作转成通用流程，不绑定单一软件界面；
3. **覆盖异常判断表**：用模拟采样点和覆盖指标训练学生标出弱覆盖或覆盖不均衡；
4. **邻区漏配证据链卡**：用“测量报告上报、目标小区更优、无切换命令、掉话、配置检查”训练归因；
5. **问题类型分类互动**：把异常现象拖入覆盖、干扰、切换、容量、体验等类别；
6. **整改建议匹配互动**：让学生把问题原因匹配到新增邻区、调整天线、检查告警、调整功率、安排复测等建议；
7. **数据分析报告模板**：形成“问题现象、关键数据、原因判断、整改建议、复测要求”的职业表达框架。

## 7. 质量边界

本轮试拆仍是图谱方法验证，不是正式教学样章。

需要继续标注的风险：

1. 原教材涉及特定仿真软件界面，正式样章应重绘或通用化处理；
2. RSRP、SINR等阈值在不同场景、频段、运营商和测试口径下可能不同，不能把教材中的数值泛化为行业统一标准；
3. “邻区漏配”案例可作为教学案例，但正式进入教材前仍需通信专业教师复核；
4. 本轮只形成节点和资源活动评价设计，尚未形成学生端完整教材正文和可运行任务页面。

## 8. 本轮对V2的验证结论

P2-T3试拆说明，V2岗位工作过程图谱可以迁移到非P4-T2任务，且比目录映射更能揭示教材生产任务：

1. 它能把P2-T3从“测试数据分析”标题拆成8个可学习、可训练、可评价的能力节点；
2. 它能明确P2-T3与P4-T2之间的前置关系；
3. 它能指导资源改造：哪些截图需要重绘、哪些指标要做成卡片、哪些案例适合互动；
4. 它能形成评价产出：数据分析任务单、指标边界表、异常清单、整改建议卡、分析报告；
5. 它也暴露了后续工作量：如果要整本教材达到P4-T2深样章粒度，每个任务都需要类似的节点拆分、资源治理、教材正文和评价量规。

结论：V2方向可以继续作为课程能力图谱基线推进，但仍需通过更多任务试拆和专业复核来稳定节点粒度。
