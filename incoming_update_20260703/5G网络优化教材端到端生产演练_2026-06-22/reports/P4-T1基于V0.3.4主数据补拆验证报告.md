1. 验证 `AU-06 优化实施与变更记录` 能否从骨架层进入详细能力节点层；
2. 验证P4-T1这类“优化实施与工程变更类任务”是否能稳定回写V0.3.4主数据；
3. 验证V0.4风险治理字段能否覆盖参数变更、工程授权、责任边界、仿真软件截图、变更记录和复测交接风险；
4. 判断节点颗粒度是否合理，避免把天线、无线、承载、核心网知识点或软件按钮误升为能力节点。

本报告只给出内部试拆结论。通信专业复核、媒体审查、学生正文、平台发布和真实教学验证均未完成。

## 3. 原文质量诊断

### 3.1 可用部分

原文能够提供P4-T1的专业对象边界：天线、无线、承载网和核心网四类优化方向。它也提供了仿真软件界面、参数表、CSI-RS案例和优化前后效果变化，这些内容适合作为资源卡、活动材料、媒体重绘对象和评价产出来源。

### 3.2 主要问题

1. 知识准备体量大，容易把P4-T1写成天线、无线、承载、核心网知识汇编；
2. 任务实施部分以仿真软件截图为主，不能直接转成学生端正式教材；
3. 原文强调“查看调整参数”，但没有充分说明工程授权、责任边界、影响范围、回退条件和复测交接；
4. 经典案例能说明参数配置影响性能，但仍需专业复核，不能直接写成通用处方；
5. 任务测评偏概念问答，缺少可检查的岗位产出，如实施任务单、参数依据记录、变更记录和验证交接清单。

## 4. 节点拆分方案

本次将P4-T1补拆为6个详细能力节点：

| 节点 | 节点名称 | 核心产出 | 拆分理由 |
| --- | --- | --- | --- |
| P4T1-N01 | 明确优化对象与实施边界 | 优化实施任务单 | 先承接整改建议和参数异常清单，明确本次是否具备实施条件 |
| P4T1-N02 | 区分优化动作类型与责任边界 | 优化动作分类与责任边界表 | 把天线、无线、承载、核心网作为分支判断，不按四类对象直接拆节点 |
| P4T1-N03 | 读取关键参数与变更依据 | 参数依据记录表 | 训练学生从参数表或教学化截图中找依据，而不是背诵软件按钮 |
| P4T1-N04 | 制定实施步骤与风险回退检查 | 实施步骤与回退检查单 | 把优化动作组织成受控流程，并补充影响范围和回退条件 |
| P4T1-N05 | 记录实施结果与变更凭据 | 优化实施变更记录 | 让实施动作可追溯，为后续验收提供证据 |
| P4T1-N06 | 形成复测验证入口并交接P4-T2 | 复测验证交接清单 | 防止直接宣称优化成功，把实施记录转入结果验证 |

该拆法保留P4-T1的“实施闭环”，但把参数知识、仿真截图、具体软件操作和四类网络对象下沉到资源活动层。

## 6. V0.4风险治理判断

P4-T1需要新增的V0.4风险治理重点如下：

| 风险对象 | 治理判断 |
| --- | --- |
| 天线、无线、承载、核心网四类优化方向 | 作为分支资源和活动场景处理，不直接拆成四个能力节点 |
| 参数变更依据 | 必须说明适用范围、影响范围、回退条件和复测入口 |

| CSI-RS经典案例 | 可作为教学案例来源，但需专业复核，不能写成通用行业处方 |
| 复测交接清单 | 只能说明进入验证的材料和口径，不等于优化效果已经达标 |
