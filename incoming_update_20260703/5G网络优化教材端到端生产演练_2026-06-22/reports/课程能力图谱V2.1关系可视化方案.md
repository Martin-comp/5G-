# 课程能力图谱V2.1关系可视化方案

生成日期：2026-06-24  
对应样本：`samples/course_capability_graph_v2_relation_review/`  
对应边表：`reports/课程能力图谱V2关系边表.csv`

## 1. 问题判断

V2四任务链条版已经解决“节点有哪些、节点属于哪个任务和能力单元”的问题，但仍存在一个明显不足：节点之间的关联不够直观。

当前页面能读出P2-T3、P4-T2、P5-T3、P6-T2四个任务链条，也能点击节点查看详情；但如果要回答“这个节点为什么连接到下一个节点”“前面哪个节点支撑了这个判断”“未闭环问题如何回流到信令复盘”，仍需要读大量文字，不够图谱化。

因此，V2.1不再继续增加节点数量，而是专门解决“边”的呈现。

## 2. 设计目标

V2.1关系可视化评审版要解决三个问题：

1. 让人一眼看出四任务主链如何递进；
2. 点击任意节点后，能看到它的前置、后续、支撑、回流关系；
3. 所有关系都能回到结构化边表，便于后续治理、复核和平台化。

本轮仍是评审样本，不是正式产品界面，不同步到整书级整体原型。

## 3. 关系类型

关系边表统一为六类：

| 关系类型 | 含义 | 主要用途 |
| --- | --- | --- |
| 直接递进 | 完成前一节点后进入后一节点 | 表达学习顺序 |
| 前置基础 | 后一节点成立前必须具备前一节点产出 | 表达先修关系 |
| 支撑判断 | 前一节点为后一节点提供读数、证据、表达或判断支撑 | 表达跨任务支撑 |
| 问题回流 | 未闭环问题进入复盘、修正或二次验证 | 表达职业工作闭环 |
| 能力挂接 | 详细节点挂接到任务或能力单元 | 表达图谱治理关系 |
| 资源证据 | 图片、图表、案例或资料为节点提供证据 | 表达媒体和依据审查 |

## 4. 呈现策略

不采用“所有线同时铺开”的大网图。原因是四任务已有30个详细节点和182条关系边，全部显示会形成线团，反而看不清。

V2.1采用三层呈现：

1. **总览视图**：只显示四任务主链和关键跨任务关系，用于回答“整体怎么走”；
2. **节点邻域视图**：点击一个节点后，只显示与该节点直接相关的入边和出边，用于回答“这个节点为什么在这里”；
3. **关系清单视图**：以表格方式列出全部边，支持按关系类型筛选，用于治理和复核。

## 5. 页面结构

样本页面包含四个区域：

1. 顶部状态区：说明当前是V2.1关系评审版，不是专家复核版；
2. 左侧节点列表：按P2-T3、P4-T2、P5-T3、P6-T2分组展示30个详细节点；
3. 中间关系图：使用SVG连线展示当前筛选后的关系；
4. 右侧详情区：显示当前选中节点的入边、出边、关系说明和复核状态。

## 6. 数据来源

关系边表从四张V0.2字段表的`relation_records`字段抽取，并补充详细节点到能力单元的挂接关系：

1. `reports/P2-T3详细能力节点字段表V0.2.csv`
2. `reports/P4-T2详细能力节点字段表V0.2.csv`
3. `reports/P5-T3详细能力节点字段表V0.2.csv`
4. `reports/P6-T2详细能力节点字段表V0.2.csv`

生成结果为：

`reports/课程能力图谱V2关系边表.csv`

## 7. 质量门禁

1. 边表必须可解析，字段数一致；
2. 页面必须显示30个详细节点；
3. 页面必须能按关系类型筛选；
4. 点击P5T3-N06时必须能看到进入AU-10或P6任务的回流关系；
5. 点击P6T2-N07时必须能看到其作为AU-10评价产出的关系；
6. 页面不得把“内部试拆”写成“专家审核通过”；
7. 浏览器QA必须覆盖桌面端、移动端、节点点击、筛选、邻域关系和无横向溢出。

## 8. 后续边界

如果V2.1人工评审通过，再考虑把关系可视化能力同步到整书级整体原型；如果仍看不清，应优先优化关系类型、默认视图和节点邻域表达，而不是继续增加节点或资源。
