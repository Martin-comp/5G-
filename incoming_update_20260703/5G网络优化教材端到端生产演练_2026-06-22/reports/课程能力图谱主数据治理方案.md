# 课程能力图谱主数据治理方案

生成日期：2026-06-24  
适用范围：《5G网络优化教材（高级）》数字教材端到端生产演练  
当前版本：V0.3  
配套表：

- `reports/课程能力图谱节点主数据表V0.3.csv`
- `reports/课程能力图谱关系主数据表V0.3.csv`
- `reports/课程能力图谱资源活动评价挂接表V0.3.csv`
- `reports/课程能力图谱输入输出物治理清单V0.3.csv`

## 1. 结论

后续流程不宜直接继续做页面、卡片或资源样本，应先建立课程能力图谱主数据基线。

原因是：当前已经形成了输入教材、整书结构、P4-T2深样章、P2/P4/P5/P6四任务详细能力节点、V2.1关系边表、整体原型和多个前端样本。如果继续按页面或资源局部推进，容易出现三个问题：

1. 输入材料、AI补强内容和生成物之间缺少统一追踪；
2. 资源卡片、活动、评价和媒体审查可能脱离能力节点；
3. 整体原型会越来越像展示系统，而不是可生产、可审核、可更新的数字教材主数据系统。

因此，V0.3的定位不是最终专家定稿图谱，而是“可继续生产的图谱主数据基线”。后续新增资源、正文、互动、动画、小游戏、教师材料、评价记录和平台输出物，都应先能回写到该基线。

## 2. 为什么需要V0.3

前期成果已经证明：单个任务可以做出相对可读的数字教材样章，四任务关系也能初步呈现“数据分析 -> 结果验证 -> 持续提升 -> 信令复盘”的闭环。但这仍不足以支撑整本教材生产。

当前主要缺口在治理层：

| 问题 | 风险 | V0.3处理 |
| --- | --- | --- |
| 输入材料分散 | 不知道某个节点来自教材、标准、AI补强还是前端样本 | 建立输入输出物治理清单，记录来源、用途、复核状态 |
| 图谱版本分散 | V2优化版、V2.1关系版、整体原型各有数据 | 汇总为节点主数据表和关系主数据表 |
| 资源与节点挂接不稳定 | 卡片好看但无法说明训练哪项能力 | 建立资源、活动、评价挂接表 |
| 媒体风险容易被页面掩盖 | 原教材截图、仿真软件图、待重绘图可能被误当成可发布资源 | 在节点和挂接中保留媒体审查、重绘和风险字段 |
| 专业口径尚未外部复核 | AI生成或教学模拟案例可能被误认为专业定稿 | 保留专业复核状态，不把试拆内容写成已通过 |

## 3. V0.3中“完整”的含义

本阶段的“完整图谱”不能理解为全书18个任务都已达到专家定稿和课堂可用。更准确的说法是：建立整书范围的主数据框架，并把已验证到不同深度的内容统一纳入治理。

V0.3的完整性包括：

1. 整本教材有课程根节点、依据层、岗位工作过程、能力单元、课程主链、项目、任务、详细能力节点、资源活动节点；
2. 已试拆的P2-T3、P4-T2、P5-T3、P6-T2四个任务进入详细能力节点层；
3. 未详细试拆的任务保留为项目任务骨架，不伪装成已完成详细拆解；
4. 四任务之间的前置、递进、支撑判断、问题回流、能力挂接和资源证据关系进入关系主数据表；
5. 当前生成的样章、整体原型、关系评审工具和媒体池进入输入输出物治理清单；
6. 每个生成物都应能说明它绑定到哪个课程、项目、任务或能力节点。

V0.3不代表：

1. 不代表通信专业教师已复核所有指标、阈值、流程和案例；
2. 不代表所有原教材媒体都可以发布；
3. 不代表出版社平台接口已经正式确定；
4. 不代表整本教材正文、互动资源和教师材料已经全部生成；
5. 不代表课程能力图谱已经达到专家评审定稿。

## 4. 四张主数据表的职责

### 4.1 节点主数据表

文件：`reports/课程能力图谱节点主数据表V0.3.csv`

当前包含117个节点。节点覆盖课程根节点、依据层、岗位工作过程、能力单元、课程主链、项目、任务、详细能力节点、媒体资源节点和资源活动节点。

该表回答：

1. 这个对象是什么；
2. 它位于图谱哪一层；
3. 它归属哪个项目、任务、岗位过程和能力单元；
4. 学生要完成什么动作、形成什么产出；
5. 它的来源、成熟度、审核状态和风险是什么。

### 4.2 关系主数据表

文件：`reports/课程能力图谱关系主数据表V0.3.csv`

当前包含213条关系。关系覆盖课程主链递进、主链挂接项目、项目包含任务、四任务详细节点之间的递进、前置、支撑、回流、能力挂接和资源证据关系。

该表回答：

1. 哪个节点连接到哪个节点；
2. 连接关系是什么类型；
3. 这条关系用于课程结构、学习导航、判断支撑、问题回流还是资源证据；
4. 关系是否已经内部试拆，是否需要专业复核。

### 4.3 资源活动评价挂接表

文件：`reports/课程能力图谱资源活动评价挂接表V0.3.csv`

当前包含145条挂接记录。挂接对象包括资源卡片、学习活动、评价产出、媒体审查对象、整体原型中的资源和教师材料。

该表回答：

1. 某个资源、活动或评价绑定到哪个节点；
2. 它训练的学生动作是什么；
3. 它要求学生形成什么产出；
4. 它的审核状态和风险是什么；
5. 它是否只是教学模拟、待专业复核或待媒体审查。

### 4.4 输入输出物治理清单

文件：`reports/课程能力图谱输入输出物治理清单V0.3.csv`

当前包含10条记录。清单覆盖原始教材、抽取文本、任务清单、媒体池、四任务V0.2字段表、V2关系边表、3.5A-1样章、整体原型、V2.1关系评审工具和本V0.3治理方案。

该表回答：

1. 这是输入材料还是生成输出物；
2. 它在生产链中承担什么治理角色；
3. 它绑定到图谱哪个对象；
4. 它当前能否继续使用；
5. 下一步需要补什么、审什么或改什么。

## 5. 后续生产流程中的位置

V0.3把课程能力图谱放在输入治理之后、资源和页面生产之前。

建议流程如下：

```text
输入材料接收
-> 输入材料治理与质量诊断
-> 课程能力图谱主数据基线
-> 教材正文、资源卡片、活动、评价和媒体改造
-> 整体原型/出版社平台挂接页面
-> 标准封装、质量检测、发布与使用数据回收
-> 图谱和资源版本更新
```

该流程的核心规则是：后续任何正式进入生产的内容，都必须能挂到图谱主数据。没有图谱挂接的内容，可以作为草稿或探索材料，但不应进入正式资源包或数字教材呈现层。

## 6. 继续生产前的门禁

进入下一轮整体原型或资源生产前，建议至少满足以下门禁：

1. 每个输入材料都有来源、用途、当前状态和下一步处理方式；
2. 每个生成输出物都有图谱绑定，不再以“好看页面”替代能力节点说明；
3. 每个节点有稳定ID、层级、父级或归属、来源、成熟度、审核状态和风险；
4. 每个资源、学习活动、评价产出和教师材料都绑定到单一节点、任务节点或课程根节点；
5. 媒体风险、专业风险和待审状态保留在主数据中，不被前端样式掩盖；
6. 复合ID不进入主数据主键字段，多节点覆盖必须拆成多条挂接或挂到上级节点；
7. 未详细试拆的任务必须标注为结构占位，不能被误当成已完成资源生产；
8. 任何新增案例、表图、动画、小游戏和互动练习，都要先确定训练节点、学生动作、评价产出和审核状态。

## 8. 当前边界与风险

1. V0.3仍是内部试拆和治理基线，不能替代外部专家复核；
2. P2-T3、P4-T2、P5-T3、P6-T2已有详细能力节点，其余任务主要是结构骨架；
3. 现有图谱依据原教材、已有试拆、AI推理和前端样本综合生成，后续仍需对接课程标准、岗位标准、专业教师意见和出版社平台要求；
4. 教材正文、互动资源、动画、小游戏和教师材料尚未按全书批量生产；
5. 媒体治理仍是高风险项，原教材截图、仿真软件截图和抽取图片不能默认发布；
6. 平台接口、标准封装、使用数据回收和版本更新仍停留在设计层，尚未进入真实平台验证。

## 9. 下一步建议

下一步不建议立即扩大页面制作范围，而应先做一次V0.3主数据评审：

1. 先审四张V0.3表的字段是否足以承载后续生产；
2. 再审节点层级是否能支撑整本教材，而不是只服务P4-T2；
3. 然后选择一个未详细试拆的普通任务做小规模补拆，验证V0.3是否能承接新增节点、资源、活动和评价；
4. 同时制定“新增资源必须回写图谱”的执行规程；
5. 通过后，再继续整体数字教材原型的上层流转、图谱入口和资源中心优化。

如果V0.3表结构经评审基本成立，后续才适合进入“按图谱生产资源”和“按图谱组织整体数字教材呈现”的阶段。
