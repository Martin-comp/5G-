## 一、计划定位

本计划用于把朱启文专家反馈从“四条批注”转化为 clean preview 的平台级吸收方案。本计划不是页面修改记录，也不是最终实现稿；它定义下一轮原型修改前必须统一的架构、边界、流程、风险和验收标准。

本轮核心判断：

1. 专家反馈不是简单文案问题，而是平台结构问题；
2. clean preview 需要从“数字教材预览 + 资源/交付说明混合界面”调整为“教材呈现端 + AI教学组织层 + 素材/生产/交付子平台”的分层表达；
3. 教师端不应继续以“课前准备”为核心入口，应改为“AI生成任务组织、讲评和复核建议，教师审核确认”；
4. 资源页和交付页不应继续作为学生/教师主学习场景的同级导航，但资源卡片和交付逻辑不能删除；
5. 课程能力图谱需要从单页图谱扩展为整书、项目、任务三级映射结构；
6. P2-T3深样章必须在本计划明确后再推进，否则会沿用旧教师端和旧资源端结构。

## 二、处理范围与不处理范围

### 2.1 本轮处理范围

| 范围 | 处理内容 |
| --- | --- |
| clean preview一级导航 | 调整“资源”“交付”在教材呈现端中的位置，避免与课程、项目、图谱、教师并列造成主学习界面混乱 |
| 教师端 | 从“课前准备/教师带教”改为“AI任务组织、讲评与复核” |
| 图谱页 | 明确整书图谱、项目图谱、任务局部图谱的分层表达 |
| 教材内资源卡片 | 保留在教材呈现端，但必须通过能力图谱映射到节点、活动和评价产出 |
| 素材/生产/交付子平台 | 在当前阶段以设计边界和入口说明呈现，不开发独立后台 |

| QA与说明书 | 明确后续必须更新的QA脚本、截图和专家说明书 |

### 2.2 本轮不处理范围

1. 不真实开发素材子平台后台；
2. 不接入真实AI助手或真实学情数据；
3. 不接入出版社平台接口；
4. 不进行全书批量页面生产；
5. 不对5G专业阈值、案例数据和结论口径做最终专业复核；
6. 不把P4-T2样章写成真实一线教学验证通过；
7. 不进入生产工具链模块拆解。

## 三、平台三层架构

### 3.1 分层原则

后续 clean preview 应按三层表达：

| 层级 | 面向对象 | 承载内容 | 当前呈现方式 |
| --- | --- | --- | --- |
| 数字教材呈现端 | 学生、教师、评审专家 | 课程、项目、任务、图谱、学习活动、任务资源卡片、教学组织 | clean preview主界面 |
| AI教学组织层 | 教师、教研人员 | AI生成任务组织建议、课堂流程、讲评重点、复核清单，教师确认后执行 | 教师页和任务级教师页 |
| 素材/生产/交付子平台 | 出版社、平台建设人员、资源制作人员 | 素材治理、媒体审查、资源包封装、接口挂接、质量检测、版本发布 | 本轮只做入口和边界说明，不开发后台 |

### 3.2 必须保留的两种输出路线

本项目最初约定的输出包括两种：

1. 资源输出：生成结构化资源，由出版社平台上传、编辑和发布；
2. 直接呈现：生成可直接挂接到出版社平台的数字教材呈现层。

专家反馈要求资源治理进入素材子平台，不等于删除资源输出路线。后续页面要这样表达：

| 输出路线 | 前台是否展示 | 展示方式 |
| --- | --- | --- |
| 资源输出 | 不作为学生/教师主学习入口 | 在素材/生产/交付子平台边界中说明，保留资源ID、节点ID和资源包输出关系 |
| 直接呈现 | 作为教材呈现端主线 | 课程、项目、图谱、任务和教师组织页面直接呈现 |

## 四、主导航调整方案

### 4.1 当前问题

当前 `index.html` 顶部导航仍为：

1. 课程
2. 项目
3. 图谱
4. 教师
5. 资源
6. 交付

当前 `app.js` 中还存在：

1. `resourceFilters`
2. `renderResources()`
3. `renderPublish()`
4. `资源上下文`
5. `交付上下文`

这与专家反馈存在冲突：资源治理和交付检查不应作为学生/教师主学习界面的同级入口。

### 4.2 建议的新导航结构

正式教材呈现端顶部导航建议调整为：

1. 课程
2. 项目
3. 图谱
4. 教师

辅助入口建议放入右上角或页尾“平台支持”区域，不作为主导航：

1. 任务资源
2. 素材子平台
3. 交付说明

说明：

1. “任务资源”只展示与当前学习任务相关的教材内资源卡片；
2. “素材子平台”只说明素材治理、媒体审查、资源包封装属于后台；
3. “交付说明”只作为出版/平台交付边界说明，不进入学生学习路径。

### 4.3 不建议的做法

1. 不建议直接删除所有资源页面，因为会破坏资源输出路线；
2. 不建议保留“资源”“交付”作为顶级学习导航，因为会继续造成主线混乱；
3. 不建议把素材子平台写成已经真实开发完成；
4. 不建议把交付说明混入学生学习任务页。

## 五、教师端AI任务组织、讲评与复核流程

### 5.1 当前问题

当前 `app.js` 中教师流程仍包含：

```text
teacherFocus: "prepare"
课前准备
确定项目、任务、资源和学生产出
```

当前P4-T2任务页中也仍保留“教师带教”表达。专家反馈要求去掉“课前准备”的传统手工备课感，改为AI给出组织建议，教师认可后执行。

### 5.2 新教师端定位

教师端主标题建议统一为：

```text
任务组织、讲评与复核
```

副标题建议：

```text
AI预生成任务组织、课堂讲评和复核建议，教师审核确认后形成可执行教学安排。
```

### 5.3 教师端流程

建议教师端改为五步：

| 步骤 | 名称 | AI生成内容 | 教师动作 | 输出 |
| --- | --- | --- | --- | --- |
| 1 | 任务组织建议 | 学习目标、任务链、课堂节奏、资源调用建议 | 审核、调整、确认 | 任务组织方案 |
| 2 | 课堂推进建议 | 提问脚本、示范顺序、练习节点、时间建议 | 选择适用版本 | 课堂执行方案 |
| 3 | 学情讲评建议 | 模拟或真实错误分布、讲评优先级、二次学习路径 | 确认讲评重点 | 讲评脚本 |
| 4 | 专业复核建议 | 指标阈值、结论口径、风险边界、待复核项 | 判断是否采用 | 复核清单 |
| 5 | 作业验收建议 | 产出要求、评分点、常见错误、补交要求 | 发布或修改 | 验收规则 |

### 5.4 责任边界

必须明确：

1. AI生成建议，不直接替代教师决策；
2. 教师负责确认课堂组织、专业口径、讲评结论和作业验收；
3. 专业阈值、案例数据和结论口径仍需通信专业教师或行业专家复核；
4. 没有真实学习数据时，学情只能写为“模拟学情示例”。

## 六、素材子平台边界与前后台资源映射

### 6.1 前台保留内容

教材呈现端必须保留：

1. 当前任务使用的学习资源；
2. 教师组织课堂需要调用的资源；
3. 图谱节点到资源卡片的映射关系；
4. 学生使用资源后形成的评价产出；
5. 资源卡片跳转到任务或节点的能力。

### 6.2 后台转移内容

素材/生产/交付子平台承载：

1. 原始素材入库；
2. 图片、软件截图、仿真界面版权审查；
3. 媒体重绘和替换；
4. 资源包封装；
5. 出版社平台接口挂接；
6. 质量检测；
7. 版本发布、回滚和追溯。

### 6.3 必须建立的统一ID

为避免素材子平台形成数据孤岛，后续至少需要以下ID：

| ID | 用途 |
| --- | --- |
| `node_id` | 课程能力图谱节点 |
| `resource_id` | 教材内资源卡片 |
| `source_asset_id` | 原始素材或媒体对象 |
| `activity_id` | 学习活动 |
| `output_id` | 学习产出或评价产出 |
| `package_id` | 资源包或交付包 |
| `version_id` | 版本与更新追溯 |

### 6.4 当前原型中的处理方式

当前阶段不开发独立后台。clean preview 中可采用：

1. 前台“任务资源”只展示资源卡片和图谱映射；
2. “素材子平台”以说明性入口呈现，说明资源治理在后台完成；
3. 治理评审版 `overall-0.5` 保留详细风险、发布门禁和资源状态；
4. clean preview 只保留必要边界提示，不展示内部审核流程。

## 七、课程能力图谱三级映射图形

### 7.1 分层目标

专家要求采用能力图谱映射图形，不能只停留在资源表格或节点清单。后续采用三级图谱：

| 图谱层级 | 使用对象 | 表达重点 | 进入位置 |
| --- | --- | --- | --- |
| 整书图谱 | 专家、教师、学生浏览整书 | 课程主链、项目承接、重点路径 | 图谱页 |
| 项目图谱 | 教师、学生进入项目 | 项目任务链、前后任务、关键能力节点 | 项目页、图谱页 |
| 任务局部图谱 | 学生学习任务、教师组织课堂 | 当前任务能力节点、资源卡片、学习活动、评价产出 | P4-T2、P2-T3任务页 |

### 7.2 图谱表达原则

1. 学生端默认看到任务局部图谱，不直接暴露完整主数据图谱；
2. 教师端可展开项目图谱和任务局部图谱；
3. 专家评审可查看整书图谱；
4. 每个资源卡片必须说明挂接节点、学习活动和评价产出；
5. 点击节点应能定位资源卡片；
6. 点击资源卡片应能反向定位节点；
7. 图谱说明语言必须教材化，不能暴露后台字段名和审核字段。

### 7.3 P4-T2示例

P4-T2任务局部图谱建议表达为：

```text
识别验证场景
  -> 区分改善与达标
  -> 读覆盖/移动性/体验容量指标
  -> 选择判断依据
  -> 形成验收结论
  -> 修正职业表达
```

每个节点挂接：

1. 学习材料；
2. 表格或互动；
3. 学生活动；
4. 评价产出；
5. 教师讲评点；
6. 专业复核点。

### 7.4 P2-T3前置要求

P2-T3任务局部图谱在实施计划中必须先设计，不能等页面制作后再补。至少应覆盖：

1. 明确分析任务与数据来源；
2. 导入与整理测试数据；
3. 识读关键指标；
4. 判断覆盖、移动性或邻区异常；
5. 归纳问题类型和原因链；
6. 制定整改建议；
7. 输出分析报告并连接复测。

## 八、对P4-T2深样章的影响

P4-T2当前仍是唯一任务级深样章样本，不能因为专家反馈而直接废弃。但需要做以下调整：

| 模块 | 当前问题 | 调整方向 |
| --- | --- | --- |
| 教师端标题 | “教师带教”仍偏传统教学提示 | 改为“任务组织、讲评与复核” |
| 课前准备 | 容易被理解为教师手工准备 | 改为AI生成任务组织建议，教师确认 |
| 任务资源 | 仍偏资源页/清单表达 | 改为任务局部图谱映射资源卡片 |
| 学情讲评 | 模拟学情已有，但AI讲评建议不够明确 | 增加AI生成讲评建议与教师确认流程 |
| 专业复核 | 已有提示，但与AI建议关系不清 | 明确AI建议不能替代专业复核 |
| 返回整书 | 已可返回 | 保持不变 |

P4-T2不需要重做学生正文；本轮主要影响教师端、任务资源端和局部图谱。

| 资源/交付被过度删除，导致资源输出路线消失 | 高 | 不删除资源输出路线，只把资源治理转入素材子平台；教材端保留资源卡片 |

| P4-T2重构范围过大 | 中 | 学生正文不重做，优先改教师端、任务资源和局部图谱 |
| P2-T3继续沿用旧结构 | 中高 | P2-T3计划必须引用本计划作为前置依据 |

| 专家说明书与原型不一致 | 中 | 原型QA通过后再更新说明书 |
| 治理版与clean preview混淆 | 中 | overall-0.5继续作为治理版，clean preview只做呈现观察版 |

## 十四、验收标准

本计划通过后，下一轮原型修改的验收标准为：

1. 顶部主导航不再把资源治理和交付检查作为学生/教师主学习场景；
2. 教师页主身份改为任务组织、讲评与复核；
3. 教师页明确AI生成建议、教师审核确认；
4. 教材端保留资源卡片，但资源治理进入素材子平台边界；
5. 图谱至少表达整书、项目、任务三级关系中的两个层级，任务局部图谱必须覆盖P4-T2；
6. 资源卡片能映射到能力节点、学习活动和评价产出；
7. P4-T2任务页不再把任务资源表达为后台资源清单；
8. P2-T3实施计划前置要求明确；
9. QA脚本更新并通过；
10. 专家说明书后续版本与原型一致；
11. 治理文件同步，不出现“当前下一步”冲突。

## 十五、当前结论

下一步不是直接改页面，也不是直接做P2-T3。应先以本计划为依据，开展一次内部评审。评审通过后，再进入 clean preview 原型修改；原型修改和QA通过后，再回到P2-T3任务级深样章实施计划。
