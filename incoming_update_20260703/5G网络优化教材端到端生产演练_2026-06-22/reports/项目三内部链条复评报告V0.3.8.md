## 4. 链条复评

### 4.1 P3-T1到P3-T2

当前关系：

`P3-T1 -> P3T2-N01`

关系含义：网管架构和功能认知是理解账号权限和监控边界的前置基础。

判断：方向成立，但P3-T1仍是任务骨架。当前它可以作为项目三入口认知节点支撑P3-T2，但不能提供细粒度资源、活动和评价支撑。

建议：暂不强制立即补P3-T1。它是项目三剩余缺口，但优先级应通过第九类候选矩阵和其他项目候选客观比较后决定。

### 4.2 P3-T2内部链条

P3-T2内部链条为：

1. 明确监控任务与账号权限边界。
2. 筛选当前告警并判断优先级。
3. 追溯历史告警与典型案例线索。
4. 创建或选择性能指标查询模板。
5. 查询指标并识别异常变化。
6. 结合日志形成监控结论与后续入口。

判断：结构成立。它围绕运行监控形成“权限边界、告警、指标、日志、结论分流”的职业动作链，没有退化为软件按钮清单。

保留问题：P3T2-N06的分流规则仍需通信专业复核。

### 4.3 P3-T2到P3-T3

关键关系：

1. `P3-T2 -> P3T3-N01`：运行监控发现异常后进入参数检查场景和对象确认。
2. `P3T2-N06 -> P3T3-N01`：监控结论发现参数或配置疑点后进入参数检查场景确认。

判断：这是项目三较稳定的内部链条。任务级关系和详细节点级关系同时存在，能够表达“先监控发现问题，再进入参数检查”的逻辑。

建议：保留两级关系。任务级关系作为项目流程表达，详细节点级关系作为学习活动和评价产出连接。

### 4.4 P3-T3内部链条

P3-T3内部链条为：

1. 明确参数检查场景与检查对象。
2. 识读容量、覆盖与功率参数口径。
3. 完成无线侧参数查询、导出与差异比较。
4. 完成传输侧参数查询与承载参数核对。
5. 完成核心网参数查询与业务控制参数核对。
6. 形成参数异常清单与后续处理建议。

判断：结构仍有效。无线、传输、核心网三类检查对象保持并列分支，没有被错误写成单一路径。

保留问题：P3-T3涉及参数、公式、QoS、核心网控制类参数和网管截图，专业复核和媒体审查仍未完成。

### 4.5 P3-T3到P3-T4

关键关系：

1. `P3T3-N03 -> P3T4-N02`：无线侧参数差异检查结果支撑参数对象和影响范围识别。
2. `P3T3-N06 -> P3T4-N01`：参数异常清单进入参数设置任务和变更依据判断。
3. `P3T2-N06 -> P3T4-N01`：监控结论确认需要参数设置或调整时进入参数设置任务。

判断：V0.3.8中该链条比V0.3.7明显增强。P3-T4不再只是任务骨架，已经能承接变更依据、参数对象、邻区方案、教学仿真操作、回退条件和复测交接。

保留问题：P3T4-N04和P3T4-N06仍是高风险节点，必须保留专业复核、工程授权、媒体审查和教学仿真边界门禁。

### 4.6 P3-T4内部链条

P3-T4内部链条为：

1. 明确参数设置任务与变更依据。
2. 识别参数对象与影响范围。
3. 制定邻区添加、删除或调整方案。
4. 完成教学仿真参数设置并记录证据。
5. 核查设置结果、风险与回退条件。
6. 形成参数变更记录并衔接复测。

判断：结构成立。该链条没有把P3-T4写成真实生产网管操作教程，而是把操作动作纳入教学仿真、证据记录、回退判断和复测交接框架。

保留问题：若后续没有合适教学仿真或教学化重绘界面，N04需要降级为“识读操作证据”或“填写操作记录”，不能强行写成真实操作训练。

### 4.7 项目三到项目四、项目五、项目六

当前跨项目关系包括：

1. P3-T4变更依据和操作证据支撑P4-T1优化实施边界确认。
2. P3-T4参数变更记录和复测交接支撑P4-T2验证场景识别。
3. P3-T4设置结果、未闭环问题和持续观察需求连接P5-T3。
4. P3-T4复杂或未闭环问题可进入P6-T2信令复盘。

判断：跨项目关系方向基本成立，但多数仍是待专业复核。当前阶段可以保留，不应过度扩展。

## 5. 主要问题

### 5.1 P3-T1仍是项目三剩余骨架

P3-T1对项目三入口有价值，但目前尚未拆成详细能力节点。它可能涉及网管架构、功能分区、系统角色、权限边界和平台认知等基础内容。

当前不建议为了追求项目三“看起来完整”而立即补拆P3-T1。是否补P3-T1，应与P6-T1、P5-T1、P1-T1等剩余候选任务一起进入候选矩阵比较。

### 5.2 P3-T4高风险节点不能过度生产化

P3T4-N04和P3T4-N06必须严格保留边界：

1. 教学仿真不等于真实网管授权。
2. 操作记录不等于优化成功。
3. 参数变更不等于工程闭环。
4. 复测交接不等于专业诊断已完成。

### 5.3 项目三风险具有共同性

项目三共同风险包括：

1. 网管账号和权限。
2. 操作日志和安全日志。
3. 参数检查和参数设置专业口径。
4. 真实网管截图。
5. 厂家系统差异。
6. 工程授权边界。
7. 告警、指标和参数口径的专业边界。

后续进入页面或资源生产前，项目三应统一形成媒体审查和风险门禁清单，不能只按任务分散处理。

建议进入第九类候选选择，但仍应保留候选矩阵步骤。

理由：

1. 项目三主链已经从P3-T2、P3-T3推进到P3-T4，当前最明显缺口不再是P3-T4。

3. 候选矩阵可以防止后续因上下文压缩把“想补P3-T1”误当成已论证结论。
4. 图谱阶段仍需要继续用有限增量验证不同任务类型，不能只在项目三内部打转。
