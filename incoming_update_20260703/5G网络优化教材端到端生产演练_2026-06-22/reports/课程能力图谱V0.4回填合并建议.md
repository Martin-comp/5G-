生成日期：2026-06-25  
建议对象：三任务V0.4字段回填样表与V0.3.3课程能力图谱主数据  
依据文件：

1. `reports/课程能力图谱节点主数据表V0.3.3.csv`
2. `reports/课程能力图谱关系主数据表V0.3.3.csv`
3. `reports/课程能力图谱资源活动评价挂接表V0.3.3.csv`
4. `reports/课程能力图谱输入输出物治理清单V0.3.3.csv`
5. `reports/课程能力图谱字段规范V0.4升级方案.md`
6. `reports/课程能力图谱字段规范V0.4字段清单.csv`

9. `reports/P4-T2_V0.4字段回填样表.csv`
10. `reports/课程能力图谱V0.4字段回填结构校验记录.md`
11. `reports/课程能力图谱V0.4字段回填试验内部评审报告.md`

## 1. 结论

建议采用“旁挂式风险治理扩展表”方案。

当前不建议把三张46列V0.4回填样表直接合并进V0.3.3节点主表、关系主表、资源活动评价挂接表或输入输出物治理清单。更稳妥的做法是：

1. V0.3.3继续作为当前推荐课程能力图谱主数据基线；
2. V0.4先形成独立的风险治理扩展层；
3. V0.4扩展层通过 `source_table`、`source_record_id`、`task_id`、`object_level` 回挂到V0.3.3主数据对象；
4. 只有经过更多任务验证后，才考虑把少量稳定摘要字段回写进主表。

本轮合并建议的直接下一步应是生成：

`reports/课程能力图谱风险治理扩展表V0.4.csv`

该表不替代V0.3.3四张主表，而是作为主表之外的治理侧表。

## 2. 为什么不直接并入V0.3.3主表

### 2.1 主表职责会被冲淡

V0.3.3四张主表已经有清晰职责：

| 主表 | 当前职责 | 是否适合直接承载39个V0.4字段 |
| --- | --- | --- |
| 节点主数据表 | 表达课程、项目、任务、能力节点和学习产出 | 不适合全量承载 |
| 关系主数据表 | 表达节点之间的递进、支撑、回流、挂接关系 | 当前不适合承载 |
| 资源活动评价挂接表 | 表达资源、活动、评价与能力节点的挂接 | 部分适合，但不宜全量承载 |
| 输入输出物治理清单 | 表达输入材料和输出成果的资产治理状态 | 适合作为资产登记，不适合承载每条资源门禁 |

V0.4字段覆盖数据安全、客户授权、服务承诺、媒体重绘、学生正文、平台接口、教学验证和发布门禁。这些字段不是图谱结构本身，而是生产治理状态。如果全量塞进主表，主表会从“能力图谱主数据”变成“图谱、资源、媒体、法律、平台、教学验证混合表”，后续维护成本会很高。

### 2.2 当前V0.4还只是三任务试验

本轮V0.4回填覆盖：

| 样表 | 行数 | 来源表分布 | 对象层级 |
| --- | ---: | --- | --- |
| P1-T3 | 22 | 节点5，挂接17 | 详细能力节点、资源卡、评价产出 |
| P3-T3 | 28 | 节点6，挂接22 | 详细能力节点、资源卡、评价产出、媒体审查 |
| P4-T2 | 55 | 节点8，挂接47 | 详细能力节点、资源卡、评价产出、媒体审查、整体原型资源 |

三任务共105行，能够证明字段有效，但还不能证明字段已经适合全书18个任务、全部资源形态和出版社平台接口。因此当前应先形成扩展表，而不是升级主表结构。

### 2.3 V0.4多数门禁仍处于未完成状态

三张样表的 `overall_publish_gate_status` 全部为 `not_ready`。这不是缺陷，而是符合当前事实：专业复核、编辑复核、数据安全审核、媒体审查、平台接口验证和真实教学验证均未完成。

如果把这些状态直接合进主表，容易让后续人员误以为V0.4已经是新的主数据正式版本。更稳妥的表达是：V0.4是风险治理扩展层，当前用于门禁识别和后续处理，不代表内容已可发布。

## 3. 推荐数据结构

### 3.1 保持V0.3.3四张主表不变

当前阶段不修改以下文件：

1. `reports/课程能力图谱节点主数据表V0.3.3.csv`
2. `reports/课程能力图谱关系主数据表V0.3.3.csv`
3. `reports/课程能力图谱资源活动评价挂接表V0.3.3.csv`
4. `reports/课程能力图谱输入输出物治理清单V0.3.3.csv`

原因是V0.3.3已经通过结构和版本化合并门禁，是当前推荐基线。V0.4应先通过扩展表与它建立关系。

### 3.2 新增一张风险治理扩展表

建议新增：

`reports/课程能力图谱风险治理扩展表V0.4.csv`

建议字段结构为：

```text
7个定位字段 + 39个V0.4字段
```

其中7个定位字段沿用回填样表：

| 字段 | 作用 |
| --- | --- |
| `backfill_record_id` | V0.4扩展记录唯一ID |
| `source_table` | 指向V0.3.3哪类主数据对象 |
| `source_record_id` | 指向V0.3.3主数据记录ID |
| `task_id` | 所属任务 |
| `object_level` | 治理对象层级 |
| `object_title` | 治理对象标题 |
| `source_risk_summary` | 从V0.3.3继承或补充的风险摘要 |

39个V0.4字段保持字段清单中的定义，不在本轮压缩或删减。

### 3.3 `source_table`映射规则

建议统一使用以下映射：

| `source_table`值 | 对应V0.3.3主数据 | 当前样表是否已有 |
| --- | --- | --- |
| `node_master` | `课程能力图谱节点主数据表V0.3.3.csv` | 有 |
| `binding_master` | `课程能力图谱资源活动评价挂接表V0.3.3.csv` | 有 |
| `edge_master` | `课程能力图谱关系主数据表V0.3.3.csv` | 暂无 |
| `asset_governance` | `课程能力图谱输入输出物治理清单V0.3.3.csv` | 暂无 |

本轮三任务样表只覆盖 `node_master` 和 `binding_master`。不应为了形式完整而强行生成 `edge_master` 或 `asset_governance` 记录。后续只有当某条关系本身存在发布、隐私、平台或教学验证风险时，才需要给关系生成V0.4扩展记录。

### 4.3 暂不作用于关系表的字段

关系表当前表达的是图谱关系，不是内容发布对象。除非关系本身要作为学生端可见解释、平台跳转逻辑或评价路径发布，否则暂不需要给每条关系生成V0.4治理字段。

本轮建议：

1. 不修改 `课程能力图谱关系主数据表V0.3.3.csv`；
2. 不生成关系类V0.4扩展记录；
3. 后续若整体原型或出版社平台把关系解释作为学生端内容展示，再为相关关系补充 `edge_master` 类型治理记录。

## 5. 合并流程建议

### 5.1 第一阶段：生成扩展表

将三张回填样表合并为：

`reports/课程能力图谱风险治理扩展表V0.4.csv`

合并规则：

1. 保留全部46列；
2. 保留原 `backfill_record_id`；
3. 不改变三张样表中的门禁状态；
4. 不把 `not_ready` 改写成 `approved` 或 `passed`；
5. 不补造 `edge_master` 或 `asset_governance` 记录；
6. 合并后总行数应为105行；
7. `source_record_id` 必须能回溯到V0.3.3节点表或挂接表；
8. `overall_publish_gate_status` 应全部保持 `not_ready`。

### 5.2 第二阶段：形成扩展表校验记录

建议同步生成：

`reports/课程能力图谱风险治理扩展表V0.4校验记录.md`

最低校验项：

| 校验项 | 通过条件 |
| --- | --- |
| CSV解析 | 可被结构化读取 |
| 字段一致性 | 46列完整，顺序一致 |
| 唯一ID | `backfill_record_id` 无重复 |
| 来源表合法 | `source_table` 只出现允许值 |
| 外键有效 | `source_record_id` 可回溯到对应V0.3.3主数据 |
| R1完整 | R1字段无空值 |
| 枚举合法 | 枚举值在V0.4字段清单允许范围内 |
| 发布门禁 | 不出现 `overall_publish_gate_status=approved` |
| 教学验证 | 不出现 `teaching_validation_gate_status=passed` |
| 平台门禁 | 不出现 `platform_gate_status=passed` |

### 5.3 第三阶段：更新输入输出物治理清单

在扩展表和校验记录形成后，建议不要直接重写V0.3.3输入输出物治理清单，而是先新增V0.4阶段治理记录。可以采用增量治理清单方式，后续再进入V0.4总账。

建议新增资产记录包括：

1. `课程能力图谱风险治理扩展表V0.4.csv`
2. `课程能力图谱风险治理扩展表V0.4校验记录.md`
3. `课程能力图谱V0.4回填合并建议.md`

## 6. 对后续生产流程的影响

### 6.1 对课程能力图谱的影响

课程能力图谱主链、节点、关系暂不因V0.4改变。V0.4只回答每个节点、资源、评价对象是否存在风险、需要谁复核、能否发布、下一步做什么。

因此后续图谱生产应形成两层数据：

```text
图谱结构层：V0.3.3主数据
风险治理层：V0.4风险治理扩展表
```

只有同时满足两层条件的对象，才可以进入正式资源生产或数字教材呈现层。

### 6.2 对资源生产的影响

资源生产前必须先查询V0.4风险治理扩展表。

建议规则：

| 场景 | 处理 |
| --- | --- |
| `overall_publish_gate_status=not_ready` | 不进入正式发布资源 |
| `media_gate_status=revision_required` | 先进入媒体重绘或标注流程 |
| `data_security_gate_status=pending` | 先进入脱敏、授权或数据安全审核 |
| `student_text_gate_status=review_pending` | 先进入教材正文审读 |
| `platform_gate_status=not_started` | 不做出版社平台挂接承诺 |
| `teaching_validation_gate_status=internal_review` | 只能写作内部评审，不能写成一线验证通过 |

### 6.3 对页面和平台的影响

当前仍不建议进入页面生产或平台对接。理由不是页面不能做，而是V0.4已经证明大量内容处于 `not_ready`。如果没有风险治理扩展表，页面会把未审内容包装成“看起来可用”的教材。

下一轮页面或整体原型只能在以下条件后启动：

1. V0.4风险治理扩展表生成并校验通过；
2. 关键媒体对象完成重绘或替代策略；
3. 学生正文门禁至少完成内部审读；
4. 平台接口字段和出版社挂接方式有明确边界；
5. 不把内部评审样本写成正式发布教材。

## 7. 当前不建议做的事

1. 不建议直接把46列V0.4字段并入V0.3.3节点主表；
2. 不建议直接把46列V0.4字段并入资源活动评价挂接表；
3. 不建议为了形成“完整V0.4”而补造关系表或资产表回填记录；
4. 不建议把V0.4回填试验写成“已具备规模化生产能力”；
5. 不建议立即选择第四个任务继续扩展；
6. 不建议立即进入数字教材页面生产、正式资源包生产或工具链模块拆解。

## 8. 下一步建议

建议下一步执行：

1. 生成 `reports/课程能力图谱风险治理扩展表V0.4.csv`；
2. 生成 `reports/课程能力图谱风险治理扩展表V0.4校验记录.md`；
3. 更新治理文件和成果索引；
4. 对扩展表进行一次短内部复核；
5. 复核通过后，再判断是否选择第四类任务做增量验证。

是否继续第四类任务的判断标准不是“还能不能拆”，而是：

1. V0.4扩展表是否能稳定挂接V0.3.3主数据；
2. 风险对象是否能被准确筛选；
3. 门禁是否能阻断误发布；
4. 后续处理责任是否足够明确；
5. 是否仍存在大量只能靠备注解释的风险。

如果以上条件通过，再做第四类任务验证才有意义。
