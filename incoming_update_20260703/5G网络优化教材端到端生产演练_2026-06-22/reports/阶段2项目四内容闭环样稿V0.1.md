## 1. 项目四学习导入

网络优化不是“看到一个指标不好，就马上改一个参数”。在真实工作中，优化通常要经历三步：先确认问题和实施边界，再用证据判断优化后是否达到目标，最后把实施过程、验证结果和未闭环问题写成别人能复核的报告。

本项目用一条完整路线训练这件事：

```text
优化方案实施
-> 优化结果验证
-> 优化报告输出
```

你在本项目中要形成三类成果：

1. 一份能说明“为什么这样实施、做了什么、还要复测什么”的优化实施记录；
2. 一段能说明“哪些已经达标、哪些只是改善、哪些仍未闭环”的验收结论；
3. 一份能把证据、边界和建议讲清楚的优化报告样稿。

注意：本项目中的案例用于学习，不代表可以直接操作真实网络。涉及参数变更、客户沟通、站点信息和外部发布的内容，都需要教师、企业导师或专业人员复核。

## 2. P4-T1 任务1：5G网络优化方案实施

### 2.1 学习情境

某高校宿舍区近期出现“晚上网速慢、视频卡顿、个别楼层信号不稳定”的反馈。前序测试和数据分析已经给出初步建议：部分区域可能存在覆盖边界问题，晚高峰容量压力较大，少量小区参数可能需要复核。

你不是马上去“改参数”。你首先要判断：这次优化到底针对什么问题？哪些动作可以在教学模拟中训练？哪些动作必须有工程授权？哪些材料要留给后续复测验证？

### 2.2 第一件事：确认优化对象和实施边界

先把问题说清楚。一个合格的优化实施任务单，不能只写“优化宿舍区网络”，而要写出更具体的对象：

| 项目 | 示例写法 |
| --- | --- |
| 问题现象 | 晚高峰视频卡顿，部分楼层弱覆盖，用户反馈集中在宿舍区北侧。 |
| 前序依据 | 投诉记录、DT/CQT测试摘要、关键KPI变化、参数异常清单。 |
| 本次优化对象 | 覆盖边界、容量压力、疑似参数配置问题。 |
| 不能直接操作的内容 | 未授权参数变更、真实网络割接、客户承诺、未经脱敏的站点截图。 |
| 后续验证入口 | 优化前后覆盖、接入、保持、体验和容量指标对比。 |

学习重点不是把表填满，而是让每一项都能解释“为什么要这样做”。如果你写不出依据，就不能把动作写成确定实施项。

### 2.3 第二件事：区分优化动作类型和责任边界

同样是“优化”，背后的动作可能完全不同。

| 动作类型 | 学习中可以训练什么 | 必须保留的边界 |
| --- | --- | --- |
| 天线类优化 | 根据覆盖问题判断是否需要调整方向角、下倾角等思路。 | 真实天线调整涉及工程条件、安全条件和现场授权。 |
| 无线参数优化 | 阅读教学化参数表，判断参数与现象之间的关系。 | 真实参数变更必须由授权岗位执行，不能把案例写成通用处方。 |
| 承载网相关优化 | 识别传输、带宽、拥塞等可能影响业务体验的线索。 | 不能凭无线侧单项数据直接判断承载网问题。 |
| 核心网相关优化 | 理解核心网配置或策略可能影响业务体验。 | 需要更高层级数据支撑，教学案例只能做边界说明。 |

这一页适合做成“分类拖拽卡”或“责任边界判断卡”。学生不是回答概念题，而是把案例中的优化建议放到对应类型，并说明谁可以做、凭什么做、做完后怎么验证。

### 2.4 第三件事：读取关键参数和变更依据

参数表不是用来背的，是用来找证据的。学生看到参数或教学化界面时，要先问四个问题：

1. 这个参数和当前问题有没有关系；
2. 当前值为什么值得关注；
3. 建议动作能解决什么问题；
4. 还缺哪些复核信息。

示例记录：

| 参数或证据 | 当前观察 | 可能影响 | 建议动作 | 仍需复核 |
| --- | --- | --- | --- | --- |
| 覆盖相关配置 | 北侧楼宇边缘区域弱覆盖明显。 | 影响RSRP和用户驻留稳定性。 | 检查覆盖方案，评估是否需要调整覆盖方向或补充覆盖。 | 需现场或仿真复核，不能直接下实施结论。 |
| 容量相关指标 | 晚高峰PRB利用率偏高。 | 可能影响速率和体验稳定性。 | 评估容量均衡或负载相关策略。 | 需结合用户数、业务量和邻区情况判断。 |
| 切换相关记录 | 个别移动路径出现切换失败。 | 可能导致移动中卡顿或掉线。 | 检查邻区、切换门限或覆盖重叠关系。 | 需结合信令或路测轨迹复核。 |

这里的资源不建议直接使用原教材仿真软件截图。正式学生端应优先使用重绘后的教学参数表、简化流程图或可标注的指标表。

### 2.5 第四件事：制定实施步骤和回退检查

实施步骤不能写成“调整参数，保存，完成”。更合格的写法应体现受控流程：

```text
确认实施对象
-> 核对依据材料
-> 标记影响范围
-> 明确授权和复核人
-> 执行教学模拟调整
-> 记录变更前后状态
-> 设置回退条件
-> 提交复测验证入口
```

示例检查单：

| 检查项 | 学生应填写的内容 |
| --- | --- |
| 实施前依据 | 来自哪一份测试、投诉、参数或验证材料。 |
| 影响范围 | 影响哪个区域、哪类用户、哪类业务或哪个指标。 |
| 授权边界 | 教学模拟、教师复核、企业导师复核或真实工程授权。 |
| 回退条件 | 哪些异常出现时需要回退或停止继续实施。 |
| 复测要求 | 优化后需要重新采集哪些指标，按什么口径比较。 |

### 2.6 第五件事：记录实施结果并交接验证

优化实施不能以“感觉变好了”结束。你必须把做过什么、为什么做、做完后怎么验证记录下来。

最小产出是两份表：

**优化实施变更记录**

| 记录项 | 示例 |
| --- | --- |
| 变更对象 | 宿舍区北侧覆盖边界相关配置，教学模拟。 |
| 变更依据 | 前序测试显示北侧楼宇边缘区域覆盖弱，用户反馈集中。 |
| 变更前状态 | 覆盖指标未稳定达标，晚高峰体验波动。 |
| 变更动作 | 调整覆盖方案或参数策略的教学模拟。 |
| 变更后待验证 | 覆盖、接入、保持、体验、容量指标是否改善并达标。 |
| 异常备注 | 若容量或切换仍异常，不能写成整体优化成功。 |

**复测验证交接清单**

| 交接项 | 示例 |
| --- | --- |
| 验证场景 | 宿舍区北侧楼宇、晚高峰、移动路径。 |
| 需复测指标 | 覆盖、接入成功率、保持能力、平均速率、边缘用户体验。 |
| 对比口径 | 优化前后同区域、同时间段或可比业务场景。 |
| 不能直接下结论的内容 | 只改善单项指标，不能证明整体体验已经达标。 |

### 2.7 P4-T1完成标准

学生完成本任务后，至少要交付：

1. 优化实施任务单；
2. 优化动作分类与责任边界表；
3. 参数依据记录表；
4. 实施步骤与回退检查单；
5. 优化实施变更记录；
6. 复测验证交接清单。

教师评价时不只看答案对错，而要看学生是否能说明“依据、边界、风险和复测入口”。

## 3. P4-T2 任务2：5G网络优化结果验证

P4-T2已经形成 `3.5A-1` 深样章，本阶段不重新改写完整正文。它在项目四中的作用是“判断中枢”：P4-T1把实施证据交过来，P4-T2负责判断这些证据能否说明优化达到目标。

学生在P4-T2中要学会三件事：

1. 先识别验证场景，不把所有投诉混在一起；
2. 区分“有改善”和“能验收”，不把单项改善写成整体达标；
3. 用判断、依据、边界和建议四部分写出验收结论。

P4-T2的深样章已经覆盖：

| 学习动作 | 对应产出 |
| --- | --- |
| 投诉线索归类 | 投诉到验证对象映射 |
| 改善与达标边界判断 | 边界表达修正记录 |
| 覆盖、移动性、体验与容量指标读取 | 指标判断、流程排序和边界标注 |
| 依据链分类 | 通过依据、必须写边界和背景信息 |
| 结论拼装与二次修正 | 四段式验收结论和修订记录 |

P4-T2结束时，学生不能只说“优化成功”。更合格的表达应类似：

> 本次优化后，宿舍区北侧覆盖指标和接入指标较优化前明显改善，其中覆盖相关指标已达到本次验收口径；但晚高峰边缘用户体验仍存在波动，容量和移动性数据还需要继续观察。建议保留后续复测任务，并在报告中单独说明未闭环边界。

这段话的价值在于它同时包含判断、依据、边界和后续建议。

## 4. P4-T3 任务3：5G网络优化报告输出

### 4.1 学习情境

现在你已经有了两类材料：P4-T1形成的实施记录和复测交接清单，P4-T2形成的验证结论和边界说明。接下来要做的不是把这些材料复制到报告模板里，而是把它们组织成别人能看懂、能复核、能继续处理的优化报告。

一份合格的优化报告至少回答四个问题：

1. 这份报告写给谁看；
2. 它依据哪些证据；
3. 哪些问题已经改善或达标；
4. 哪些问题还没有闭环，不能承诺。

### 4.2 第一件事：明确报告对象和交付口径

报告对象不同，表达重点也不同。给教师看的学习报告、给项目组看的实施复盘、给客户看的交付说明，口径不能混用。

示例确认单：

| 项目 | 学生填写示例 |
| --- | --- |
| 报告对象 | 项目组内部复盘或教学模拟客户说明。 |
| 报告类型 | KPI指标优化类报告、测试指标优化类报告或典型案例分析报告。 |
| 证据范围 | 实施记录、复测指标、验收结论、测试数据分析摘要。 |
| 可说明内容 | 优化动作、指标变化、已达标项、未闭环项、建议。 |
| 不可承诺内容 | 未经授权的真实客户承诺、未经复核的行业结论、未脱敏站点信息。 |

### 4.3 第二件事：归集实施与验证证据

报告不能靠印象写。学生要先把证据分成四类：

| 证据类型 | 例子 | 能做什么 |
| --- | --- | --- |
| 实施依据 | 优化实施任务单、参数依据记录表。 | 说明为什么要做这些优化动作。 |
| 实施过程 | 实施步骤与回退检查单、变更记录。 | 说明做了什么、是否可追溯。 |
| 验证结果 | 覆盖、接入、保持、体验和容量指标对比。 | 支撑改善、达标或未闭环判断。 |
| 边界材料 | P4-T2中的依据链分类和修正句。 | 防止把部分改善写成整体成功。 |

如果一条材料只能说明背景，就不能把它当成通过依据。如果一条材料涉及截图、站点名或客户信息，必须先标记待审或脱敏。

### 4.4 第三件事：选择报告结构并组织材料

报告结构不是固定模板，而是服务于证据表达。对于本项目，可以采用五段式结构：

1. 问题概述：说明优化前的主要现象和影响范围；
2. 优化措施：说明实施动作、依据和责任边界；
3. 验证结果：说明优化前后数据变化；
4. 结论边界：说明哪些达标、哪些未闭环、哪些需要继续复测；
5. 后续建议：说明继续观察、二次分析或补充优化方向。

学生组织材料时要避免两类问题：

1. 只贴表格，不解释表格说明了什么；
2. 只写结论，不说明结论依据来自哪里。

### 4.5 第四件事：对比指标并写出结论边界

报告中最容易出错的地方，是把“数据变好”写成“已经成功”。更稳的写法是先分层判断：

| 判断层次 | 写法示例 |
| --- | --- |
| 改善 | 优化后覆盖指标较优化前提升，弱覆盖区域减少。 |
| 达标 | 在本次验收口径下，覆盖指标达到设定目标。 |
| 未闭环 | 晚高峰边缘用户体验仍不稳定，需要继续跟踪容量指标。 |
| 需二次分析 | 若切换失败率仍偏高，应进入移动性或信令复盘。 |

学生应把原来过度的句子改成有边界的句子。

| 原句 | 问题 | 修改后 |
| --- | --- | --- |
| 本次优化已经彻底解决宿舍区网络问题。 | 结论过满，没有边界。 | 本次优化后覆盖和接入指标改善明显，但晚高峰体验仍需继续复测。 |
| 指标变好了，所以验收通过。 | 缺少达标口径。 | 在本次覆盖验收口径下，覆盖指标达到目标；容量和移动性仍需单独说明。 |
| 客户可以放心使用。 | 越权承诺。 | 建议在后续观察期继续跟踪用户体验，并由项目组确认是否进入最终交付。 |

### 4.6 第五件事：编写典型案例分析段

典型案例不是“贴一张图，再写优化成功”。至少要写清六个部分：

1. 问题现象；
2. 可能原因；
3. 优化措施；
4. 效果证据；
5. 未闭环边界；
6. 适用范围。

示例段落：

> 在宿舍区北侧楼宇案例中，优化前用户主要反馈为晚高峰视频卡顿和个别楼层信号不稳定。结合测试记录，问题可能与覆盖边界和容量压力共同相关。本次教学模拟中先对覆盖方案和相关参数依据进行复核，并形成实施变更记录。复测结果显示，覆盖相关指标较优化前改善，接入表现趋于稳定；但晚高峰边缘用户体验仍存在波动，不能直接写成整体网络问题已经全部解决。该案例适用于训练覆盖和容量边界判断，不能作为真实网络参数调整处方。

### 4.7 第六件事：修订报告表达并准备沟通

报告写完后，还需要修订。学生可以按四条标准检查：

1. 有没有写清依据；
2. 有没有写清边界；
3. 有没有删除越权承诺；
4. 有没有把后续建议写成可执行动作。

客户沟通提纲只能用于教学模拟。示例：

| 沟通要点 | 稳妥表达 |
| --- | --- |
| 已改善内容 | 覆盖和接入类指标较优化前有明显改善。 |
| 已达标内容 | 在本次验收口径下，覆盖指标达到目标。 |
| 未闭环内容 | 晚高峰体验和移动性表现仍需继续观察。 |
| 后续建议 | 建议保留复测计划，必要时进入容量或信令分析。 |

### 4.8 P4-T3完成标准

学生完成本任务后，至少要交付：

1. 报告交付口径确认单；
2. 报告证据链清单；
3. 报告结构草稿；
4. 指标对比结论段；
5. 典型案例分析段；
6. 优化报告输出样稿与沟通提纲。

教师评价时要重点看学生是否能把P4-T1和P4-T2的证据用起来，而不是只套报告模板。

## 6. 教师带教建议

项目四建议按“实施前判断、结果验证、报告表达”组织。现阶段不直接给出全章课时定稿，但可以采用如下带教逻辑：

1. P4-T1用于训练学生不要盲目实施，先确认优化对象、依据、边界和复测入口；
2. P4-T2用于训练学生读指标、分依据、写边界，保留2课时深样章作为可直接观察样本；
3. P4-T3用于训练学生把证据组织成报告，避免模板化、空泛化和过度承诺。

教师讲评时，可以把常见错误分成四类：

| 常见错误 | 讲评方向 |
| --- | --- |
| 一看到问题就写“调整参数” | 追问依据、授权和影响范围。 |
| 单项指标改善就写“优化成功” | 追问达标口径和未闭环指标。 |
| 报告只有标题和模板 | 追问每段证据来源和表达功能。 |
| 对客户表达过满 | 追问哪些内容还需要复核、观察或授权。 |

## 7. 当前边界

本样稿仍有以下边界：

1. 专业阈值和案例逻辑未经过通信专业专家最终复核；
2. 原教材中的仿真软件截图、站点信息和测试截图不能直接进入正式资源；
3. 客户沟通表达只能用于教学模拟，不得作为真实交付话术；
4. P4-T1和P4-T3目前是轻量样稿，质量尚未达到P4-T2 `3.5A-1` 深样章水平；
5. 本样稿可用于阶段2原型制作和内部评审，不能用于正式出版发布。
