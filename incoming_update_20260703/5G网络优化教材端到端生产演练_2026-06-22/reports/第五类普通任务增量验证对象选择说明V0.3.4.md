# 第五类普通任务增量验证对象选择说明V0.3.4

生成日期：2026-06-25  
依据基线：课程能力图谱V0.3.4当前推荐主数据  
配套矩阵：`reports/第五类普通任务增量验证候选矩阵V0.3.4.csv`  
结论：推荐 `P4-T1 任务1：5G网络优化方案实施` 作为第五类普通任务增量验证对象。当前只完成对象选择，不直接开始P4-T1补拆。

## 1. 当前选择目标

第五类普通任务增量验证的目标不是继续扩大任务数量，而是检验V0.3.4主数据和V0.4风险治理口径能否迁移到尚未充分覆盖的新任务类型。

此前已经覆盖的代表类型包括：

| 已验证任务 | 已验证类型 |
| --- | --- |
| P1-T3 | 投诉信息采集、客户沟通、隐私和服务表达 |
| P2-T1 | DT/CQT测试准备与执行 |
| P2-T2 | 测试问题处理分支 |
| P2-T3 | 测试数据分析 |
| P3-T3 | 参数检查和配置管理 |
| P4-T2 | 优化结果验证和深样章呈现 |
| P5-T3 | 全网性能提升验证 |
| P6-T2 | 信令问题分析与复杂复盘 |

当前尚未被充分验证的是“优化实施与工程变更类”任务，尤其是AU-06优化实施与变更记录。

## 2. 候选排序

本轮候选矩阵共纳入18个任务。已验证任务继续排除，未验证任务重新评分。

前三名为：

| 排名 | 任务 | 分数 | 判断 |
| ---: | --- | ---: | --- |
| 1 | P4-T1 5G网络优化方案实施 | 90 | 推荐作为第五类普通任务 |
| 2 | P3-T4 5G网络参数设置 | 84 | 第二候选 |
| 3 | P4-T3 5G网络优化报告输出 | 79 | 第三候选 |

## 3. 推荐P4-T1的理由

P4-T1最适合作为第五类任务，理由如下：

1. 它能验证AU-06“优化实施与变更记录”是否可以进入课程能力图谱主数据；
2. 它与已验证的P4-T2结果验证不同，P4-T2解决“优化后怎么看是否有效”，P4-T1解决“优化方案如何实施并留下可追溯记录”；
3. 它能把P2/P3形成的问题判断、参数检查和P4-T2结果验证连接起来，补上“问题 -> 方案 -> 实施 -> 验证”的中间环节；
4. 它能暴露新的治理风险：工程实施、参数变更、跨专业协同、变更记录、责任边界、媒体重绘和方案适用范围；
5. 它比P3-T4更能检验跨专业优化实施，而不是只继续验证参数链条；
6. 它比P4-T3更能补主数据能力缺口，因为报告输出更偏成果表达，P4-T1更偏职业动作。

## 4. 为什么不是P3-T4

P3-T4有价值，但不宜作为第五类首选。

主要原因：

1. P3-T4与P3-T3都在参数链条内，虽然一个是检查、一个是设置，但类型差异仍小于P4-T1；
2. 如果第五类先选P3-T4，图谱验证会继续集中在参数和网管侧，不能充分检验工程实施类任务；
3. P3-T4适合作为后续AU-06参数配置专项验证，尤其用于验证配置授权、回退记录和误操作风险。

因此P3-T4保留为第二候选。

## 5. 为什么不是P4-T3

P4-T3也有价值，但更适合作为后续表达类专项。

主要原因：

1. P4-T3与P4-T2深样章距离较近，新增任务类型价值低于P4-T1；
2. P4-T3容易被拆成报告格式、章节模板和结论句式，必须等工程实施链条更清楚后再做；
3. AU-08职业表达已有P4-T2-N08和P1-T3-N05提供局部支撑，但AU-06优化实施还缺少稳定详细节点。

因此P4-T3保留为第三候选。

## 6. P4-T1的主要风险

选择P4-T1并不表示它容易处理。主要风险包括：

1. 原文图片多，存在媒体重绘和标注压力；
2. 天馈、无线、承载、核心网等优化对象可能并列出现，容易把节点拆成技术清单；
3. 参数变更和工程实施涉及责任边界，不能写成学生可以随意操作；
4. 优化方案的适用范围、前置条件和副作用需要专业复核；
5. 需要明确实施记录、变更依据、回退方案和复测入口，否则无法与P4-T2结果验证闭环。

这些风险不是否定P4-T1，而是说明它恰好适合作为下一类增量验证对象。
