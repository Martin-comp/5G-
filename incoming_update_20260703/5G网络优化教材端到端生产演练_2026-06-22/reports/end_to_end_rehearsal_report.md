## 0. 结论摘要

本轮已完成一本文字教材的样本级端到端演练，路径为：

传统电子教材输入 -> 文本和媒体抽取 -> 全书结构化 -> 政策/标准/能力依据补全 -> 代表性任务能力图谱 -> 资源输出包样本 -> 直接呈现样本 -> 初步质量门禁。

本轮证明：用一本教材作为输入先走完整流程，比先拆工具模块更合理。原因是它暴露了真实瓶颈：标题样式不一致、图片 alt 缺失、题库非结构化、专业参数需专家审核、版权状态不明、平台接口未知、数字教材标准封装需要元数据和版权文件支撑。

本轮没有证明：该教材已经可以自动批量转成正式出版级数字教材。当前成果是“技术流程样本”和“工具链建设依据”，不是正式出版物。

## 3. 端到端流程与初步技术方案

### 3.1 输入接收与分级

目标：判断输入是大纲、教材、资源包还是完整出版源文件。

本轮做法：

- 读取 DOCX 元数据、文件体量、媒体数量；
- 抽取 Markdown、图片、表格和标题；
- 判定输入等级为 L1+。

工具链模块建议：

- 输入资产探测器；
- 文档结构抽取器；
- 输入等级判定器；
- 缺口清单生成器。

### 3.2 标准与互联网补全

目标：当只有一本教材时，用政策、专业教学标准、国家职业标准和行业资料补齐外部参照。

本轮做法：

- 抓取并保存教育部政策文件；
- 转换本地 TCADPA 标准 PDF；
- 通过人社官方接口获取国家职业技能标准；
- 下载教育部专业教学标准；
- 将 1+X 排除并留痕。

工具链模块建议：

- 来源检索与可信度分级；
- 标准条款抽取；
- 政策/标准证据库；
- 排除来源管理。

### 3.3 全书结构化

目标：把传统教材转成机器可处理的项目、任务、环节、资源、测评结构。

本轮做法：

- 识别 6 个项目、18 个任务；
- 生成任务清单、媒体引用清单；
- 发现标题样式不一致，已通过标题清洗规则修正。

工具链模块建议：

- 章节标题规范化；
- 项目-任务结构识别；
- 教学环节识别；
- 资源引用反查；
- 异常结构提示。

### 3.4 课程能力图谱

目标：将“章节目录”升级为“岗位任务-能力单元-知识技能点-资源-评价证据”的图谱。

本轮做法：

- 以专业教学标准和国家职业标准确定能力边界；
- 为项目四任务2生成能力图谱样本；
- 图谱节点包括标准、课程目标、岗位任务、能力、知识、技能、资源、测评。

工具链模块建议：

- 能力节点抽取；
- 标准对齐；
- 资源绑定；
- 测评绑定；
- 专家审核状态管理。

### 3.5 资源输出包

目标：面向出版社平台上传和编辑，输出可拆解资源，而不是只输出页面。

本轮做法：

- 生成结构化题库 JSON；
- 生成资源清单和包级元数据；

工具链模块建议：

### 3.6 直接呈现样本

目标：面向“直接挂接出版社平台”的路径，形成可读、可交互、可埋点的数字教材页面样本。

本轮做法：

## 5. 本轮发现的关键瓶颈

| 瓶颈 | 具体表现 | 对工具链的要求 |
| --- | --- | --- |
| 标题样式不一致 | 任务标题有的带粗体、有的带锚点、有的无冒号 | 建立鲁棒的标题清洗和结构识别 |
| 图片资源缺少语义 | alt 为空或为临时文件名 | 自动生成图题、图注、资源说明，并进入人工审核 |
| 媒体格式复杂 | 存在 EMF/WMF | 自动转换为 Web 友好格式 |
| 题库不结构化 | 缺答案、解析、难度、能力点、评分规则 | 题库抽取与命题审核模块 |
| 专业准确性风险 | 5G 指标、流程、参数有强专业性 | 专家审核和行业标准校核不可省略 |
| 版权状态不明 | 教材图片、截图、案例、仿真软件界面授权未知 | 版权元数据和授权工作流 |
| 平台接口未知 | 未提供出版社平台字段和挂接方式 | 需要平台适配层 |
| 使用数据缺失 | 无真实学习行为数据 | 只能先设计埋点，后续接入平台验证 |

## 6. 阶段性判断

本轮端到端流程是走通的，但只达到“样本级走通”，还没有达到“规模化自动生产”。

可以进入下一阶段，但下一阶段不应直接全书批量生成成品，而应先把本轮验证过的流程拆成可复用模块：

1. 输入解析模块；
2. 标准补全模块；
3. 结构化目录模块；
4. 能力图谱模块；
5. 资源颗粒化模块；
6. 题库结构化模块；
7. 资源包封装模块；
8. 直接呈现生成模块；
9. 质量门禁与审核模块；
10. 平台接口适配模块。

下一轮建议选择两条并行验证路径：

1. 对全书 18 个任务做轻量批处理，验证结构化和能力图谱的稳定性；
2. 对项目四任务2继续做高保真深化，补齐答案解析、互动资源、参数数据、专家审核清单和平台接口样例。
