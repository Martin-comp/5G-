# 课程能力图谱字段规范V0.4升级方案

生成日期：2026-06-24  
适用范围：《5G网络优化教材（高级）》数字教材端到端生产演练  
上一版本：`reports/课程能力图谱字段规范V0.2.md`  
依据报告：`reports/课程能力图谱V0.3.3主数据评审与下一步建议.md`  
配套字段清单：`reports/课程能力图谱字段规范V0.4字段清单.csv`

## 1. 升级结论

V0.4不是重建课程能力图谱字段体系，而是在V0.2字段规范和V0.3.3主数据基线之上，增加一层可执行的风险治理字段。

V0.3.3已经证明课程能力图谱主数据机制阶段性成立：节点、关系、资源活动评价挂接和输入输出物治理可以版本化合并，也能承接P2-T2、P3-T3、P1-T3三类不同任务。

但V0.3.3也暴露出一个新的问题：字段治理仍偏粗。尤其是P1-T3引入的客户信息、电话录音、客户授权、服务承诺、反馈表达和案例真实性，不能继续只写在 `review_required_type=data_security`、`professional_risk_type` 或备注字段里。

因此，下一步应先做V0.4字段治理升级，再继续第四类任务增量或工具链拆解。

## 2. V0.4定位

V0.4有效字段体系定义为：

```text
V0.4有效字段 = V0.2基础字段 + V0.4新增/修订风险治理字段
```

V0.4不要求立刻重写所有V0.3.3主数据表，也不要求把全部18个任务重新拆分。V0.4先解决字段规范不足，再通过小范围回填试验验证字段是否真正可用。

## 3. 升级目标

V0.4主要解决五类问题：

1. 把数据安全风险从备注字段转为结构化字段；
2. 把客户沟通、服务承诺和外部话术风险转为结构化字段；
3. 把案例真实性、教学模拟、来源改写和发布可用性转为结构化字段；
4. 把专业、编辑、媒体、数据安全、学生正文、平台接口等门禁转为可筛选状态；
5. 为后续工具链提供“可自动生成、必须人工复核、禁止发布、需脱敏后发布”的判断依据。

## 4. V0.4新增字段组

### 4.1 数据安全字段组

该组字段用于治理姓名、电话、地址、工单、录音、终端、客户等级等敏感信息。

核心字段包括：

1. `contains_personal_info`
2. `personal_info_type`
3. `anonymization_required`
4. `anonymization_status`
5. `authorization_required`
6. `authorization_status`
7. `recording_involved`
8. `data_security_review_scope`
9. `data_security_gate_status`

这些字段应优先用于P1-T3、投诉类任务、客户沟通类资源、工单表、电话录音、现场记录和任何涉及真实用户信息的材料。

### 4.2 服务表达与承诺边界字段组

该组字段用于治理反馈话术、处理承诺、责任表达、升级边界和对外可用性。

核心字段包括：

1. `service_commitment_risk_type`
2. `customer_communication_review_type`
3. `communication_expression_status`
4. `external_statement_allowed`
5. `service_wording_review_note`

这些字段能够区分“教学中可讨论的话术”和“可对外直接使用的话术”。正式数字教材中，未经编辑复核和专业复核的话术不能作为学生可直接套用的外部表达。

### 4.3 案例真实性与教学模拟字段组

该组字段用于治理真实案例、脱敏案例、AI创造案例、教学模拟案例和来源改写案例。

核心字段包括：

1. `case_authenticity_type`
2. `case_applicability_boundary`
3. `source_sensitivity_level`
4. `source_transformation_type`
5. `publishability_status`

这些字段可以防止把教学模拟案例伪装成真实案例，也可以防止把真实案例在未脱敏、未复核的情况下进入学生端或出版社平台。

### 4.4 门禁状态字段组

该组字段用于把“仍需复核”的自然语言表述，转为可阻断、可统计、可筛选的状态字段。

核心字段包括：

1. `professional_gate_status`
2. `editorial_gate_status`
3. `data_security_gate_status`
4. `media_gate_status`
5. `student_text_gate_status`
6. `platform_gate_status`
7. `teaching_validation_gate_status`
8. `overall_publish_gate_status`
9. `gate_blocking_reason`
10. `gate_next_action`

这些字段是后续生产工具链的重要前置条件。没有明确门禁状态，就无法判断哪些内容可以自动生成，哪些必须人工复核，哪些不得发布。

### 4.5 回填与迁移治理字段组

该组字段用于控制V0.4字段如何从试验进入正式主数据。

核心字段包括：

1. `field_backfill_status`
2. `migration_batch_id`
3. `schema_change_reason`

这些字段用于记录某条节点、关系或资源挂接是否已经完成V0.4回填，避免同一批数据重复迁移或误认为已经达标。

## 5. 对V0.2字段的修订

V0.4需要修订V0.2中的四个字段口径：

| 字段 | 修订原因 | V0.4处理 |
| --- | --- | --- |
| `field_schema_version` | 版本仍停留在V0.2 | 允许填写V0.4 |
| `review_required_type` | 现有枚举无法区分学生正文、教学验证、发布门禁等 | 增加 `student_text`、`teaching_validation`、`publication`、`legal` |
| `professional_risk_type` | P1-T3已出现 `privacy`、`communication` 等实际值，但V0.2枚举不支持 | 增加 `privacy`、`communication`、`service_commitment`、`authorization`、`publication_boundary` |
| `review_owner_role` | 缺少数据安全、法务合规、教学验证责任角色 | 增加 `data_security_officer`、`legal_compliance`、`teaching_reviewer` |

这些修订不是为了扩大字段数量，而是为了让已有主数据中已经出现的风险有合法、稳定、可校验的字段口径。

## 6. 字段分级

V0.4新增字段采用R1/R2/R3分级。

| 等级 | 含义 |
| --- | --- |
| R1 | 高风险节点、资源或评价必须填写；低风险对象可填 `not_applicable` |
| R2 | 建议填写，用于后续回填、复核、筛选和治理 |
| R3 | 平台化、资源包发布、学习数据回收阶段填写，当前可预留 |

V0.4不要求所有字段在全量V0.3.3主数据中立即填满。更合理的方式是先做代表任务回填试验。

## 7. 回填试验范围

V0.4字段规范形成后，建议先选三个代表任务做小范围回填：

| 任务 | 回填目的 |
| --- | --- |
| P1-T3 投诉信息采集 | 验证数据安全、电话录音、客户授权、服务承诺和反馈表达字段 |
| P3-T3 5G网络参数检查 | 验证公式、参数、截图、媒体审查和专业口径字段 |
| P4-T2 5G网络优化结果验证 | 验证深样章、学生正文、教师材料、评价量规和页面呈现门禁字段 |

回填试验的目标不是追求数据量，而是检查字段是否能覆盖真实风险，是否能减少备注字段堆积，是否能支持后续自动化门禁。

## 8. 质量门禁

V0.4字段升级方案通过的最低条件：

1. 字段清单CSV可以被结构化解析；
2. 每个字段都有中文名、字段组、分级、数据类型、允许值、填写规则和示例；
3. 关键枚举值能覆盖P1-T3、P3-T3、P4-T2三类代表风险；
4. 字段不会替代专业复核、编辑复核、数据安全审核和平台接口验证；
5. 字段不会让学生端暴露后台审核语言；
6. 字段能支撑后续回填试验和门禁统计。

## 9. 下一步建议

建议下一步按以下顺序执行：

1. 校验 `reports/课程能力图谱字段规范V0.4字段清单.csv`；
2. 制作P1-T3、P3-T3、P4-T2三任务V0.4字段回填样表；
3. 对回填样表做结构校验和内部评审；
4. 判断V0.4是否足以支撑第四类任务增量；
5. V0.4回填试验通过前，不进入页面生产或工具链模块拆解。

最终判断：V0.4是从“主数据能合并”走向“主数据可治理、可复核、可生产”的必要过渡层。
