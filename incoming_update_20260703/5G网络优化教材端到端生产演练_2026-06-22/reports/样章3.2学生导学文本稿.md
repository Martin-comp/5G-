# 样章3.2学生导学文本稿

生成日期：2026-06-23  
样章对象：《5G网络优化教材（高级）》项目四 / 任务2：5G网络优化结果验证  
当前用途：先把学生真正能读懂、能跟着完成任务的教材正文写出来，再决定界面如何承载。

## 1. 本稿定位

3.1样章已经验证了任务工作台、能力地图、材料聚焦看板和资源抽屉的基本交互，但它仍然有一个核心问题：一个不了解5G网络优化的学生进入页面后，不一定知道自己该怎样开始学习，也不一定能在阅读后形成可靠判断。

因此，3.2不先继续增加页面形式，而是先补上“导学正文”。这里的“导学”不是提纲，也不是目录，而是学生端教材正文：学生读到每一段，都应知道自己正在解决什么问题、为什么要看这项内容、应该怎样判断、读完后要形成什么表达。

本稿中的指标、阈值和结论仍使用样章教学模拟数据。正式教材发布前，必须由通信专业教师或行业专家复核。

## 2. 可信依据如何转化为教材写法

本稿参考了职业教育和数字教材建设的相关要求，并把这些要求转化为样章写作约束。

教育部职业教育教学改革相关文件强调，应普遍推行项目教学、案例教学、情境教学和工作过程导向教学。对本样章而言，这意味着学生不能一上来就面对一串指标和术语，而应先进入一个真实任务，再在任务中学习必要知识。

职业教育教材建设相关文件和本项目已整理的政策标准材料强调，新形态教材应体现新技术、新规范、新标准、新形态，并可采用活页式教材、工作手册式教材、数字教材等形式。对本样章而言，这意味着内容不能只是电子化排版，而应像岗位工作单一样组织：情境、判断、数据、操作、结论和反馈要连在一起。

案例学习、问题学习和探究学习的通行做法也有共同点：用真实或接近真实的情境引出问题，让学习者先形成判断，再通过必要资料、教师引导和实践活动修正判断。对本样章而言，这意味着“先给案例引发疑问，再答疑，再实践”的方向是成立的，但不能停留在方法口号上，必须写成学生能直接阅读和操作的教材正文。

本稿采用的学习段落顺序为：

```text
真实案例 -> 引发疑问 -> 学生先判断 -> 答疑导学 -> 示范读数据 -> 学生实践 -> 反馈纠偏 -> 形成职业表达
```

这个顺序不是前端页面目录。前端可以做成卡片、任务流、地图、抽屉、弹层或工作台，但教材正文必须先保证上述学习闭环成立。

## 3. 学生端教材正文

### 3.1 一通投诉电话引出的判断任务

某高职院校宿舍区刚完成一轮5G网络优化。优化完成后的第二天，学生反馈普通网页访问基本恢复正常，图片和文字页面能够正常打开；但到了晚间高峰，视频通话仍然偶发卡顿，直播上行时延偏高，推流画面有时会明显慢半拍。

现在，你的角色是网络优化助理工程师。你的任务不是简单回答“优化成功”或“优化失败”，而是根据优化前后的数据，判断本次优化结果是否达标，并说明你的判断依据和后续建议。

读到这里，先不要急着查术语。你可以先抓住一个最基本的问题：用户真正关心的是“网页能不能打开”，还是“视频通话和直播业务能不能稳定使用”？如果网页恢复了，但视频和直播仍然有问题，本次优化是否还能直接写成“全部达标”？

请先写下你的初步判断：

```text
我认为本次优化结果可能是：达标 / 部分达标 / 未达标 / 暂时无法判断。

我的理由是：

我最想先查看的数据是：
```

这个初步判断不要求一次答对。它的作用是让你带着问题阅读后面的材料，而不是被指标名称牵着走。

### 3.2 为什么“网页恢复正常”不等于“优化全部成功”

网页访问、视频通话和直播上行，对网络的要求不完全一样。

普通网页访问通常对实时性要求较低。网页打开慢一点，用户可能还能接受；页面加载完成后，短时间的网络波动不一定马上表现出来。视频通话和直播上行则不同，它们更依赖连续、稳定、低时延的网络。如果网络时延忽高忽低，或者晚高峰负荷较重，用户就可能看到画面卡顿、声音延迟、推流不同步。

所以，在本任务中，不能只看一个现象，更不能只看一个指标。正确的思路是：

```text
先看覆盖有没有明显改善；
再看切换和业务连续性有没有风险；
最后看视频、直播等业务体验是否真正恢复。
```

如果覆盖变好了，但业务体验仍有未达标项，结论就应更谨慎。职业岗位中的报告不能只写“有改善”，还要写“改善到什么程度、是否达到目标、还缺少哪些验证”。

### 3.3 先把问题分成三类

面对“视频卡顿、直播上行延迟高”这类投诉，可以先把问题放进三个入口中理解。

第一类是覆盖问题。覆盖问题主要回答“终端能不能收到足够强、足够稳定的5G信号”。如果覆盖差，用户可能出现速率低、接入困难、业务不稳定等问题。

第二类是切换问题。学生在宿舍区、楼道、操场或食堂移动时，手机可能需要从一个小区切换到另一个小区。切换如果过晚、过早、失败或频繁发生，业务可能出现短暂中断或卡顿。

第三类是端到端业务体验问题。它更接近用户真实感受，例如视频通话时延、直播上行时延、上传速率、卡顿次数、掉线或异常释放等。一个网络覆盖看起来改善了，并不代表所有业务体验都已经达标。

本任务不要求你马上掌握5G网络优化的全部理论。你先要学会一件事：看到投诉现象后，知道应该从哪几类数据入手，而不是只盯着一个截图或一个数值。

### 3.4 读覆盖数据：它能说明什么，不能说明什么

先看覆盖数据。下面的数据是样章教学模拟数据，正式教材中的阈值需要专业教师复核。

| 指标 | 优化前 | 优化后 | 先这样理解 |
| --- | ---: | ---: | --- |
| SS-RSRP覆盖率 | 88.4% | 96.3% | 信号强度覆盖明显改善 |
| SS-SINR覆盖率 | 84.2% | 94.1% | 信号质量改善，但是否达标还需看目标值 |
| 弱覆盖采样点占比 | 12.6% | 3.8% | 弱覆盖问题明显减少 |

SS-RSRP可以先理解为“信号强度够不够”。从88.4%提升到96.3%，说明优化后更多采样点达到了较好的信号强度，这可以支持“覆盖强度明显改善”的判断。

SS-SINR可以先理解为“信号质量干不干净，受不受干扰”。它从84.2%提升到94.1%，也说明质量有改善。但如果本任务的参考目标是95%，那么94.1%仍然不能直接写成完全达标。这里最容易犯的错误是：看到数据提升，就写成“已经达标”。实际报告中要区分“改善”和“达标”。

弱覆盖采样点占比从12.6%降到3.8%，说明弱覆盖问题明显缓解。这条数据也支持覆盖优化有效。

读完这组数据后，可以形成一个比较稳妥的表达：

```text
覆盖强度改善明显，弱覆盖采样点明显减少；但覆盖质量是否完全达标仍需结合SS-SINR目标值确认。仅凭覆盖数据，不能证明视频通话和直播上行体验已经全部恢复。
```

这句话比“覆盖优化成功”更适合写入教材任务答案，因为它说明了依据，也说明了边界。

### 3.5 读切换材料：流程图不是现场日志

再看切换材料。

在5G网络中，终端移动时可能需要从当前服务小区切换到更合适的小区。A3事件可以先理解为一种切换触发条件：当邻区比当前服务小区更适合提供服务时，网络可以根据测量结果触发切换。

切换流程通常包括测量、判决、资源准备、切换执行和资源释放。流程图能帮助你理解“正常情况下切换应该怎么发生”，但流程图本身不能证明本次宿舍区现场的切换一定没有问题。

因此，切换材料在本任务中的作用是帮助你提出核查方向，而不是直接给出最终结论。你可以这样理解：

```text
如果视频卡顿发生在学生移动过程中，就需要关注切换是否及时、是否失败、是否频繁发生。
如果教材只给出切换流程图，而没有现场切换成功率、失败记录、重建记录或异常释放记录，就不能直接判断切换已经完全正常。
```

这类材料进入正式数字教材时，不能只放一张软件截图或复杂流程图。它需要被重绘成学生能读懂的教学图，并标出“先看哪里、每一步说明什么、还缺哪些现场数据”。

### 3.6 读业务体验数据：平均值达标不代表所有用户都顺畅

最后看业务体验数据。它最接近用户真实感受。

| 指标 | 优化前 | 优化后 | 先这样判断 |
| --- | ---: | ---: | --- |
| 视频通话平均端到端时延 | 78 ms | 42 ms | 平均体验明显改善 |
| 直播上行95分位时延 | 180 ms | 110 ms | 有改善，但仍可能未达目标 |
| 10分钟业务卡顿次数 | 6次 | 2次 | 卡顿减少，但仍需继续核查 |

视频通话平均端到端时延从78 ms降到42 ms，可以支持“视频通话平均体验明显改善”的判断。如果样章参考目标允许42 ms，那么这一项可以写成已达标。

但直播上行95分位时延从180 ms降到110 ms，只能说明它改善了，不能直接说明它达标。95分位可以先这样理解：它不是平均水平，而是提醒我们关注体验较差的一部分情况。对于直播上行这类业务，少数高时延时段也可能造成明显卡顿和延迟。

10分钟业务卡顿次数从6次降到2次，也说明问题有所缓解。但如果目标是尽量接近0次或不高于1次，那么2次仍然不能写成完全解决。

读完业务体验数据后，更稳妥的表达是：

```text
视频通话平均时延已经明显改善，但直播上行95分位时延和卡顿次数仍需核查。用户体验有改善，但不能判断为全部达标。
```

这一段是本任务的关键。学生如果只看平均时延，可能会误判为优化全部成功；如果能同时关注95分位和卡顿次数，判断就更接近真实岗位要求。

### 3.7 现在重新判断：改善、达标、部分达标不是一回事

读完三类材料后，再回到最开始的问题：本次优化结果是否达标？

先把三个词分清楚。

“改善”表示优化后比优化前好。例如SS-RSRP覆盖率提升、时延下降、卡顿次数减少，都可以叫改善。

“达标”表示优化后的结果达到预设目标。例如某项指标不仅变好了，而且达到课程或项目设定的验收要求，才可以写成达标。

“部分达标”表示有些关键指标达到目标，有些指标仍未达到目标，或者某些材料不足以支撑最终判断。

在本样章给出的数据中，覆盖强度明显改善，视频通话平均时延也明显改善；但SS-SINR、直播上行95分位时延和卡顿次数仍需要核查。因此，比较稳妥的判断是：

```text
本次优化结果为部分达标。
```

注意，这不是保守地“不敢判断”，而是有依据地判断。职业岗位中的结论要能经得起追问：你为什么这么说？你看了哪些数据？哪些数据还不能证明你的结论？

### 3.8 学生实践：把数据变成结论依据

现在请你把下面三类数据写进自己的判断中。不要只抄数值，要说明每条数据支持什么、还不能说明什么。

覆盖数据：

```text
SS-RSRP覆盖率从88.4%提升到96.3%，这说明：

但它还不能说明：
```

业务体验数据：

```text
直播上行95分位时延从180 ms降到110 ms，这说明：

但它还不能说明：
```

卡顿次数：

```text
10分钟业务卡顿次数从6次降到2次，这说明：

但它还不能说明：
```

如果你暂时写不出来，可以先用下面的句式：

```text
这条数据支持我判断____已经改善，因为____。
但是它不能单独证明____已经达标，因为____。
```

这个练习的目的不是让你背指标，而是训练你把数据变成岗位报告里的判断依据。

### 3.9 常见错误与修改示范

错误一：

```text
本次优化成功，因为覆盖率提升了。
```

这句话的问题是只看了覆盖，没有看业务体验。它没有回答视频通话和直播上行是否恢复，也没有说明仍未达标或需核查的部分。

可以改成：

```text
本次优化覆盖强度改善明显，但不能仅凭覆盖率提升判断全部达标。还需要结合视频通话时延、直播上行95分位时延和卡顿次数综合判断。
```

错误二：

```text
视频通话平均时延达标，所以业务体验已经恢复。
```

这句话的问题是把一个业务指标的平均值扩大成全部业务体验。它没有处理直播上行95分位时延和卡顿次数。

可以改成：

```text
视频通话平均时延已经改善，但直播上行95分位时延和卡顿次数仍提示晚高峰体验可能存在问题，因此业务体验不能判断为全部恢复。
```

错误三：

```text
教材截图显示已经优化，所以可以作为结论依据。
```

这句话的问题是没有说明截图来源、字段含义和读图路径。非通用仿真软件截图如果没有标注，学生很难判断图上数据代表什么。

可以改成：

```text
原仿真截图可以作为补充材料，但正式结论应优先引用可解释的指标表、日志或重绘后的教学图。未标注截图不能单独作为最终判断依据。
```

### 3.10 可提交的结论示例

完成以上阅读和练习后，可以写出如下结论。正式作答时不要求逐字一致，但必须包含判断状态、数据依据、边界说明和后续建议。

```text
本次优化结果建议判断为部分达标。

依据是：SS-RSRP覆盖率从88.4%提升到96.3%，弱覆盖采样点占比从12.6%降至3.8%，说明覆盖强度和弱覆盖问题已有明显改善；视频通话平均端到端时延从78 ms降至42 ms，说明视频通话平均体验明显改善。

但还不能判断为全部达标。SS-SINR覆盖率优化后为94.1%，是否达到目标仍需复核；直播上行95分位时延从180 ms降至110 ms，虽然有改善，但仍可能高于样章目标；10分钟业务卡顿次数从6次降至2次，说明卡顿减少但尚未完全消除。

后续建议补充晚高峰真实路测数据、直播上行业务日志、切换成功率和异常释放记录，并对原仿真截图进行标注或重绘后再作为教学材料使用。
```

这段结论不是为了写得长，而是为了把“判断、依据、边界、建议”四件事说完整。学生如果能写出类似结构，就基本完成了本任务的学习闭环。

## 4. 课堂模式和自学模式应如何区分

课堂模式和自学模式不应只换几句提示语。它们使用同一套教材正文，但学习组织方式不同。

课堂模式中，教师可以在3.1、3.4、3.6和3.10四个位置暂停：

| 暂停点 | 教师组织 | 学生产出 |
| --- | --- | --- |
| 案例读完后 | 让学生先独立判断，再举手或投票 | 初步判断 |
| 覆盖数据读完后 | 小组讨论“改善”和“达标”的区别 | 覆盖判断句 |
| 业务体验数据读完后 | 对比平均值和95分位 | 业务体验判断句 |
| 结论示例前 | 先让学生提交自己的结论，再讲评示例 | 任务结论 |

自学模式中，学生没有教师即时讲解，所以每一段需要更多支架。自学界面不应只显示“请认真阅读”，而应提供具体帮助：

```text
读不懂SS-RSRP时，先把它理解为信号强度。
读不懂SS-SINR时，先把它理解为信号质量和干扰情况。
不知道95分位是什么时，先记住它用来提醒我们关注体验较差的部分情况。
写不出结论时，按“我的判断是……依据是……但还不能说明……所以建议……”组织。
```

因此，后续前端实现中，课堂模式应强调教师停顿点、小组分工、汇报和讲评；自学模式应强调术语解释、分步提示、作答句式和自动反馈。两种模式不是两套完全不同教材，但必须改变学生完成任务的路径。

| 读覆盖数据 | 判断覆盖优化效果 | 覆盖数据解读卡 |
| 读切换材料 | 判断切换验证流程合理性 | 切换流程解读卡 |
| 读业务体验数据 | 判断业务体验是否恢复 | 业务体验数据卡 |
| 常见错误与修改示范 | 形成优化结果验证结论 | 反馈纠偏卡 |
| 可提交的结论示例 | 形成优化结果验证结论 | 结论任务卡 |

能力图谱的作用是让学生知道自己正在完成哪个能力节点，也能点击节点查看相关材料。但学生真正学习时，不能只看到节点名和资源名。节点必须落到像本稿这样的教材正文、任务动作和反馈中。

卡片仍然可以作为最小资源单元。关键是每张卡片不能只是标题，而应至少包含：

1. 一段学生能读懂的正文；
2. 一个明确学习动作；
3. 一条判断依据或数据材料；
4. 一句“能说明什么、不能说明什么”；
5. 一个可以被教师或系统检查的产出。

## 6. 对3.1原型的直接修正方向

基于本稿，3.1原型后续不宜只做视觉调整。建议先做以下内容级修正：

1. 首屏不要只显示任务工作台摘要，应增加“案例正文”和“先做初判”的可读区域；
2. 覆盖、切换、业务体验三类材料不应只是材料入口，应改为“正文解释 + 数据表 + 判断动作 + 反馈提示”；
3. 自学模式必须给出术语解释、读数步骤、句式支架和错误原因；
4. 课堂模式应提供教师暂停点、小组分工和汇报节点；
5. 资源抽屉里的知识卡应减少抽象概念，改为完成当前任务所需的最小解释；
6. 能力地图点击节点后，不只打开资源名，还应定位到对应教材正文段落或练习。

如果以上内容级修正没有完成，继续增加动画、卡片样式或地图效果，对“学生看完仍然不会学”的问题帮助有限。

## 7. 3.2文本质量门禁

后续把本稿写入前端前，至少应按以下标准检查：

1. 学生进入后能在30秒内知道自己面对的是哪一个真实问题；
2. 每个专业词都只解释完成任务所需的含义，不扩展成通信理论讲义；
3. 每个数据表后都有“能说明什么、不能说明什么”；
4. 每个学习段落都有学生动作，不只是阅读；
5. 每个练习后有可理解的反馈或修改示范；
6. 课堂模式和自学模式在学习组织方式上有差异；
7. 结论示例包含判断状态、数据依据、边界说明和后续建议；
8. 所有教学模拟数据、阈值和专业判断均标注待专业复核。

这些门禁通过后，再进入样章3.2前端改造更稳妥。
