## P4T2-C01 情境卡：视频卡顿是不是优化没做好？

卡片类型：情境卡  
能力节点：识别优化验证场景  
来源：原教材任务导入 + AI 教学重构  
审核状态：待专家审核  
建议时长：3 分钟

### 学生可见内容

你现在扮演网络优化助理工程师。某校园区域完成了一轮 5G 网络优化，优化人员反馈“覆盖问题已经处理，站点参数也已调整”。但是，晚间学生宿舍区仍有人反馈两个问题：

1. 微信视频通话偶发卡顿；
2. 直播上行时延偏高，推流画面偶尔延迟。

现场已有一组优化前后数据，包括覆盖指标、切换流程记录、端到端性能指标和仿真软件截图。你的任务不是马上判断“优化成功”或“优化失败”，而是先判断：这个问题更可能与哪类验证对象有关？

本任务需要你最终完成一份简短结论：

> 本次 5G 网络优化结果是否达标？你的判断依据是什么？如果证据不足，还需要补充哪些数据？

### 学习动作

请先写出一句初步判断，格式如下：

> 我认为当前问题可能主要与____有关，因为____。但我还需要查看____证据。

### 反馈规则

如果学生只写“网络不好”“优化没做好”，提示其补充问题类型。  
如果学生能指出覆盖、切换、时延、速率、容量或掉线中的一个方向，判定为可进入下一卡。  
如果学生主动提出“证据不足”，判定为较好，因为优化验证必须依赖证据链。

### 学习证据

初步判断文本。

## P4T2-C02 诊断交互卡：问题可能属于哪一类？

卡片类型：诊断交互卡  
能力节点：区分覆盖、切换、性能问题  
来源：原教材任务要求 + AI 教学重构  
审核状态：待专家审核  
建议时长：3 分钟

### 学生可见内容

原教材把本任务分为六类优化结果验证：覆盖、切换、时延、速率、容量、掉线。真实工作中，这六类问题经常互相关联，但分析时不能混在一起。你需要先做问题分流，再看对应证据。

请选择你认为最需要优先验证的方向，可多选：

1. 覆盖问题：信号强度或质量不足，可能导致卡顿、掉线或速率低；
2. 切换问题：移动过程中小区切换过早、过晚、失败或频繁切换；
3. 端到端性能问题：时延、速率、容量等指标影响业务体验；
4. 掉线或业务保持问题：业务过程中连接异常释放或长时间无数据；
5. 证据不足：目前不能判断，需要继续查看数据。

### 学习动作

完成两步：

1. 选择 1 至 3 个最可能方向；
2. 写出你选择它们的理由。

### 反馈规则

- 选择覆盖：提示查看 SS-RSRP、SS-SINR、弱覆盖和交叉覆盖证据；
- 选择切换：提示查看测量报告、A 类/B 类事件、SA/NSA 切换流程；
- 选择端到端性能：提示查看时延、速率、容量和业务体验指标；
- 选择掉线：提示查看异常释放、RLF、重建立、切换失败等证据；
- 选择证据不足：提示其后续必须说明缺什么证据，不能停留在“不知道”。

没有唯一正确答案。优秀答案应能说明“为什么先看这些证据”。

### 学习证据

问题类型选择记录、修改记录、选择理由。

## P4T2-C03 知识卡：覆盖验证看什么

卡片类型：知识卡  
能力节点：理解覆盖验证指标  
来源：原教材“覆盖优化基础知识”重构  
审核状态：待专家审核  
建议时长：3 分钟

### 学生可见内容

覆盖优化是网络业务和性能的基础。原教材指出，5G NR 覆盖优化主要处理覆盖空洞、弱覆盖、越区覆盖和导频污染等问题。从现场可实施角度，可以先归纳为两类：弱覆盖和交叉覆盖。

覆盖验证最常看的指标是 SS-RSRP 和 SS-SINR：

| 指标 | 可以帮助判断什么 | 学习提示 |
| --- | --- | --- |
| SS-RSRP | 同步信号接收功率，反映信号强度 | 数值过低通常提示弱覆盖风险 |
| SS-SINR | 同步信号信干噪比，反映信号质量 | 数值差可能提示干扰或交叉覆盖风险 |

原教材表4-2-1给出中国电信 5G NR 边缘覆盖要求。例如，在宽波束、城区和一般城区场景下，可参考 SS-RSRP≥-105 dBm、SS-SINR≥-7 dB 的覆盖率要求。原文后续写到“SS-RSRP≥105dBm”，本样章暂按“≥-105 dBm”理解，需专家审核。

需要注意：覆盖改善不等于业务体验一定改善。视频卡顿和直播上行时延还可能与切换、传输、核心网、服务器、容量或终端有关。因此，覆盖验证只能回答“覆盖是否改善”，不能单独证明“端到端优化全部达标”。

### 学习动作

判断下面说法是否成立：

1. SS-RSRP 主要用于观察信号强度；
2. SS-SINR 主要用于观察信号质量和干扰情况；
3. 只要覆盖指标达标，就能证明视频通话一定不卡顿。

### 反馈规则

前两项应判断为成立。第三项应判断为不成立，因为视频通话卡顿还可能由时延、切换、容量、传输或应用侧问题导致。

### 学习证据

指标含义判断结果。

## P4T2-C04 证据卡：优化前后覆盖指标对比

卡片类型：证据卡  
能力节点：判断覆盖优化效果  
来源：原教材覆盖指标要求 + 教学模拟数据  
审核状态：待专家审核  
建议时长：3 分钟

### 学生可见内容

下面是一组教学模拟数据，用于练习覆盖验证。正式项目中应以实测数据、路测报告、网管数据或仿真平台导出结果为准。

| 覆盖指标 | 参考要求 | 优化前 | 优化后 | 初步判断 |
| --- | ---: | ---: | ---: | --- |
| SS-RSRP≥-105 dBm 覆盖率 | ≥95% | 88.4% | 96.3% | 已达到参考要求 |
| SS-SINR≥-7 dB 覆盖率 | ≥95% | 84.2% | 94.1% | 接近但未达到参考要求 |
| 弱覆盖采样点占比 | 越低越好 | 12.6% | 3.8% | 明显改善 |
| 交叉覆盖疑似区域数 | 越少越好 | 8 个 | 3 个 | 有改善但仍需核查 |

从这组数据看，优化后 SS-RSRP 覆盖率已经达到参考要求，弱覆盖问题明显改善；但 SS-SINR 覆盖率仍低于 95%，说明信号质量或干扰问题可能没有完全解决。此时不能直接写“覆盖优化完全达标”，更稳妥的结论是“覆盖强度基本达标，覆盖质量仍需进一步核查”。

### 学习动作

请完成三项判断：

1. 哪些指标支持“覆盖有改善”？
2. 哪些指标提示“覆盖仍未完全达标”？
3. 这组覆盖数据能否单独证明视频卡顿问题已解决？

### 反馈规则

较好答案应包含：

- 支持改善的证据：SS-RSRP 覆盖率提升、弱覆盖采样点下降、交叉覆盖疑似区域减少；
- 未完全达标的证据：SS-SINR 覆盖率只有 94.1%，未达到 95% 参考要求；
- 证据边界：覆盖数据不能单独证明端到端业务体验已恢复，还需看切换和性能指标。

### 学习证据

覆盖证据标注、证据边界判断。

## P4T2-C05 知识卡：切换验证看什么

卡片类型：知识卡  
能力节点：理解切换事件与流程  
来源：原教材“切换优化基础知识”重构  
审核状态：待专家审核  
建议时长：3 分钟

### 学生可见内容

切换指终端从一个小区或信道变更到另一个小区或信道时，业务仍能继续进行。原教材指出，5G NR 切换流程与 4G 类似，仍包括测量、判决、执行三个阶段。

切换验证要重点看两类内容：

| 内容 | 作用 | 教学化理解 |
| --- | --- | --- |
| 测量事件 | 判断终端什么时候上报信号变化 | 终端告诉网络“我这里信号变化了” |
| 切换流程 | 判断网络是否及时、正确完成切换 | 网络决定“要不要切、切到哪里、是否成功” |

A 类事件主要用于 NR 系统内或频内/频间测量与切换，B 类事件主要用于异系统邻区测量。例如：

- A2：服务小区信号低于门限，常用于打开测量；
- A3：邻区信号比服务小区高出一定偏移，常用于触发切换；
- A5：服务小区低于门限1且邻区高于门限2，适合需要快速切换的场景；
- B1/B2：关注异系统邻区，常用于系统间切换或互操作。

切换异常可能导致视频通话中断、卡顿或掉线。常见问题包括切换不及时、切换过早、邻区漏配、PCI 冲突、随机接入失败等。

### 学习动作

把下面事件与含义匹配：

1. A2  
2. A3  
3. A5  
4. B1/B2

选项：

A. 邻区比服务小区更好，常用于切换触发；  
B. 服务小区低于门限且邻区满足条件，适合时间关键切换；  
C. 服务小区低于门限，通常提示需要打开测量；  
D. 异系统邻区测量或系统间切换相关。

### 反馈规则

正确匹配：A2-C，A3-A，A5-B，B1/B2-D。  
若学生混淆 A3 和 A5，提示其区分“相对更好”和“双门限条件”。  
若学生把 B 类事件也理解为普通 NR 内切换，提示其关注“异系统”。

### 学习证据

切换事件识别结果。

## P4T2-C06 交互卡：切换流程是否合理？

卡片类型：交互卡  
能力节点：判断切换验证流程合理性  
来源：原教材 SA/NSA 切换流程重构  
审核状态：待专家审核  
建议时长：4 分钟

### 学生可见内容

下面是 SA 组网下基于 Xn 接口切换的教学化步骤。请将步骤排成合理顺序。

待排序步骤：

A. 源 gNodeB 根据测量上报判决是否切换；  
B. UE 上报测量结果；  
C. 源 gNodeB 通过 Xn 接口向目标 gNodeB 申请资源；  
D. 目标 gNodeB 完成目标小区资源准备；  
E. 源 gNodeB 通过空口重配消息通知 UE 切换；  
F. UE 接入目标小区并完成切换；  
G. 目标 gNodeB 通知源 gNodeB 释放原小区无线资源；  
H. 源 gNodeB 未发送数据转发到目标侧，并更新用户面、控制面路径。

### 学习动作

完成两项：

1. 拖拽或填写正确顺序；
2. 判断下面异常更可能发生在哪个阶段：  
   “终端已经上报测量报告，但网络侧一直未下发切换命令。”

### 反馈规则

参考顺序：B -> A -> C -> D -> E -> F -> G -> H。

异常判断：  
“上报测量报告后未收到切换命令”应优先检查判决和命令下发阶段，也要排查邻区配置、切换参数、基站状态和传输状态。原教材的掉话案例中，邻区漏配会导致终端上报 MR 后仍未收到切换命令，最终引发掉话。

如果学生只把异常归因于“终端坏了”，提示其先看基站、邻区、切换参数和信令流程证据。

### 学习证据

流程排序结果、异常阶段判断。

## P4T2-C07 知识卡：端到端性能验证看什么

卡片类型：知识卡  
能力节点：理解端到端性能指标  
来源：原教材时延、速率、容量、掉线基础知识重构  
审核状态：待专家审核  
建议时长：3 分钟

### 学生可见内容

端到端性能验证关注用户业务是否真正变好。原教材分别介绍了时延、速率、容量和掉线。

| 验证对象 | 关注问题 | 与业务体验的关系 |
| --- | --- | --- |
| 时延 | 数据从发送端到接收端或服务器返回的时间 | 影响视频通话、直播、远程控制等实时业务 |
| 速率 | 单位时间内传送的数据量，常用吞吐率表示 | 影响下载、上传、高清视频和直播推流 |
| 容量 | 系统可承载用户数或业务量 | 高负荷区域可能出现拥塞、速率下降 |
| 掉线 | 业务保持过程中异常释放或长时间无数据 | 用户直接感知为断连、掉话或业务中断 |

原教材指出，端到端时延受到终端、无线接入网、传输网、核心网和应用服务器等多个环节影响。因此，如果覆盖已经改善，但直播上行仍延迟，不能只继续盯着 RSRP，还要看上行速率、端到端时延、容量负荷和掉线记录。

### 学习动作

判断下面业务投诉应优先查看哪些指标：

1. 微信视频偶发卡顿；
2. 直播上行延迟明显；
3. 晚高峰下载速度下降；
4. 业务过程中突然断开。

### 反馈规则

参考判断：

- 视频偶发卡顿：时延、抖动、切换、掉线、无线质量；
- 直播上行延迟：上行速率、上行时延、容量负荷、传输链路；
- 晚高峰下载速度下降：下行速率、容量、小区负荷；
- 业务突然断开：掉线率、RLF、重建立、切换失败。

### 学习证据

业务现象与指标匹配结果。

## P4T2-C08 证据卡：业务体验与性能指标对照

卡片类型：证据卡  
能力节点：判断性能优化效果  
来源：原教材性能指标框架 + 教学模拟数据  
审核状态：待专家审核  
建议时长：3 分钟

### 学生可见内容

下面是一组教学模拟数据，用于练习端到端性能判断。该数据不是正式验收阈值，仅用于样章任务。

| 指标 | 样章参考目标 | 优化前 | 优化后 | 判断 |
| --- | ---: | ---: | ---: | --- |
| 视频通话平均端到端时延 | ≤50 ms | 78 ms | 42 ms | 已改善并达到样章目标 |
| 直播上行 95 分位时延 | ≤80 ms | 180 ms | 110 ms | 明显改善但未达目标 |
| 上行平均吞吐率 | ≥15 Mbps | 8 Mbps | 16 Mbps | 达到样章目标 |
| 晚高峰小区负荷 | ≤70% | 86% | 74% | 仍偏高 |
| 10 分钟业务卡顿次数 | ≤1 次 | 6 次 | 2 次 | 改善但未达目标 |
| 掉线次数 | 0 次 | 1 次 | 0 次 | 达到样章目标 |

这组数据说明，优化后性能总体改善，但直播上行时延、晚高峰小区负荷、卡顿次数仍未完全达标。因此，如果最终结论写“全部优化完成且业务体验恢复正常”，证据不足。

### 学习动作

请完成三项：

1. 选出已经达到样章参考目标的指标；
2. 选出仍未达标或需要继续核查的指标；
3. 判断本次优化结果应写成“达标”“部分达标”“未达标”还是“无法判断”。

### 反馈规则

较好答案应判断为“部分达标”。理由是覆盖强度、视频平均时延、上行吞吐率和掉线次数已有明显改善，但直播上行 95 分位时延、晚高峰负荷和卡顿次数仍未达到样章目标。

如果学生判断“达标”，提示其说明为什么忽略未达标指标。  
如果学生判断“未达标”，提示其区分“完全无效”和“部分改善”。  
如果学生判断“无法判断”，提示其指出缺失证据，而不是笼统否定。

### 学习证据

性能证据判断、达标状态选择。

## P4T2-C09 证据卡：仿真截图能说明什么

卡片类型：证据卡  
能力节点：使用仿真结果辅助验证  
来源：原教材任务实施图片 image287 至 image293  
审核状态：待编辑审核  
建议时长：2 分钟

### 学生可见内容

原教材任务实施要求学生登录网络优化仿真软件，在 step4 中查询站点的覆盖、切换、容量、掉话、速率、时延等优化结果。对应资源包括：

| 图片 | 内容 |
| --- | --- |
| image287 | 仿真软件 step4 查询界面 |
| image288 | 覆盖优化结果 |
| image289 | 切换优化结果 |
| image290 | 时延优化结果 |
| image291 | 速率优化结果 |
| image292 | 容量优化结果 |
| image293 | 掉线优化结果 |

仿真截图的价值是：帮助你快速看到某一站点或场景下的结果变化，并把分散指标放回任务场景中。但截图也有边界：截图本身通常不能替代完整测试报告，不能单独证明真实用户体验完全恢复，也不能说明长期稳定性。

### 学习动作

请判断仿真截图在证据链中适合支持哪些结论：

1. 可以辅助说明某站点覆盖、切换、时延、速率、容量、掉线等结果；
2. 可以单独证明所有真实用户都不会卡顿；
3. 可以作为任务单中的证据之一；
4. 可以替代所有原始指标和路测记录。

### 反馈规则

正确判断：1 和 3 成立，2 和 4 不成立。  
若学生过度依赖截图，提示其补充指标表、日志、路测、网管或业务侧数据。  
若学生完全否定截图价值，提示其截图可以作为教学演练和站点结果观察材料。

### 学习证据

仿真证据边界判断。

P4T2-C10 写出优化结果验证结论。

## P4T2-C10 任务卡：写出优化结果验证结论

卡片类型：任务卡  
能力节点：形成优化结果验证结论  
来源：原教材任务实施与任务测评重构  
审核状态：待专家审核  
建议时长：4 分钟

### 学生可见内容

你已经查看了覆盖、切换、端到端性能和仿真截图证据。现在请形成一份结构化验证结论。注意：验证结论不是一句“好”或“不好”，而是要说明判断、依据和后续建议。

### 学习动作

请填写任务单：

| 字段 | 填写要求 |
| --- | --- |
| 问题类型判断 | 覆盖、切换、时延、速率、容量、掉线、证据不足，可多选 |
| 核心证据 | 至少选择 2 条证据 |
| 优化前后变化 | 写出 2 至 4 个关键指标变化 |
| 是否达标 | 达标、部分达标、未达标、无法判断 |
| 判断理由 | 80 至 150 字 |
| 后续建议 | 1 至 2 条 |

### 参考作答框架

可以按以下结构写：

> 本次优化结果可判断为____。依据是：____指标从____改善到____，说明____；但____指标仍未达到____，说明____。因此，建议后续重点核查____，并补充____数据。

### 反馈规则

高质量结论应满足：

1. 有明确达标状态；
2. 至少引用两类证据；
3. 不把局部改善等同于整体达标；
4. 能说明证据不足或后续核查方向；
5. 语言简洁，适合工程记录。

低质量结论包括：

- “优化成功了”，但没有指标依据；
- “网络还有问题”，但没有指出问题类型；
- 只引用覆盖数据，不看业务体验；
- 只引用截图，不看指标变化；
- 把教学模拟目标当成正式运营商验收标准。

### 学习证据

结构化短报告。

## P4T2-C11 反馈卡：你的证据链完整吗？

卡片类型：反馈卡  
能力节点：修正证据链与表达  
来源：AI 教学重构  
审核状态：待专家审核  
建议时长：2 分钟

### 学生可见内容

请用下面的清单检查你的验证结论：

| 自查问题 | 是/否 |
| --- | --- |
| 我是否说明了“达标、部分达标、未达标或无法判断”？ |  |
| 我是否至少引用了覆盖和性能两类证据？ |  |
| 我是否说明了未达标或证据不足的部分？ |  |
| 我是否避免了“覆盖改善 = 全部业务恢复”的错误？ |  |
| 我是否给出了后续核查建议？ |  |

### 常见误区

1. 只看 SS-RSRP，不看 SS-SINR 和业务体验；
2. 只看平均时延，不看 95 分位时延或卡顿次数；
3. 只看仿真截图，不看原始指标；
4. 把“部分改善”写成“完全达标”；
5. 把“无法判断”当成结论，但没有说明缺什么证据。

### 参考反馈

如果你的结论是“部分达标”，可以这样表达：

> 本次优化结果可判断为部分达标。覆盖强度明显改善，SS-RSRP 覆盖率达到样章参考要求，弱覆盖采样点明显下降；视频通话平均时延、上行吞吐率和掉线次数也有改善。但 SS-SINR 覆盖率仍低于参考要求，直播上行 95 分位时延和晚高峰负荷仍未达目标。因此，后续应继续核查干扰、交叉覆盖、容量负荷和上行链路性能，并补充真实业务侧测试数据。

### 学习动作

根据自查结果修改你的结论，至少修改一处理由、证据或后续建议。

### 反馈规则

如果学生修改后补充了证据，判定为“证据链增强”。  
如果学生只改了措辞，未补充证据，提示其回到 C04 或 C08。  
如果学生能说明“证据能支持什么、不能支持什么”，判定为优秀。

### 学习证据

修订记录、最终结论。

## P4T2-C12 教师卡：课堂讲评与学情观察

卡片类型：教师卡  
能力节点：组织讲评与观察学情  
来源：AI 教学重构  
审核状态：待教师审核  
建议时长：教师课前 5 分钟浏览，课堂讲评 5 至 8 分钟

### 教师可见内容

本卡用于教师组织课堂，不展示为学生主学习卡。样章阶段下列学情数据均为模拟数据，不能声称来自真实课堂。

### 教学目标

本任务不是让学生背诵全部 5G 网优参数，而是训练一个最小能力闭环：

1. 能把业务问题分流到覆盖、切换、端到端性能等验证方向；
2. 能读懂 SS-RSRP、SS-SINR、切换事件、时延、速率、容量、掉线等基本证据；
3. 能用证据写出“达标、部分达标、未达标或无法判断”的短结论。

### 模拟学情看板

| 指标 | 模拟结果 | 讲评含义 |
| --- | ---: | --- |
| 完成人数 | 38/42 | 大部分学生能完成任务 |
| 首次判断选择“覆盖问题”的比例 | 71% | 学生容易从信号强度入手 |
| 同时选择“性能问题”的比例 | 43% | 仍需强调端到端体验 |
| 判断“完全达标”的比例 | 31% | 部分学生忽略未达标指标 |
| 漏选 SS-SINR 未达标证据的比例 | 48% | 需要讲 SS-RSRP 和 SS-SINR 区别 |
| 漏写后续建议的比例 | 52% | 需要训练工程结论表达 |

### 建议讲评顺序

1. 先展示学生选择分布，让学生看到大家为何容易先判断覆盖；
2. 对比 SS-RSRP 和 SS-SINR，说明强度改善不等于质量完全达标；
3. 引导学生查看直播上行 95 分位时延和晚高峰负荷；
4. 讲解“部分达标”的表达方式；
5. 选取一份证据链完整的学生结论和一份证据不足的结论对比讲评。

### 教师动作

教师使用本卡时完成三件事：

1. 课前选择本节课保留哪些学生卡，基础较弱班级可只保留 C01、C02、C04、C08、C10、C11；
2. 课堂中查看学生的问题类型选择、证据漏选和最终结论；
3. 课后根据学生结论样本，决定是否补讲覆盖质量、切换流程或端到端性能证据。

### 反馈规则

如果多数学生判断“完全达标”，教师应追问其是否忽略 SS-SINR、直播上行时延和晚高峰负荷。  
如果多数学生判断“无法判断”，教师应要求其明确缺失证据类型。  
如果学生结论普遍没有后续建议，教师应补讲工程结论的基本表达：判断状态、核心依据、证据边界、后续动作。

### 教师可调整项

- 基础较弱班级：减少 A 类/B 类事件细节，只保留 A2、A3、A5；
- 基础较好班级：增加 SA/NSA 切换流程对比；
- 实训课：加入仿真软件实际操作；
- 理论课：重点做证据链判断和短报告表达；
- 课后作业：要求学生补写完整网优验证报告。

### 教师注意事项

1. 不要把教学模拟数据作为正式运营商验收标准；
2. 专业阈值和结论模板需专家复核；
3. 如果课堂时间不足，优先保留 C01、C02、C04、C08、C10、C11；
4. 页面美观度不是主要评价标准，关键看学生能否完成判断并形成证据链。

### 学习证据

教师讲评记录、模拟学情看板、学生最终结论样本。
