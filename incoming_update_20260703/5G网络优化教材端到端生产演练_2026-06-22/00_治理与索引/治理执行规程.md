# 治理执行规程

生成日期：2026-06-22  
用途：把“持续更新治理文件”从依赖记忆的习惯，变成后续任务必须执行的操作规程。

## 1. 为什么需要本规程

本任务周期长、文件多、判断持续演化。仅靠对话上下文记忆不可靠，尤其在上下文压缩后，容易出现以下风险：

1. 新文件生成了，但没有进入索引；
2. 新决策形成了，但没有写入决策日志；
3. 设计原则变化了，但质量门禁没有更新；
4. 旧样本被误认为当前成果；
5. 下一步任务在上下文压缩后丢失；
6. 继续执行时跳过治理层，直接改原型或写报告。

因此，治理文件本身也必须被治理。本规程就是治理层的更新规则。

## 2. 每次继续任务的启动动作

后续每次继续本任务，尤其是用户输入“继续”“治理”“下一步”“开始实施”“生成样章”“检查资产”等指令时，应先读取：

1. `00_治理与索引/README_先读我.md`
2. `00_治理与索引/治理执行规程.md`
3. `00_治理与索引/任务连续性记录.md`
4. `00_治理与索引/数字教材样章设计原则与质量门禁.md`
5. `00_治理与索引/决策日志.md`
6. `00_治理与索引/资产总表.md`

如果任务涉及具体实现，再继续读取相关报告、样章代码和QA文件。

## 3. 每次阶段结束前的收尾动作

每次完成一个阶段性动作后，必须做一次轻量治理检查。

阶段性动作包括：

1. 新增报告、计划、规范、样章、资源包、QA结果；
2. 修改主线设计方向；
3. 形成新的原则、门禁或术语约定；
4. 用户提出新的硬性要求；
5. 旧文件被判定为历史版本或不再适用；
6. 从设计阶段进入实现阶段；
7. 从实现阶段进入评审或QA阶段；
8. 完成一次浏览器QA、媒体审查或资源包输出。

检查后，应判断是否需要更新本规程第4节列出的治理文件。

## 4. 治理文件更新触发器

| 发生的变化 | 必须更新的文件 |
| --- | --- |
| 新增主线报告、样章、资源包、QA结果 | `成果索引.md`、`资产总表.md`、`任务连续性记录.md` |
| 新增或改变关键决策 | `决策日志.md`、`任务连续性记录.md` |
| 新增或改变设计原则、质量标准、语言规范 | `数字教材样章设计原则与质量门禁.md`、`决策日志.md` |
| 用户提出新的长期约束 | `任务连续性记录.md`，必要时更新 `数字教材样章设计原则与质量门禁.md` |
| 某个文件从当前主线降级为历史版本 | `资产总表.md`、`成果索引.md`，必要时更新 `任务连续性记录.md` |
| 新增治理文件 | `README_先读我.md`、`资产总表.md`、`成果索引.md` |
| 下一步任务发生变化 | `任务连续性记录.md` |
| QA环境、运行方式、验证命令发生变化 | `任务连续性记录.md`、相关样章README |
| 原型目录结构发生变化 | `资产总表.md`、`成果索引.md`、相关README |

## 5. 最小治理检查清单

每次轻量治理检查至少回答以下问题：

1. 是否新增了文件；
2. 新文件是否进入 `成果索引.md`；
3. 新文件是否在 `资产总表.md` 中被分级；
4. 是否形成了新决策；
5. 新决策是否进入 `决策日志.md`；
6. 是否形成了新原则或新门禁；
7. 新原则是否进入 `数字教材样章设计原则与质量门禁.md`；
8. 当前阶段和下一步是否写入 `任务连续性记录.md`；
9. 是否有旧文件需要降级为历史版本；
10. 是否存在“看起来像成果、实际只是过程记录”的文件需要标注。

如果答案中有任一项为“是”，应更新对应治理文件。

## 6. 治理文件自身的优先级

| 优先级 | 文件 | 作用 |
| --- | --- | --- |
| G0 | `README_先读我.md` | 入口和恢复顺序 |
| G0 | `治理执行规程.md` | 规定治理文件如何持续更新 |
| G0 | `任务连续性记录.md` | 当前状态和下一步 |
| G0 | `数字教材样章设计原则与质量门禁.md` | 长期原则和质量约束 |
| G0 | `决策日志.md` | 关键决策和开放问题 |
| G0 | `资产总表.md` | 文件主次、分级和用途 |
| G1 | `成果索引.md` | 全局成果入口 |

如果这些文件互相不一致，优先处理顺序是：

1. 先修正 `任务连续性记录.md` 的当前状态；
2. 再修正 `决策日志.md` 的关键判断；
3. 再修正 `数字教材样章设计原则与质量门禁.md` 的原则；
4. 再修正 `资产总表.md` 和 `成果索引.md` 的索引；
5. 最后检查 `README_先读我.md` 的读取顺序是否仍正确。

## 7. 治理更新的粒度

治理更新不要求每次都重写所有文件。应按影响范围选择最小更新：

1. 只是阶段进度变化：更新 `任务连续性记录.md`；
2. 只是新增普通过程文件：更新 `资产总表.md`，必要时更新 `成果索引.md`；
3. 新增主线成果：更新 `成果索引.md`、`资产总表.md`、`任务连续性记录.md`；
4. 新增原则：更新 `数字教材样章设计原则与质量门禁.md` 和 `决策日志.md`；
5. 改变路线：更新 `决策日志.md`、`任务连续性记录.md`、`README_先读我.md`，必要时更新 `资产总表.md`。

## 8. 用户可定期触发的治理提示词

用户后续可以输入：

```text
请执行一次过程资产治理与连续性检查：先读取 00_治理与索引 下的 README、治理执行规程、任务连续性记录、设计原则与质量门禁、决策日志、资产总表；然后检查新增/修改资产，更新必要的治理文件和成果索引，确认当前主线、关键决策、设计原则、下一步任务是否仍然清晰。不要移动文件，优先更新治理层。最后简短汇报结果。
```

执行该提示词时，必须优先按本规程操作。

## 9. 不允许依赖记忆的事项

以下事项不得只依赖对话记忆，必须写入文件：

1. 用户提出的长期约束；
2. 路线选择；
3. 放弃或排除的依据；
4. 样章主形态；
5. 教师端和学生端边界；
6. 能力图谱角色；
7. 媒体治理要求；
8. 语言表达要求；
9. QA环境和可复跑命令；
10. 下一步任务入口。

## 10. 本规程的更新规则

如果后续发现治理流程仍有漏洞，可以修改本规程。但修改时必须同步更新：

1. `README_先读我.md` 的读取顺序；
2. `任务连续性记录.md` 的当前状态；
3. `决策日志.md` 的相关决策；
4. `资产总表.md` 的S0治理资产列表；
5. `成果索引.md` 的治理入口。
