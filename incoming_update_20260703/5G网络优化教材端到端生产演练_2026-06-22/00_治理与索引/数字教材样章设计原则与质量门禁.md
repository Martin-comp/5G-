# 数字教材样章设计原则与质量门禁

生成日期：2026-06-22  
用途：收口本任务已经形成的设计原则，作为后续样章3.0、技术方案和工具链建设的硬性约束。

## 1. 总原则

本任务的目标不是生成一个演示网页，而是验证一套面向职业教育数字教材的AI生产流程。最终成果必须同时能服务三件事：

1. 生成可上传到出版社平台的资源包；
2. 生成可直接挂接到出版社平台的数字教材呈现层；
3. 通过一本真实教材的端到端演练，识别流程、样本、瓶颈和标准门禁。

## 2. 输入原则

现实输入可能非常不完整。工具链不能假设用户一定提供完整教材资源。

输入情况按质量从低到高分为：

1. 只有教学大纲或课程标准；
2. 只有一本传统电子教材；
3. 有教材、大纲、课程标准、PPT、题库、视频、实训资料等多类资源；
4. 有完整教学资源和平台数据。

当输入不足时，必须允许通过互联网检索、政策标准检索、专业依据检索来补足背景，但所有补足内容都要标注来源、适用边界和审核状态。

输入教材、教学大纲或课程标准只是生产起点，不是内容上限。AI生产工具链不能被原教材质量完全锁死：如果原教材存在过时、缺漏、表达不清、媒体不可用、案例不真实、知识组织不适合学生学习等问题，应结合大模型知识储备、可信互联网来源、政策标准、专业教学标准、职业技能标准和行业材料进行纠偏、补强和扩展。

补强后的内容必须区分来源和审核状态：

1. 原教材内容；
2. AI基于已有知识的教学化改写或推断；
3. 来自可信互联网来源的补充材料；
4. 来自政策、标准或专业教学标准的依据；
5. 需要专业教师或行业专家复核的技术判断。

不能把原教材中的错误或薄弱表达原样数字化，也不能把AI扩展内容伪装成原教材内容或已审核事实。

## 3. 输出原则

输出分为两类，不能混淆：

1. 资源输出：形成可上传到出版社平台的结构化资源包，由出版社平台继续编辑和呈现；
2. 直接呈现输出：生成完整数字教材前端，可挂接到出版社平台。

资源输出重在规范、颗粒、元数据、审核状态。  
直接呈现输出重在教材性、可读性、学习闭环、教师可用性和平台适配。

## 4. 端到端演练原则

不应先分散制作局部工具链。当前阶段应先用一本教材走通完整流程，再反推工具链模块。

已选定演练对象：

1. 输入教材：`/Users/ny/Downloads/5G网络优化教材（高级).docx`
2. 深度样章对象：项目四 / 任务2：5G网络优化结果验证

端到端演练必须产出：

1. 输入诊断；
2. 内容抽取；
3. 结构识别；
4. 能力图谱；
5. 资源拆分；
6. 样章设计；
7. 资源包样本；
8. 直接呈现样本；
9. QA和质量门禁；
10. 瓶颈和下一步技术方案。

## 5. 依据原则

本任务不采用1+X作为依据。此前已经明确：1+X已移交人社部，当前任务不应继续围绕1+X展开。

后续依据应优先来自：

1. 教育部数字教材政策文件；
2. 数字教材出版业务流程、平台功能、内容要素、质量检测等相关标准；
3. 职业教育专业教学标准；
4. 国家职业技能标准；
5. 通信行业真实岗位能力要求；
6. 课程能力图谱相关政策与专家阐释。

所有依据都应区分“政策要求”“标准要求”“专家观点”“本任务推断”，不能混写。

## 6. 教材性原则

数字教材首先是教材，不是网页、课件、知识库或资源展示平台。

面向一线教师和学生的样章必须满足：

1. 学生能读懂；
2. 教师能拿来教；
3. 学生能完成任务；
4. 教师能组织讲评；
5. 内容之间有逻辑衔接；
6. 每个资源单元有完整内容，不只是标题；
7. 学习任务、专业判断和反馈修正形成闭环。

好看的页面不能替代教材性。只有标题、卡片、动画或占位图的Demo，不能视为合格数字教材样章。

## 7. 语言表达原则

学生端和教师端语言必须教材化，不能过度机器化。

底层可以有“能力节点、资源卡片、证据项、状态字段、元数据、映射关系”，但前端面向学生时应转译为教学语言。

| 后台或机器化表达 | 学生端建议表达 |
| --- | --- |
| 能力节点未完成 | 你还没有完成“判断问题类型”这一步 |
| 请选择证据项 | 请选择一条支持你判断的数据 |
| 证据链不完整 | 你的结论还缺少依据，请再查看切换或性能数据 |
| 资源卡片P4T2-C04 | 覆盖指标对比 |
| 点击节点跳转卡片 | 查看这个知识点相关内容 |
| 媒体资源待审核 | 这张图还需要教师或编辑确认后才能正式使用 |

学生端应多使用：

1. 我现在要解决什么问题；
2. 我需要看哪些数据；
3. 这些数据说明什么；
4. 这些数据还不能说明什么；
5. 我的判断依据是什么；
6. 我还需要补充什么。

教师端可以使用教学语言，如教学目标、课堂组织、常见误区、讲评建议、学情观察。

出版社和平台后台才使用资源、元数据、审核状态、接口字段等管理语言。

## 8. 卡片原则

卡片是最小资源单元，不是天然的页面单元。

一张合格卡片必须至少包含：

1. 明确学习目标；
2. 完整内容；
3. 学习动作；
4. 与能力图谱节点的关系；
5. 完成后产生的学习记录或判断结果；
6. 与前后任务的衔接；
7. 审核状态。

卡片可以是文字、图表、音频、视频、交互动画、小游戏、任务单、反馈卡等。但不能只是一句标题或漂亮封面。

## 9. 页面形态原则

样章3.0不应继续以“线性卡片翻页”作为主形态。

推荐结构是：

1. 任务工作台作为主界面；
2. 卡片作为资源层；
3. 能力图谱作为可展开、可点击的探索导航层；
4. 学习依据和学习记录作为产出层；
5. 教师讲评作为独立支持层。

第一屏应让学生看到真实任务，而不是封面、目录或卡片列表。

## 10. 能力图谱原则

能力图谱是数字教材的关键纽带，但不建议作为第一屏主形态。

能力图谱在3.0中的建议角色是“局部导航层”：

1. 学生可打开完整图谱；
2. 图谱节点可点击、可展开；
3. 点击节点后显示相关知识、任务、数据、练习和完成状态；
4. 节点可以跳转到相关卡片，但不应只是跳转目录；
5. 图谱应显示前置关系、后续关系和当前学习位置；
6. 教师可用图谱观察学生在哪些能力点卡住。

更准确的关系是：

```text
任务工作台是主界面
能力图谱是导航层
卡片是资源单元
学习记录是产出
```

### 10.1 课程能力图谱字段规范原则

课程能力图谱不能只停留在可视化层。后续新增、试拆或迁移节点的基础字段必须按 `reports/课程能力图谱字段规范V0.2.md` 和 `reports/课程能力图谱字段规范V0.2字段清单.csv` 执行；涉及个人信息、电话录音、客户授权、服务承诺、案例真实性、资源发布、评价敏感性和门禁状态的对象，还必须按 `reports/课程能力图谱字段规范V0.4升级方案.md` 和 `reports/课程能力图谱字段规范V0.4字段清单.csv` 补充风险治理字段。V0.1保留为P5-T3第二试拆的历史依据，不再作为后续新增节点主规范。

最低要求：

1. 节点必须有稳定 `node_id`，不得使用不可追溯的临时编号；
2. 节点层级、岗位工作过程、能力单元、资源类型、学习活动类型、审核状态和来源类型必须使用受控枚举；
3. 详细能力节点必须写明前置节点、后续节点、学生端表达、学生动作、评价产出和掌握标准；
4. 能力节点必须能挂接资源卡片、学习活动、评价产出和学习记录事件；
5. 学生端不得直接暴露节点ID、审核状态、资源生产状态、证据编号等后台字段；
6. 专业判断、媒体资源、AI补强内容和教学模拟案例必须保留审核状态和风险说明；
7. 后续节点迁移或试拆至少必须完整填写字段规范V0.2中的R1字段；进入V0.4回填试验或涉及高风险治理对象时，还必须填写V0.4要求的R1风险治理字段；
8. `primary_job_process_id` 和 `primary_ability_unit_id` 必须唯一，次级挂接写入 `secondary_job_process_ids` 和 `secondary_ability_unit_ids`；
9. 三任务横向对比确认字段口径未统一前，不得进入全书批量详细拆分；
10. P2-T3、P4-T2、P5-T3等已试拆任务必须逐步迁移到V0.2字段规范，不能让旧12/13字段表、V0.1 59字段表与V0.2字段表长期并存为同等主数据；
11. AU-10“信令分析与复杂问题复盘”必须通过P6任务试拆验证，不能由P5-T3的未闭环入口替代。
12. 增量样表只有经过内部评审、用户确认和结构校验后，才能合并为新的主数据版本；旧增量样表不得自动升格为主表，必须明确标注“历史验证样例”“已合并依据”或“当前推荐主数据”。
13. V0.4字段是风险治理扩展层，不是对V0.3.3主数据的全量重做；在回填试验通过前，不得把字段清单存在本身等同于数据安全、编辑审核、平台发布或真实教学验证已经完成。

如果节点只写了名称、说明和关联任务，而没有资源、活动、评价、审核和学习记录字段，只能作为草稿节点，不能作为正式课程能力图谱节点。

### 10.2 课程能力图谱呈现分层原则

课程能力图谱可以有不同呈现层，不能把评审界面、教师编辑界面和学生学习界面混为一体。

1. 完整关系评审版适合教师、编辑、专家和研发人员使用，用于检查节点、关系、资源、审核状态和风险，不应直接作为学生端主学习界面；
2. 整书级整体原型可以展示课程主链、代表任务关系层、任务节点和节点邻域，用于说明图谱暗线如何贯穿整本教材；
3. 学生端最终只应展示与当前学习任务相关的局部路径、前后关系和可学习资源，不应把182条关系边、审核状态、资源证据编号等后台信息直接压给学生；
4. 教师端可以看到更完整的关系、任务衔接、讲评优先级和学生学习卡点；
5. 出版/编辑端可以看到资源审核、媒体风险、专业复核和平台挂接状态；
6. 所有图谱呈现都必须说明边界：内部试拆、待专业复核、待媒体审查不能写成最终定稿或专家审核通过。

### 10.3 V0.3.13接入整书原型字段路由原则

阶段1基线对齐后，后续从V0.3.13主数据进入整书原型、任务页、资源中心、教师端和出版/编辑端时，必须遵守 `reports/V0.3.13接入整书原型字段视图映射表V0.1.csv`。

基本规则：

1. V0.3.13是数据底座，不是学生正文；进入学生端前必须完成教学化转译；
2. 学生端可显示 `student_title`、`student_learning_goal`、`student_action`、`student_output`、`assessment_output`、资源类型和学习活动类型；
3. 学生端不得直接显示 `v03_record_id`、`node_id`、`audit_status`、`review_required_type`、`risk_level`、`media_handling_status`、`professional_risk_type`、`source_files` 等后台字段；
4. 教师端可以看到任务衔接、讲评优先级、专业风险和媒体风险，但仍应转译为教学语言；
5. 出版/编辑端可以承接完整审核、来源、媒体、风险、平台和版本治理字段；
6. 整书级原型只作为呈现框架复用，其静态数据不得覆盖V0.3.13主数据；
7. 3.5A-1只作为教材质量样章复用，不得写成全书所有任务均已完成同等质量生产。

## 11. 学习依据和学习记录原则

此前文档中大量使用“证据”一词，后续应更精确。

需要区分三类：

1. 专业判断依据：学生判断网优结果时查看的数据、图表、日志、截图等；
2. 学习过程记录：学生选择、填写、引用、修改、提交形成的学习痕迹；
3. 教材质量依据：图片是否可用、内容是否审核、阈值是否准确等质量记录。

学生端不宜频繁出现“证据项E03”这类表达，应改为：

1. 支持你判断的数据；
2. 你已经查看的材料；
3. 你的结论依据；
4. 还缺少的数据；
5. 提交前检查。

底层仍可保留 evidence_id、evidence_output 等字段，但前端要转译。

## 12. 自学模式原则

自学模式不能只是每张卡增加一句通用提示。

有效自学模式应按资源类型提供差异化支持：

| 资源类型 | 自学支持重点 |
| --- | --- |
| 情境任务 | 解释背景、角色和最终产出 |
| 知识说明 | 解释术语、关键概念和反例 |
| 数据材料 | 说明先看哪里、怎么看、能说明什么 |
| 交互练习 | 提供分层提示和错误原因 |
| 结论任务 | 提供写作框架和提交前检查 |
| 反馈修正 | 给出具体修改方向 |

如果自学模式没有改变学生完成任务的能力，就不能算真正支持自学。

## 13. 教材正文先行原则

数字教材不能把大纲、标题、资源入口和页面组件拼接后直接交给学生。

样章3.2形成以下硬性要求：

1. 先写学生能直接阅读的教材正文，再决定前端如何承载；
2. 教材正文必须围绕真实案例展开，不以知识点目录开场；
3. 学习段落应形成“真实案例 -> 引发疑问 -> 学生先判断 -> 答疑导学 -> 示范读数据 -> 学生实践 -> 反馈纠偏 -> 形成职业表达”的闭环；
4. 每个专业词只解释完成当前任务所需的含义，不能扩展成脱离任务的理论讲义；
5. 每组数据都要说明“能支持什么、不能说明什么”；
6. 每个学习段落都应有学生动作，如判断、填写、比较、解释、修改或提交；
7. 前端卡片、能力图谱、资源抽屉和学习记录都必须服务教材正文，不能替代教材正文；
8. 课堂模式和自学模式可以共用同一套正文，但必须改变学习组织方式。

如果样章只有大纲式标题、资源名称、指标堆叠或交互入口，即使页面美观，也不能通过教材性门禁。

## 14. 教师模式原则

教师内容必须和学生学习路径分离。

学生端不应出现教师卡。教师端可包含：

1. 教学目标；
2. 课堂流程；
3. 建议时间；
4. 学生常见错误；
5. 学习记录汇总；
6. 典型答案；
7. 讲评建议；
8. 资源开启或关闭设置；
9. 媒体和专业审核风险提示。

教师模式不是答案页，而是教学组织和学情诊断工具。

课时建议分配、分钟段、课堂节奏和控场安排原则上属于教师端信息。学生端可以看到学习顺序、当前任务、完成标准和最终产出，但不应把教师课时安排直接放入学生主学习界面，除非该信息会直接帮助学生完成学习任务。

## 15. 媒体治理原则

原教材图片不能因为来自教材就默认可用。

每个图片、视频、仿真截图进入样章前，都应判断：

1. 来源是否明确；
2. 是否清晰；
3. 是否有版权或授权风险；
4. 学生是否能看懂；
5. 是否有读图路径；
6. 能支持什么判断；
7. 不能支持什么判断；
8. 是否需要重绘、替换、标注或删除。

非通用仿真软件截图尤其不能裸用。正式样章中应采用以下处理之一：

1. 保留并补充清晰标注和读图说明；
2. 重新绘制成教学版图示；
3. 检索或制作通用化替代图；
4. 删除或转入附录。

占位符只能标记问题，不能解决问题。

## 16. 表图互动和资源转化原则

表、图、动画、互动和小游戏对数字教材是必要资源形态，但它们必须服务学习段落，而不能替代教材正文。

后续资源转化应遵守：

1. 每一屏或每一关优先解决一个小问题；
2. 表格必须配套“先看哪里、怎么看、能说明什么、不能说明什么”；
3. 图表必须服务判断动作，不能只作为装饰；
4. 动画优先用于展示过程变化、前后对比、因果链条和读图步骤；
5. 互动优先用于选择、匹配、排序、读数、判断、纠错和提交；
6. 小游戏只有在能训练岗位判断或学习动作时才使用，不能为了新颖而游戏化；
7. 资源转化位可以先标出，但不能把“未来可做动画/小游戏”伪装成已经完成的正式资源；
8. 当前样章如仍看不懂，应优先改文字、学习顺序和反馈支架，再增加资源形态。

样章3.3新增的硬性判断是：对于非专业首读学生，“从哪里开始学、每一步为什么做、做完后得出什么”必须显性呈现。学生不应先研究页面结构，才能理解学习任务。

## 17. 教学模拟案例原则

职业教育数字教材可以使用教学模拟案例。案例是否真实不是唯一标准，关键是是否正确、可复核、能传递知识和技能。

教学模拟案例必须遵守：

1. 明确标注为教学模拟，不能伪装成真实项目；
2. 指标、判断逻辑和结论必须符合专业基础知识；
3. 阈值只能作为本课目标或案例目标，不能写成行业通用标准；
4. 能通过可信来源、标准方向、原教材材料或专家复核解释其合理性；
5. 每个案例要承担明确教学功能，如入门示范、对照纠错、半扶手练习或独立实践；
6. 多案例不是堆数量，而是形成递进：看懂一个、比较两个、迁移一个、独立完成一个；
7. 案例内容不足时，优先检索可信来源和标准；仍不足时，可以结合基础知识合理化创造，但必须列出复核点。

样章3.4新增的硬性判断是：一节课不能只靠一个案例从头讲到底。高质量样章应通过多角度、递进式案例，让学生经历“示范 -> 对照 -> 练习 -> 独立实践”的学习过程。

## 18. 课程能力图谱与练习活动原则

课程能力图谱不是“能力地图”的简单改名，也不是教材目录或案例目录的可视化。

后续样章和工具链必须遵守：

1. 课程能力图谱应连接课程标准、岗位任务、项目任务、能力节点、卡片资源、学习活动和评价方式；
2. 课程能力图谱可以作为暗线导航层，但不能只是点击后跳转页面；
3. 图谱节点至少应能说明学习目标、前置/后续关系、关联卡片、学习活动、评价方式和审核状态；
4. 节点与卡片不必强制一一对应，可以是一对一、一对多、多对一或多对多，但必须可追踪；
5. 学生端可以使用更自然的语言，但后台治理和资源封装必须保留节点映射；
6. 练习方式应服务学习动作，慎用单纯问答；
7. 优先采用投诉线索归类、指标匹配、流程排序、读表标注、依据分类、错误结论修订、结论拼装和任务提交等能产生可检查产出的活动；
8. 互动、动画和小游戏必须绑定能力节点和评价规则，不能只为新颖或美观而存在。

样章3.5新增的硬性判断是：课程能力图谱必须成为数字教材核心脉络之一，至少在样章层面证明节点可以组织案例、卡片、学习活动和评价方式。练习多样化必须体现岗位动作价值，不能只是选择题换皮。

## 19. 整书级整体原型优先原则

单任务样章不能直接推导整书生产流程和工具链模块。即使某个任务样章已经形成内部正向基线，也只能说明该任务的呈现方式和学习闭环阶段性成立，不能说明整本数字教材的课程层、项目层、任务层、课程能力图谱暗线、教师视图、资源中心和出版/编辑视图已经成立。

进入生产流程与工具链模块拆解前，必须先验证整书级信息架构或整体原型：

1. 课程首页能说明课程整体学习路径；
2. 项目层能说明项目目标、任务链和对应能力群；
3. 任务层能承接一个纵向深样章，并能标明其他任务的结构占位状态；
4. 课程能力图谱能贯穿课程、项目、任务、卡片资源、学习活动和评价记录；
5. 学生视图、教师视图、资源中心、出版/编辑视图边界清楚；
6. 其他任务未完成深度制作时，必须明确标注为结构占位，不能伪装为完整数字教材内容；
7. 工具链拆解只能在整体原型证明层级和流转基本成立后进行。

当前整书级整体原型应采用“横向整书框架 + 一个纵向深样章”：3.5A-1作为项目四任务2深样章嵌入，其他项目和任务先用于验证结构、流转和映射，不继续消耗精力做任务级细节打磨。

## 20. 课程能力图谱主数据先行原则

课程能力图谱不能只作为前端可视化入口。进入资源生产、页面生产、平台挂接或工具链模块拆解前，必须先形成可维护的图谱主数据基线。

后续生产必须遵守：

1. 输入教材、课程标准、教学大纲、互联网补强材料和AI生成内容都要有来源、用途、复核状态和图谱绑定；
2. 节点、关系、资源、活动、评价、教师材料、媒体资源和输出物必须使用稳定ID；
3. 正式资源、活动、评价和页面呈现必须能挂接到课程根节点、项目任务节点或详细能力节点；
4. 多节点覆盖不能写成不可解析的复合主键，应拆成多条挂接或挂到上级节点；
5. 资源是否好看、页面是否完整，不能替代“它训练哪个能力节点、学生完成什么动作、形成什么产出、如何评价”的说明；
6. 媒体风险、专业风险、待审状态和模拟边界必须保留在主数据中，不能被前端展示效果掩盖；
7. 未进入图谱主数据的内容只能作为探索草稿，不应进入正式资源包或数字教材呈现层；
8. 工具链模块拆解应建立在主数据基线可扩展、可校验、可回写的基础上。

V0.3新增的硬性判断是：后续不是先继续扩大页面或资源样本，而是先评审课程能力图谱主数据基线。只有能稳定进入节点表、关系表、资源活动评价挂接表和输入输出物治理清单的内容，才适合进入下一轮正式生产。

## 20.1 用户信息与数据安全治理原则

P1-T3投诉信息采集暴露出用户信息治理门禁：凡涉及投诉人姓名、联系电话、详细地址、工作单位、号码、录音、投诉工单、客户等级、敏感客户身份、处理承诺和回访记录的内容，不能按普通教材表格或普通练习数据处理。

后续生产必须遵守：

1. 学生练习和样章展示优先使用脱敏或教学模拟数据；
2. 真实用户信息不得进入公开样章、资源包或截图；
3. 投诉信息表、电话录音、回访记录和处理承诺必须标注 `data_security` 或等效审核类型；
4. 客户沟通话术必须经过专业和编辑复核，不能鼓励越权承诺、推诿、误导或未取得同意的信息采集；
5. 投诉分类、升级边界、处理时限和客户等级相关表述必须保留来源和审核状态；
6. 如果后续字段规范发现 `review_required_type=data_security` 不足以表达脱敏、授权、录音和平台留痕要求，应升级字段规范，而不是把风险写在备注里长期滞留。

## 20.2 实训安全与位置数据治理原则

P2-T1 DT/CQT测试准备和执行暴露出现场测试类任务的治理门禁：凡涉及车辆路测、现场入场、设备供电、GPS打点、测试路线、CQT场景、测试卡、终端标识、测试LOG和客户场地的内容，不能按普通课堂练习或普通数据表处理。

后续生产必须遵守：

1. 学生端不得引导学生在无教师、企业导师或安全条件保障的情况下自行进行车辆路测、现场入场测试或真实公共场景拨测；
2. 路线图、GPS打点、测试点、客户场地和站点位置优先使用教学模拟或脱敏数据；
3. 测试卡号、终端标识、测试LOG、车辆信息和异常事件记录不得直接暴露真实工程数据；
4. 原教材中的软件界面、测试设备连接图和测试任务配置截图必须经过媒体审查、去厂商化重绘或教学化流程图替代后才能进入正式学生端；
5. 测试工具和设备清单只能作为资源、核对表或安全检查项，不得因为设备重要就升格为能力节点；
6. 如果后续字段规范发现现有 `teaching_validation`、`data_security`、`location` 等字段不足以表达实训安全和位置数据边界，应升级字段规范，而不是长期依赖备注说明。

## 20.3 项目链条关系表达原则

P2项目内部链条评审暴露出一个关系表达门禁：课程能力图谱不能把所有相邻任务都机械写成固定线性流程。项目内任务之间可能同时存在正常主线、异常处理分支、支撑判断和后续复用关系。

后续生产必须遵守：

1. 正常学习主线和异常处理分支必须分开表达，不能把异常处理任务写成所有场景必经关卡；
2. 对P2项目而言，更准确的表达是“测试采集主线 + 异常处理分支 + 数据分析输出”，而不是简单的“任务1 -> 任务2 -> 任务3”；
3. 图谱关系边应区分 `直接递进`、`支撑判断`、`问题回流`、`能力挂接` 和 `资源证据`，不能为了连线完整而混用关系类型；
4. 教材正文应向学生说明“什么时候直接进入分析，什么时候需要先处理异常”，不能只给目录式跳转；
5. 项目链条进入主数据合并前，同一项目内相关任务的字段治理成熟度应基本一致；如果某任务已进入V0.4风险治理，相关前后任务也应补齐必要的V0.4风险记录；
6. 链条评审通过只代表结构逻辑成立，不代表专业复核、媒体审查、数据安全、学生正文、页面呈现或平台发布门禁已完成。

## 20.4 优化实施与变更记录治理原则

P4-T1优化方案实施暴露出工程实施类任务的治理门禁：凡涉及天线调整、无线参数、承载网参数、核心网参数、网管或仿真软件界面、参数变更、实施记录和复测交接的内容，不能按普通知识讲解或普通软件操作题处理。

后续生产必须遵守：

1. 学生端不得引导学生在无授权、无教师或企业导师监督的情况下操作真实网络、真实网管或真实工程参数；
2. 学生训练重点应是识别优化对象、说明参数依据、判断责任边界、填写变更记录、标出风险回退条件和交接复测验证，不是独立执行真实工程变更；
3. 天线、无线、承载网和核心网可以作为专业分支资源、案例或活动场景，不应简单按四类对象拆成并列能力节点；
4. 原教材中的网管、仿真软件和数据中心界面截图必须经过媒体审查、去厂商化重绘、教学化参数表替代或标注为内部分析材料后才能进入正式学生端；
5. 任何参数调整建议都必须说明适用范围、可能副作用、回退条件和复测入口，不能写成通用处方；
6. 优化实施类节点进入主数据合并前，必须完成专业风险、媒体风险、数据安全、工程授权边界和真实教学验证门禁标注。

## 20.5 项目级内容闭环验证原则

阶段2项目四闭环样本说明：一个项目级闭环应能把前置任务、判断中枢和表达出口连起来，而不是只把三个任务并列展示。

后续生产必须遵守：

1. 项目级闭环至少应说明“输入证据从哪里来、学生做什么、形成什么产出、如何进入下一任务、发现问题如何回流”；
2. 轻量教材样稿可以用于验证项目链条，但必须标明尚未达到深样章质量，不能伪装为正式教材定稿；
3. 深样章可以作为质量锚点，但不能自动代表同项目其他任务已经达到同等质量；
4. 整书原型新增版本应优先新建目录，保留上一阶段基线，除非明确需要覆盖；
5. 阶段2项目闭环通过QA，只说明页面结构、交互和基本内容可运行，不代表专业复核、媒体审查、平台接口或真实教学验证完成；
6. 进入工具链模块拆解前，至少应有一个项目级闭环完成内部审计，并优先判断是否需要第二个项目级闭环复制验证。

## 20.6 项目级闭环复制验证原则

阶段2内部全量评审和轻量补强记录说明：第二个项目级闭环复制验证不能理解为继续铺页面，而应检验项目四方法是否能迁移到不同任务类型。

后续生产必须遵守：

1. 第二项目复制验证前，应先形成实施计划和闭环映射表，不得直接写页面；
2. 第二项目应优先选择与项目四任务类型明显不同的项目，用于验证方法迁移，而不是验证相同结构的重复页面；
3. 项目级闭环至少包含项目定位、任务角色、输入证据、学生动作、学生产出、回流关系、深样章锚点、图谱挂接、教师使用和出版门禁；
4. 轻量教材样稿只用于验证项目链条和内容组织，不得称为深样章或正式定稿；
5. 每个轻量样稿至少应包含学习情境、核心问题、学习步骤、结构化支架、学生产出、完成标准、教师讲评点、风险门禁和图谱绑定；
6. 教师视图不能只有状态说明，至少应说明课堂组织路径、讲评焦点和产出检查方式；
7. 资源中心必须区分已有样稿、待专业复核、待媒体重绘或替换、不可发布或仅作内部分析；
8. 出版/编辑视图必须说明是否只是挂接位置原型、是否有平台字段样例、是否有质量检测项和哪些事项阻断正式发布；
9. 两个项目级闭环稳定前，不进入生产工具链模块拆解。

## 20.7 第二项目原型收口原则

阶段3项目二闭环复制验证说明：第二项目原型通过QA和内部评审，只能说明项目级闭环方法具备一次跨项目迁移证据，不能自动推导出任务级深样章完成或工具链可拆解。

后续生产必须遵守：

1. P2-T3可作为深样章候选，但在形成独立任务级深样章页面、学习活动、教师材料和QA前，不得写成深样章已完成；
2. 项目级原型可以验证课程层、项目层、任务层、资源中心、教师视图和出版门禁是否连通，但不能替代学生实际学习页的深度制作；
3. P2-T2必须继续作为异常处理分支表达，不得在后续页面或图谱中退回机械线性三步；
4. 本地闭环节点和关系评审层如出现同编号节点，必须在数据治理或前端文案中说明来源，避免用户误以为是两个不同能力；
5. 移动端完整图谱即使无横向溢出，也只能作为评审视图；学生端仍应使用局部路径和当前任务相关图谱；
6. 两个项目级闭环稳定后，应先提炼共性流程，再决定是否制作P2-T3任务级深样章或进入工具链模块拆解。
7. 在至少形成第二个任务级深样章前，不宜把项目级闭环共性流程直接抽象为完整生产工具链。

## 20.8 整书综合母版治理原则

overall-0.5说明：整书综合母版可以解决多个阶段原型入口分散的问题，但它仍是综合入口和验证母版，不是完整数字教材定稿。

后续生产必须遵守：

1. 整书综合母版可以汇总阶段成果，但不得把轻量项目样稿写成深样章；
2. 母版应明确显示哪些项目已经形成闭环、哪些任务已有深样章、哪些任务只是候选；
3. 旧原型、阶段原型、任务深样章和图谱评审版必须保留可追溯入口，不能被新母版覆盖后失去证据链；
4. 母版中的图谱页适合作为教师、编辑和内部评审入口，不应直接替代学生第一学习界面；
5. 母版通过QA只代表入口整合、页面结构和基础交互成立，不代表专业复核、媒体审查、真实教学验证、平台接口或正式发布完成；
6. 如果母版暴露出项目层级、图谱层级或任务层级关系不清，应先修正入口和文案边界，不直接推进工具链模块拆解。

## 20.9 角色流程审计原则

整书母版和任务级深样章说明：页面QA能证明基本可运行，但不能证明教师和学生能顺畅使用。凡涉及整书入口、深样章入口、课堂/自学模式、教师页、资源页和跨页面返回的版本，应增加角色流程审计。

后续生产必须遵守：

1. 学生课堂带学流程至少应验证：从整书入口进入任务、看到第一步和完成标准、完成主要学习活动、形成可检查产出、能返回整书；
2. 学生自学跟练流程至少应验证：自学模式差异、术语支持、错误反馈、再试路径、局部课程能力图谱和移动端可用性；
3. 教师流程至少应验证：整书教师入口、任务级深样章入口、课时安排、提问脚本、典型答案、模拟或真实学情、课堂/自学验收边界和资源治理入口；
4. 跨页面入口不能只检查链接存在，必须真实点击并验证目标页面关键内容加载；
5. 角色流程审计通过只说明静态原型流程可走通，不代表真实一线教学验证、专业复核、媒体审查、平台接口或正式发布完成。

## 20.10 正式呈现层与治理评审层分离原则

数字教材预览说明：正式教材观察层不能被研发过程语言污染。学生、教师、出版社或非项目成员观察最终呈现时，应看到教材学习内容、教学组织、资源用途和交付方式，而不是“占位、候选、未接入、不是定稿、发布门禁、评审准备”等过程说明。

后续生产必须遵守：

1. 正式呈现观察版和治理评审版应分层保存，不能互相覆盖；
2. 正式呈现观察版应默认隐藏研发过程语言，只保留学习者和教师真正需要的内容；
3. 治理评审版必须继续保留风险、边界、复核状态、版本追溯和质量门禁，不能为了“看起来完整”而删除证据；
4. 教材必要的专业学习概念，如“边界、未闭环、后续建议、复测入口”，不得误删；
5. 给外部人员观察最终呈现时，应优先使用clean preview；需要审查风险和过程资产时，再打开治理评审版。

## 20.11 AI教师端与素材子平台边界原则

专家反馈说明：教师端不能继续表现为传统手工备课清单，也不能把AI表述为完全替代教师。更合理的产品定位是“AI预生成任务组织、讲评和复核建议，教师审核确认后执行”。同时，资源治理、素材加工、媒体审查和交付检查属于素材子平台或生产后台，不应在数字教材主学习界面中持续干扰教师和学生。

后续生产必须遵守：

1. 教师端主身份应聚焦任务组织、讲评和复核，而不是泛化的课前准备或带教提示；
2. AI可以生成教学组织建议、课堂节奏、提问脚本、讲评重点、复核清单和作业验收建议，但必须保留教师审核确认责任；
3. 不得把AI写成完全替代教师备课、专业判断、课堂组织和结果验收；
4. 素材入库、版权审查、媒体重绘、资源包封装、平台接口和质量检测应进入素材子平台/生产交付后台，不应作为学生和教师主阅读界面的同级学习场景；
5. 教材呈现端可以保留必要的资源卡片，但必须通过课程能力图谱映射说明资源服务哪个能力节点、学习活动和评价产出。

## 21. 质量门禁

后续样章进入评审前，至少应通过以下门禁：

1. 首屏是学习任务，不是卡片目录；
2. 学生端语言自然、教材化；
3. 不是大纲、标题或资源入口拼接，而是完整教材正文；
4. 教师端与学生端分离；
5. 每个资源单元内容完整；
6. 学生能完成一个可检查的任务产出；
7. 专业判断依据能说明“能支持什么、不能支持什么”；
8. 每组数据都有读法、边界和反馈；
9. 自学模式提供差异化帮助；
10. 课程能力图谱可打开、可点击，并能说明节点关系、关联卡片、学习活动和评价方式；
11. 媒体资源有审查状态；
12. 专业阈值、数据和结论有待审核标记；
13. 桌面端和移动端通过浏览器QA；
14. 表、图、动画、互动和小游戏有明确学习用途，不是资源堆叠；
15. 每一屏或每一关能说明学生当前要解决的小问题；
16. 教学模拟案例标注清楚，不伪装成真实项目；
17. 一节课样章应包含示范、对照、练习和独立实践，不只是一例到底；
18. 练习方式具有明确教学目的，不能只是问答题或选择题堆叠；
19. 旧低保真样本不得作为高质量成果展示；
20. 用户个人评审、内部预评审和浏览器QA不能替代真实一线教师/学生试看；
21. 教学模拟案例、专业阈值和结论口径在通信专业复核前，必须继续标注为待复核或教学模拟边界；
22. 进入工具链模块拆解前，必须至少形成整书级信息架构或整体原型，验证课程层、项目层、任务层、课程能力图谱暗线和多角色流转；
23. 进入正式资源、活动、评价或页面生产前，必须能回写到课程能力图谱主数据，不能让内容游离于节点、关系和审核状态之外。
24. 涉及用户投诉信息、个人联系方式、地址、录音、客户等级和处理承诺的内容，必须完成脱敏、数据安全和服务表达边界治理后，才能进入正式学生端或资源包。
25. 涉及V0.4字段治理范围的节点、资源、活动、评价和输出物，必须完成字段回填、结构校验和内部评审后，才能作为下一轮正式生产或自动化门禁依据。
26. 涉及车辆路测、现场入场、测试路线、CQT场景、GPS打点、测试卡、终端标识、软件截图和测试LOG的内容，必须完成实训安全、位置数据、媒体审查和数据安全治理后，才能进入正式学生端或资源包。
27. 涉及优化方案实施、参数调整、网管/仿真软件界面、工程变更记录和复测交接的内容，必须完成专业责任边界、工程授权、媒体重绘、风险回退和复测验证门禁后，才能进入正式学生端或资源包。
28. 课程能力图谱主数据建设与内部结构验证阶段完成，只能说明图谱主数据可作为后续内容生产基础；不得表述为整本数字教材完成、专家定稿完成、媒体审查完成、出版社平台发布完成或真实教学验证完成。
29. 项目级内容闭环样本通过QA，只能说明一个项目范围内的内容、资源、活动、评价、教师和出版门禁可以在原型中连起来；不得表述为全书数字教材完成或生产工具链完成。
30. 第二项目级闭环复制验证前，必须先形成实施计划和闭环映射表，并通过轻量补强检查表约束；不得直接进入页面生产或工具链模块拆解。
31. 第二项目级闭环原型通过QA和内部评审后，必须先形成阶段收口审计和跨项目共性流程提炼；不得直接表述为P2-T3深样章完成、全书批量生产开始或生产工具链模块拆解开始。
32. 进入生产工具链模块拆解前，至少应具备两个项目级闭环样本和两个任务级深样章证据；当前只有P4-T2一个任务级深样章。受2026-06-29专家反馈影响，P2-T3深样章前应先完成clean preview专家反馈吸收计划，明确AI教师端、素材子平台边界和能力图谱映射图形后，再继续P2-T3深样章验证。
33. 整书综合母版形成后，仍必须区分综合入口、项目级闭环样本和任务级深样章；母版通过QA不能替代第二个任务级深样章证据。
34. 跨页面入口不能只检查链接文本、`href` 或目标文件存在；必须真实点击并验证目标页面加载、关键标题/正文出现、控制台无错误。
35. 涉及学生、教师、资源和跨页面流转的版本，必须补充角色流程审计；角色流程审计通过不能替代真实一线试看和专业复核。
36. 正式呈现观察版不得展示会干扰最终效果判断的研发过程语言；治理评审信息必须保留在治理版或内部评审层中。
37. 整书级平台界面必须区分一级导航、二级导航和右侧上下文：顶部导航只表示使用场景，左侧栏只表示当前场景下的对象选择；需要右侧上下文栏的页面，右侧栏只解释当前选中对象和下一步动作；图谱页可取消右侧上下文栏以保证图谱主体可读面积。不得在课程、图谱、教师、资源或交付页长期显示项目目录，造成层级混乱。
38. 课程能力图谱页不能只以节点清单、文字说明或评审表格替代图谱；正式呈现观察版至少应表达课程主链、项目路径、能力节点、资源卡片和评价产出之间的层级关系，并支持能力节点到资源卡片、资源卡片到能力节点的双向定位。
39. 教师端不得只呈现备课清单或课堂提示，应体现AI生成任务组织、讲评和复核建议，并由教师审核确认后执行。
40. 资源治理、素材加工、媒体审查和交付检查不得混入学生/教师主学习界面；正式呈现端保留的资源必须通过课程能力图谱映射到能力节点、学习活动和评价产出。

## 22. 后续执行纪律

每次进入新阶段前，应检查：

1. 是否违反本文件原则；
2. 是否需要更新决策日志；
3. 是否需要更新资产总表；
4. 是否需要更新任务连续性记录；
5. 是否新增了未分类文件。

如果设计或实现与本文件冲突，应先更新原则并说明理由，再继续执行。
